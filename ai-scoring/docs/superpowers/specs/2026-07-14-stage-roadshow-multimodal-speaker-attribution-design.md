# 现场路演多模态人物归属系统设计

**日期：** 2026-07-14  
**状态：** 待用户最终审阅  
**适用范围：** 上传视频评分、在线路演实时分析及终场报告  
**设计原则：** 场景约束、多模态互证、高准确优先、安全降级、评分解耦

## 1. 背景与问题

现场路演通常由四名参赛选手共同完成，但整场录制中的实际发言人数不受四人限制。评委、工作人员、指导人员或其他临时人员可能进入画面、画外提问、插话或打断。系统必须稳定识别四名参赛选手，同时允许任意数量的动态外部人员和画外发言人。

现有链路并行运行云端 ASR、本地声纹分离和本地 LR-ASD，之后根据时间重叠把主动说话人证据融合进声纹 turn。真实视频验证表明，这种后置融合无法解决核心问题：纯音频声纹可能把同一人拆成多个簇，而 LR-ASD 只判断当前画面候选人是否说话，不负责跨镜头人物身份统一。由此会出现“画面中四名选手，最终展示八名发言人”的错误产品解释。

本设计将人物归属从后置补丁升级为独立的多模态证据系统，目标是生成可信的“谁在什么时候说了什么”，但不直接生成、读取或修改评分字段。

## 2. 目标与非目标

### 2.1 目标

- 为上传视频和在线路演提供同一套人物归属逻辑。
- 稳定维护四名参赛选手身份，同时支持零到多名动态外部人员和画外发言人。
- 将 ASR 文字按稳定人物和准确时间范围拆分。
- 在线阶段提供低延迟临时结果，并允许短时间自动修订。
- 终场阶段使用全局证据合并身份碎片并冻结最终结果。
- 在低置信、重叠、画外或媒体缺失时明确降级，不强制猜测人物。
- 保持证据流与评分流解耦，避免外部人员发言污染选手证据。
- 复用现有时间轴、音频网关、ASR、LR-ASD、Java 持久化和前端报告基础。

### 2.2 非目标

- 不承诺所有文字都能自动分配到具体人物。
- 不把团队人数作为整场说话人数上限。
- 不把声纹簇、人脸轨迹或身体轨迹直接等同于人物。
- 不要求用户预先录制声纹。
- 不依赖用户人工修正才能完成正式流程。
- 本阶段不训练通用端到端音视频日志大模型。
- 本系统不直接参与评分计算。

## 3. 核心产品原则

1. 四名选手是业务角色先验，不是聚类数量约束。
2. 同一人物可关联多个脸部轨迹、身体轨迹和声纹簇。
3. 新声音不得因为已有四名选手而被强制合并给某位选手。
4. 外部人员和画外人员完整保留在会议纪要中，但不默认成为参赛选手证据。
5. 证据不足时使用“发言人待确认”或“画外发言人”，准确率优先于覆盖率。
6. 所有自动人物决定必须保留证据来源、置信度、冲突原因和模型版本。
7. 临时结果可修订；终态结果只能通过更高 revision 的完整终态快照替换。

## 4. 方案选择

### 4.1 放弃继续扩展后置融合

“ASR + 纯音频分离 + LR-ASD，最后按时间重叠拼接”成本较低，但声纹簇仍然决定人物基础，无法避免重复人物和错误外部人员合并，只保留为降级通道。

### 4.2 暂不采用通用端到端模型作为主链路

端到端音视频日志模型理论上具备更高长期上限，但当前缺少路演场景标注数据，低清远景、画外音、本地实时推理和故障解释风险较高。后续可作为影子模型进行评测，达到门槛后替换局部组件。

### 4.3 采用场景约束型多模态人物归属系统

系统将检测、跟踪、主动说话、声纹、ASR 和身份图解耦。每种模型只负责自身擅长的证据，由可解释的融合引擎产生最终人物归属。这是当前商业可交付性、稳定性、准确率、并发和长期演进的最优平衡。

## 5. 总体架构

```text
                    统一音视频入口
                           │
                   同步时钟与分片器
                           │
       ┌───────────────────┴───────────────────┐
       │                                       │
   音频证据链                              视频证据链
VAD / 流式ASR / 声纹                 人脸 / 身体 / 轨迹
说话切换 / 重叠检测                  LR-ASD / 可见性判断
       │                                       │
       └───────────────────┬───────────────────┘
                           │
                    本场人物身份图
                           │
                   多模态人物归属引擎
                           │
             ┌─────────────┴─────────────┐
             │                           │
        实时临时结果                 终场全局校正
        1～3秒延迟                  合并身份碎片
        最近10秒可修订              冻结最终人物版ASR
```

### 5.1 在线路演

- 继续使用现有实时 PCM 网关和云端流式 ASR。
- 本地媒体订阅器只订阅 LiveKit 摄像头轨道作为人物画面，屏幕共享不进入人物识别。
- 摄像头以 5～8 fps 提供带原始 PTS 的画面给视觉工作池。
- 实时阶段输出 provisional 人物分段，最近 10 秒允许自动修订。
- 会议结束后使用完整录制和本场身份图执行全局修正，目标 1～3 分钟完成。
- 实时视频或视觉模型不可用时，音频和完整录像继续保留，终场可补算。

### 5.2 上传视频

- 以媒体 PTS 为统一主时钟，将视频按时间顺序高速送入同一人物归属引擎。
- 音频、视频、ASR 和声纹分支并行运行。
- 文件结束后执行同样的全局身份归并。
- 最终输出契约与在线路演一致。

## 6. 现有时间轴复用

现有系统已经具备可复用基础：前端按音频采样数生成 `startMs/endMs`；Python 音频网关支持 sequence、哈希、断线恢复、幂等、缺口和覆盖率；证据契约递归校验毫秒范围；实时 finalizer 能冻结转写和视觉证据；Java 能按时间排序、校验并持久化 ASR 分段。

不重新建设时间轴，只补充以下能力：

- `clockId`、`timebase` 和 `masterSource`。
- 在线视频 PTS 到音频采样时钟的映射。
- 音视频漂移检测、校正记录和置信度降级。
- 视频序列完整性和覆盖率。
- provisional revision 与终态冻结语义。
- `speakerTurns` 和 `speakerIdentities` 的正式填充。

在线路演以音频采样时钟为主，上传视频以媒体 PTS 为主。原始时间戳永远保留，校正值单独记录。

## 7. 人物身份模型

### 7.1 人物类型

- `CONTESTANT`：参赛选手，对应可选的 `contestantSlot=1..4`。
- `VISITOR`：进入画面且发生有效发言的外部人员。
- `OFFSCREEN`：有稳定声音但没有可靠画面对应的人。
- `UNKNOWN`：当前证据不足。
- `OVERLAP`：多人同时发言，无法可靠拆分为单人。

四个参赛角色槽位在会话开始时创建，但不预绑定声纹簇或脸部轨迹。

### 7.2 三层身份结构

1. 原始观测：脸部轨迹、身体轨迹、声纹簇、主动说话区间、ASR 词语时间戳。
2. 本场稳定人物：`personId`、人物类型、轨迹集合、本场声纹库、首末出现时间和模型 revision。
3. 用户显示身份：1号选手、AI算法工程师、工作人员1、画外发言人1或发言人待确认。

原始观测用于审计和重新计算，前端只展示稳定人物。

### 7.3 人物状态机

```text
OBSERVED → CANDIDATE → STABLE → CONTESTANT / VISITOR / OFFSCREEN
                         ├──→ MERGED
                         └──→ RETIRED
```

- `OBSERVED`：只出现单一弱观测。
- `CANDIDATE`：积累连续证据，但不足以正式展示。
- `STABLE`：达到稳定身份门槛。
- `MERGED`：确认与另一个 personId 为同一人物。
- `RETIRED`：误检、噪声或无效短轨迹。

## 8. 模型职责

### 8.1 LR-ASD

LR-ASD 保留为可替换插件，只回答“时间窗口内某个画面轨迹正在说话的概率”。它不确定人数、不创建最终人物、不命名、不决定声纹簇，也不直接修改 ASR。

接口稳定后可在同一输入输出契约下影子评测 TalkNet、LoCoNet 或其他模型，不改动 Java、前端和身份图。

### 8.2 人脸和身体身份

- 人脸证据用于清晰正脸或可接受姿态下的高精度身份匹配。
- 身体外观、服装、空间位置和运动连续性用于低清、转身和遮挡场景。
- 同一人跨镜头重新出现时应复用 personId，而不是创建新人物。
- 同一时间出现在两个位置是强冲突，禁止合并。

### 8.3 本场声纹自动注册

当单一主要声音、主动说话、人物轨迹稳定、发言持续充分且不存在重叠时，自动积累该人物的本场声纹。声纹用于遮挡、背对镜头和画外延续场景，不要求用户预录。

声纹簇允许多对一关联到人物。新声音不能仅因“在四名选手中最相似”而强制合并。

## 9. 人物创建、合并和拆分

### 9.1 新声音处理

1. 优先检查是否匹配已有稳定人物声纹。
2. 若不匹配，检查同期是否存在高置信主动说话的稳定画面人物。
3. 若存在，创建或归入 `VISITOR`。
4. 若没有可靠画面但形成稳定新声纹，创建 `OFFSCREEN`。
5. 若证据不足，保留 `UNKNOWN`，不丢弃文本。

### 9.2 合并门槛

满足至少两种独立证据一致，或单一强人脸证据达到严格门槛且无冲突，才能合并人物。证据包括人脸、身体、声纹、时空连续性、主动说话同步、自我介绍语义和舞台位置。

以下条件具有否决权：同一时间同屏不同位置、重叠声音、跨模态持续冲突、只有相对相似而绝对分数不足。

### 9.3 自动拆分

如果后续出现同一 personId 同时处于两个位置、两个长期分离声纹中心或持续音视频冲突，实时身份允许拆分并提升 revision。终态冻结后只能通过新终态版本替换，旧终态保留审计信息。

### 9.4 画外人员进入画面

先出现的 `OFFSCREEN_n` 在后续与新画面人物的主动说话和声纹稳定匹配时升级为 `VISITOR_n`，并在终场全局修正中回填历史分段。

### 9.5 重叠发言

检测到多人同时说话时保存候选人物并标记 `OVERLAP`。只有音频分离和 ASR 能可靠拆出独立语音时才生成子段，否则不强制选择单人。

## 10. 决策与置信度

不能简单对多项概率做无约束平均，采用四级决策：

1. 有效性检查：媒体、时间戳和模型状态可用。
2. 候选打分：人脸、身体、声纹、LR-ASD 和时间连续性。
3. 领先优势：第一候选必须明显高于第二候选。
4. 冲突否决：同屏、重叠、漂移或跨模态冲突直接降级。

建议初始门槛：

- `CONFIRMED`：综合置信度不低于 0.85，领先优势充分且无否决冲突。
- `PROVISIONAL`：0.70～0.85，只用于实时临时结果。
- `UNKNOWN`：低于 0.70 或存在关键冲突。
- `OVERLAP`：确认存在多人同时发言。

阈值必须配置化，并通过真实路演片段校准。团队人数只能提供弱角色先验，不能直接提高人物身份置信度。

## 11. ASR 人物切段

- 优先使用词级或短句级时间戳。
- 人物切换持续超过最小稳定时间后才拆段，避免语气词造成抖动。
- 短停顿后仍是同一人物时合并。
- 外部人员插话必须切断前后选手发言，不能形成同一大段。
- 实时阶段最近 10 秒允许 revision 更新。
- 终场阶段根据完整身份图重新生成最终分段。

## 13. 服务职责

### 13.1 Python

负责音视频同步、人脸和身体跟踪、主动说话判断、声纹注册、动态人物创建、身份图、ASR 人物切段、实时修订、终场归并和证据置信度。Python 不直接写 Java 数据库，不产生评分字段。

### 13.2 Java

负责会话、媒体资产、版本化回调、事务落库、终态保护、报告 API、租户权限、有效快照和回调重放。Java 不重新计算声纹和人物归属。

### 13.3 前端

按 `segmentId + revision` 更新实时分段，最终报告只读取终态；区分参赛选手、外部人员、画外人员、待确认和重叠；不展示声纹簇或脸部轨迹数量。人工编辑保留为管理员纠错能力，但不属于正式流程依赖。

## 14. 数据库演进

复用现有 `ai_score_speaker_identity` 和 `ai_score_transcript_segment`。

人物表新增：`person_id`、`person_type`、`contestant_slot`、`model_revision`、`first_seen_ms`、`last_seen_ms`、`identity_state`、`evidence_summary_json`、`finalized_at`。

转写表新增：`segment_uid`、`revision`、`person_id`、`speaker_state`、`speaker_confidence`、`is_final`。

迁移必须向后兼容：旧 `speakerLabel` 继续可读，新会话优先使用 `personId`；在影子运行阶段不删除旧字段。

## 15. 并发与性能

### 15.1 调度

```text
调度器
 ├─ 实时会议高优先级队列
 ├─ 上传视频普通队列
 └─ 终态补算低优先级队列
          ↓
持久化模型工作池
 ├─ 人脸/身体 Worker
 ├─ LR-ASD Worker
 └─ 声纹 Worker
```

- 一个视频只解码一次，视觉模块共享帧。
- 音频只转换一次 16 kHz PCM。
- ASR、视觉和声纹分支并行运行。
- LR-ASD 和其他本地模型使用常驻 worker，不为每个任务重新加载。
- 实时任务优先，上传任务允许在安全分片边界暂停。
- 并发容量由目标硬件启动基准确定，不能写死固定路数。
- 微批处理必须通过准确率和延迟基准后启用。

### 15.2 性能目标

- 在线 ASR 临时文字 P95 不超过 1.5 秒。
- 在线临时人物归属 P95 不超过 3 秒。
- 实时推理积压超过 3 秒时主动降帧，不无限积压。
- 在线会议终场人物校正目标 1～3 分钟。
- 一小时上传视频的人物归属分支目标不超过 12 分钟。
- 整体评分流水线保持原有约 15 分钟目标，人物分析不得串行增加十几分钟。

性能目标必须在实际部署硬件上通过压力测试后对外承诺。

## 16. 降级与错误处理

| 故障 | 行为 |
|---|---|
| LR-ASD 不可用 | 保留 ASR 和声纹，视觉归属降级 |
| 人脸过小 | 使用已注册声纹、身体和上下文 |
| 声纹不可用 | 使用主动说话和视觉，低置信保留待确认 |
| 实时视频中断 | 音频继续，恢复后重新关联，终场补算 |
| 音频存在缺口 | 标记缺口范围，禁止该范围高置信归属 |
| 画外人员插话 | 创建 OFFSCREEN 或 UNKNOWN |
| 多人同时发言 | 标记 OVERLAP，不强制单人 |
| GPU/MPS 繁忙 | 实时优先，上传排队或安全暂停 |
| Python 回调失败 | 自动重试，Java 保留旧终态并支持重放 |
| 终场校正失败 | 保留完整临时快照并标记未完成终审 |

人物识别失败不能造成 ASR 丢失，也不能使主任务停留在无终态状态。

## 17. 验收指标

### 17.1 准确率指标

- 外部人员错误归入参赛选手的发言时长比例低于 1%。
- 高置信片段人物准确率不低于 95%。
- 同一选手不能在终态中被重复展示为多个稳定人物。
- 不同人物不能因声纹相似而错误合并。
- 所有低置信片段具有明确 `UNKNOWN`、`OFFSCREEN` 或 `OVERLAP` 状态。
- 同时统计人物归属文字错误率和待确认覆盖率，不能通过大量拒识伪装准确率。
- 切换门禁只接受独立人工标注时间段，不得以模型置信度、自我一致性或候选身份数量代替准确率。
- 首次切换至少需要 10 分钟独立标注时长，且高置信已归属时长覆盖率不低于 50%；覆盖不足即使命中率为 100% 也不得切换。

### 17.2 稳定性指标

- 单一视觉模型失败时 ASR 和评分任务仍能完成。
- 相同终态回调幂等，旧 revision 不能覆盖新终态。
- 断线恢复不重复写入人物和分段。
- 媒体缺口、时钟漂移和降级原因可审计。

### 17.3 性能指标

- 在线人物归属 P95 不超过 3 秒。
- 一小时上传视频人物分支不超过 12 分钟。
- 在线会议结束后终态人物校正目标 1～3 分钟。
- 在线 P95 必须来自实际增量人物归属消费者的端到端样本；仅有摄像头传输、采样或队列延迟不得冒充人物归属延迟。
- 上传任务不得以不可抢占的长任务占满唯一模型 worker 并阻塞实时人物归属；未验证资源隔离前门禁保持关闭。

短期不建设完整黄金样本集。使用真实视频中的开场、自我介绍、轮换发言、远景、遮挡、画外插话和重叠发言等关键片段建立小规模验收片段集。该标注仅用于测试，不进入用户工作流，也不用于人工修正正式结果。

## 18. 实施顺序与检查点

### 检查点 1：契约与兼容层

- 升级证据契约、回调 DTO 和数据库迁移。
- 旧报告和旧 `speakerLabel` 继续可读。
- 不改变当前对外人物结果。

### 检查点 2：上传视频终态身份图

- 实现人物状态机、身份图、自动声纹注册和多对一簇合并。
- 先使用上传视频离线终态验证，不接实时流。
- 真实视频不得再把四名选手展示成八名人物。

### 检查点 3：视觉身份增强

- 加入身体轨迹、跨镜头重识别和冲突否决。
- 覆盖转身、遮挡、重新入镜和外部人员进入画面。

### 检查点 4：常驻模型工作池

- LR-ASD、视觉和声纹模型改为常驻 worker。
- 单次解码共享帧，完成耗时和并发基准。

### 检查点 5：在线实时接入

- 增加 LiveKit 摄像头订阅和统一时钟映射。
- 增加 provisional revision、积压降帧和断线恢复。

### 检查点 6：Java 终态落库与 API

- 事务写入 identity、turn 和 transcript。
- 增加终态保护、回调重试和完成回调重放。

### 检查点 7：前端呈现

- 结果按稳定人物显示。
- 参赛选手、外部、画外、待确认和重叠具有清晰标签。
- 不展示原始簇数量。

### 检查点 8：影子运行和切换

- 新旧人物结果并行但仅旧结果对外。
- 比较准确率、拒识率、延迟和稳定性。
- 达到门槛后切换新链路，旧链路保留为降级通道。
- 任一准确率、覆盖率、在线端到端延迟、上传耗时或终态可靠性证据缺失时输出具名 `NO_GO`，不得自动修改开关。

## 19. 风险与控制

- **低清人脸和嘴部像素不足：** 不放宽阈值强认，依赖身体、声纹和高置信锚点。
- **外部人员短暂插话：** 保留文字和 UNKNOWN，不因持续时间短而归给选手。
- **声纹随距离和朝向变化：** 允许一个人物关联多个簇，用视觉锚点和全局图合并。
- **服装相似或人员换位：** 身体证据不能单独决定身份，必须与时空、人脸或声纹互证。
- **实时资源不足：** 有界队列、实时优先、主动降帧、上传安全暂停。
- **模型升级改变结果：** 保存模型版本、原始证据引用、revision 和终态快照哈希。
- **用户误解人数：** UI 展示稳定人物和状态，不展示声纹簇数量。

## 20. 最终决策

采用场景约束型多模态人物归属系统作为正式产品架构。保留 LR-ASD 作为可替换的主动说话检测组件，保留现有纯音频人物链路作为明确降级通道。四名参赛选手作为角色先验而非人数限制，动态外部人员和画外人员不设上限。低置信结果安全降级，不为了覆盖率牺牲人物归属准确率。
