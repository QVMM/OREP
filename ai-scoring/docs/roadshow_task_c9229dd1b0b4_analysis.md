5. 视觉风格干净但薄：整体统一、可读，但太像通用 SaaS 信息图，缺少 paper-ppt-agent 那种信息密度、叙事张力和视觉完成度。

## 3. 内容分析

### 3.1 已经做对的地方

这版内容已经明显具备“路演汇报”的基本骨架：

- 覆盖了项目定位、问题洞察、技术架构、核心功能、实操演示、数据证据、职业素养、风险控制、应用价值、团队协作。
- 引入了 55 分钟现场讲解逻辑，而不是单纯生成一份静态说明 PPT。
- 保留了匿名团队角色 A/B/C/D，符合不能出现个人信息的要求。
- 实操环节不是一句话带过，而是拆成设备接入、数据采集、异常注入、工单处理、安全审计、报告导出。
- 证据链意识已经出现，能表达日志、截图、工单、审计报告、输出文件、现场录像等材料。

这些说明 `roadshow_agent` 的方向是对的，至少已经不再是论文 PPT 的叙事结构。

### 3.2 内容上的主要问题

#### 问题一：项目标题没有锁定

材料分析阶段识别出的项目名称是：

> 智能仓储设备健康监测与安全作业辅助系统

但 design spec 和 SVG 中统一变成：

> 智慧仓储预测性运维系统

这不是简单改名，而是改变了项目定位。原项目强调“健康监测 + 安全作业辅助”，生成稿偏向“预测性运维”。这会导致评委看到的 PPT 与作品说明书不一致。

原因判断：

- 资料分析阶段识别正确。
- strategist 阶段重新抽象项目名时发生了改写。
- executor 后续又把错误项目名固化到页脚、封面、章节页。

修复方向：

- 增加 `locked_project_title`，从资料分析阶段开始锁定，后续 agent 不允许改写。
- 如果需要短标题，只能生成 `display_short_title`，不能覆盖正式标题。
- 封面、页脚、design spec、export metadata 都必须使用同一个锁定标题。

#### 问题二：出现占位符，正式比赛不可用

第 1 页封面保留了：

> `[团队名称/编号] · [赛事名称] · [日期]`

第 42 页封底 spec 中还写了：

> `[团队名称/编号] | [联系方式] (可选)`

这违反了我们已经确定的比赛约束：不要出现姓名、学校、电话、邮箱等个人或归属信息。即便是占位符，也会给用户误导。

修复方向：

- 路演 PPT 禁止输出任何团队名称、学校、联系方式占位符。
- 可替换为“职业院校技能大赛作品汇报”“现场演示材料”“参赛作品展示”等中性文字。
- 增加最终合规扫描：命中 `团队名称`、`学校`、`联系方式`、`电话`、`邮箱`、`[日期]` 等占位符时，正式导出拦截。

#### 问题三：数据证据存在二次编造

材料分析中确定的数据是：

| 指标 | 材料中数据 |
| --- | --- |
| 平均采集延迟 | 2.4 秒 |
| 异常识别准确率 | 91.7% |
| 告警生成成功率 | 100% |
| 工单闭环完整率 | 100% |
| 离线补传成功率 | 98.6% |
| 测试数据规模 | 1200 条 |
| 设备数量 | 6 台 |
| 闭环工单 | 18 条 |

但第 26 页生成了：

| 指标 | 生成数据 |
| --- | --- |
| 识别准确率 | 97.2% |
| 告警响应时间 | 3.8s |
| 平均无故障时间提升 | +35% |
| 工单闭环率 | 100% |
| 报告生成时间 | 28s |

这些数据中一部分来自材料，一部分是模型新增。对于职业院校技能大赛，这很危险，因为我们之前明确要求“不能信息造假，数据最好标注来源”。

修复方向：

- 证据链 agent 需要输出 `verified_metrics` 和 `unverified_claims`。
- 页面生成只能使用 `verified_metrics`。
- 如果想展示推测性目标，只能标注为“目标值 / 待实测”，不能写成“达成情况”。
- 对每个 KPI 强制带 `source`、`verification_method`、`confidence`。

#### 问题四：联网研究结果污染上下文

外部研究结果中出现了这样一段内容：

> 我目前没有联网搜索工具可供调用。

同时查询词是：

> web: "智"

这说明前面的标题/关键词抽取出了问题，只拿到了一个“智”字去搜索。更严重的是，Mimo 返回的不是研究结果，而是模型自述，但系统仍把它写入了 enrichment context。

影响：

- 研究增强没有提供真实外部资料。
- 后续 agent 可能误以为已经有外部研究。
- 用户侧会以为“深度研究”已完成，但实际没有有效联网资料。

修复方向：

- 联网研究结果必须做结构校验：URL 为空、标题为道歉、自述无工具、无来源时直接丢弃。
- 查询词不能低于 6 个汉字，不能是单字。
- 如果联网失败，前端和日志必须显示“联网研究无有效结果”，不能静默进入后续阶段。

#### 问题五：内容有比赛结构，但缺评委视角的“回答”

这版 PPT 页面很多是在“介绍系统有什么”，但比赛 PPT 更需要回答评委的隐含问题：

- 你为什么做这个项目？
- 任务难点在哪里？
- 技能水平体现在哪里？
- 现场操作能证明什么？
- 数据怎么来的？
- 证据是否可追溯？
- 团队如何协作？
- 风险怎么控制？
- 改进方向是否真实？

当前页标题虽然覆盖这些模块，但页面内部往往没有明确的“评委关注点 -> 证据 -> 结论”闭环。例如第 8 页 KPI 是目标卡片，第 26 页是达成卡片，但没有把两者用数据来源和测试方法强绑定起来。

## 4. 视觉样式分析

### 4.1 整体视觉优点

这一版有一些基础优点：

- 页面整体统一，白底、蓝绿主色、卡片、时间轴、流程图风格基本一致。
- 文字可读性尚可，大部分页面没有明显越界。
- 第 2 页目录、第 20 页异常注入、第 26 页性能指标、第 27 页证据链属于相对可用页面。
- 章节页风格一致，不会突兀。
- 没有早期那种过度复杂的深色科技背景，也没有明显重叠。

### 4.2 视觉核心问题

#### 问题一：太“淡”，缺少比赛作品页的视觉重心

大量页面留白过大，主视觉不够强。例如第 9、10、11 页本应是技术架构重点页，但实际画面非常空，信息集中在下半部或右侧，评委远距离看会觉得“没东西”。

这和 paper-ppt-agent 的差距主要在于：

- paper-ppt-agent 会把论文中的模型结构、公式、实验图、对比结果压成高信息密度页面。
- 当前路演分支把内容拆成了很轻的卡片和列表，缺少“一页一个强图”的意识。

#### 问题二：页面形式重复

31 页中大量页面使用同一套结构：

- 左上标题
- 底部页脚
- 中间卡片/列表
- 蓝绿强调线

统一不是坏事，但现在缺少“页面角色差异”。封面、目录、架构、实操、数据、风险、团队页应该有不同的视觉语法。

当前的问题是：`page_role` 有了，但 executor 没有把 `page_role` 转换成稳定的版式策略。

#### 问题三：图形质量像“临时示意”，不是“作品展示”

第 27 页证据链卡片里的日志、曲线、流程、视频等图形是模型手绘的符号，能说明意思，但不够像真实证据。第 20 页告警弹窗也是模拟得比较规整，但仍偏“假 UI”。

比赛 PPT 可以接受模拟数据，但证据页应该尽量像“系统真实产物”：

- 日志要有时间戳、设备编号、事件类型。
- 告警截图要像真实系统界面。
- 工单记录要有处理状态、复核字段、证据编号。
- 审计报告要有结论、风险等级、导出编号。

现在的视觉只是“证据概念”，不是“证据材料”。

#### 问题四：封面不够像正式比赛作品

第 1 页封面干净，但问题明显：

- 标题被改写。
- 没有主题相关插画或具体设备/系统视觉。
- 背景是通用科技点线和淡色几何，辨识度弱。
- 底部有占位符。
- “职业技能大赛路演演示”过于泛，缺少作品汇报感。

封面应该做到：项目名准确、视觉对象明确、无无效占位、比赛气质稳。

#### 问题五：架构页是最大短板

第 9 页本应是核心架构页，但实际渲染后几乎没有架构图，只剩标题和底部说明文字。SVG 中虽然引用了 `fig_001_p10_table.png`，但该图片其实是 KPI 表格，不是五层架构图。

这直接导致：

- 页面标题是“五层系统架构”，但画面没有五层架构。
- 图片素材语义错配。
- 页面视觉重心消失。

这是“图乱截”的典型来源。

## 5. 图片与素材问题

### 5.1 当前抽取到的图片

系统只抽取了 3 张图片，全部来自 PDF 表格区域：

| 图片 | 实际内容 | 被系统标注用途 |
| --- | --- | --- |
| `fig_001_p10_table.png` | 指标、测试结果、数据来源、验证方法表 | 五层架构图 |
| `fig_002_p11_table.png` | 团队角色分工表 | 技术选型表 |
| `fig_003_p12_table.png` | 55 分钟汇报时间安排表 | 数据流图 |

这个匹配完全错了。不是模型画图能力的问题，而是素材语义分类失败。

### 5.2 为什么会“乱截图”

原因链路是：

1. PDF 解析器把表格区域抽成图片。
2. figure review 只给出尺寸、页码、质量分，没有识别图片语义。
3. design spec 根据章节需要，把这些图片硬塞成“架构图、技术选型图、数据流图”。
4. executor 按 spec 引用图片。
5. 最终页面就出现“标题是架构，图却是 KPI 表”“标题是数据流，图却是时间安排表”的问题。

### 5.3 应该如何修

路演 PPT 的图片策略必须和论文 PPT 不一样。

论文 PPT 中，PDF 图片通常确实是论文图表，可以直接引用。比赛作品说明书中，PDF 里很多“表格截图”不一定适合当视觉素材。

需要增加路演专用素材门禁：

| 素材类型 | 是否默认可用 | 说明 |
| --- | --- | --- |
| 系统截图 | 可用 | 最适合路演 PPT |
| 架构图/流程图 | 可用 | 需语义识别正确 |
| 实操照片 | 可用 | 需去除个人/学校信息 |
| 测试结果表 | 谨慎可用 | 更适合转成 KPI 卡片 |
| 团队分工表 | 不建议直接用图 | 应转成匿名角色卡片 |
| 时间安排表 | 不建议直接用图 | 应转成时间轴 |
| PDF 页面裁剪 | 默认禁用 | 容易变成乱截图 |

## 6. 逐页观察

### 第 1 页 封面

可读、干净，但正式不可用。项目名漂移，底部有占位符，背景缺少和“仓储设备健康监测、安全作业”相关的视觉对象。建议改成：准确项目名 + 中性比赛说明 + 抽象仓储设备/监测系统插画或系统界面蒙版。

### 第 2 页 目录

这是较好的页面。章节清楚，55 分钟节奏有表达。但右侧时间轴的文字偏小，15 分钟功能演示的重点标识有轻微挤压。建议把“功能演示”作为视觉重点强化，并减少右侧空白。

### 第 3、7、12、24、28、31 页 章节页

章节页风格统一，但数量偏多。用户之前已经明确说章节过渡页没必要存在。当前 42 页中仍有大量过渡页，导致页数膨胀，同时降低信息密度。建议路演版只保留少数必要分隔，或把章节信息融合进下一页标题区。

### 第 4-6 页 问题洞察

内容方向正确，但偏通用。痛点如“响应慢、成本高、风险大”成立，却没有把材料中的四个核心问题“状态不透明、异常发现滞后、安全风险依赖人工、维护记录难追溯”讲具体。第 6 页视觉比第 4 页更好，但仍缺实际场景证据。

### 第 8 页 KPI 目标

卡片结构清晰，视觉较可用。但目标指标和后面第 26 页达成指标没有严格绑定。建议每个 KPI 标注来源状态：材料已提供 / 需用户补充 / 待实测。

### 第 9 页 五层系统架构

不合格。架构图没有正确出现，页面大量留白，标题与内容不匹配。该页应当是全套 PPT 的技术核心页，需要确定性生成“端、边、智、用、审”五层架构，而不能依赖 PDF 裁图。

### 第 10 页 技术栈选型

不合格。页面几乎没有主体图，且引用素材实际是团队分工表，不是技术选型。即使图片成功显示，也会错。建议改成确定性技术栈矩阵，并要求数据来自材料。

### 第 11 页 数据流与关键技术

中等偏弱。右侧三点结构清晰，但左侧本应展示数据流图，实际空缺。建议改成主流程图：设备数据 -> 边缘网关 -> 异常识别 -> 告警工单 -> 审计报告。

### 第 13 页 功能模块

视觉简单但可理解。问题是六大模块没有和实操步骤绑定，像功能列表，不像比赛汇报中的“闭环能力展示”。建议增加输入/输出箭头和证据点。

### 第 14-16 页 功能讲解

这几页信息密度较高，接近可用。但第 14、15 页偏表格化，缺少系统界面感。第 16 页闭环流程较清楚，是较好的基础页。

### 第 17-23 页 实操演示

这是当前路演分支最有价值的一组页面。它已经围绕现场实操组织内容，且包含准备、设备、步骤、异常、工单、审计、报告、应急预案。

主要问题：

- 仍然是“示意流程”，不是“真实演示脚本”。
- 缺少每一步预计耗时。
- 缺少实操前检查清单。
- 缺少失败时切换离线包/截图备份的明确动作。
- 缺少每一步对应评委评分点。

第 20 页视觉相对较好，右侧告警弹窗能表达结果，但里面出现了 `2024-06-13 10:32:45` 这种未确认时间，正式版要禁止。

### 第 25-27 页 数据证据

第 25 页基础还可以，第 26 页视觉是可用的，但数据真实性风险最高。第 27 页证据链视觉清楚，不过还停留在图标级别，不够像真实系统截图。

建议：

- 第 25 页显示数据集来源、样本构成、模拟规则。
- 第 26 页只显示已核验指标。
- 第 27 页使用真实或用户上传的截图；没有截图时显示“待补充证据”，正式版禁止导出。

### 第 29-30 页 职业素养与风险控制

方向正确，但内容偏模板化。职业素养页应该更贴近比赛评分要素，例如安全意识、规范操作、质量意识、职业道德，而不是泛泛而谈。风险预案页表格清楚，但需要把“负责人”改成匿名角色，不要暗示真实个人信息。

## 7. 与 paper-ppt-agent 效果差距的根因

paper-ppt-agent 做论文 PPT 时效果好，不只是因为模型强，而是因为论文材料天然提供了高质量结构：

- 论文标题稳定。
- 摘要、方法、实验、结果、结论结构清晰。
- 图表本身就是论文核心视觉资产。
- 每页可以围绕一个论文图、一个实验表或一个方法模块展开。

路演 PPT 当前材料则不同：

- 说明书里很多内容是文本和表格，不是可直接展示的图。
- 比赛 PPT 需要现场演示、证据链、团队协作、风险预案，这些不是论文逻辑。
- 说明书中没有真实系统截图时，模型只能画“模拟界面”，视觉可信度自然下降。
- 评分标准要求不能造假，但模型默认会补齐漂亮数据。

所以差距不是单纯“页面数量太少”，而是：

> 论文 PPT 的视觉资产来自论文图表；比赛 PPT 的视觉资产必须来自系统截图、实操证据、架构/流程确定性图和真实 KPI。当前路演分支还没有建立这套资产门禁和证据驱动机制。

## 8. 根因拆解

### 8.1 前半段问题

| 阶段 | 当前问题 | 后果 |
| --- | --- | --- |
| 资料解析 | 标题抽取曾退化成单字“智” | 联网查询失败，项目名漂移 |
| 联网研究 | 无效搜索结果未过滤 | 模型自述污染上下文 |
| 素材识别 | 表格裁图被当作图表 | 架构页、技术页素材错配 |
| 大纲生成 | 保留大量章节过渡页 | 页数膨胀、信息密度下降 |
| manuscript | 有视觉字段，但内容仍泛 | executor 只能画通用页面 |
| 证据链 | 未区分已验证与待补充 | 数据可能被模型补造 |

### 8.2 后半段问题

| 阶段 | 当前问题 | 后果 |
| --- | --- | --- |
| strategist | 重新改写项目名 | 全套页面标题错误 |

## 9. 改进建议

### 9.1 最高优先级

1. 锁定项目标题与关键事实  
   `material_analysis` 输出 `locked_project_title`、`verified_metrics`、`verified_assets`，后续 agent 不得改写。

2. 建立路演素材门禁  
   PDF 抽图必须经过语义分类。不能把表格裁图自动当作架构图、流程图、系统截图。

3. 禁止正式版数据补造  
   页面中所有数值必须来自 `verified_metrics`。没有来源的数据只能作为“目标/待测”，不能作为“达成”。

4. 架构页和实操页改为确定性图形生成  
   “端、边、智、用、审”五层架构、6 步实操闭环不应依赖模型自由画，应由代码生成基础结构，再让模型填内容和微调视觉。

5. 删除或压缩章节过渡页  
   用户已明确章节过渡页没必要存在。42 页里过渡页太多，应把信息密度让给实操、证据、评分回应。

### 9.2 中优先级

1. 增加“评委问题”驱动的页面策划  
   每页都要回答一个评委关心的问题，而不是只展示主题。

2. 真实截图优先  
   用户没有截图时，系统应提示补充核心截图；如果没有，生成可预览草稿，但正式导出门禁提示缺失证据。

3. 生成前做页面角色分配  
   `cover / agenda / architecture / live_demo / evidence / risk / teamwork / summary` 应各有稳定视觉规则。

4. 增加 partial resume  
   第 32 页失败后，应能从第 32 页继续，而不是整套重跑。

5. 把视觉审查从“SVG 合规”升级为“页面质量审查”  
   检查图文是否匹配、标题是否准确、是否有占位符、是否有无来源数据、是否有素材错配。

## 10. 对当前任务的可复用价值

这次任务虽然失败，但有三部分可以保留：

1. 路演大纲方向  
   七大部分覆盖较完整，可以作为后续路演 PPT 的基础结构。

2. 实操章节设计  
   第 17-23 页的实操链路是对的，应该继续深化。

3. 部分页面风格  
   第 2、16、20、26、27 页可以作为临时参考，但需要更真实的证据和更强的视觉重心。

不建议保留的部分：

- 第 9-11 页基于错误图片的技术页。
- 所有带占位符的封面/封底信息。
- 自动生成的无来源 KPI 达成数据。
- 大量章节过渡页。

## 11. 下一步建议

下一步不应该继续单纯调模型或重跑 42 页，而应该先修路演分支的“事实锁定 + 素材门禁 + 确定性核心页”。

建议开发顺序：

1. 在 roadshow_agent 中新增 `locked_facts` 输出，锁定项目名、应用场景、指标、设备、实操步骤、团队匿名角色。
2. 改 figure review，给每张抽图加语义类型：`architecture / flow / screenshot / metric_table / team_table / schedule_table / unknown`。
3. 禁止 `metric_table/team_table/schedule_table` 被当成架构图或数据流图直接使用。
4. 对架构页、实操页、证据页使用确定性 SVG 结构生成，再让模型填文案。
5. 增加导出前门禁：占位符、无来源数据、图片语义错配、个人信息风险、证据缺失。
6. 支持从失败页继续生成，避免第 32 页失败后浪费前 31 页成果。

## 12. 最终判断

`c9229dd1b0b4` 证明路演支线已经能跑出“比赛路演形态”，但还没有达到“可正式参赛”的标准。

它的最大价值是暴露了一个非常清晰的问题：我们不能把 paper-ppt-agent 的论文图表逻辑直接套到比赛作品说明书上。比赛 PPT 的质量核心不是“把 PDF 截图放进去”，而是围绕评分标准，把真实材料转成项目名准确、数据有源、证据可追溯、实操可演示、风险可说明的页面系统。

当前版本的问题不是没希望，而是缺少三道关键闸门：事实闸门、素材闸门、正式导出闸门。把这三道闸门补上，再强化架构、实操、证据三类核心页面，才有机会接近 paper-ppt-agent 在论文 PPT 上的稳定质量。
