# 职业院校技能大赛 PPT 九 Agent 生成方案

本方案只服务职业院校技能大赛选手，目标不是生成通用商业 BP，而是生成一套 35-45 页、证据可追溯、匿名合规、适合现场路演和实操答辩的 PPT。

## 核心约束

- 不出现个人信息：姓名、学校名称、电话、邮箱、身份证号、微信/QQ 等一律清除。
- 不伪造项目事实：测试数据、运行结果、截图、成果只能来自用户资料、上传素材或系统日志。
- 联网资料只用于政策、行业背景、公开数据和技术标准，必须标注来源。
- 页数由系统固定在 35-45 页，不让用户选择页数。
- 资料不足时先生成补料清单或草稿，正式版导出必须过证据门禁。

## 九个 Agent

1. 参赛材料采集与成熟度 Agent：把输入分为 A 完整、B 不完整、C 只有文字、D 只有想法。
2. 合规净化 Agent：清除个人信息和学校识别信息。
3. 赛项意图分析 Agent：识别赛项场景、技术方向、评分目标和页数策略。
4. 补料澄清 Agent：针对缺失资料生成填空问题和可接受证据类型。
5. 联网资料研究 Agent：使用 Mimo web_search 搜索政策、行业背景和公开来源。
6. 证据账本 Agent：维护用户资料、联网来源、缺失证据和可用事实边界。
7. 比赛大纲梳理 Agent：生成 35-45 页比赛叙事大纲。
8. 页面策划 Agent：为每页绑定页面契约、评分点、证据类型和表达方式。
9. 内容策划 Agent：把内容写成页面要点和讲稿提示，缺证据处明确标记待补充。

## 资料分级策略

- A 完整资料：允许生成正式版 PPT。
- B 有资料但不完善：允许生成草稿，正式导出前必须补齐缺失证据。
- C 只有文字描述：允许生成结构草稿，所有成果和指标不得写成事实。
- D 只有想法：不进入完整 PPT，先输出资料采集表和补料清单。

## 正式版最低证据门槛

- 真实应用场景
- 至少 3 个痛点
- 解决方案闭环
- 5 步以上实操流程
- 架构、系统或截图类证明
- 3 项测试或运行结果数据
- 2 个创新点与成效
- 岗位化团队分工
- 安全、规范、知识产权措施
- 政策或行业数据来源

## 当前代码接入边界

保留现有 PPT 渲染、页面契约、评分检查和 V6 表达规划能力。新增 `competition_agents` 作为前置语义层，`PPTService.create_task` 在创建任务前运行九 Agent，把生成的大纲直接交给原有 `_generate_outline_async` 后续链路。其它业务模块不参与本次改造。
