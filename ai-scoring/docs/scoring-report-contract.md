# 评分报告与评分流程合同

本文是学生报告和评分模型的同一份边界。报告允许出现的章节，模型才可以写；模型每个字段只服务一章。官方 15 个观测点的满分、权重、梯度不改。

读者：参赛学生（高中 / 职校）。读完应能用三句话说清：这场为什么在这个分数区间、最大扣分是什么、下一轮第一件改什么。

---

## 1. 原则

1. **一事实一住处**  
   一场路演最多 3 条主问题。成绩单、动作、判定不要再把事故写成第二遍故事。官方给分表每一行保留该观测点自己的证据，不写成「详见某某点」。

2. **先地图，后证据，再动作**  
   分数解释落在哪；证据解释凭什么；动作解释怎么补。三层不许混写。

3. **高中生能读**  
   数字必须带含义。禁止直接出场：`wpm`、融合分、手势分、J0x、证据通道百分比、算法权重。必须出现时先翻译成人话。

4. **深度在档位，不在形容词**  
   每个观测点写清：官方梯度的哪一档 + 一条证据 + 一条缺口。禁止「本维有基础，证据仍不足」这类空壳总评。

5. **报告不发明分，模型不发明章节**  
   报告不得改分。模型不得为了填章编造用户、专利、检测报告、假评委、跨时段伪矛盾。缺数据就缺章。

6. **首尾呼应合法，中间复读非法**  
   结论三句话必须能指回前面章节。中间章禁止互相复述。

---

## 2. 阅读路径（7 章）

入口句：先看成绩单，再看凭据，再看讲述，最后只看下一轮改什么。

| 章 | 读者问题 | 唯一允许写的 | 数据来源 | 禁止 |
|---|---|---|---|---|
| 封面 | 这是谁的场 | 项目、赛道、场次、时长 | 会话元信息 | 任何评价 |
| 01 成绩单 | 打了几分，为什么在这个区间 | 总分、五维条、完整诊断（不中截）、亮点/问题短标签各 ≤3 | `score_overview` | 展开事故；转写段数等内部指标 |
| 02 证据台账 | 这些话站不站得住 | 主张 → 证据等级 → 时间或原文 → 影响哪个观测点；末尾最多 3 条评委可能问 | `evidence_audit`，`judge_questioning` | 改进建议；再打一遍分；把标签写成故事 |
| 03 官方给分 | 15 个点各掉在哪一档 | 每点：得分/满分、档位名、本点自己的证据、一条缺口 | `dimensions.*.items` | 把证据改成「详见某某点」；空壳维级总评；把「技能熟练度」写成「技能水平」 |
| 04 讲述质量 | 讲得清不清楚 | 语速/停顿/填充词的含义；最多 3 条同一时刻音画不一致；结构只评时间分配 | `speech_quality`，`audio_visual_fusion.contradictions`，`pitch_structure_benchmark` | 再判技术对不对；把相隔超过 2 分钟的两件事捏成一对矛盾 |
| 评审团（仅开启时） | 不同评委会怎么看这场，值在视角差不在第二份总分 | 1) 合议均分对照官方分，写清卷面以官方分为准 2) 跨评委共识最多 4 条，同类问题必须归并并写票数 3) 不同视角会追问什么：每位评委一条别人不一定会问的问题 4) 五维对照：官方 / 评委均分 / 评委分差 5) 每位评委：盯什么 + 打分时看重 + 一条带证据的认可 + 一条本视角质疑 + 一条下一刀 | 磁盘真实 `jury_session`（highlights / critical_issues / improvement_priorities / persona_view） | 用 LLM 编造的 `jury_review` 冒充；展示 MBTI/J0x；把评委分写成第二份官方分；九张卡复读同一条冷场；只留角色+分数+一句关注 |
| 05 下一轮动作 | 具体改什么才算补上 | 最多 4 条，P0 优先；动作、负责人、时限、可检查验收 | `action_plan` | 再讲事故故事；验收写成「加强/优化」 |
| 06 谁来练 | 谁练哪一块 | 每人一行：短板一句话 + 一个练习 | `team_optimization` | 复制第 05 章 method 全文 |
| 07 判定 | 走时记住三件事 | 优势 / 扣分 / 补齐各 ≤3 条 | `final_verdict` | 新事实、新建议、九评委口吻 |

不进主报告：

- 能力画像长文（`character_profile`）。需要时另开附录人物卡，本轮主路径不收录。
- 未开启评审团时的任何评委人格、J0x、MBTI 打分表。
- 路演全文附录（除非显式打开 `OREP_REPORT_INCLUDE_TRANSCRIPT_APPENDIX`）。
- 规则引擎 shadow 分、抽帧机密、内部权重。

合法首尾呼应示例：

- 01「最大短板是演示稳定性」
- 03 技能熟练度详写约 94 秒中断
- 07「见 §03 技能熟练度：演示必须零中断，并备录播」

## 3. 证据等级（给学生看的说法）

内部仍可用「口头 / PPT / 演示 / 数据」做判断，报告里写成：

| 内部 | 报告用词 | 含义 |
|---|---|---|
| 强证据 | 站得住 | 时间或原文或画面能对上，主张成立 |
| 弱证据 | 偏弱 | 只口头说了，或画面对不上关键数据 |
| 缺失证据 | 还缺 | 主张需要的证明没出现 |
| 矛盾证据 | 对不上 | 同一时刻说的和看到的不一致 |

## 4. 官方 15 点：学生看见的一行

不改满分和梯度。每点固定写：

1. 官方名  
2. 得分 / 满分  
3. 档位名（由分数落入的梯度翻译，见下表）  
4. 一条证据（时间或原话或画面，择一写清）  
5. 一条缺口（上到下一档还缺什么）

每个观测点都写满 5 列。证据列必须是本点自己的理由，不得改成「详见某某点」。缺口列写本点独有、上到下一档还缺什么。

观测点官方名不得改写。尤其禁止：「技能熟练度」→「技能水平」。

## 5. 流水线各环节：职责 / 达标 / 失败时报告怎么写

### 5.1 转写

- 职责：分段文本、大致说话人、时长。
- 达标：有时长，有可用正文，封面时长与此一致。
- 失败：不出「讲得很完整」；成绩单诊断写「转写不足，评分偏保守」。
- 报告：不把段数、字数当成绩。

### 5.2 语音质量

- 职责：语速、停顿、最长停顿、填充词率。只服务第 04 章。
- 达标：数字能对上时长；报告必须翻译。参考：200–250 字/分为合适；持续 >280 为偏快；填充词占比 <5% 为少。
- 失败：第 04 章语音块缺省，不编造语速。
- 边界：不改五维官方分。现场讲解效果最多按既有规则参考扣 0.5，正文仍写人话。

### 5.3 音视频融合

- 职责：同一时刻嘴里说的和镜头/屏幕上的是否一致。
- 达标：每条矛盾同时有时间、所说、所见；两条事件时间差 >2 分钟不得标成一对矛盾。
- 失败：第 04 章不写融合，或写「本场音画不足以判断是否一致」。
- 报告：最多 3 条过关矛盾。

### 5.4 证据抽取（规则侧）

- 职责：主张和观测点结构化，给规则引擎，不直接当学生正文。
- 达标：关键主张能挂到 15 点之一；正式分数字段不外泄到学生报告。
- 报告：第 02 章优先用评分模型的 `evidence_audit`。

### 5.5 官方五维评分

- 职责：按 2025 世赛职业院校口径给 15 点独立打分。这是深度本体。
- 达标：每点 `reason` 至少引用时间或原文或画面之一；一场事故只在一个主责点详写；维级不写可被渲染拿去复读的长诊断；官方名不改写。
- 失败：该点记 0 或按缺失证据档，并写明缺什么。
- 赛制：50–60 分钟是合理完成区间。约 54 分钟不得写成超时。

主责约定（常见事故）：

| 事故 | 主责观测点 |
|---|---|
| 演示中断 / 模块崩溃 | 技能熟练度 |
| 代码或流程讲解过长 | 现场讲解效果 |
| 关键数据没来源 | 创新成效（若讲的是创新效果）或经济性（若讲的是成本），二者只选一个写深 |
| 标准只口头提了 | 操作规范性 |
| 开场没有记忆点、后段没有收束 | 第 04 章结构，不进五维重复判 |

### 5.6 报告专用字段

见第 6 节。缺字段就缺对应章，禁止用套话填满。

### 5.7 能力画像

- 职责：若仍生成，只服务附录人物卡。
- 本轮主报告不收录。
- 达标（若跑）：3–4 张人物卡；禁止节奏长文、禁止 `wpm`、禁止再写五维理由。

### 5.8 报告渲染

- 职责：按第 2 节取字段，不镜像整份 JSON。
- 达标：7 章结构；「93.96 / 演示故障」类情节详写 ≤1 次、结论点名 ≤1 次；维级总评若模型没写就留空；熟练度名称不被替换。
- 旧场次重渲染能立刻去掉：套话总评、误替换、画像长文、内部指标表、跨时段伪矛盾。
- 旧场次重渲染消不掉：各细项 `reason` 里已经互相复读的长文。那要等下一轮评分。

## 6. 模型字段互斥

| 字段 | 只服务 | 上限 | 达标 |
|---|---|---|---|
| `score_overview.diagnosis` | 01 | 1 句，≤60 字 | 只解释分数区间 |
| `score_overview.highlights` / `key_issues` | 01 | 各 ≤3 个，每条 ≤16 字 | 标签不是段落 |
| `evidence_audit` | 02 | 8–15 条 | 每条有 level、claim、source、impact |
| `judge_questioning` | 02 末 | 报告取 ≤3 | 指向真实缺口，禁止假评委人格 |
| `dimensions.*.items` | 03 | 15 点全有 | 主责规则；可带 `band`、`gap` |
| `audio_visual_fusion.contradictions` | 04 | 模型 ≤5，报告 ≤3 | 同一时刻音画 |
| `pitch_structure_benchmark` | 04 | 7 段各一行 | 只写时段是否失衡 |
| `action_plan` | 05 | ≤4 条 | 有可检查验收 |
| `team_optimization` | 06 | ≤4 行 | 不复制 action.method |
| `final_verdict` | 07 | 三类各 ≤3 | 只回扣 |
| `highlights` / `critical_issues` 长段 | 内部，不再渲染成长文 | — | 与 overview 标签重复时以 overview 为准 |
| `jury_review` | 禁止出现在评分 JSON | — | 多评委只走 `jury_enabled` 独立流水线 |
| `character_profile` | 不进主报告 | — | 本轮渲染忽略 |

禁止 backfill 发明：融合矛盾、结构 5 分行、假评委。可以从已有亮点/问题推导 `score_overview` 和 `final_verdict` 的短句，这是回扣不是新事实。

## 7. 讲述质量用词

| 数字 | 人话 |
|---|---|
| 语速 200–250 字/分 | 合适，评委跟得上 |
| 语速持续 >280 字/分 | 偏快，关键句容易被冲掉 |
| 语速 <180 字/分 | 偏慢，后段容易散 |
| 填充词占比 <5% | 少，不影响听 |
| 填充词占比 >15% | 偏多，显得没准备好 |
| 单次停顿 >30 秒 | 冷场，要说明是故障还是在想词 |

禁止把语音数字单独做成一页成绩。时长已在封面出现时，第 04 章不再重复「总时长」大号数字。

## 8. 怎样算整件事达标

对同一场样本（如 session 26）同时满足：

1. 不回头翻页，能用三句话说清：总分区间原因、最大扣分、下一轮第一件事。
2. 除结论回扣外，任一主问题的完整情节只出现一次。
3. 15 个观测点都能看到档位 + 证据或缺口。
4. 动作条有可检查验收（「连续 5 次演示零中断」算；「加强稳定性」不算）。
5. 模型 JSON 不再编造评委人格、跨时段伪矛盾、商业数据。
6. 本文第 5 节 8 个环节都有「职责 / 达标 / 失败时报告怎么写」，代码与之一致。
