# OREP 长期价值系统化分析与优化方案

> 文档版本：V1.0  
> 生成日期：2026-06-05  
> 适用对象：产品规划、商业计划书、路演汇报、学校客户沟通、研发迭代排期  
> 核心命题：OREP 不能只做“比赛备赛工具”，应升级为“职业院校项目路演与学生能力成长平台”。

---

## 1. 总体结论

OREP 当前已经具备较完整的“路演训练闭环”基础能力：

- 在线会议与路演参与
- 屏幕共享、会议记录、会议历史
- 实时评分与问题记录
- AI 路演评分分析
- 五维评分、趋势图、问题分类
- 讲稿编辑与模板管理
- AI PPT 生成、预览、质检、导出
- 路演复盘中心与数据统计
- AI 复盘问答入口

这些功能已经可以支撑“职业院校技能大赛备赛”场景，但如果只围绕比赛叙事，产品价值会存在明显风险：

1. 比赛规则可能变化，导致平台看起来像“赛制附属工具”。
2. 学校采购时更关心长期教学价值，而不是某一届比赛的短期效率。
3. 学生真正需要的是表达能力、项目理解能力、复盘能力和就业展示能力的持续成长。
4. 老师真正需要的是教学诊断、过程评价和学生改进追踪。
5. 学校领导真正需要的是可量化的培养成果、专业建设数据和创新创业成果沉淀。

因此，OREP 的战略定位应从：

> OREP 在线路演评审平台

升级为：

> OREP 职业院校项目路演与能力成长平台

更完整的产品定义是：

> OREP 面向职业院校项目化学习、技能竞赛、创新创业、毕业答辩和就业展示场景，把学生项目的准备、展示、评价、复盘、整改和成果沉淀形成数字化闭环，帮助学生从“会做项目”走向“会讲项目、会证明项目、会改进项目”。

## 2. 外部环境与长期机会

### 2.1 职业教育用户规模足够大

根据教育部《2024 年全国教育事业发展统计公报》，全国普通、职业本专科在校生规模达到 3891.26 万人，其中职业本科在校生 40.68 万人，高职专科在校生 1764.66 万人。这说明 OREP 面向的职业院校学生群体不是小众市场，而是一个持续存在的大规模教育场景。

对 OREP 的启示：

- 如果只服务竞赛队伍，用户规模有限。
- 如果扩展到项目化课程、创新创业训练、毕业展示、就业面试，平台可服务的人群会从“少数参赛学生”扩大到“多数项目制学习学生”。
- 产品长期价值应建立在“职业院校学生成长”上，而不是某一届比赛规则上。

### 2.2 比赛是入口，但不能成为唯一价值

教育部 2025 年世界职业院校技能大赛实施方案提到，大赛参照国民经济行业分类和职业教育专业设置，结合国家产业发展、重点行业、民生福祉和生产实践需要，共设置 42 个赛道。2025 年获奖名单通知显示，该赛事覆盖 28 个国内赛区和东南亚、中亚、非洲、欧洲 4 个海外赛区，来自 76 个国家 2892 所职业学校和机构、8956 支队伍、33706 名选手和 17762 名指导教师参加比赛。

对 OREP 的启示：

- 技能大赛仍是 OREP 的强入口，因为学校有明确备赛需求。
- 赛道会变化，但项目展示、专家评价、材料生成、答辩训练、能力复盘不会消失。
- OREP 要把“赛道模板”抽象成“项目类型模板”，避免被具体赛制锁死。

### 2.3 教育强国与数字教育方向支持长期叙事

《教育强国建设规划纲要（2024-2035 年）》强调教育数字化、人才培养质量、职业教育和终身学习体系建设。OREP 可以从这个方向切入，把自己讲成职业教育数字化工具，而不是比赛周边软件。

对 OREP 的启示：

- 平台应强调“学生能力成长数据资产”。
- 平台应强调“教学过程评价与改进”。
- 平台应强调“项目化学习、产教融合、创新创业成果沉淀”。
- 平台应支持长期使用，而不是只在比赛季打开。

## 3. OREP 当前功能盘点

### 3.1 已有功能地图

结合当前项目代码和已有产品资料，OREP 现有功能可以归纳为 8 个模块：

| 模块 | 当前能力 | 对长期价值的作用 |
|---|---|---|
| 首页工作台 | 展示在线会议、AI PPT 生成、讲稿编辑、数据分析等入口 | 已具备平台化入口，但叙事偏任务流，缺少项目成长主线 |
| 在线会议 | 加入会议、会议历史、会议号和密码、路演参与 | 是路演训练和课程展示的基础场景 |
| 会议室 | 路演互动、屏幕共享、评分流程、音视频能力 | 是学生真实表达和专家评价的现场 |
| AI 评分分析台 | 综合评分、五维雷达、关键帧、语音视觉融合趋势、PDF 下载 | 已有“证据化评价”雏形，是长期能力画像基础 |
| 路演复盘中心 | 分数趋势、五维评分聚合、问题排行、最近路演对比、闭环分析 | 已有“持续改进”雏形，但需要扩展到学生、班级、专业和学校层面 |
| 讲稿编辑 | 我的讲稿、模板管理、从模板新建、另存模板 | 能支持表达训练，但需要与项目、PPT、评分报告打通 |
| AI PPT 生成 | 问卷、大纲、生成、预览、导出、质检 | 能降低材料制作门槛，但需要从“生成 PPT”升级为“项目叙事训练” |
| 资源中心 | PPT 模板、评分标准、资料下载 | 可扩展为赛道模板库、课程模板库、优秀案例库 |

### 3.2 当前产品主线

当前 OREP 的主线可以概括为：

```text
创建/加入路演会议
→ 展示项目
→ 评委/AI 评分
→ 生成问题与报告
→ 查看统计与复盘
→ 优化讲稿/PPT
```

这条主线适合比赛备赛，但对长期教育价值来说，还缺少三个关键环节：

1. **项目生命周期**：一个项目从想法、调研、方案、开发、测试、展示到成果沉淀，应有完整过程空间。
2. **学生能力生命周期**：学生每次训练后的表达、逻辑、技术说明、协作、复盘能力应被持续记录。
3. **教学改进生命周期**：老师和学校要看到哪些能力普遍薄弱，哪些课程或专业需要加强。

## 4. 当前问题诊断

### 4.1 产品定位问题

当前 OREP 的产品表述偏向“在线路演评审平台”，容易被客户理解为：

- 为技能大赛服务
- 为路演评审服务
- 为某一届赛制变化服务
- 类似在线会议加评分系统

这个定位可以成交一部分竞赛需求，但不利于长期采购。学校长期采购需要回答：

- 平时不用比赛时，这个平台还能做什么？
- 它对学生长期成长有什么帮助？
- 它对老师日常教学有什么帮助？
- 它对学校专业建设、人才培养、就业创业有什么帮助？

### 4.2 价值链条偏短

当前价值链条主要围绕一次或多次路演：

```text
路演 → 评分 → 报告 → 改进
```

长期价值链条应升级为：

```text
项目创建
→ 学习准备
→ 阶段展示
→ 多维评价
→ AI 复盘
→ 整改任务
→ 再展示
→ 能力成长档案
→ 优秀成果沉淀
→ 教学质量改进
```

### 4.3 用户分层不够清晰

当前功能更像给“参赛团队”和“评审老师”使用，但学校采购时至少涉及四类用户：

| 用户 | 关注点 | 当前满足度 |
|---|---|---|
| 学生 | 怎么改、怎么练、怎么成长 | 中等，有评分和报告，但成长档案不足 |
| 老师 | 怎么指导、怎么追踪、怎么诊断共性问题 | 中等，有统计和问题排行，但教学维度不足 |
| 学院/专业负责人 | 哪些项目好、哪些能力弱、专业建设如何改 | 偏弱，缺少专业/班级/课程维度 |
| 学校领导 | 平台覆盖面、成果、竞赛贡献、就业价值 | 偏弱，缺少校级驾驶舱和成果报告 |

### 4.4 AI 价值表述需要调整

当前“AI 评分”容易引发客户疑问：

- AI 准不准？
- 能不能替代专家？
- 分数依据是什么？
- 学生会不会只为了迎合 AI？

更合适的定位是：

> AI 不做最终裁判，而做学生的路演教练、老师的复盘助理、学校的教学数据分析员。

AI 的核心价值不应是“给分”，而应是：

- 发现表达短板
- 解释问题证据
- 生成整改建议
- 模拟评委追问
- 帮助材料迭代
- 形成长期能力画像

### 4.5 商业故事不够完整

当前故事容易讲成：

> 因为 2025 年比赛改革新增路演答辩，所以我们做了 OREP。

这个故事短期有效，但长期不稳。更强的故事应是：

> 职业院校学生不缺动手实践，但很多项目输在讲不清、证据弱、价值表达不足。OREP 把每一次项目展示变成可记录、可评价、可复盘、可改进的学习过程，让学生从会做走向会讲、会证、会改，让老师从经验点评走向数据化指导，让学校沉淀项目化教学和学生能力成长资产。

## 5. 新定位：从比赛工具到成长平台

### 5.1 推荐定位

**OREP 职业院校项目路演与能力成长平台**

### 5.2 推荐副标题

面向项目化学习、技能竞赛、创新创业、毕业答辩和就业展示的一体化训练与评价平台。

### 5.3 一句话价值主张

让每一次项目展示都成为一次可记录、可复盘、可进步、可沉淀的学习过程。

### 5.4 核心价值观念

OREP 的核心价值观念应从“帮学校赢比赛”升级为：

1. **以学生成长为中心**：学生不是为了拿一次分数，而是形成长期表达、逻辑、技术说明、应用价值表达和团队协作能力。
2. **以项目实践为载体**：平台围绕真实项目展开，而不是围绕孤立会议展开。
3. **以过程评价为方法**：每次展示、评分、反馈、整改都成为成长证据。
4. **以持续改进为闭环**：问题不是报告里的文字，而是下一次训练要验证的任务。
5. **以学校数据资产为结果**：长期沉淀学生能力画像、项目案例库、专业短板分析和教学改进依据。

### 5.5 价值边界

OREP 不应该声称：

- 替代老师
- 替代评委
- 自动保证获奖
- AI 分数就是最终结论

OREP 应该声称：

- 辅助老师更高效地指导
- 辅助学生更清楚地改进
- 辅助学校更系统地沉淀项目成果
- 辅助竞赛、课程、创新创业和就业展示形成统一训练体系

## 7. 三类核心用户的长期价值

### 7.1 对学生：从一次路演到长期成长

学生使用 OREP 不应只是为了“这次讲得更好”，而应形成长期成长路径：

```text
我的项目
→ 我的材料
→ 我的路演
→ 我的评分
→ 我的短板
→ 我的整改
→ 我的下一次提升
→ 我的能力档案
```

#### 学生需要看到的内容

| 能力维度 | 平台应提供的反馈 |
|---|---|
| 表达能力 | 语速、停顿、口头禅、清晰度、现场节奏 |
| 逻辑能力 | 开场、问题、方案、技术、价值、总结是否连贯 |
| 技术表达 | 架构、流程、难点、创新点是否讲清楚 |
| 应用价值 | 用户痛点、场景、效果、经济性、可持续性是否充分 |
| 团队协作 | 分工是否清楚，交接是否自然，角色是否互补 |
| 答辩能力 | 是否能回应追问，是否能把问题转化为优势 |
| 复盘能力 | 是否按反馈改进，问题是否反复出现 |

#### 学生端建议新增功能

1. 我的能力成长档案
2. 我的项目空间
3. 我的整改任务
4. 我的路演训练记录
5. 我的讲稿/PPT 版本变化
6. AI 评委追问训练
7. 面试/答辩模拟模式
8. 学期成长报告

### 7.2 对老师：从经验指导到数据化教学诊断

老师使用 OREP 的长期价值，不是少打一张分数表，而是更高效地知道：

- 哪些学生需要重点辅导
- 哪些项目讲不清应用价值
- 哪些团队反复出现同类问题
- 哪些课程目标没有达成
- 哪些优秀案例可以复用

#### 教师端建议新增功能

| 功能 | 说明 |
|---|---|
| 班级/课程项目看板 | 按课程、班级、项目查看训练情况 |
| 学生能力分布 | 展示表达、逻辑、技术说明、团队协作等能力分布 |
| 高频问题热力图 | 识别学生普遍薄弱环节 |
| 整改追踪 | 每个问题可分配负责人、截止日期和验证方式 |
| 课程评价报告 | 将路演数据转化为课程过程评价材料 |
| 指导工作台 | 快速查看待点评、待复盘、待整改项目 |
| 优秀案例推荐 | 把优秀 PPT、讲稿、答辩片段沉淀为教学资源 |

### 7.3 对学校领导：从单项系统到人才培养数据资产

学校领导关心的不是某一页 PPT，而是平台是否能回答：

- 覆盖了多少学生？
- 训练了多少项目？
- 学生能力是否提升？
- 哪些专业表现好？
- 哪些能力短板普遍存在？
- 是否支撑竞赛成果？
- 是否支撑就业创业？
- 是否形成可展示的教学成果？

#### 校级驾驶舱建议新增指标

| 指标类型 | 具体指标 |
|---|---|
| 覆盖规模 | 覆盖学院数、专业数、课程数、学生数、项目数 |
| 训练过程 | 路演次数、平均训练轮次、报告生成数、整改任务数 |
| 成长结果 | 平均分提升、问题减少率、表达能力提升趋势 |
| 教学诊断 | 高频短板、专业对比、课程目标达成度 |
| 成果沉淀 | 优秀项目数、优秀讲稿数、优秀 PPT 数、案例库数量 |
| 竞赛支撑 | 校赛/省赛/国赛项目过程数据、获奖项目训练轨迹 |
| 就业创业 | 可用于作品集、面试展示、创业路演的项目成果包 |

## 8. 产品优化总蓝图

### 8.1 新产品主线

OREP 长期版本应形成以下主线：

```text
项目空间
→ 材料准备
→ AI 讲稿/PPT 辅助
→ 阶段路演
→ 人工+AI 评价
→ 证据化复盘
→ 整改任务
→ 再次展示
→ 学生成长档案
→ 教师教学看板
→ 学校成果驾驶舱
```

### 8.2 新模块架构

| 层级 | 模块 | 说明 |
|---|---|---|
| 基础层 | 用户、学校、学院、专业、班级、课程、项目、角色权限 | 支撑学校长期组织管理 |
| 项目层 | 项目空间、项目阶段、项目材料、团队成员、指导老师 | 把路演从单次会议绑定到完整项目 |
| 训练层 | 在线路演、模拟答辩、AI 评委追问、录制回放 | 支撑真实训练 |
| 评价层 | 人工评分、AI 分析、评分模板、证据链、问题报告 | 支撑可信评价 |
| 改进层 | 整改任务、版本对比、复演验证、问题闭环 | 支撑持续进步 |
| 成长层 | 学生能力画像、项目成长轨迹、学期报告 | 支撑学生长期成长 |
| 教学层 | 教师看板、课程评价、班级分析、共性短板 | 支撑教学改进 |
| 校级层 | 学校驾驶舱、成果报告、优秀案例库、专业建设分析 | 支撑领导决策和成果展示 |

## 9. 关键优化方案

### 9.1 新增“项目空间”

#### 为什么要做

当前 OREP 以会议、评分、PPT、讲稿为核心对象，但学校真实管理的是“项目”。如果没有项目空间，平台数据会碎片化：

- PPT 是一份文件
- 讲稿是一份文件
- 会议是一次记录
- 评分是一份报告
- 问题是一组文本

这些必须被一个“项目”串起来。

#### 建议功能

| 功能 | 说明 |
|---|---|
| 项目基本信息 | 项目名称、所属学院、专业、课程、赛道、团队、指导老师 |
| 项目阶段 | 立项、调研、方案、开发、测试、展示、复盘、成果归档 |
| 项目材料 | PPT、讲稿、视频、图片、文档、代码说明、调研材料 |
| 路演记录 | 每次展示关联到同一个项目 |
| 评分报告 | 每次评分进入项目时间线 |
| 整改任务 | 每个问题生成任务并追踪完成情况 |
| 版本对比 | 对比 PPT、讲稿、评分和问题变化 |
| 成果包 | 一键生成项目成果包，用于比赛、课程、就业、展示 |

#### 价值

- 学生看到项目成长轨迹。
- 老师看到项目指导过程。
- 学校看到优秀项目沉淀。
- 销售能讲出“项目化学习全周期平台”的故事。

### 9.2 新增“学生能力成长档案”

#### 为什么要做

如果 OREP 只有项目分数，学生长期价值不明显。必须让学生看到自己的能力成长。

#### 能力模型建议

| 一级能力 | 二级指标 | 数据来源 |
|---|---|---|
| 表达能力 | 语速、停顿、口头禅、流畅度、现场节奏 | ASR、语音分析、AI 复盘 |
| 逻辑能力 | 结构完整、因果清晰、章节衔接、重点突出 | 转写文本、讲稿、AI 分析 |
| 技术说明能力 | 架构说明、流程说明、难点说明、创新说明 | 转写文本、PPT、专家评分 |
| 应用价值表达 | 用户痛点、应用场景、经济价值、可持续性 | PPT、讲稿、评分维度 |
| 团队协作 | 分工、交接、配合、互补 | 会议记录、评分、视频分析 |
| 答辩应变 | 问题理解、回应质量、追问承接 | 问答记录、专家评价、AI 模拟 |
| 复盘改进 | 整改完成率、重复问题减少率、版本提升 | 整改任务、评分趋势 |

#### 页面建议

学生端新增“我的成长”：

- 本学期训练次数
- 我的能力雷达
- 最近 5 次路演趋势
- 我的高频短板
- 我的最佳表现片段
- 我的待完成整改
- AI 给我的下一步训练建议
- 可导出的个人成长报告

### 9.3 新增“整改任务闭环”

#### 为什么要做

只生成报告不等于真正改进。OREP 要把每条问题变成可追踪任务。

#### 建议流程

```text
评分/AI 发现问题
→ 自动归类
→ 生成整改建议
→ 指定负责人
→ 设置截止时间
→ 上传改进材料
→ 下一次路演验证
→ 标记已解决或继续跟踪
```

#### 数据字段建议

| 字段 | 说明 |
|---|---|
| 问题标题 | 如“应用价值缺少数据支撑” |
| 关联维度 | 表达、技术、应用价值、团队协作等 |
| 严重程度 | 高、中、低 |
| 负责人 | 学生或团队成员 |
| 指导老师 | 负责确认的人 |
| 建议动作 | 具体应该怎么改 |
| 关联材料 | PPT 页、讲稿段落、视频时间点 |
| 截止时间 | 便于老师管理 |
| 验证方式 | 下次路演、重新生成 PPT、补充文档等 |
| 状态 | 待处理、处理中、待验证、已解决 |

### 9.4 新增“教师教学看板”

#### 为什么要做

老师需要把 OREP 用进日常课程，而不是只在赛前打开。

#### 建议看板

| 看板 | 说明 |
|---|---|
| 课程项目总览 | 某门课程下所有项目的训练次数、平均分、整改率 |
| 班级能力分布 | 看班级整体表达、逻辑、技术说明、协作短板 |
| 学生预警 | 长期不训练、进步慢、重复问题多的学生 |
| 项目预警 | 分数低、问题多、材料缺失、整改停滞的项目 |
| 高频问题 | 用于反向调整教学内容 |
| 指导任务 | 老师待点评、待确认、待复盘事项 |
| 课程报告导出 | 形成过程性评价材料 |

#### 典型教学用法

1. 老师布置项目展示作业。
2. 学生在 OREP 上传 PPT 和讲稿。
3. 班级进行线上或线下路演。
4. 老师和同伴按模板评分。
5. AI 生成复盘建议。
6. 学生完成整改任务。
7. 下次展示验证提升。
8. 期末导出课程项目成长报告。

### 9.5 新增“校级成果驾驶舱”

#### 为什么要做

学校领导需要看到平台带来的组织价值，而不是某个页面好不好用。

#### 建议驾驶舱结构

| 区域 | 指标 |
|---|---|
| 覆盖概览 | 学院数、专业数、课程数、学生数、项目数 |
| 训练概览 | 路演次数、AI 报告数、人工评分数、整改任务数 |
| 成长概览 | 平均能力提升、问题减少率、优秀项目增长 |
| 专业对比 | 各学院/专业项目质量、表达能力、应用价值得分 |
| 教学诊断 | 高频短板、课程目标薄弱点、待改进专业 |
| 成果沉淀 | 优秀案例库、竞赛成果、创新创业项目、就业展示材料 |
| 报告导出 | 学期报告、年度报告、竞赛训练报告、创新创业成果报告 |

#### 校级故事

校级驾驶舱能帮助 OREP 对领导讲：

> OREP 不只服务某个竞赛队，而是在帮助学校看见学生项目能力的成长，沉淀优秀项目案例，反向改进课程教学，并形成专业建设和人才培养质量的可视化证据。

### 9.6 新增“赛道/项目类型模板库”

#### 为什么要做

OREP 要继续吃到比赛需求，但不能被比赛赛制限制。解决办法是把赛道抽象为“项目类型”。

#### 模板设计

| 项目类型 | 模板重点 |
|---|---|
| 人工智能项目 | 数据来源、模型能力、应用场景、效果指标、伦理安全 |
| 新一代信息技术项目 | 系统架构、数据流程、安全性、部署能力、应用价值 |
| 智能制造项目 | 工艺流程、设备控制、效率提升、安全规范、现场演示 |
| 现代农业项目 | 生产痛点、技术方案、降本增效、推广价值、乡村振兴 |
| 康养服务项目 | 用户画像、服务流程、风险控制、体验提升、社会价值 |
| 文旅服务项目 | 用户体验、文化资源、运营模式、商业转化 |
| 创新创业项目 | 痛点、用户、市场、产品、商业模式、财务预测 |
| 毕业设计项目 | 研究背景、设计过程、技术实现、测试验证、成果总结 |
| 就业面试项目 | 项目职责、技术难点、个人贡献、成果数据、复盘反思 |

#### 每个模板应包含

- PPT 结构模板
- 讲稿结构模板
- 评分维度模板
- 常见问题库
- AI 评委追问库
- 优秀案例参考
- 常见短板清单
- 数据指标建议

### 9.7 AI 从“评分员”升级为“教练”

#### 新 AI 能力建议

| AI 能力 | 说明 |
|---|---|
| AI 讲稿教练 | 帮学生优化讲稿结构、语言和时间分配 |
| AI PPT 导演 | 不只是生成页面，而是优化项目叙事和证据表达 |
| AI 评委追问 | 根据项目内容模拟专家追问 |
| AI 复盘教练 | 路演后生成下一步训练计划 |
| AI 教学助理 | 给老师总结班级共性问题 |
| AI 成果报告助手 | 给学校生成学期/年度成果报告 |
| AI 证据解释器 | 给出评分依据、视频片段、讲稿片段、PPT 页关联 |

#### AI 话术定位

不建议说：

> OREP 用 AI 自动评分，替代专家评委。

建议说：

> OREP 用 AI 做复盘辅助和证据分析，帮助学生知道怎么改，帮助老师更快发现问题，最终评价仍由老师和专家确认。

## 10. 赛道策略与市场切入

### 10.1 优先切入赛道

| 优先级 | 赛道/项目类型 | 原因 |
|---|---|---|
| P0 | 人工智能、新一代信息技术、软件与数字化项目 | 技术复杂，最需要讲清架构、数据、创新和应用价值 |
| P0 | 智能制造、智能装备、工业控制类项目 | 强依赖流程演示、安全规范、团队协作和技术说明 |
| P1 | 创新创业、互联网+、挑战杯类项目 | 强依赖商业画布、痛点、市场、模式、路演表达 |
| P1 | 现代农业、乡村振兴类项目 | 应用价值强，但需要补齐数据化表达和推广故事 |
| P2 | 康养服务、文旅服务、公共管理与服务类项目 | 更强调用户场景、服务流程和体验表达，需要后续模板适配 |
| P2 | 毕业设计、课程项目、就业面试项目 | 长期空间大，但需要先通过竞赛和课程样板打磨产品 |

### 10.2 切入顺序

1. **先用比赛切入**：学校有明确痛点，容易理解，能快速试点。
2. **再进入课程项目**：把竞赛训练方法迁移到项目化课程。
3. **再进入创新创业和就业展示**：把学生项目成果用于更长期场景。
4. **最终形成校级项目成长数据平台**：服务教学、竞赛、就业、成果展示。

### 11.3 第三阶段：服务学校领导，10-16 周

| 优先级 | 功能 | 说明 |

### 11.4 第四阶段：形成壁垒，16 周以后

目标：形成 OREP 的长期竞争力。

| 功能 | 说明 |
|---|---|
| 赛道/项目类型模板库 | 覆盖 AI、信息技术、智能制造、农业、康养、创新创业等 |

| AI 教练计划 | 为学生生成连续训练计划 |

| 优秀案例知识库 | 沉淀校内优秀项目、讲稿、PPT、答辩片段 |

## 13. 客户需求清单

### 13.1 学校领导需求

- 平台是否能长期使用，而不是只用于比赛。
- 能否形成学校人才培养成果。
- 能否看到覆盖规模、项目质量、学生成长和专业对比。
- 能否输出汇报材料和年度成果报告。
- 能否支撑竞赛、创新创业、就业和专业建设。

### 13.2 教务处/教学管理部门需求

- 能否用于项目化课程过程评价。
- 能否支持课程、班级、专业多维统计。
- 能否识别共性教学短板。
- 能否导出课程评价和教学改进报告。

### 13.3 创新创业学院/竞赛办需求

- 能否快速组织路演训练。
- 能否沉淀项目材料和专家意见。
- 能否跟踪项目从校赛到省赛再到国赛的全过程。
- 能否生成商业画布、讲稿、PPT、答辩问题库。

### 13.4 指导老师需求

- 能减少重复点评。
- 能快速定位学生短板。
- 能追踪整改是否完成。
- 能保存优秀案例。
- 能批量管理多个项目。

### 13.5 学生需求

- 知道自己哪里讲得不好。
- 知道下一次具体怎么改。
- 能练习评委追问。
- 能优化讲稿和 PPT。
- 能形成个人项目成长档案。
- 能把项目成果用于就业面试、创业路演、毕业展示。

### 13.6 信息中心需求

- 支持私有化部署。
- 支持数据隔离和权限控制。
- 支持水印、访问日志和资料保护。
- 支持稳定运维、备份恢复、账号接入。

## 14. 销售 QA 话术

### Q1：OREP 是不是只服务比赛？

不是。比赛是最容易落地的入口，但 OREP 的长期目标是服务职业院校项目化学习和学生能力成长。学生在课程展示、毕业答辩、创新创业、就业面试、产教融合汇报中都需要讲清项目、证明价值、回应问题。OREP 服务的是这种长期能力。

### Q2：如果以后比赛改革了，OREP 会不会没用？

不会。因为 OREP 不把价值绑定在某个赛制上，而是沉淀在项目展示、过程评价、能力成长和教学改进上。比赛规则会变，但学生会做项目、会讲项目、会改进项目的需求不会变。

### Q3：学校已经有腾讯会议，为什么还要 OREP？

腾讯会议解决“开会”，OREP 解决“训练和成长”。OREP 会把路演过程、评分标准、问题报告、整改任务、PPT 讲稿、成长档案和教学数据全部串起来。它不是会议工具，而是项目路演训练与能力成长系统。

### Q4：AI 评分能替代专家吗？

不能，也不应该替代。OREP 的 AI 是复盘助手和证据分析员，帮助学生知道怎么改，帮助老师更快发现问题。最终评价仍由老师和专家确认。

### Q5：对学生有什么长期帮助？

学生能看到自己多次训练后的表达能力、逻辑能力、技术说明能力、应用价值表达和团队协作能力变化。平台不仅告诉学生这次得了多少分，更告诉学生下一次应该怎么改。

### Q6：对老师有什么帮助？

老师可以看到班级和项目的共性短板，快速发现哪些学生需要重点辅导，哪些问题反复出现，哪些课程内容需要加强。OREP 把老师的经验点评转化为可追踪、可复盘的教学数据。

### Q7：对学校领导有什么帮助？

学校可以看到平台覆盖了多少学生、训练了多少项目、学生能力是否提升、哪些专业表现更好、沉淀了多少优秀案例，并能形成竞赛训练报告、课程改革报告、创新创业成果报告。

## 15. 对外讲故事版本

### 15.1 简短版

职业院校学生不缺实践机会，但很多项目输在讲不清、证据弱、价值表达不足。OREP 把每一次项目展示变成可记录、可评价、可复盘、可改进的学习过程，帮助学生从“会做项目”走向“会讲项目、会证明项目、会改进项目”。

### 15.2 完整版

过去，学生做完一个项目，往往只在比赛、答辩或课堂展示时集中呈现一次。老师凭经验点评，学生听完之后很难持续改进；项目材料散落在不同文件里，路演问题没有沉淀，学生成长也看不见。

OREP 想改变这件事。

它把项目路演从一次性的展示活动，变成一个持续学习过程。学生可以在平台中准备讲稿和 PPT，参加路演训练，接受老师、专家和 AI 的多维反馈，再把每个问题变成整改任务。下一次路演时，平台会继续追踪这些问题是否解决，能力是否提升。

对学生来说，OREP 是项目表达和成长教练。它帮助学生学会讲清技术、证明价值、回应问题、持续复盘。

对老师来说，OREP 是教学诊断和指导助手。它帮助老师发现班级共性短板，追踪项目整改，沉淀优秀案例。

对学校来说，OREP 是项目化学习和人才培养的数据资产平台。它让学校看到学生能力成长，看到专业建设短板，也看到创新创业和竞赛训练成果。

所以 OREP 的目标不是服务一场比赛，而是服务职业院校学生的长期成长。

## 17. 阶段验收标准

### 17.1 第一阶段验收

- 每次路演能关联到一个项目。
- 项目详情页能看到材料、会议、评分、问题、整改。
- AI/人工评分问题能生成整改任务。
- 学生能看到个人能力趋势。
- 至少支持 3 类项目模板：人工智能、信息技术、创新创业。

### 17.2 第二阶段验收

- 老师能按课程/班级查看项目训练情况。
- 老师能看到高频问题和学生预警。
- 能导出课程项目训练报告。
- 支持同一项目多次路演对比。

### 17.3 第三阶段验收

- 学校领导能看到校级覆盖、训练、成长和成果指标。
- 能导出学校级学期报告。
- 支持学院、专业、课程多维对比。
- 支持权限、水印和资料访问日志。

## 18. 最终建议

OREP 最需要优化的不是再堆更多孤立功能，而是重构产品叙事和数据闭环。

短期用比赛切入，这是对的；但长期必须落到：

- 学生能力成长
- 老师教学诊断
- 学校成果沉淀
- 项目化学习过程评价
- 职业教育数字化数据资产

如果要用一句话概括优化方向：

> OREP 要从“评一场路演”升级为“陪一个项目成长，陪一个学生进步，帮一所学校看见人才培养质量”。

这才是能讲故事、能长期使用、能被学校持续采购的软件价值。
