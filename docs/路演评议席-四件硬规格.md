# 路演评议席 · 四件硬规格

| 项 | 内容 |
|----|------|
| 地位 | 评议席的**验收合同**。与《路演评议席-产品方案》冲突时，以本文为准 |
| 日期 | 2026-08-15 |
| 范围 | 送评议（上传 / 会议后出分）主路径 |
| 容器 | 席位只负责展示与路由，**不构成卖点、不单独验收** |

爆点只有四句，全部必须可测：

1. 同一条录像，分数经得起复评。  
2. 先核套壳 / 先进 / 价值，没查过就写没查过。  
3. 评完是任务书，不是鸡汤。  
4. 修完旧问题也不等于满分。

---

## 0. 总则

**必须**

- 一场评议只公布 **一份权威分** `officialScore`。  
- 结论首页同时可见：权威分、复评稳定性、三条实质核验、满分差距、最多 4 条任务书。  
- 每条实质判断带 `claimStatus`：`seen_in_session` | `retrieved_cited` | `unverified`。  
- `unverified` 不得写成肯定句。  
- 上轮闭环率与本场预测分是两个字段，禁止合成一个「进度分」。

**禁止**

- 用席位名称、9 人均分、雷达图代替上述四句。  
- 「完全客观」「所有意见」「已联网审查全部项目」「两年无法抄袭」。  
- 无有效锚点仍给极端分或极端扣分。  
- 验收写成「加强 / 优化 / 提升」。  
- 把上轮问题修完加成到 100。

**席位映射（仅容器）**

| 硬规格 | 可挂的席（展示用） |
|--------|-------------------|
| 复评稳定 | 记录席 |
| 实质核验 | 实质核验席；质询席可引用其结论 |
| 任务书 | 本场必做，不叫席 |
| 满分差距 | 满分对照席 |

没有实现对应硬规格的席，UI 不准点亮。

## 1. 复评稳定

### 1.1 冻结卷宗

同一场卷宗 `docketId` 由下列哈希锁定，缺一不可：

- 视频文件 sha256  
- 量表 `ruleVersion` + `ruleHash`  
- 流水线 `contractVersion`  
- 赛道 id  

**同一 `docketId` 再次评分 = 复评，不是新场。**  
换视频、换量表、换合同版本，必须开新 `docketId`。

### 1.2 必须落库的数

对每个 `docketId` 至少保留最近 3 次成功跑分：

| 字段 | 含义 |
|------|------|
| `runIndex` | 1..n |
| `officialScore` | 权威总分 |
| `dimensionScores[]` | 五维 |
| `transcriptCoverage` | 转写覆盖 0–1 |
| `seekableAnchorRate` | 可跳转锚点数 / 声明锚点数 |
| `scoreDeltaAbs` | 与第一次成功跑的总分绝对差 |

### 1.3 阈值（MVP 写死，改阈值走版本号）

| 指标 | 绿 | 黄 | 红 |
|------|----|----|----|
| 同卷宗 3 次总分最大差 | ≤ 2.0 | ≤ 3.0 | > 3.0 |
| 任维最大差 | ≤ 该维满分 8% | ≤ 12% | > 12% |
| `seekableAnchorRate` | ≥ 0.70 | ≥ 0.50 | < 0.50 |

红：结论页置顶「本场不稳定，请教师复核」；不得对学生暗示「已经很准」。  
只有 1 次跑分：显示「尚未复评」，不显示绿。

### 1.4 验收

- 同一文件连评 3 次，三次分与 `scoreDeltaAbs` 在结论页可见。  
- 人为把某次跑分改掉超过 3 分，必须出红标。  
- 禁止「为了好看」对同卷宗做温度采样式重写分。

## 2. 实质核验

只评三条。不多开「产业大盘」栏目。

| `claimType` | 老师的问题 | 怎样算 `seen_in_session` | 怎样算 `retrieved_cited` |
|-------------|------------|--------------------------|--------------------------|
| `wrapper` | 是不是开源 / 成稿改了改 | 本场自己讲了差异，且有运行画面或代码/设备证据 | 对照到具体公开项目 / 仓库 / 论文，并给出链接或标准名 |
| `advancement` | 到底先不先进 | 有对比、测试数、真实调用或设备联动，能跳到本场证据 | 对照到可核对的公开基准或文献 |
| `value` | 对行业 / 区域有没有用 | 本场说清服务谁、替代什么，且不是口号 | 对照到可核对的产业 / 地方公开材料 |

每条结构必须是：

```text
claimType
verdict          pass | fail | insufficient
claimStatus      seen_in_session | retrieved_cited | unverified
statement        一句人话；unverified 时必须含「本场未核验」
evidenceRefs[]   锚点 / 转写 / 页码；unverified 时必须为空
sources[]        仅 retrieved_cited
scoreCapHint     该条失败时相关观测点建议封顶（写数字，供规则席用）
```

**必须**

- 三条全展示。缺证据 → `insufficient` + `unverified` 或 `seen_in_session`，不得省略。  
- `unverified` 的 `statement` 不得使用「赋能 / 领先 / 填补空白 / 已验证」等肯定词。  
- `wrapper=fail` 时，创新 / 先进性相关观测点不得进入最高档。  
- 表达分不得用来抬 `wrapper` / `advancement` / `value`。

**禁止**

- 无 `sources` 却标 `retrieved_cited`。  
- 模型用常识补「他们一定做了实验」。  
- MVP 对外说「已联网审查」。

**验收**

- 预置「套壳样例」：`wrapper` 不得为 `pass`。  
- 预置「只口头先进」：`advancement` 不得为 `pass`。  
- 关掉检索开关：不得出现任何 `retrieved_cited`。

## 3. 任务书

从本场最多产出 **4** 条必做，P0 优先。进学生待办前必须教师发布。

每条字段全部必填，缺一不得入库：

| 字段 | 约束 |
|------|------|
| `title` | ≤ 24 字，动词开头，禁止「加强/优化/提升」 |
| `goal` | 评委 60 秒内能看见什么变化 |
| `steps[]` | 2–5 步，每步可单独打勾 |
| `acceptance` | 可检查：跳到某秒、某页有对比表、录屏 ≥ N 秒等 |
| `evidenceNeeded` | 下场必须补上的证据类型 |
| `expectedGain` | 分位区间，如 `+2~4`，文案必须带「下场对照，不保证」 |
| `ownerRole` | 主讲 / 项目经理 / 指定队员 |
| `dueHint` | 相对下场或天数 |
| `sourceRefs[]` | 指向扣分、质询或核验条；禁止无来源任务 |

**禁止入库的标题**：加强表达、优化PPT、提升创新性、多练、注意节奏。

**验收**

- 随机抽 10 条生成任务，0 条含「加强|优化|提升」。  
- 学生完成打勾但未回挂 `evidenceNeeded`，闭环率不得记 100%。  
- 教师未发布，学生待办中心不得出现该条。

## 4. 满分差距

一场必须同时输出：

| 字段 | 含义 | 可否到 100 |
|------|------|------------|
| `closureRate` | 上轮任务书验收通过的比例 | 可以 100% |
| `officialScore` | 本场权威预测分 | 不因 `closureRate=1` 自动到 100 |
| `ceilingGaps[]` | 相对赛道满分仍缺的块，最多 4 条 | — |
| `deltaFromLast` | 相对上场权威分，首场为 null | — |

`ceilingGaps[]` 每条：`title`、`whyNotFull`、`relatedClaimType?`、`relatedDimension`。

**封顶规则（MVP）**

- `wrapper=fail` 或 `advancement=fail`：创新 / 技能水平相关维不得进入该维满分档。  
- 本场无稳定演示证据：演示 / 熟练度相关维建议封顶到次高档（具体分值跟赛道表，禁止代码写死 100）。  
- `closureRate` 只允许加 **修复奖励**，奖励上限单独配置，且必须有回挂证据；奖励后仍 `min(…, 赛道上限)`。

**验收**

- 构造「上场问题全修、本场仍无运行证据」：`closureRate=1` 且 `officialScore < 满分`，`ceilingGaps` 至少 1 条。  
- 结论页两个百分数并排，禁止合成「完成度 100%」。

---

## 5. 结论首页（唯一首屏）

只允许这 6 块，顺序固定：

1. 权威分 + 量表版本 + 教师是否确认  
2. 复评稳定性（绿/黄/红/尚未复评）  
3. 实质核验三条（套壳 / 先进 / 价值）及 `claimStatus`  
4. `closureRate` | `officialScore` | `ceilingGaps`  
5. 最多 4 条任务书标题 + 预计提分  
6. 教师确认状态  

9 人评议、五维展开、为何页，全部是下钻，不准和这 6 块抢首屏。

---

## 6. 状态机（挂在现有 Session 上）

```text
sensing → draft → verify_claims → challenge → await_teacher → frozen
```

- `verify_claims` 失败不得假装已检索。  
- `challenge` 失败：仍可出草案，必须标「本场未完成质询」。  
- 复评是对同一 `docketId` 再跑，不新开场。  
- 教师未确认：按校配置不公布终局，或不进待办。默认两者都不对学生生效。

## 7. 门禁（做不到不准说「评议席已上」）

| # | 门禁 |
|---|------|
| G1 | 同卷宗 3 次分差对学生、教师可见 |
| G2 | 无检索开关时 0 条 `retrieved_cited` |
| G3 | 套壳样例 `wrapper ≠ pass` |
| G4 | 任务书 0 条「加强/优化/提升」 |
| G5 | 闭环率 100% 不能把预测分顶到满分 |
| G6 | 全场一份 `officialScore`，与为何页、教师页一致 |
| G7 | 文案无法庭 / 开庭 / 落槌；无「已审查全部项目」 |

G1–G7 全部绿，才允许对外用「路演评议席」四个字。只改了席位皮肤 = 未上线。
