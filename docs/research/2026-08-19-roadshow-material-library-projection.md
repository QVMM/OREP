## 摘要

修订稿 B 把路演内容从「页」和「评分回执」里抽出来，放到材料库，并规定生成方向 \(L\Rightarrow S\Rightarrow G\)。这个主轴是对的，本版保留（E 起改称「生成依赖单向，评价反馈受控回写」，见第 2.1 节）。B 里三个判断必须留下：材料对象才是事实源；22 个叶是材料组织结构而不是页面结构；评分是覆盖检查，不是改稿发动机。

B 的主要危险不在「没想清楚」，而在对象设计过于封闭、过于静态。它把一条材料同时写成 `claim + slide_line + speak_line + sources + rubric_ids`。这样一来，所谓投影只是搬运已经写好的上页句和讲稿句；所谓智能只剩加权排序。落地之后最大的风险不是 AI 乱写，而是材料库变成人工维护的大型数据库，系统退化成高级内容管理加模板拼装器。

本版做五处结构性改动，不另起炉灶。

第一，把原来的 Material 拆成三层：Evidence（事实证据）、Claim（可引用命题）、Expression（当场生成的页文案与口述要点）。事实 ≠ 命题 ≠ PPT 表达 ≠ 讲稿表达。一个命题可以由多条证据共同证明。

第二，把评分覆盖从布尔命中升级为证据充分度。观测点不再是「提到了 / 没提到」，而是准备态的充分度矩阵。产品对外仍沿用平台已有的 E0–E5 业务等级；本模型用 str/ver 解释它，不改写 v1.2 的评分定义。

第三，把 Page 从槽位升级成 Page Intent（页面任务）。先定义这一页在整场叙事里要完成什么，再按「期望证据轮廓」去选命题和证据。抽取不再是分区 Top-K。

第四，22 个分区退到后台本体。用户看见的是项目证据地图——哪里已有证据、哪组关系已形成、哪个观测点充分度不够——而不是 22 个空文件夹。

第五，把整条链补到现场表现和复盘：Narrative 拥有页面任务定义权（模板仍然没有命题权）；页数由 Presentation Profile 计算，38–45 只是 1 小时竞赛画像下的健康实例；智能评分用来回答「有材料为什么还是没表现出来」，而不是用来自动改 PPT。

智能化被重新定义在四处可观察的判断：为什么选这条证据、为什么放在这一页、为什么这样讲、现场哪一层失败。只把短句填进槽，不叫投影智能。

D 不改这条主结构。它只把 C 里已经写出、但边界不清的五个对象钉死，避免工程实现时把 Claim 做成胖对象、把 E0–E5 当成一根天然纵轴、把 Intent 停在输入约束、把 Performance 停在录像桶、把 A/B/C 当成最终分类。

**关键词：** 证据与命题分离；页面任务；Claim–Rubric Assessment；选择理由；成功条件；现场观察；失分风险

## 1. 对修订稿 B 的诊断

### 1.1 必须保留的三个判断

**事实源在材料对象，不在 PPT、不在讲稿、不在评分报告。** 任何允许上台的事实或数字，都必须能指回已核验证据。否则系统会重新掉进「页上有一句、库里对不上」的对照修补。

**22 个叶 ≠ 22 页。** 全景图是备赛叙事编码表，回答材料按什么架子放。把它印成 22 页目录，系统会退化成普通 PPT 模板：时事一页、政策一页、调研一页。

**评分不是改稿发动机。** 「评分下降 → 自动补一句 → 再评上涨」不可控，且极容易变成套话机器。评分报告的正当位置是质量审计：检查材料有没有托住观测点，以及托住的充分度够不够。

这三句成立，\(L\Rightarrow S\Rightarrow G\) 就仍然成立。本版不改主轴。

### 1.2 B 的结构性隐患

B 把「严谨」做成了「封闭」。

材料对象里预写 `slide_line` 和 `speak_line` 之后，Projection 不再需要理解这一页要完成什么任务，只需要挑选已经写好的句子。讲稿也不再需要把命题展开成适合这一页角色的口述，只需要朗读 `speak_line`。于是：

\[
\text{人工或模型先写成上页句和讲稿句}
\;\longrightarrow\;
\text{投影搬运}
\;\longrightarrow\;
\text{讲稿再搬运}
\]

稳定，但不是智能。库越规范，系统越像 CMS。这是本版要拆掉的结构，不是要润色的句子。

B 还有四处会在落地时走形：

1. 「唯一已核验条目」写得太绝对，模型倾向「一个材料 = 一个事实 = 一个来源」。真实项目里，一条命题常常由实验记录、后台数据、现场测试、第三方检测共同支撑。冲突检测、可信度、证据强度都要求「一命题多证据」。
2. \(\mathrm{Cover}(S)=\bigcup\rho(m)\) 是布尔并。挂上「技术先进性」五个字，覆盖即为 1。评委并不会因此给高分。
3. 选择逻辑是补洞、相关、新鲜、可演示、多样性之后取前 \(k\)。这是加权排序器。真实选页问的是：这一页在整场叙事里承担什么作用。
4. \(n\in[38,45]\) 被写成公理。它只是当前 1 小时竞赛画像下的健康体量。15 分钟场次若继续当公理，模型自己打自己。

### 1.3 本版五个改动（只改结构，不加更多禁令）

| # | B | C |
|---|---|---|
| 1 | Material = claim + slide_line + speak_line | Evidence / Claim / Expression 三层；表达在投影时生成 |
| 2 | \(\rho(m)\subseteq R\)，Cover 为布尔并 | 观测点 → 充分度 \(0\)–\(5\)，检查的是证据充分度矩阵 |
| 3 | Page = slot + cite | Page Intent：先有页面任务，再选证据轮廓 |
| 4 | 22 叶必须都有库位，并倾向于直接展示 | 后台 22 本体；前台是证据地图 |
| 5 | 材料库 → PPT → 讲稿 | Evidence → Claim → Narrative → Projection → Verbalization → Performance → Evaluation |

改完之后，核心底层理念仍然是 B 里那句，也是本文件唯一需要对外反复使用的句子：

> PPT 是材料库在页数与时长预算下的抽取投影，讲稿是该投影的口头展开。

现在要让这句话在产品里形成一条能走通的链：证据存在 → 为什么选它 → 放在哪一页 → 为什么这样讲 → 现场表现怎样 → 哪个地方没发挥出来。

### 1.4 修订稿 D：五处边界（主结构不动）

C 已经从「概念正确」进入「模型基本成立」。D 只修实现时会歧义的边界，不另起炉灶。

| # | C 的含糊处 | D 的钉法 |
|---|---|---|
| 1 | `sufficiency[]` 写在 Claim 上 | 充分度是关系对象 Assessment\((k,r)\)，与符号 \(\chi(k,r)\) 同构 |
| 2 | E0–E5 被写成一根纵轴 | 内部是证据强度 × 可验证性，再映射成业务等级 |
| 3 | Page Intent 只有输入约束 | 补 Success Criteria：这一页怎样才算任务完成 |
| 4 | Performance 是录像记录层 | 补 Observation：预计发生什么 / 实际发生什么 / 偏差是什么 |
| 5 | 评价停在 A/B/C 单标签回写 | 预留 D（完整性失败）；回写是根因候选 → 最小修复。投影对象补 Selection Rationale |

另有两句产品纪律，写进正文以免以后走形：七层是对象层，不是七个产品模块；证据地图的首页是「下一步最该补的 3 件事」，不是充分度百分比驾驶舱。

### 1.5 修订稿 E：四处定型（不再加层）

D 已可定型。E 不增加新对象层，只消除四个以后会打脸的歧义。

| # | D 的含糊处 | E 的钉法 |
|---|---|---|
| 1 | 仍称「单向依赖」，同时允许 Evaluation 回写 | 生成依赖单向；评价反馈受控回写 |
| 2 | \(\mathrm{Suff}(S,r)=\max\chi\) 写成唯一形式 | \(\mathrm{Suff}=\mathrm{Aggregate}(\{A(k,r)\})\)；V1 默认 max，允许组合规则 |
| 3 | \(\Delta\) 与选择一起落盘，仍可能事后编理由 | \(\Delta\) 必须含决策轨迹：约束命中、排序因子、违反项；理由由轨迹生成 |
| 4 | Success 有的能自动判、有的不能 | 硬成功可机检；软成功人审或模型辅助，不得假装都能自动 |

E0–E5 与 v1.2 的关系同时写死：业务等级仍是 v1.2 的；str/ver 是本模型内部解释变量；正文中的映射表是当前默认解释，不是对 v1.2 条文的修改。未逐条校准前，禁止把「E4 = str2 + ver2」写成评分规则。

下一阶段不再往理论上加层，转向最小可运行原型定义。

## 2. 系统对象：七层对象，不是七个产品模块

### 2.1 层与职责

| 层 | 名称 | 回答的问题 | 持有什么 | 不持有什么 |
|---|---|---|---|---|
| ① | Evidence | 这件事有没有发生过、数从哪来 | 出处、摘录、度量、核验状态 | 上页句、讲稿句、页面任务 |
| ② | Claim | 我们到底在主张什么 | 命题句、证据集合、状态 | 充分度、评分映射、上页句 |
| ③ | Narrative | 整场路演的任务序列是什么 | Presentation Profile、有序 Page Intent（含成功条件） | 具体句子、具体分数 |
| ④ | Projection | 这一页如何被看见、为何这样选 | 引用、生成表达、Selection Rationale | 新事实 |
| ⑤ | Verbalization | 这一页如何被说出来 | 口述展开、交接、现场指示 | 新数字、新专名 |
| ⑥ | Performance | 现场相对预期发生了什么 | 录像等介质 + Observation（预计/实际/偏差） | 对库的直接改写 |
| ⑦ | Evaluation | 哪一层失败、最小修复是什么 | Assessment 矩阵、A/B/C/D、根因候选 | 自动改稿加分；一条评分只贴一个标签 |

生成方向仍是：

\[
E \;\Rightarrow\; K \;\Rightarrow\; N \;\Rightarrow\; S \;\Rightarrow\; G \;\Rightarrow\; P \;\Rightarrow\; V
\]

评价回写是受控反馈，不是把链倒过来：

\[
V \;\rightsquigarrow\; \{E,K,N,G,P\}
\]

**生成依赖单向，评价反馈受控回写。** 页和讲稿不得发明新事实（生成单向）。评价可以打开补证、改命题、改页面任务、改讲稿或安排复训，但必须经过根因候选与最小修复，禁止把评分结果直接写成页上的套话（受控回写）。不得再把整条系统叫做「单向链」——那样与回写矛盾。

其中 \(E\) 证据，\(K\) 命题，\(N\) 叙事，\(S\) 投影页，\(G\) 讲稿，\(P\) 现场（相对计划的偏差），\(V\) 诊断。\(V\) 解释已有评分、证据关系和现场观察，不重新打分。

**这七层是对象层，不是七个产品模块。** 工程不得做成 Evidence 服务、Claim 服务、Narrative 服务……的并列系统。产品能力仍是 OREP 已有的七件：资源中心、智能文档、PPT、讲稿、路演、评分、复盘。本模型只规定这七件底下的统一对象关系。PPT 是其中一个输出端，不是产品本体。

B 的 \(L\Rightarrow S\Rightarrow G\) 是生成方向的中段压缩。本版把它展开，并接到 OREP 已经存在的路演与评分。Evaluation 是诊断层，不是第二套评分引擎：

\[
\text{已有评分}\;+\;\text{证据模型}\;+\;\text{Intent}\;+\;\text{Observation}
\;\longrightarrow\;
\text{Diagnosis}
\]

禁止：AI 重新判断「应该打多少分」。

### 2.2 与 OREP 现有模块的一一对应

| 层 | 已有模块 | 本模型中的职责 | 明确不做 |
|---|---|---|---|
| Evidence | 资源中心、上传材料、出处字段 | 收原件、摘录、日期、核验 | 把搜索摘要直接标已核验 |
| Claim | 智能文档中的整理段、条目属性 | 从证据提炼可引用命题 | 一条材料同时写死 PPT 句和讲稿句 |
| Narrative | 路演逻辑全景图、赛道规则、场次设置 | 生成 Page Intent 序列 | 把 22 叶印成 22 页 |
| Projection | 旧智能 PPT 版式、无稿出新页 | 按页面任务选命题并生成表达 | 槽内默认文案上场；对已有设计稿改 XML |
| Verbalization | 智能文档 / 讲稿表 | 按页展开，与页同序 | 讲稿另写一套事实 |
| Performance | 路演录像、转写、关键帧、Collabora 原页观看 | 对照 Intent.success 做 Observation | 用自绘页冒充原件；只有录像没有「预计/实际」 |
| Evaluation | 智能评分报告、v1.2 证据等级、复盘追问 | 诊断：解释已有评分 + Assessment + Intent + Observation，给出最小修复 | 重新评分；对照界面改分；预告加分；新造「评分诊断引擎」另打一套分 |

两条产品门保持分离，与 B 相同：

- **已有设计稿：** 页数不动；库与命题用于写/对讲稿和检查充分度；预览用原件真实渲染。
- **无稿要从库出新 PPT：** 才走 Narrative → Projection；页数由本场 Presentation Profile 计算。

### 2.3 产品不是 CMS，当且仅当表达层可再生

系统被称为 CMS + 模板拼装器，当且仅当下面三句同时成立：

1. 用户必须按 22 个目录把上页句和讲稿句预先写完；
2. 出稿只是按分区取前 \(k\) 条，把预写短句填进槽；
3. 评分只检查「有没有挂上观测点名字」。

本版用三句反过来卡死：

1. 用户维护的是证据和命题，不是 22 套成品文案；
2. 出稿先有页面任务，再生成表达；
3. 检查的是充分度，以及上场之后有没有发挥出来。

## 3. 理论框架

### 3.1 符号

| 符号 | 含义 |
|---|---|
| \(R\) | 本场统一评分表的观测点有限集 |
| \(R_{\mathrm{must}}\) | 本场必须被托住的观测点子集 |
| \(T=(U,C,E_T)\) | 逻辑全景图：一级干、叶分区、从属边。后台本体，不是 UI 目录 |
| \(e\in E\) | 一条证据（Evidence） |
| \(k\in K\) | 一条命题（Claim） |
| \(\mathrm{Ev}(k)\subseteq E\) | 支撑该命题的证据集合，允许 \(\lvert\mathrm{Ev}(k)\rvert\ge 1\) |
| \(\sigma(e),\sigma(k)\) | 状态：草稿 / 已核验 / 禁用 |
| \(A(k,r)\) | Claim–Rubric Assessment：命题 \(k\) 对观测点 \(r\) 的评价对象 |
| \(\mathrm{str}(k,r)\in\{0,1,2,3\}\) | 内容证据强度（主张→事实→来源→对照/结果） |
| \(\mathrm{ver}(k,r)\in\{0,1,2\}\) | 现场可验证性（不能看→能指认→能当场跑） |
| \(\chi(k,r)=\mu(\mathrm{str},\mathrm{ver})\in\{0,1,2,3,4,5\}\) | 映射后的业务充分度，对齐 E0–E5 |
| \(\Phi\) | Presentation Profile（时长、听众、赛制、评分表、密度） |
| \(n=f(\Phi)\) | 本场页数预算，由画像计算 |
| \(N=\langle \iota_1,\ldots,\iota_n\rangle\) | 叙事：有序页面任务 |
| \(\iota_i\) | 第 \(i\) 页的 Page Intent |
| \(\psi(\iota)\) | 该页的期望证据轮廓（Required / Optional）——输入约束 |
| \(\mathrm{Succ}(\iota)\) | 该页成功条件，分硬成功（可机检）与软成功（人审/模型辅助） |
| \(S=\langle s_1,\ldots,s_n\rangle\) | 投影后的页 |
| \(\mathrm{cite}(s_i)\subseteq K\) | 页引用的命题 |
| \(\mathrm{expr}(s_i)\) | 当场生成的表达：页文本、视觉指令、口述要点 |
| \(\Delta(s_i)\) | 该页决策轨迹 + 由其生成的选择理由（不是事后文案） |
| \(G=\langle g_1,\ldots,g_n\rangle\) | 与页同序的讲稿段 |
| \(\mathrm{Suff}(S,r)=\mathrm{Aggregate}(\{A(k,r)\})\) | 观测点整体充分度。V1 默认 Aggregate = max；允许组合规则 |
| \(o_i\) | 第 \(i\) 页的 Performance Observation |
| \(P\) | 现场表现：介质 + \(\{o_i\}\) |
| \(V\) | 评价：Assessment 矩阵 + 根因候选 + 最小修复 |

B 中的材料库 \(L\) 在本版拆成 \(E\cup K\)。分区函数仍在：每条证据、每条命题可标注 \(\mathrm{cat}(\cdot)\in C\)，用于组织与检索，不用于「一叶一页」。

### 3.2 公理（修订）

**公理 1（证据源，而不是单条材料源）。** 任何允许上台的事实或数字，必须追溯到至少一条 \(\sigma(e)=\) 已核验的证据。页与讲稿不得持有无指针的事实。一个命题可以由多条证据共同支撑。不要求「一个事实只有一个来源」。

**公理 2（生成依赖单向，评价反馈受控回写）。** 生成方向：证据变更先打回其命题；命题变更先更新或取消引用它的页，再更新对应讲稿。禁止只改讲稿而使页仍指向旧命题。评价可以回写 \(E/K/N/G/P\)，但必须经根因候选与最小修复，且遵守系统修复优先级（完整性 → 证据 → 叙事 → 现场 → 表达）。禁止把评价直接写成页上的补句。

**公理 3（权利分层）。** 版式槽没有命题权：不得在引用为空时填充默认命题句。叙事拥有页面任务定义权：它可以规定这一页要完成什么、需要何种证据轮廓。命题权在 Claim，任务权在 Narrative，版式权在 Template，三者不可互换。

**公理 4（空指针禁抽）。** \(\sigma(k)\ne\) 已核验，或 \(\mathrm{Ev}(k)\) 中没有已核验证据，或不存在任何 \(A(k,r)\)，则 \(k\notin\mathrm{cite}(S)\)。仅有命题句、没有证据的条目不得上场。充分度不得写回 Claim。

**公理 5（充分度不是分数）。** \(\chi(k,r)\) 是单命题对单观测点的准备态。\(\mathrm{Suff}(S,r)\) 是该观测点上本场引用命题的聚合，V1 默认取 max，不是理论唯一形式。二者都不是实得分。\(\chi=1\) 不得被界面解释成「已覆盖」。E0–E5 仍是 v1.2 的业务等级；str/ver 是内部解释，映射表是本模型默认解释，不修改 v1.2。

**公理 6（页数是画像函数）。** \(n=f(\Phi)\)。当前 1 小时、统一评分表、中等密度的竞赛画像下，健康实例是 \(n\in[38,45]\)。该区间是配置，不是理论公理。更换时长或赛制必须重估 \(f\)，不得沿用。

### 3.3 推论

**推论 1（表达不是源）。** \(\mathrm{expr}(s_i)\) 可以由命题、证据摘录和页面任务生成；它不是第三条事实源。改页上的字若改变了事实，必须回写为新的证据或命题草稿，而不是只改表达缓存。

**推论 2（讲稿不得超页）。** \(g_i\) 中的事实集合必须是 \(\mathrm{cite}(s_i)\) 及其 \(\mathrm{Ev}(\cdot)\) 的口头闭包。可加无事实含量的衔接。引入新数即违反公理 1。

**推论 3（换任务必换选）。** 若第 \(i\) 页的 Intent 从「制造问题紧迫感」改为「从社会问题转到项目问题」，即使候选证据集合不变，选中的命题与生成的表达也必须重算。这是投影智能的最小可检验命题，用来反对 Top-K。

**推论 4（模板复用合法当且仅当命题变）。** 两个项目共用版式槽合法；若生成的页文本也相同且证据出处不同，视为内容模板泄漏。

### 3.4 三种「权」必须写进理论，不能只写进产品文案

B 写「版式没有命题权」是对的。B 后半又用 38–45 页叙事弧规定第 4–5 页是时事、第 10–12 页是痛点。命题权并没有消失，只是从 Template 转移到了 Narrative。

本版明确承认这件事。否则理论不严密：一边说没有人有权规定页上讲什么，一边又用叙事弧在规定。正确的分层是：

- **Template：** 位置、字号、条数、图文结构。
- **Narrative：** 这一页的任务、所需证据轮廓、成功条件、在整场中的位置。
- **Claim / Evidence：** 这一页实际可以主张什么、用什么证明。Claim 不持有充分度。
- **Assessment：** 这句命题对某个观测点证据够不够。它是 \((k,r)\) 上的关系，不是 Claim 的数组字段。
- **Expression：** 在上述给定之后，当场生成怎么写、怎么说。
- **Rationale：** 为什么选这些、为什么不选那些。

叙事有权说「这一页要制造紧迫感」；它无权捏造一条损耗率。版式有权说「这页只放两行大字」；它无权写「响应国家战略」。

## 4. 三层内容对象

### 4.1 Evidence（事实证据）

只保存事实，不保存上页句。

| 字段 | 含义 | 禁写 |
|---|---|---|
| `evidence_id` | 稳定唯一 | — |
| `source` | 文件、URL、系统导出、现场记录 | 无指针的「内部资料」 |
| `source_date` | 出处自身的时间 | 用整理日期冒充发生日期 |
| `original_quote` | 可回原文定位的摘录 | 改写后的宣传句 |
| `extracted_fact` | 从摘录抽出的原子事实 | 带立场的判断（那是 Claim） |
| `metric` | 数值、单位、口径、样本、测量协议 | 无口径的百分比 |
| `context` | 对象、场景、条件 | 用「某企业」永久匿名到无法核验 |
| `verification_status` | 草稿 / 已核验 / 禁用 | 模型输出直接已核验 |
| `category` | 后台分区，可空待分 | 强迫用户先选对 22 叶才能保存 |
| `project_id` | 所属项目 | 跨项目默默复用无出处套话 |

一条证据证明一件可核验的事。它不是一条新闻的「成品分析文章」，也不是一页 PPT。

「乱库」在证据层的操作定义：已核验但无出处；摘录无法回原文；同一度量冲突且未进入命题层裁决；所谓「8 份」是 8 个未打开的 URL。

### 4.2 Claim（命题）

Claim 只回答一件事：**我们到底在主张什么。** 它不评价自己对评分点够不够，不规定自己出现在第几页，不保存上页句。

| 字段 | 含义 |
|---|---|
| `claim_id` | 稳定唯一 |
| `proposition` | 一句可上台的判断，必须能被证据支持 |
| `evidence_ids[]` | \(\mathrm{Ev}(k)\)，允许大于 1 |
| `status` | 草稿 / 已核验 / 禁用 |
| `category` | 后台分区 |
| `project_id` | 所属项目 |

C 把 `rubric_ids[]`、`sufficiency[]`、`confidence`、`pair_id`、`conflicts[]` 全塞进 Claim，Claim 同时承担业务命题、评分映射、证据评价、关系约束，会在工程上长成胖对象。D 把后四类拆出去：

| 从 Claim 拿走的 | 放到哪 | 回答什么 |
|---|---|---|
| `sufficiency[]`、`rubric_ids[]` | Claim–Rubric Assessment \(A(k,r)\) | 这对 \((k,r)\) 证据够不够 |
| `confidence` | Assessment 上的派生量，或人改并留痕 | 对「这句命题支撑这个观测点」有多有把握 |
| `pair_id`、`conflicts[]` | ClaimRelation（成对、冲突、支撑） | 命题之间什么关系 |

**多证据是一等结构，不是来源列表的别名。** 命题「企业生产效率提升 23%」可以同时挂实验记录、系统后台、现场测试、第三方检测。核验看这组证据是否口径一致；冲突记在 ClaimRelation 上，不记成 Claim 的私有数组。

已核验命题的最低条件：

1. `proposition` 非空且不是空话（禁止单独成条的「采用人工智能、大数据、物联网等先进技术」升到已核验）；
2. 至少一条已核验证据；
3. 数值类命题必须能指到带口径的 `metric`；
4. 若要上场，必须存在至少一条 Assessment \(A(k,r)\)。没有 Assessment 的命题可以在库里，不能进 \(\mathrm{cite}(S)\)。

「系统效率提高 23%」对技术先进性可能是 4，对经济性可能是 3。这不是 Claim 有两个充分度字段，而是两条 Assessment。数据模型必须跟符号 \(\chi(k,r)\) 一致。

### 4.2.1 Claim–Rubric Assessment

```
Assessment A(k, r) = {
  claim_id,
  rubric_id,
  strength,          // 0–3，内容证据强度
  verifiability,     // 0–2，现场可验证性
  chi,               // μ(strength, verifiability)，对齐 E0–E5
  confidence,        // 可选，人可改并留痕
  rationale          // 为何是这个强度/可验证性，须能指回证据
}
```

Assessment 可以建议、必须可改、改了必须留痕。它不是分数，也不是 Claim 的固有属性。同一 Claim 换一个 \(r\)，就是另一条 Assessment，不得覆盖前一条。

### 4.3 Expression（表达）

表达不是库里的第三份定稿，而是某一次投影的产物。

```
Expression(s_i) = {
  slide_text,            // 本页可见文字
  visual_instruction,    // 图、对比、演示指示，不是新事实
  speaking_points        // 本页口述要点，不是逐字稿定本
}
```

生成函数：

\[
\mathrm{expr}(s_i)=\Gamma\bigl(\iota_i,\;\mathrm{cite}(s_i),\;\mathrm{Ev}(\mathrm{cite}(s_i)),\;\mathrm{slot}(s_i)\bigr)
\]

同一命题在不同页面任务下必须能生成不同表达。例如同一条「某产区采后损耗高」：

- 页面任务 = 制造问题紧迫感 → 短句强调规模与当下，视觉要冲击；
- 页面任务 = 从社会问题转到本项目 → 短句强调与成熟度误判的相似结构，视觉要对照。

若系统对两个任务吐出同一句 `slide_line`，说明表达仍被预写锁死，投影智能不成立。

V1 允许把某次生成的表达缓存下来供人改字，但缓存的身份是「本场投影草稿」，不是事实源。人改了事实，必须回写成 Evidence / Claim 草稿。

### 4.4 为什么这一刀决定系统是不是「智能」

智能不在「把 22 个盒子填满」，而在四步判断都可陈述：

1. 这些证据能不能支撑这句命题（冲突、口径；记在 ClaimRelation / Assessment）；
2. 这句命题是不是这一页任务所需要的那种证据（轮廓匹配，不是分数最高）；
3. 为了完成这一页任务，命题应该被写成哪一种可见文字和口述要点；
4. 为什么选它，以及为什么不选同库里另外两条。

B 把 2 和 3 提前写进材料对象，这两步就没有计算了。本版把它们留在投影时计算。第 4 步是投影对象的一部分，不是事后注释。这是「Projection Intelligence」的最小定义。

## 5. 充分度：从 Cover 到证据充分度矩阵

### 5.1 布尔覆盖为什么不够

「提到了评分点」≠「这个评分点被充分支撑」。

反例：观测点「技术先进性」，命题是「采用人工智能、大数据、物联网等先进技术。」`rubric_ids` 可以挂上先进性，Cover 为 1。评委不会给高分。B 的 \(\rho(m)\subseteq R\) 无法区分这句话和一条带对照基线、测试协议、现场演示路径的命题。

### 5.2 两维基础量，再映射成 E0–E5

C 把 0–5 写成一根纵轴：提及 → 事实 → 证据 → 对照 → 现场可验证。逻辑能用，但混了两个不同的东西。

- **维度 A：内容证据强度 \(\mathrm{str}\in\{0,1,2,3\}\)。** 有没有主张 → 事实 → 来源 → 对照 / 结果 / 第三方。
- **维度 B：现场可验证性 \(\mathrm{ver}\in\{0,1,2\}\)。** 能不能给评委看、当场跑、复现。

二者不同步。一份第三方检测报告 \(\mathrm{str}\) 可以很高，但现场不可复现，\(\mathrm{ver}\) 低。一场现场演示 \(\mathrm{ver}\) 可以是 2，但未必有第三方背书，\(\mathrm{str}\) 不一定到 3。把两者都叫「E5」，以后一定会被问：它们证明的是同一件事吗？不是。

**关系必须写清，避免「说是对齐，其实在重写规则」。**

- E0–E5 是 OREP v1.2 **已经在用的业务等级**，评分引擎继续按当季正式文本打分。
- \(\mathrm{str}/\mathrm{ver}\) 是本模型的 **内部解释变量**，用来拆开「内容强不强」和「现场能不能验」。
- 下面的 \(\mu\) 是本模型当前 **默认映射**，便于准备态和界面短句对齐到用户已经熟悉的 E 档。它 **不等于** 修改 v1.2 的评分定义，也 **未经** 对 v1.2 逐条观测点的校准。
- 未校准前，禁止在产品或规则文档里写「E4 = str2 + ver2」。只允许说：「按本模型默认解释，这条准备态接近 E4；正式分仍由评分引擎给出。」

内部仍先存两维，再映射为准备态标签：

\[
\chi(k,r)=\mu\bigl(\mathrm{str}(k,r),\,\mathrm{ver}(k,r)\bigr)
\]

| \(\mathrm{str}\) | 含义 |
|---|---|
| 0 | 无主张 |
| 1 | 只有主张 / 口号 |
| 2 | 有事实且有可打开出处 |
| 3 | 有对照、结果或第三方背书 |

| \(\mathrm{ver}\) | 含义 |
|---|---|
| 0 | 现场指不出、跑不出、打不开 |
| 1 | 页上或材料可指认（报告、截图、原件） |
| 2 | 当场可演示或可复现 |

默认映射 \(\mu\)（配置项，可按赛季校准，不得写死在版式里，不得冒充 v1.2 原文）：

| 强度 \ 可验证 | 0 | 1 | 2 |
|---|---|---|---|
| 0 | E0 | E0 | E1 |
| 1 | E1 | E1 | E2 |
| 2 | E2 | E3 | E4 |
| 3 | E4 | E4 | E5 |

于是：第三方报告且现场指得出原件 ≈ E4；第三方报告但带不走、现场也无法打开 ≈ 仍是高强度、低可验证，映射为 E4 而不是 E5；现场演示跑通但无对照基线 ≈ E4；两者都有 ≈ E5。E5 不再是「第三方」和「现场」的混称。

对外对用户仍说短句，不说 \(\mathrm{str}/\mathrm{ver}\)：

| 准备态 \(\chi\) | 界面仍借用的业务档 | 产品里对用户说的话 |
|---|---|---|
| 0 | E0 | 这个点还没准备 |
| 1 | E1 | 只是提到了，评委很难给分 |
| 2 | E2 | 有说法，缺能打开的证据 |
| 3 | E3 | 有证据，还缺对照或口径 |
| 4 | E4 | 有对照或结果，现场要能指出来 |
| 5 | E5 | 既能证明，现场也能验证 |

评分引擎继续打正式分。本模型不输出「预计 87 分」，只输出：「先进性目前是 1 级（提及），上场会被当成套话；库里其实有测试记录，本场没投影。」后半句才是产品价值。

### 5.2.1 观测点整体充分度是聚合，不是永远取 max

\(\chi(k,r)\) 仍是 **单命题充分度**，保留。  
\(\mathrm{Suff}(S,r)\) 是 **观测点整体充分度**：

\[
\mathrm{Suff}(S,r)=\mathrm{Aggregate}\bigl(\{A(k,r):k\in\mathrm{cite}(S)\}\bigr)
\]

V1 默认 \(\mathrm{Aggregate}=\max\)。这够用在「一条强命题就能托住该点」的情况。它不是理论唯一形式。

反例：观测点「技术先进性」需要原理 + 对照 + 测试结果。三条 Claim 分别是 2、3、3，\(\max=3\)；组合起来可能已经是一条完整证据链，高于任一单条。反过来说，单独一条 Claim 到了 4，若缺必要环节，该观测点仍可能完不成。

因此区分：

| 对象 | 回答 |
|---|---|
| \(\chi(k,r)\) | 这一句主张，单独看，对这个点够不够 |
| \(\mathrm{Suff}(S,r)\) | 本场引用的这组主张合在一起，对这个点够不够 |

V2 允许把 Aggregate 换成组合规则，例如按观测点配置的必要环节集合（原理、对照、结果）做「齐套提升」。未配置组合规则的观测点，继续用 max。准备完成条件仍是 \(\mathrm{Suff}(S,r)\ge\theta(r)\)。\(\theta\) 必须公开。禁止用「已覆盖」代替级数。

### 5.3 评价：A/B/C 是 V1 标签，不是最终分类

假设库有企业合作证据，页有，讲稿有，评委仍不认。V1 用三个表现缺口，并预留第四个完整性缺口：

| 类型 | 名称 | 判据 |
|---|---|---|
| A | 没讲清楚 | 转写里关键命题未出现，或出现在超时之后 |
| B | 讲了但没有证明 | 转写有主张，\(\chi\le 2\)，或关键帧 / 材料对不上 |
| C | 证明了但呈现弱 | \(\chi\ge 3\)，现场有证据，但任务不匹配、视觉不可读、口述被淹没 |
| D | 事实 / 命题完整性失败 | 页上的数与证据不一致；前后命题冲突；命题超出证据（过度主张） |

D 不是润色问题。PPT 写 23%、证据是 22.8% 且口径未说明，或前面说提升 30%、测试记录是 18%——最危险的往往不是没讲，而是讲错。完整性未过，不得先去改讲稿腔调。

### 5.4 系统修复优先级（不只是评价算法的一步）

整场备赛的修复顺序升格为系统规则，不单写在 Evaluation 里：

**完整性 → 证据 → 叙事 → 现场 → 表达**

| 序 | 优先级 | 看什么 | 典型标签 |
|---|---|---|---|
| 1 | 有没有说错 | 数冲突、过度主张、证据与陈述不一致 | D |
| 2 | 有没有证据 | 单命题 \(\chi\) 或组合后的 \(\mathrm{Suff}\) 低于 \(\theta\) | B |
| 3 | 证据有没有进对的叙事 | 库有未投影；硬成功不满足 | 未投影 / Intent |
| 4 | 现场有没有做到 | Observation 的偏差 | A / C |
| 5 | 视觉还能不能更好 | 表达、版式消费 | Expression |

「技术先进性没表现出来」经常同时穿过多层。禁止一条评分结果对应一个回写层。改成：评分问题 → 根因候选集 → 按上表取最小修复。A/B/C/D 可并存；系统交付的是有序修复清单。

Evaluation **不重新评分**。它只解释：已有评分报告 + Assessment + Intent + Observation。这是诊断，不是第二套打分引擎。

这正接上 OREP 已有的路演录像 + AI 评分 + 复盘追问。

## 6. Page Intent：页成为一等对象

### 6.1 页不是槽，是任务

B 中 \(S=\langle s_1,\ldots,s_n\rangle\)，页大约是 slot + cite。真实路演页的选择问题不是「哪两条材料分数最高」，而是「这一页在整场叙事里面承担什么作用」。

Page Intent 至少包含：

```
PageIntent ι = {
  index,                 // 本场中的位置
  role,                  // 这一页要完成的叙事任务
  required_profile,      // 必须出现的证据轮廓（输入约束）
  optional_profile,      // 有则更好
  forbidden,             // 本页禁止出现的东西
  budget,                // 可引用命题数、口述秒数
  hard_success,          // 可机检：Required/Forbidden/budget/指定关系/pair
  soft_success           // 人审或模型辅助：桥接是否自然、是否真正紧迫
}
```

\(\psi(\iota)\) 是输入约束：页上要有什么。\(\mathrm{Succ}(\iota)\) 是输出验收，必须拆成两类，禁止混成一句「V1 先看」：

| 类 | 谁判 | 例子 |
|---|---|---|
| 硬成功 | 系统自动 | Required 命题是否都在；是否触发 Forbidden；是否超 budget；痛点—策略 pair 是否成对；是否存在「外部事件—项目痛点」这条指定关系边 |
| 软成功 | 人审，模型可建议 | 评委能否从外部事件自然理解项目问题；是否真正形成紧迫感；桥接是关系还是三句并列 |

硬成功不通过，页不得标完成。软成功不通过，页标「待人审」，不得假装系统已经判定「评委理解了」。

实例（不必是第 12 页）：

```
Intent: 从社会问题转到本项目问题
Required:
  - 1 个外部问题证据
  - 1 个结构相似性
  - 1 个项目痛点
Forbidden:
  - 本页不引入技术方案
Budget:
  - 至多 3 个命题；口述 ≤ 90 秒
Hard success:
  - Required 三项都引用
  - 存在 ClaimRelation(外部事件, 项目痛点, type=桥接)
  - 未引用技术实现类命题
Soft success:
  - 人确认：读完能从外部事件理解项目问题
  - 人确认：不是三句话并列
```

「Required 三项都在，但没有桥接关系边」是硬失败，可自动。 「有关系边，但读起来不像桥接」是软失败，V1 交给人。

### 6.2 期望证据轮廓，不是分区配额

定义 \(\psi(\iota)\) 为该页的 Desired Evidence Profile。候选选择是轮廓匹配：

\[
\pi(\iota,K,E)=\arg\operatorname{match}\bigl(\psi(\iota),\;K,\;E\bigr)
\]

match 要可陈述，建议按这个顺序，而不是先算一个总分再取 Top-K：

1. **硬过滤。** 已核验；证据未过期；成对约束；本页 forbidden 不触发；数值有口径。
2. **轮廓满足。** Required 每一项至少有一个候选能填上。若某一 Required 全库都空，该页标「本场无法完成该任务」，禁止用套话填洞。
3. **任务适配。** 同一组候选，按 Intent.role 重排。制造紧迫感优先冲击力、可指认现场、新鲜度；转到项目问题优先结构相似、能挂到已有痛点命题；证明先进性优先对照基线和可演示。
4. **充分度增益。** 在仍未达到 \(\theta(r)\) 的观测点上，优先选能把 \(\mathrm{Suff}\) 从 1 拉到 3 以上的命题，而不是再选一条「提及」。
5. **多样性与预算。** 同事件簇不占满一页；不超过 `budget`。
6. **生成表达。** 调用 \(\Gamma\) 写 `slide_text` / `speaking_points`。
7. **落下决策轨迹。** 输出 \(\Delta(s_i)\)。没有轨迹的页，投影交付不合格。禁止先选定再让模型写一段漂亮话。
8. **对照成功条件。** 先跑硬成功（自动）。软成功进入人审队列。硬成功失败不得标绿。

第 3 步是排序器变成投影的地方。第 7 步是投影智能可被检验的地方：理由必须能从轨迹回放，不能只是文案。

### 6.2.1 决策轨迹（理由必须由此生成）

「与选择一起落盘」并不能证明理由导致了选择。模型可以先选 N4，再编一句为什么 N4 好。那是事后合理化（post-hoc rationale），不是投影智能。

```
ProjectionDecision Δ(s_i) = {
  selected_claims[],
  rejected_candidates[],
  per_candidate: {
    claim_id,
    constraints_matched[],    // 命中了哪些 Required / 硬成功
    constraints_violated[],   // 触犯了哪些 Forbidden / 多样性 / 留给下页
    ranking_factors[]         // 冲击、可指认、桥接价值、与下页重复度……当时的分项
  },
  decision_trace[]            // 过滤 → 轮廓 → 排序 → 取舍 的有序步骤
  reasons[]                   // 只能由 trace + factors 生成，禁止另写
}
```

用户看见的应是轨迹的可读展开，例如：

```
N4  真实性 ✓  冲击 ★★★★★  可指认 ★★★★★  与下页重复：低  多样性 ✓
    → 本页 role=紧迫感，取冲击最高且可指认者

N8  真实性 ✓  冲击 ★★★    桥接 ★★★★★  本页任务不是桥接
    → 违反「本页不做桥接」，留给下一页

N1  真实性 ✓  冲击 ★★     与 N4 同簇
    → 冲击弱；多样性已由 N4 占据
```

验收：给定同一 trace，换一个文案模型，reasons 的命题内容不得改变（可以改措辞）。若 reasons 里出现 trace 中没有的因子，交付不合格。这才是「有限证据空间里、在明确任务约束下做选择」，而不是解释性文案。

### 6.3 叙事弧仍可用，但降为某一种 Profile 的默认 Intent 序列

B 第 18 节那张 40 页表（封面 → 时事 → 政策 → 痛点 → 策略 → 架构 → 实施 → 创新 → 价值）仍然是 1 小时竞赛画像下的合法默认 Narrative。它不再是唯一合法叙事，更不是 22 叶的展开。

换 Profile 时，变的是 Intent 序列，不是把同一张表硬压缩。15 分钟场次不是「把 40 页每页删一半字」，而是另一组更短的任务序列：问题真实、方案对应、一次可演示、一个结果。时事可能从「两页制造紧迫感」变成「二十秒内一句桥接」，甚至 \(k=0\)。

## 6.4 Performance 是 Plan vs Actual，不是「现场发生了什么」

没有 Intent，就无法判断现场好不好。Performance 的准确定义是：**现场表现相对于演示计划的偏差。** 介质仍是录像、转写、关键帧、演示是否跑通；对象是 Observation：

```
Observation o_i = {
  page, timestamp,
  claim,
  expected,     // 来自 Intent.success + Expression.visual_instruction
  actual,       // 来自转写 / 关键帧 / 演示日志
  deviation,    // expected 与 actual 的差
  on_slide      // 证据当时是否在页上
}
```

实例：

```
Page 18  00:31:12
Claim:    系统可以实时识别异常
Expected: 指向屏幕右侧演示结果
Actual:   口头说了，但没有指屏幕
On_slide: 画面已经存在
Deviation: 有主张、有画面、无指示
→ 候选 C（呈现失败），不是 B（没证明）
```

于是完整的现场链是：

\[
\mathrm{Intent}\;\rightarrow\;\mathrm{Projection}+\Delta\;\rightarrow\;\mathrm{Observation}\;\rightarrow\;\mathrm{Evaluation}
\]

没有 expected，录像只是桶，A/C 只能靠评分模型猜。expected 必须在投影时从硬成功、视觉指示写好；软成功的 expected 标「待人审」。现场只填 actual。这一层是计划对照，不是独立的录像分析。

## 7. Presentation Profile 与页数

### 7.1 画像

```
PresentationProfile Φ = {
  duration,          // 秒
  audience,          // 评委 / 企业 / 校内预演
  competition,       // 赛项、赛段
  scoring_system,    // 本场 R 与 R_must、θ
  page_density       // 每页目标秒数，或「图主导 / 字主导」
}
```

\[
n = f(\Phi)
\]

\(f\) 的最小约束：页数 × 目标秒数不超过时长预算；Intent 序列必须能覆盖 \(R_{\mathrm{must}}\) 的 \(\theta\)；禁止为凑 \(n\) 复制同一命题。

### 7.2 38–45 的地位

在 \(\Phi=\)（约 3600 秒，正式评委，当前赛项，统一评分表，中等密度，约 80–90 秒/页）时，\(f(\Phi)\in[38,45]\) 是健康实例。番茄 38 页设计稿落在这个实例里，所以 B 用它当工作区间是有现场根据的。

它不能再当公理。实施配置里应写成：

```
profiles:
  contest_1h: { duration: 3600, n_range: [38, 45], sec_per_page: [75, 95] }
  defense_15m: { duration: 900, n_range: [8, 14], sec_per_page: [60, 80] }
```

超时先改 Intent 序列或降低某页 budget，不把 1 小时稿压成十几页还声称同一场比赛。

## 8. 22 分区：后台本体，前台证据地图

### 8.1 后台：B 第 4 节仍然有效

22 个叶的定义、典型证据、禁止写入、与观测点的 \(\mu(c)\)，以修订稿 B 第 4 节为本体附录，本版不重抄一遍。它们继续回答「材料按什么架子放」，继续禁止把工匠精神写成「精益求精」、把经济性写成无账「节约 X 万」。

完备性改写为：后台 22 个库位可以存在，允许空。空的含义是「这类证据尚未形成」，不是「用户还没交作业」。\(k_c=0\) 仍表示有意识裁剪。二者必须在证据地图上区分。

### 8.2 前台：用户看见的是缺口，不是文件夹

用户打开项目时，不先看见：

```
项目背景
 ├ 时事
 ├ 政策
 ├ 调研
 ├ 动因
 …
```

而先看见**下一步最该补的 3 件事**。地图可以按叙事一级聚合，但首页禁止做成：

```
证据充分度 86%
关键点 13/16
投影率 74%
表现率 82%
```

那是另一种「竞赛大脑数据驾驶舱」。学生看完仍不知道干什么。百分比可以留在内部质量，不得当首页主视觉。

首页三件事必须是可执行动作，例如：

1. 技术先进性目前只有 E1，有测试记录但还没形成命题；
2. 企业合作证据在库，还没投影到承担「落地真实性」的那一页；
3. 第 18 页有证据，录像里说到了，但没有指到屏幕上的结果。

背后仍按区块汇总（给老师展开，不给首页）：

| 地图区块 | 展开后看见 | 背后实际在看什么 |
|---|---|---|
| 项目背景 | 已有 12 条证据，缺 2 个关键证据 | 时事/政策/调研/动因；「问题真实」的 Assessment |
| 方案逻辑 | 已形成 6 组痛点—策略关系 | ClaimRelation 成对数 |
| 技术实现 | 已有 18 项实现证据 | 架构/五岗/测试中 \(\chi\ge 3\) 的 Assessment 数 |
| 创新价值 | 经济成效缺证据 | 经济性 \(\mathrm{Suff}=0\) 或只有 1 |

空文件夹对用户是进入门槛；缺关键证据才是备赛动作。22 叶可以在「查看全部证据」时展开，不能当首页。

### 8.3 入库不再要求一次写完表达

入库目标从「每个分区 N 条带 slide_line 的材料」改为：

1. 收到可打开的证据；
2. 抽原子事实；
3. 形成或挂到命题；
4. 需要上场时，为 \((k,r)\) 建 Assessment（强度、可验证性；\(\chi\) 由映射得出），人确认；
5. 更新「下一步 3 件事」。

检索、去重、核验仍按 B 第 6 节的纪律做。模型可以起草 `extracted_fact` 和 `proposition`，默认草稿。不再要求入库员同时写出上页 28 字和口述 80 字——那是投影的工作，提前写等于把智能做死。

## 9. 讲稿展开（Verbalization）

映射仍是 \(g_i=\gamma(s_i)\)。输入改为：页面任务 \(\iota_i\)、引用命题、证据摘录、本页已生成的 `speaking_points`、角色分工。允许增加称呼、翻页、交接、现场指示。不允许增加新数字、新政策名、新合作方、新精度。

一致性：

\[
\mathrm{Consist}(S,G)\iff \forall i,\; \mathrm{Facts}(g_i)\subseteq \mathrm{Facts}\bigl(\mathrm{cite}(s_i)\cup\mathrm{Ev}(\mathrm{cite}(s_i))\bigr)
\]

变更传播比 B 多一条：改 Page Intent，必须重选或重生成该页表达与讲稿，即使引用的命题集合碰巧没变。改命题的证据集，必须重算充分度；若充分度掉到 \(\theta\) 以下，该页标风险，不自动补套话。

## 10. 产品承诺：降低失分风险

科学上继续坚持：覆盖不是分数，充分度不是分数，不承诺提分。产品上不能停在这三句否定。

用户要的不是「帮你多得 5 分」。用户要的是：

> 确保你已经准备的关键证据，在路演中没有丢掉。

这是可交付、可观察、不依赖评委随机性的价值。

三种必须能说清楚的状态：

| 状态 | 对用户的句子 | 系统动作 |
|---|---|---|
| 库无 | 经济成效还没有能上台的证据 | 去收证据，禁止生成假账 |
| 库有未投影 | 你有企业合作证据，这场 PPT 里评委看不到 | 建议加入某个 Page Intent，或标「本场主动不讲」 |
| 已投影未发挥 | 页上有，录像里没讲清 / 没指到图 / 被超时吃掉 | 写 Observation，进根因候选，不改库里的数 |
| 讲错了 | 页上的数和证据对不上 | 标 D，先修命题或证据，禁止润色 |

「证据存在，但本场未投影」和「下一步 3 件事」是主界面一等提示。覆盖率百分比不是。

对外口径固定为降低失分风险。对内指标仍算充分度、追溯率、未投影关键命题数。禁止把对内指标画成预计得分仪表盘，也禁止画成充分度驾驶舱。

## 11. 智能化的操作定义（重写）

系统在本模型下被称为表现出投影智能，当且仅当同时满足：

1. **条件依赖。** 固定版式与 Intent 模板，更换项目主题，命题与生成表达显著变化。
2. **任务依赖。** 固定证据与命题，只改某页 Intent.role，选中集合或生成表达发生变化（推论 3）。
3. **充分度依赖。** 固定库，把某观测点从「仅提及」补到「有证据 + 对照」，地图与投影优先使用新命题，而不是继续搬运旧套话。
4. **拒绝发明。** Required 轮廓无法满足时，该页输出「本场无法完成该任务」或拒绝出页，不生成默认命题。
5. **可追溯。** 上场每一短句回溯到命题，再回溯到至少一条已核验证据。
6. **可解释选择。** 每页 \(\Delta\) 同时给出选中理由和落选理由，且能指回 role / profile / success。
7. **可验收任务。** Required 齐而 success 不成立时，不得标该页完成。
8. **可解释失败。** 对一次已评分路演，系统给出根因候选与最小修复，而不是只贴一个 A/B/C。D 若成立，优先于润色。

只满足「8 秒填完一页版式」，或只满足「按分区取前 k 条预写短句」，是排版自动化或 CMS，不得称投影智能。

## 12. 完整算例：同一库，两个页面任务，选出不同的两条

### 12.1 设定

项目主题 \(\tau=\) 设施番茄成熟度误判导致损耗。  
库中已核验的时事类命题 8 条（类型，不编造具体新闻标题）：

| id | 证据轮廓 | 冲击 | 与「成熟误判」结构相似 | 过期 |
|---|---|---|---|---|
| N1 | 产区损耗通稿 | 中 | 弱 | 否 |
| N2 | 与 N1 同事件另一家媒体 | 中 | 弱 | 否 |
| N3 | 设施农业政策动态 | 低 | 无 | 否 |
| N4 | 采后储运爆仓，有现场图 | 高 | 中 | 否 |
| N5 | 无关宏观财经 | — | — | 否 |
| N6 | 地方智慧农业试点启动 | 低 | 弱 | 否 |
| N7 | 三年前旧闻 | 中 | 中 | 是 |
| N8 | 另一产区因分级误判导致损耗，有对照数字 | 中 | 高 | 否 |

硬过滤去掉 N5、N7。N1 与 N2 同簇，一页最多留一条。

### 12.2 任务 A：第 4 页，制造问题紧迫感

```
role: 制造问题紧迫感
required: 真实性, 冲击力, 可指认现场
optional: 数据
success: 评委感到问题就在当下、可指认；本页不解释方案
```

合法选：N4（现场图、爆仓、当下）。N8 可作第二页，但本页不是它。  
不合法：N3（无冲击）、N1+N2（同簇占满）、按「与评分点相关」选出 N3+N6（相关但完不成紧迫感）。

\(\Delta\) 必须写下：选 N4 因为冲击+可指认；不选 N1 因为冲击弱；不选 N8 因为留给下一页桥接。  
生成表达必须服务于冲击，而不是复述政策语感。Required 齐了但评委读完仍不知道「当下急在哪」，success 不成立。

### 12.3 任务 B：第 5 页，从社会问题转到项目问题

```
role: 从社会问题转到本项目的成熟度误判
required: 问题相似性, 能挂到已有痛点命题
optional: 对照数据
forbidden: 本页不展开技术方案
success: 桥接关系可被指出；页结束时项目问题已明确；未展开技术
```

合法选：N8（分级误判 ↔ 成熟误判，结构相似，有对照）。  
N4 冲击强，但桥接弱，不应只因「分数高」再占这一页。\(\Delta\)：不选 N4，因为它已完成上一页紧迫感，本页再用会重复任务。

B 的加权排序器在两个任务上很容易给出同一对 \(\{N4,N8\}\) 或同一对「最相关」。本模型要求两页的 *role* 不同，则 \(\Delta\) 必须不同。解释写不出来，就还不是投影。N8 和痛点命题都在、但页上只是并列两句，success 不成立——这是 Intent 审计，不是缺材料。

### 12.4 Assessment，不是 Claim.sufficiency

N4 对「问题真实」：\(\mathrm{str}=2\)（有出处、有现场图），\(\mathrm{ver}=1\)（图可指认）→ \(\chi=3\)。若还有对照结果，\(\mathrm{str}=3\)，仍无现场复现则 \(\chi=4\)，不是自动 E5。  
「采用物联网等先进技术」对「技术先进性」：\(\mathrm{str}=1\) → \(\chi=1\)。同一命题若另挂经济性，是另一条 Assessment，不得覆盖本条。

若评分仍扣「问题不真实」而 N4 已投影：先看 Observation（指没指到图），再标 A 或 C，不写套话。若页上损耗率与 N4 证据不一致：先 D。若 N4 从未投影：走「库有未投影」。

## 13. 质量指标（可计算，不展示成预计得分）

1. **追溯率** \(T_r\)：上场短句能指回已核验命题及至少一条已核验证据的比例。目标 1。
2. **表达非源性**：上场短句中，以库内预写 `slide_line` 为唯一来源、且未经过 \(\Gamma(\iota)\) 的比例。目标 0。
3. **任务可解释率**：每页 \(\Delta\) 同时含选中理由与至少一条落选理由，且能指回 role / profile / success。目标 1。
4. **成功条件可检率**：每页 Intent 有非空 \(\mathrm{Succ}\)，且 Required 齐而关系未形成时被标未完成。目标 1。
5. **充分度达标率** \(\lvert\{r\in R_{\mathrm{must}}:\mathrm{Suff}(S,r)\ge\theta(r)\}\rvert/\lvert R_{\mathrm{must}}\rvert\)。缺口必须列表。\(\chi\) 必须来自 Assessment，不得读 `claim.sufficiency`。
6. **提及冒充覆盖数**：\(\mathrm{Suff}=1\) 却被界面写成「已覆盖」的次数。目标 0。
7. **关键未投影数**：某条 Assessment \(\chi\ge 3\) 的命题未进入 \(\mathrm{cite}(S)\) 且 \(r\in R_{\mathrm{must}}\) 的个数。失分风险主指标。
8. **讲稿超事实率**：目标 0。
9. **成对完整率**：上场策略经 ClaimRelation 带合法痛点的比例。目标 1。
10. **完整性冲突数**：已投影命题与证据数值/口径不一致的条数（D）。目标 0。
11. **Observation 覆盖率**：已路演页中既有 expected 又有 actual 的比例。内部质量。
12. **内容模板泄漏**：跨项目生成页文本完全相同且证据出处不同的条数。目标 0。

一次投影交付必须附带 1–10。缺测则交付不合格。百分比不得上首页。

## 14. 评价协议与可证伪命题

### 14.1 每次投影必跑

- 指针闭包：短句 → 命题 → 已核验证据。
- Required 轮廓未满足的页不得用默认句出页。
- Required 齐而 \(\mathrm{Succ}\) 不成立的页不得标完成。
- 每页有 \(\Delta\)，含至少一条落选理由。
- \(\mathrm{Consist}(S,G)=1\)。
- \(n=f(\Phi)\) 或显式偏离理由。
- Assessment 矩阵与「下一步 3 件事」一并导出。

### 14.2 对照实验

固定项目与库，比较四种出稿：版式默认文案、B 式分区 Top-K 预写短句、本模型（Intent + 生成表达）、人工选条。评阅人只判断两个东西：观测点充分度（0–5，不是总分）；能否一眼看出该页任务。预期：本模型在「页任务可识别」上高于 Top-K；追溯率 100%；默认文案充分度集中在 0–1。

另做任务依赖实验：只改一页 role，其余不动，断言选中或表达变化。不变化则投影智能不成立。

### 14.3 可检验命题

**P1** 上场任一短句可回溯到已核验命题及至少一条已核验证据。  
**P2** \(\chi(k,r)\) 存在于 Assessment，不存在于 `claim.sufficiency`。\(\mathrm{Suff}\) 是 Aggregate；未配置组合规则时等于 max，配置后可以高于任一单条 \(\chi\)。\(\mu\) 不得冒充 v1.2 原文。  
**P3** 固定库，只改一页 Intent.role，选中集合或表达变化；\(\Delta\) 含决策轨迹，reasons 中的因子都能在 trace 里找到。  
**P4** 硬成功失败则页不得标完成；软成功失败只标待人审，系统不得宣称「评委已理解」。  
**P5** Assessment \(\chi\ge 3\) 但未投影的命题，必须出现在「库有未投影」，不得沉默。  
**P6** 已评分路演给出根因候选与最小修复，遵守完整性→证据→叙事→现场→表达；Evaluation 不输出新分数。  
**P7** 已路演页的 Observation 是 Plan vs Actual：有 expected 与 actual。

P1 继承 B。其余是防止自己变成 CMS、胖 Claim、或评分贴标签器的钉子。任一长期为假，应停称「投影智能」。

## 15. 失效条件

1. 已核验证据无出处仍上场。
2. 讲稿出现库中没有的数。
3. 版式默认句成为命题。
4. 以单次 AI 评分涨跌作为唯一验收。
5. 22 叶被做成用户必须填的 22 页或 22 个空文件夹首页。
6. 材料对象再次要求预写 `slide_line`/`speak_line` 才能入库，投影只搬运。
7. Cover 重新变成布尔，充分度 1 被显示成已覆盖。
8. \(n\in[38,45]\) 被写进与时长无关的硬编码。
9. 已有设计稿门的预览不是原件真实渲染。
10. 评价直接改页上套话，而不回到证据、命题或页面任务。
11. 充分度重新写回 Claim 字段，或 E0–E5 不再能拆回强度 × 可验证性。
12. 投影交付没有决策轨迹，或 reasons 含 trace 中不存在的因子。
13. 七层被做成七个并列产品模块。
14. 把整条系统再写成「单向链」，却同时用评价回写库。
15. Evaluation 输出「应该得多少分」，或把默认映射表写成 v1.2 的修改。
16. 软成功被系统自动标绿。

## 16. 实施顺序（仍然只用现有模块）

原则：先让证据和命题活起来，再让地图能指出缺口，再让某一页按任务生成表达。禁止从「先出 40 页空模板再填句」倒做。

**阶段 I — 证据与命题。** 资源中心收证据，智能文档形成命题。Claim 按第 4.2 节保持瘦：命题 + 证据集合 + 状态。不要 `slide_line`，不要 `sufficiency[]`。成对与冲突走 ClaimRelation。先做时事、政策、痛点、策略、经济/知产。

**阶段 II — Assessment 与「下一步 3 件事」。** 为需要上场的 \((k,r)\) 建强度 / 可验证性，映射 E0–E5。首页只给三件可执行的事。不做百分比驾驶舱。

**阶段 III — 一个 Profile 的 Page Intent。** 先只做 `contest_1h`。每页有 role、required、forbidden、budget、**hard_success / soft_success**。

**阶段 IV — 投影 + 决策轨迹。** 无稿：按 6.2 的步骤选命题，落盘 trace 与由其生成的 reasons，再 \(\Gamma\)。已有设计稿：不改图，只对 Intent / cite / \(\Delta\)。

**阶段 V — Plan vs Actual。** 投影时写 expected；路演后填 actual。没有 expected 的录像不进入自动 A/C。软成功的 expected 待人审。

**阶段 VI — 诊断与最小修复。** 已有评分报告 + Assessment + Observation → 按系统修复优先级给出清单。不重新打分。

阶段 I–II 不做自动出 PPT，也可以单独成为有用产品：备赛证据操作系统。这比先做拼装器更接近本模型。

## 17. 结论

B 已经把最有产品价值的判断立住了：事实源是材料对象；22 叶不是 22 页；评分是审计不是发动机。主轴 \(L\Rightarrow S\Rightarrow G\) 和那句

> PPT 是材料库在页数与时长预算下的抽取投影，讲稿是该投影的口头展开。

继续作为整个产品的底层理念。

B 的问题是把材料写成了成品答案，把抽取写成了排序，把覆盖写成了布尔，把 22 叶和 38–45 页写得太像用户必须遵守的封闭世界。那样落地，系统会很稳，也会立刻不再智能。

C 做结构开放。D 把对象边界钉死。E 把四个会打脸的歧义钉死：生成单向、评价受控回写；Suff 可组合；理由来自轨迹；成功分硬软。不再加层。

B 解决「AI 不胡说」。C/D 解决「AI 做选择」。E 保证这个选择在工程上不会变成事后文案、单条 max 卡住复杂评分点、或第二套打分引擎。

竞赛大脑的核心资产是：证据有没有 → 主张是什么 → 为什么选这个（轨迹） → 为什么放这页 → 怎么讲 → 相对计划实际怎样 → 按优先级下一步最小修什么。PPT 是投影结果。产品能力仍然是资源中心、智能文档、PPT、讲稿、路演、评分、复盘。

理论到此定型。下一份文件应是最小可运行原型定义，不是修订稿 F。

未满足追溯率 1、Assessment 不写回 Claim、Suff 可声明为组合、\(\Delta\) 含可回放轨迹、硬成功可机检、Evaluation 不输出新分数，不得对外称本模型已落地。

## 附录 F  落地冻结（不是新对象层）

理论不再加层。下面三条是防把系统做重的工程纪律，实施时视为 E 的一部分。

1. **Assessment 按需实例化。** 不要求 Claim × Rubric 全覆盖。只在命题进入某页候选集时，对该页相关观测点建 \(A(k,r)\)。禁止做成全量关系矩阵后台。
2. **决策轨迹内部完整、界面只看关键决策。** 全量候选参与计算。持久化并展示的只有：入选、差一点入选、被关键约束淘汰、与下一页抢资源的候选。每页界面最多「选它的 2 个原因 + 没选另外 2 个的原因」。禁止把 200 条候选做成用户调试器。
3. **V1 的 Aggregate 冻结为 max。** 组合规则只留函数接口，不实现、不配 42 赛道 × 观测点的齐套引擎。

ClaimRelation 最小类型集（不再用「一网打尽」的自由字符串）：`supports` / `contradicts` / `responds_to` / `bridges_to` / `depends_on` / `refines`。痛点→策略是 `responds_to`，外部事件→项目痛点是 `bridges_to`。

核验分层：Evidence 已核验 ≠ Claim 已被证明。界面禁止把「已核验命题」写成「这句话已被证明」。证据为真只说明材料在；命题是否被支持，看 Assessment，不看状态机上的一个勾。
