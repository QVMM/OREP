# 教师端学习资料上传反馈设计

## 背景

教师在“集训营 → 计划与日任务 → 今日学习”上传视频或课件时，当前界面在请求期间会清空已有提示，但不会展示上传状态；按钮也没有切换为上传中。上传接口继承教师端 Axios 的 20 秒普通请求超时，较大的视频或课件容易在仍然上传时被前端判定失败。

多文件上传当前只在所有文件全部成功后才更新资源列表。如果后续文件失败，前面已经上传到服务器的文件不会出现在当前列表中，老师容易误判为全部失败。

## 目标

- 上传开始后立即提供可见、连续的状态反馈。
- 上传结束后同时提供模块内结果和页面级消息。
- 多文件上传允许部分成功，已成功文件必须立即出现在列表中。
- 视频和课件上传不再受到 20 秒普通请求超时限制。
- 错误提示必须包含失败文件和可理解的失败原因。

## 非目标

- 不修改服务器允许上传的文件类型和大小限制。
- 不改造为分片上传或断点续传。
- 不新增阻塞式上传弹窗。
- 不修改“任务附件”和其他页面的上传交互。

## 交互状态

### 空闲

- 按钮文案为“上传视频或课件”。
- 不展示历史上传状态；开始新上传时清除“学习内容已移除”等过期提示。

### 上传中

- 按钮文案变为“上传中…”，并保持禁用，防止重复选择。
- 模块内状态显示：
  - 当前序号，例如“正在上传 1/3”；
  - 当前文件名；
  - 当前文件上传百分比；
  - 全部文件的总体百分比。
- 状态区域使用 `role="status"` 和 `aria-live="polite"`。

总体进度按顺序上传计算：

```text
(已完成文件数 + 当前文件进度) / 文件总数
```

### 全部成功

- 每个文件成功后立即加入学习资源列表。
- 模块内显示绿色成功提示，例如“3 项学习内容已上传，可直接修改名称”。
- 页面右上角显示一次成功消息，不按文件逐条弹出。

### 部分成功

- 继续尝试上传其余文件，不因单个文件失败而终止整批上传。
- 已成功文件保留在列表中。
- 模块内显示警告结果，包含成功数、失败数和失败文件名。
- 页面右上角显示一次警告消息。

### 全部失败

- 模块内显示红色错误提示，包含首个失败文件名和错误原因。
- 页面右上角显示一次失败消息。
- 按钮恢复可用，老师可以重新选择文件。
- 错误状态区域使用 `role="alert"`。

## 数据流

1. 老师选择一个或多个文件。
2. 组件立即进入上传中状态并清空过期提示。
3. 文件按选择顺序逐个上传。
4. API 通过 `onUploadProgress` 回传当前文件已上传字节数和总字节数。
5. 组件换算当前文件进度和整批总体进度。
6. 单个文件成功后立即合并到 `resources`，并触发 `update:modelValue`。
7. 单个文件失败时记录文件名和错误原因，然后继续下一个文件。
8. 全部尝试完成后，根据成功数与失败数进入成功、部分成功或全部失败状态，并发送一次页面级消息。

## API 调整

`uploadTeacherLearningResource` 增加可选上传配置参数：

- `onUploadProgress`：上传进度回调；
- `timeout`：该请求专用超时，默认 2 小时。

只调整学习资料上传请求，不改变教师端普通 API 的全局 20 秒超时。

## 错误处理

- 优先展示后端返回的业务错误，其次展示网络错误，最后使用“学习内容上传失败”。
- 超时错误使用明确文案：“上传超时，请检查网络后重新上传”。
- 失败信息必须关联具体文件名。
- 页面级消息使用 Element Plus：
  - 全部成功：`ElMessage.success`；
  - 部分成功：`ElMessage.warning`；
  - 全部失败：`ElMessage.error`。
- 页面级消息显示在固定顶栏下方，保留 5 秒并提供关闭按钮。
- 页面级消息只汇总展示一次，避免批量上传时连续弹窗。

## 组件边界

- `TrainingLearningResourcesEditor.vue`
  - 管理上传批次状态、总体进度、逐文件结果和页面级消息；
  - 负责把成功文件立即提交给父组件。
- `src/api/index.js`
  - 只负责构造表单并透传上传进度与专用超时；
  - 不包含 UI 文案或批量状态判断。
- `CampPlanView.vue`
  - 保持现有 `v-model` 接口，不新增上传状态逻辑。

## 验证

- 选择文件后立即出现上传中状态，按钮禁用且文案变化。
- 上传进度回调能更新文件进度和总体进度。
- 单文件成功时列表立即新增资源，并出现模块内和页面级成功反馈。
- 单文件失败时出现文件名和失败原因。
- 多文件部分失败时，成功文件仍留在列表，后续文件仍继续上传。
- 上传请求使用 2 小时专用超时，不改变普通请求的 20 秒超时。
- 运行教师端专项测试和生产构建。
- 在本地教师端页面分别模拟成功与失败响应，检查状态颜色、文案、按钮恢复和控制台错误。

## 验收标准

- 老师在上传开始后的一个界面刷新周期内能看到“正在上传”状态。
- 上传最终结果不会静默结束。
- 所有失败结果都能指出失败文件。
- 部分成功不会造成服务器已有文件在当前页面中消失。
- 新交互不影响外部链接、资源重命名、排序、删除和预览。
