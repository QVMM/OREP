# AI 应用中心分类目录与响应式布局设计

日期：2026-07-30  
页面：`/ai-apps`  
状态：已确认并实施

## 1. 背景

当前 AI 应用中心只有 PPT 制作与讲稿制作两个入口，页面使用固定双列卡片，并将目录宽度限制为 `--ds-page-max`（1280px）且左对齐。该结构在较宽屏幕上会形成明显的不对称右侧留白，卡片下方也存在大面积空白；页面仅有标题和两张功能说明卡，缺少可持续扩展的目录层级。

产品后续会持续接入不同类型的 AI 应用，因此本次不能只调整边距，还需要建立可扩展的分类与卡片数据结构。参考成熟应用中心的分类思路，但不照搬其商城化、排行榜或多层筛选结构。

## 2. 已确认决策

1. 使用“顶部分类导航 + 响应式应用卡片网格”。
2. 首版只展示实际有应用的分类，不展示空分类或“即将上线”占位。
3. 当前分类为：
   - 全部
   - 路演创作
4. 分类由应用数据自动派生；未来新增其他类别的应用后，分类导航自动出现对应入口。
5. 首版不增加“推荐应用”“最近使用”等重复专区。
6. 页面不显示“AI 创作工具”眉题，直接从“AI 应用中心”标题开始。
7. 应用状态必须来自真实数据；没有可靠进度数据时使用“开始制作”“开始撰写”等明确入口，不伪造“继续上次进度”。

## 3. 目标

- 修复大屏内容左重右空、四周留白不协调的问题。
- 在桌面、平板和手机上保持完整、对称且不过度拥挤的页面边距。
- 建立无需重做页面即可扩展分类和应用的前端数据模型。
- 让卡片从“功能说明”升级为“任务入口”，帮助用户快速理解应用用途与产出。
- 保持当前两项应用的真实数量，不使用虚假占位填充页面。

## 4. 非目标

本次不包含：

- 新增 AI 应用。
- 新增应用搜索；工作台顶栏已有全局搜索，当前两个应用不需要局部搜索。
- 推荐算法、排行榜、应用热度、使用人数或付费标签。
- 空分类页面、“即将上线”分类或虚假应用槽位。
- 新增后端分类接口或应用管理后台。
- 接入 PPT、讲稿的跨应用历史任务聚合。
- 修改 PPT 制作或讲稿制作详情页的内部流程。

## 5. 信息架构

页面从上到下分为四层：

1. 页面标题
   - 标题：AI 应用中心
   - 说明：选择一项任务，让 AI 帮你更快完成项目成果。
2. 分类导航
   - “全部”固定排在第一项。
   - 其他分类按照显式的分类配置顺序展示。
   - 只展示当前应用数据实际使用的分类。
3. 目录工具行
   - 左侧显示当前目录标题，例如“全部应用”或“路演创作”。
   - 右侧显示当前筛选结果数量，例如“2 个应用”。
4. 应用网格
   - 当前显示 PPT 制作与讲稿制作。
   - 分类切换后只显示匹配应用。
   - 筛选结果为空属于防御性状态，正常首版流程不应出现。

## 6. 应用数据结构

页面内的应用配置至少包含：

```js
{
  key: 'ppt',
  name: 'PPT 制作',
  category: 'roadshow',
  summary: '把项目资料整理成可演示、可继续修改的路演材料。',
  outcome: '汇报结构、页面视觉、配套讲稿和可下载版本',
  action: '开始制作',
  icon: Picture,
  to: '/ppt-editor',
}
```

分类配置至少包含：

```js
{
  key: 'roadshow',
  label: '路演创作',
  order: 10,
}
```

规则：

- “全部”是页面级虚拟分类，不写入每个应用。
- 其他分类从 `apps` 中使用的 `category` 去重后生成。
- 标签文案由分类配置提供，不从应用名称临时拼接。
- 新增应用时必须指定分类；未知分类在开发环境应给出清晰警告，生产环境不得导致页面崩溃。
- 当前实现可继续使用页面内静态配置，但结构需支持未来替换为接口数据。

## 7. 卡片设计

每张卡片包含：

1. 应用图标。
2. 应用名称。
3. 一句话用途说明。
4. 分类标签“路演创作”。
5. “完成后得到”及真实成果说明。
6. 明确的进入操作与方向箭头。

交互规则：

- 整张卡片保持为真实链接，支持浏览器原生打开方式。
- 卡片操作文案与落地页行为一致：
  - PPT 制作：开始制作。
  - 讲稿制作：开始撰写。
- 鼠标悬停只做轻微边框、背景与箭头位移反馈，不做明显浮起或大幅缩放。
- 键盘聚焦必须有清晰焦点环。
- 分类标签是信息文本，不单独可点击，避免与整卡链接形成嵌套交互。

## 8. 布局与响应式

### 8.1 内容宽度

- 页面内容在工作台主内容区内水平居中。
- 移除当前目录的 1280px 左对齐限制。
- 页面内容宽度使用 `width: 100%`，并设置约 1480px 的安全最大宽度，防止超宽屏卡片无限拉伸。
- 页面自身不重复添加工作台已经提供的外层边距。
- 在 AI 应用中心局部重置 `.student-page` 于 1023px 和 720px 断点增加的横向内边距，避免与 `.workspace-main` 的响应式边距叠加；不修改其他学生页面。

### 8.2 页面边距

- 桌面宽屏：外层工作台边距 40–48px。
- 常规桌面与平板横屏：24–32px。
- 手机：16px，并保留底部导航所需安全距离。
- 页面标题、分类导航、工具行和应用网格使用同一左右边线。

### 8.3 网格

- 适合双列时显示两列。
- 可用宽度不足以保证单卡可读性时自动切换为单列。
- 桌面卡片之间使用 20–24px 间距。
- 手机卡片间距使用 16px。
- 首版不强制构造第三列，也不复制应用填充空间。

### 8.4 移动端

- 分类导航允许水平滚动，但隐藏滚动条；当前两项不会产生滚动。
- 分类文字保持单行，选中态同时使用文字颜色与下边线。
- 应用卡片单列排列。
- 卡片分类标签可移至标题区下方或隐藏重复标签，但应用分类信息仍需可被辅助技术读取。
- 操作区域完整显示，不使用伸出卡片边界的按钮。

## 9. 视觉层级

- 页面标题是首个内容层级，不增加“AI 创作工具”眉题。
- 分类导航作为第二层级，使用轻边线与品牌橙选中态。
- 目录标题与数量使用较低视觉权重，不与页面标题竞争。
- 卡片保持白色或轻暖色表面；PPT 卡片可使用轻微品牌暖色强调，但两个入口必须保持同一组件结构。
- 橙色用于选中分类、主操作和聚焦反馈，不用于大面积背景。

## 10. 页面状态

### 默认状态

- 默认选中“全部”。
- 显示两个应用和“2 个应用”。

### 分类筛选状态

- 选中“路演创作”。
- 显示两个应用和“2 个应用”。
- 切换不改变路由，不刷新页面。

### 防御性空状态

如果应用数据异常导致选中分类无结果：

- 显示“该分类暂时没有可用应用”。
- 提供“查看全部应用”操作。
- 不显示空白网格。

### 数据异常

- 单个应用缺少非关键说明时仍显示名称和入口。
- 缺少 `to` 或关键标识的应用不渲染为可点击入口，并在开发环境发出警告。

## 11. 可访问性

- 分类导航使用可识别的标签组语义；每个分类使用按钮。
- 当前分类提供 `aria-selected` 或等价可访问状态。
- 分类切换后，结果数量在可见区域同步更新。
- 应用列表继续使用列表语义。
- 应用链接保留清晰的 `aria-label`。
- 交互目标高度不低于 40px。
- 所有文字与背景满足现有设计系统的对比度要求。
- `prefers-reduced-motion` 下取消非必要位移动效。

## 12. 实现范围

主要修改：

- `frontend/user/src/views/AiAppCenter.vue`

如需补充页面级响应式变量，可复用既有设计令牌，不修改其他页面的全局布局行为。除非验证证明工作台边距本身存在全局问题，否则不修改：

- `frontend/user/src/components/workspace/WorkspaceShell.vue`
- `frontend/user/src/styles/student-flow.css`
- `frontend/user/src/styles/workspace-tokens.css`

AI 应用中心需要用局部样式覆盖 `student-flow.css` 在平板和手机断点给 `.student-page` 添加的横向内边距，确保整个页面只有 `WorkspaceShell` 提供一层外边距。

## 13. 验收标准

### 功能

- 默认显示“全部”和“路演创作”两个分类。
- “全部”显示 PPT 制作与讲稿制作。
- “路演创作”显示 PPT 制作与讲稿制作。
- 应用入口路由保持不变。
- 新增一个使用新分类配置的应用后，新分类可由数据自动生成。
- 页面不显示“AI 创作工具”。

### 桌面布局

- 1545×1071 视口下，内容区左右边距视觉对称，目录不再出现明显的额外右侧空白。
- 两张卡充分利用内容区宽度，保持双列且没有横向溢出。
- 超宽屏内容居中，卡片不无限拉伸。

### 响应式

- 1024px 左右视口下不出现内容裁切。
- 720px 以下切换为单列卡片。
- 390px 视口下分类、标题、卡片操作完整可见。
- 页面不产生横向滚动条。

### 质量

- 前端构建通过。
- 与 AI 应用中心相关的自动化测试通过。
- 桌面与移动端截图检查通过。
- 键盘可完成分类切换和应用进入。

## 14. 后续扩展规则

后续新增应用时：

1. 先确定稳定的业务分类，不以文件格式作为分类。
2. 在应用配置中增加 `category`。
3. 在分类配置中增加显示名称与顺序。
4. 只有分类内至少存在一个可用应用时才展示分类。
5. 当应用数量达到需要搜索或二级筛选的规模后，再单独评估搜索、标签筛选、推荐和最近使用专区。
