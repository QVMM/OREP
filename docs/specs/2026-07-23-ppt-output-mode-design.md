# PPT 输出类型选择设计

## 目标

在“路演资料准备”抽屉中允许用户选择两种输出：

- 生成图片 PPT：默认选项，使用 `render_engine=image2`，最终 PPTX 每页为整页图片。
- 生成可编辑 PPT：使用 `render_engine=svg`，最终 PPTX 尽可能保留原生文字、形状和矢量元素。

论文 PPT 继续固定使用 SVG 链路，不展示路演输出类型选择器。

## 交互

“生成对象”下方增加输出类型选择器。由于资料抽屉宽度有限，两种模式使用上下排列的全宽选择行，不在窄空间内并排挤压文字。每项包含类型缩写、名称、单行能力说明和右侧选择标记。

当前项使用浅橙背景、橙色描边和实心选择标记；未选项保持浅色中性背景。悬停只增强边框和背景，不改变布局。说明文字保持一行，避免卡片高度和换行随抽屉宽度抖动。

任务处于规划、等待卡片确认、生成或导出阶段时锁定选择，避免同一任务中途切换引擎。任务结束后允许用户修改选择并重新生成。新建 PPT 时恢复默认的图片 PPT。

图片型任务的页面编辑工具禁用；可编辑型任务完成后保持现有文字、形状、图片和表格编辑能力。

## 数据流

前端使用单一状态 `roadshowOutputType`：

- `image` 映射为 `image2`
- `editable` 映射为 `svg`

映射后的 `render_engine` 必须进入以下请求：

1. 首次生成 `/api/ppt/generate`
2. 内容卡片确认 `/api/ppt/roadshow/plan/{job_id}/confirm-render`
3. 反馈重生成 `/api/ppt/refine`

后端任务状态和历史记录接口返回 `render_engine`。前端打开历史任务、恢复上次任务或轮询状态时同步输出类型，确保下载、重生成和编辑权限与原任务一致。

## 后端链路

`image2` 继续使用现有 image2 页面生成器，当前运行配置 `IMAGE2_EXPORT_MODE=image`，下载时由 `create_image2_image_pptx` 生成整页图片 PPTX。

`svg` 继续使用现有 SVG executor，下载时由 `create_pptx` 转换为 PowerPoint 原生元素。

本次不修改两条渲染器的视觉生成逻辑，只补充前端选择、任务元数据回传和模式一致性控制。

## 错误处理

- image2 未配置时，图片选项显示不可用并说明原因；SVG 仍可使用。
- 任务创建失败时保留用户选择和资料。
- 历史任务缺少旧版 `render_engine` 时，路演任务兼容回退为 `image2`，论文任务回退为 `svg`。
- 当前任务运行期间禁止切换输出类型。

## 验证

1. 前端构建通过，选择两种模式时三个相关请求均发送正确的 `render_engine`。
2. 状态和历史接口返回并恢复正确的 `render_engine`。
3. image2 真实生成任务完成并输出 PPTX；检查每页包含整页图片。
4. SVG 真实生成任务完成并输出 PPTX；检查至少存在原生文字或矢量形状。
5. 两种模式的预览、卡片确认、下载和反馈重生成保持同一引擎。
