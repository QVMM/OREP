# 首页设计理念调研 · 选型简报

> **目的**：跳出「卡片好不好看」的纠结，先定**产品首页哲学**，再谈样式。  
> **范围**：登录后的**产品首页 / Dashboard**（不是官网营销页）。  
> **方法**：综合 SaaS/仪表盘 UX 文献、大厂产品惯例、认知与信息架构原则；提取**共性**与**可选理念**，供决策。  
> **色板**：沿用现有主题色；本简报不讨论换色。

---

## 0. 先对齐：我们到底在设计什么

用户说「首页像一整页、不好找重点、卡片难受、不好介绍」——这通常不是「少一张卡或多一张卡」的问题，而是：

| 表层问题 | 底层问题 |
|----------|----------|
| 找不到重点 | 没有**唯一主叙事**（首页在回答哪个问题？） |
| 卡片难受 | 多块**平权信息**同时抢注意力（工作记忆过载） |
| 不好介绍 | 演示时说不清「用户登录后第一步该干什么」 |

优秀产品的首页，先有一句**哲学一句话**，再有布局。

## 1. 文献与行业里反复出现的共性（统计口径：理念，非皮肤）

来源包括：Toptal SaaS UX、仪表盘设计原则综述、Nielsen 渐进披露、认知负荷理论（Sweller）、F 型扫视（NN/g）、以及 Linear / Stripe / Slack / Notion / Asana 等产品的公开设计立场与惯例。

### 1.1 高频共性（几乎所有「好首页」都满足）

| # | 共性理念 | 含义 | 出现频率（粗评） |
|---|----------|------|------------------|
| 1 | **决策优先，不是数据优先** | 每个区块要能回答「因此我要做什么」，不是「这里有个数字」 | 极高 |
| 2 | **首页只答 3～5 个问题** | 工作记忆约 3～5 项；超过就变仪表盘垃圾场 | 极高 |
| 3 | **倒金字塔 / 一眼区** | 最上：状态与结论；中间：趋势/依据；下：明细入口 | 极高 |
| 4 | **渐进披露** | 先摘要，细节进二级页；首页不展开全书 | 极高 |
| 5 | **一个主行动（Primary Action）** | 同时多个主按钮 = 没有主按钮 | 高 |
| 6 | **状态 → 问题 → 待办 → 开干** | Toptal 经典五问精简版：我怎么样？有什么新情况？要注意什么？要做什么？怎么开始？ | 高 |
| 7 | **角色/情境匹配深度** | 执行者看「下一刀」；管理者看「进度」——同一首页不能服务所有人格到同样深度 | 高 |
| 8 | **空状态也是产品** | 无分时 = 引导完成第一次闭环，不是空白 KPI 墙 | 高 |
| 9 | **减少外在认知负荷** | 装饰灯、平权卡片、重复指标 = 浪费脑力 | 高 |
| 10 | **可介绍性（Narrative）** | 能用 15 秒讲清：用户进来看到什么、点哪里、闭环是什么 | 产品叙事层，高价值 |

### 1.2 仪表盘类型（选错类型会「永远改不对」）

| 类型 | 回答的问题 | 典型产品 | 不适合什么 |
|------|------------|----------|------------|
| **操作型 Operational** | 现在怎样？先干什么？ | 客服队列、告警、待办首页 | 长篇分析、五维全展开 |
| **分析型 Analytical** | 为什么这样？趋势？ | 增长看板、BI | 当「每天登录入口」会过重 |
| **工作台型 Workbench** | 我在哪个项目里继续？ | Notion、部分项目管理 | 没有强「当前项目」时会空 |
| **收件箱型 Inbox** | 有什么变化要我处理？ | Linear Inbox、通知流 | 没有事件流时硬造会假 |

**竞赛大脑首页更接近：操作型 + 少量分析摘要**，不是完整分析型大盘。

### 1.3 大厂/标杆产品的「理念关键词」（案例，非抄 UI）

| 产品 | 首页/入口哲学（一句话） | 对我们的启发 |
|------|-------------------------|--------------|
| **Linear** | 减噪、恢复动量；进来快速知道「该推进什么」 | 少装饰、主列表清晰、强调动量而非大屏 KPI |
| **Stripe Dashboard** | 渐进披露；品牌色几乎只用于主行动 | 主色克制；主 CTA 唯一 |
| **Slack** | 入门先完成「建工作区」最小闭环，可跳过 | 空状态走闭环，不堆功能说明 |
| **Asana / 任务类** | 空状态预填「你说过要做的事」 | 无分时给步骤，有分时给下一刀 |
| **Notion** | 工作区是内容本身，首页不抢戏 | 若以项目为中心，可弱化「能力橱窗」 |
| **Apple HIG 精神** | 清晰、遵从、深度；一次一事 | 层级严格：主结论 > 次信息 > 入口 |
| **Nielsen 渐进披露** | 先少量最重要选项，其余二级 | 「引擎能做什么」不宜与本场判定平权 |

## 2. 可选的首页哲学（请你选「故事」，不是选「圆角」）

下面 6 种都是**可落地的产品叙事**。每种都写了：核心承诺、结构骨架、介绍话术、优势/风险、是否带卡片、与 OREP 契合度。

### 理念 A · 指挥台（Command Center）

**一句话**：登录 = 看态势、看风险、看待办、开任务。  
**结构**：上排 3～4 个状态指标 → 中区问题/告警 → 下区待办与入口。  
**介绍话术**：「首页告诉你备赛现在怎么样、有没有雷、今天该干啥。」  
**卡片**：要，且**多卡平权**（典型 KPI 墙）。  
**优势**：B 端用户熟悉、信息全。  
**风险**：最容易变成「几个卡片很难受」——我们现在痛点高度重合。  
**契合度**：中低（备赛不是运维监控）。

---

### 理念 B · 教练台（Coach / Next Best Action）★ 推荐候选

**一句话**：登录 = 教练只推**下一刀** + 一句判断；其余都是支撑。  
**结构**：**一块主舞台**（分数 + 读后感 + 主 CTA）→ 一块「下一刀」→ 其余折叠/次级。  
**介绍话术**：「不是仪表盘，是教练：看完分，告诉你先改哪一刀。」  
**卡片**：要，但**一张主卡 + 极少辅卡**（1 主 0～2 辅），禁止四宫格平权。  
**优势**：好讲、好记、符合「评分大脑」；解决找不到重点。  
**风险**：辅信息太少会被说「空」——需 1 条路径入口补足。  
**契合度**：高。

---

### 理念 C · 成绩单叙事（Scoreboard Editorial）★ 推荐候选

**一句话**：登录 = 先读**本场结论**（像成绩单头版），再决定行动。  
**结构**：大数字 + 判断句（编辑式）→ 短指标条 → 主行动 → 五维只作摘要条。  
**介绍话术**：「打开就是本场成绩单：多少分、什么意思、去看总结。」  
**卡片**：主结论区**必须成块**（可叫卡/托盘/舞台），辅区可弱。  
**优势**：与已有「本场得分 / 读后感」资产一致；演示极强。  
**风险**：无分时叙事要单独设计，否则空洞。  
**契合度**：高（当前产品叙事已在这条路上）。

---

### 理念 D · 收件箱动量（Inbox Momentum）

**一句话**：登录 = 看「发生了什么 / 要我处理什么」，不是看大盘。  
**结构**：时间线/变更列表为主；分数只是其中一条事件。  
**介绍话术**：「像备赛动态：出分、任务、材料，按时间处理。」  
**卡片**：列表为主，卡片次之。  
**优势**：Linear 式清晰。  
**风险**：事件不够密时首页空；「大脑引擎」品牌感弱。  
**契合度**：中（可作辅模块，不宜整页哲学）。

---

### 理念 E · 项目工作台（Project Workbench）

**一句话**：登录 = 回到**当前参赛项目**继续干。  
**结构**：项目头 + 阶段进度 + 材料/任务入口；评分为项目内一块。  
**介绍话术**：「首页就是你的项目桌面，评分是其中一环。」  
**卡片**：2～3 块：项目 / 评分 / 训练。  
**优势**：团队协作场景清晰。  
**风险**：弱化「评分大脑」差异化；与侧栏「项目团队」重叠。  
**契合度**：中（支撑层合适，不宜压过评分主叙事）。

---

### 理念 F · 能力橱窗（Capability Showcase）

**一句话**：登录 = 展示引擎能做什么（营销式功能墙）。  
**结构**：多能力卡片平铺 + 入口。  
**介绍话术**：「我们有评分、评委、训练……」  
**卡片**：多，且平权。  
**优势**：销售演示功能全。  
**风险**：**最差日常首页**；与「找重点」冲突；当前失败路径之一。  
**契合度**：低（可放帮助/关于，不进日常首页主层）。

## 3. 交叉统计：若「必须有卡片」，优秀做法的共性

「带卡片」≠「多张一样的白卡」。统计优秀做法：

| 规则 | 说明 |
|------|------|
| **主从分明** | 主卡面积 ≥ 辅卡之和；或主卡独占首屏 60%+ |
| **一张卡 = 一个决策** | 不是「一个数据源一张卡」 |
| **卡内有动词** | 至少一枚明确行动，否则是展板 |
| **同级卡 ≤ 3** | 第四张起进「更多」或二级 |
| **指标不重复** | 分数不要在主卡、条带、右栏、支撑区各说一遍 |
| **能力说明不进主层** | 「引擎能做什么」是说明书，不是每日必看 |

## 4. 结合竞赛大脑的判断（我的立场）

**不建议**：A 指挥台满配、F 能力橱窗当主结构——这正是「几个卡片很难受、不好介绍」的来源。

**建议主哲学**（二选一或组合）：

| 选项 | 组合 | 首页一句话 |
|------|------|------------|
| **★ 首选** | **C 成绩单叙事 + B 教练下一刀** | 「看本场结论 → 下一刀 → 进总结」 |
| 备选 | C + E 轻工作台 | 主叙事仍是成绩单，底部才是项目/训练入口 |
| 不推荐作主 | A / D / F | 可借鉴局部模式，不作整页哲学 |

**结构承诺（若选首选）**：

1. **首屏只有一个主角**：本场判定（分 + 一句话 + 主按钮）。  
2. **第二焦点唯一**：下一刀（可嵌在主卡内，不必第二张大卡）。  
3. **右栏或次屏**：节奏/路径（扫读，不抢主结论）。  
4. **02 能力、03 支撑**：降权——更小、更淡，或折叠；**禁止与 01 视觉平权**。  
5. **卡片**：允许，但是 **1 主舞台 + 至多 1 辅托盘 + 底部轻入口**，不是三层多卡矩阵。

**可介绍性脚本（15 秒）**：

> 「同学登录先看本场得分和一句话判断；系统指出下一刀；点开评分总结改；改完再评。项目和训练在下面，需要时再进。」
