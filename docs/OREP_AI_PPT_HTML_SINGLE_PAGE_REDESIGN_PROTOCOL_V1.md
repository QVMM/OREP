# OREP AI 生成 PPT 式 HTML

## 单页重设计协议 V1

> 目标：把“页面修复”从当前偏补丁式的 repair，升级成真正可执行、可收敛、可审查的单页重设计协议。

> 这份协议要解决的问题是：
>
> 1. 为什么很多页面反复修复还是不好
> 2. 什么问题不应该继续“小修小补”
> 3. 单页重设计到底输入什么、输出什么、怎么验收
> 4. 它如何接入 prompt、视觉审查、替换正式页和回滚机制

---

## 1. 先说结论

当前系统已经具备：

- 单页修复预览
- 修复历史
- 收益判断
- 自动升级到 `structure_rebuild`
- 视觉审查

这些已经是很好的基础。

但从机制上讲，当前 repair 仍然经常像：

- 改一点文案
- 调一点结构
- 再看一次质量

这对轻问题有效，但对下面这些问题不够：

- 模板化严重
- 页面焦点弱
- 页面太像网页
- 页面空洞
- 证据位与结构冲突
- 页面虽然内容对，但放在整套路演里位置感不对

所以必须新增一层协议：

> **把单页问题先升级成“页面设计问题”，再去重做这页，而不是直接把当前 HTML 当成唯一修复对象。**

---

## 2. 单页重设计与普通修复的区别

## 2.1 普通修复

适用于：

- 小范围文案问题
- 局部视觉问题
- 轻度留白/重叠问题
- 某些明显占位词清理

特征：

- 目标是“在现有页面上修”
- 输入主要是当前 HTML + 失败项
- 输出仍然是一版 HTML 候选

## 2.2 单页重设计

适用于：

- 页面类型本身不对
- 页面结构和本页目标不匹配
- 焦点弱 / 空洞 / 模板化严重
- 证据无法通过局部补图解决
- 多次修复收益不足

特征：

- 目标是“重新设计这页”
- 输入不是只有当前 HTML，而是“当前页在整套故事里的角色 + 页面契约 + 视觉问题 + 证据要求”
- 输出不应只有 HTML，而应先输出“新页面结构方案”

---

## 3. 什么情况下必须触发单页重设计

以下任一条件满足，就不应继续走普通 repair，而应直接进入单页重设计。

## 3.1 模板化高风险

表现：

- `template_page_risk = fail`
- 同页多次出现通用短语
- 页面结构与其他页高度雷同

## 3.2 主焦点缺失

表现：

- `no_visual_focus`
- 多个同级焦点
- 看起来像网页模块拼装

## 3.3 空洞或重心失配

表现：

- 页面并不空白，但没有主信息重量
- 文字很多，主结论不清
- 留白很大但不是高级留白

## 3.4 证据和结构冲突

表现：

- 这页理论上应证据优先，但当前结构没有证据主位
- 证据图只能硬塞
- 图一上传，页面更乱

## 3.5 多次 repair 收益不足

建议阈值：

- 连续 2 次 `effective = false`
- 或 `score_delta` 很小
- 或 `failed_checks` 核心项不变

## 3.6 当前页角色与页面表达不匹配

例如：

- 技术架构页长得像普通说明页
- 实操页长得像纯流程页
- 总结页长得像普通介绍页

---

## 4. 单页重设计的输入协议

单页重设计不能只吃“当前 HTML + 失败项”，而应吃一份完整设计上下文。

## 4.1 基础输入

| 字段 | 含义 |
|---|---|
| `task_id` | 当前任务 |
| `page_index` | 当前页码 |
| `page_title` | 当前页标题 |
| `section` | 当前章节 |
| `page_role` | 当前页角色 |
| `act_phase` | 当前属于四幕中的哪一幕 |

## 4.2 编导输入

| 字段 | 含义 |
|---|---|
| `page_goal` | 这一页最核心的目标 |
| `transition_role` | 这页如何承接前后页 |
| `served_scoring_dimensions` | 服务哪些评分项 |
| `story_context_before` | 前一页 / 前一段在讲什么 |
| `story_context_after` | 后一页 / 后一段应讲什么 |

## 4.3 页面契约输入

| 字段 | 含义 |
|---|---|
| `contract_id` | 页面契约编号 |
| `required_blocks` | 必须块 |
| `forbidden_blocks` | 禁止块 |
| `primary_visual_type` | 主视觉类型 |
| `required_evidence_types` | 所需证据 |
| `common_failure_modes` | 典型失败模式 |

## 4.4 质量与视觉输入

| 字段 | 含义 |
|---|---|
| `failed_checks` | 当前失败项 |
| `quality_summary` | 当前页质量摘要 |
| `visual_review_issues` | 视觉检察官问题 JSON |
| `issue_profile` | 单页问题档案 |
| `repair_history_summary` | 最近修复历史摘要 |

## 4.5 素材与证据输入

| 字段 | 含义 |
|---|---|
| `confirmed_materials` | 已确认绑定素材 |
| `recommended_materials` | 推荐素材候选 |
| `evidence_status` | 证据是否缺失、是否临时图、是否需真人 |

---

## 5. 单页重设计的输出协议

单页重设计不应一步只输出 HTML，而是建议拆成两段输出。

## 5.1 第一段：页面结构方案

必须先输出：

| 字段 | 含义 |
|---|---|
| `redesign_summary` | 这次重设计在解决什么问题 |
| `new_layout_type` | 新版式类型 |
| `primary_visual_plan` | 主视觉怎么放 |
| `content_block_plan` | 内容块怎么分配 |
| `evidence_plan` | 证据如何承载 |
| `scoring_expression_plan` | 评分点怎么显式表达 |
| `removal_plan` | 需要删掉哪些旧内容 |

## 5.2 第二段：HTML 候选页

结构方案确认后，再输出：

- `html`
- `speaker_script`
- `page_annotations`

其中 `page_annotations` 仅供系统内部使用，不进入最终页面。

---

## 6. 单页重设计的执行流程

建议执行顺序如下：

1. 识别当前页是否应进入重设计
2. 聚合完整 `design_context`
3. 生成“页面结构方案”
4. 依据结构方案生成 HTML 候选
5. 运行视觉审查
6. 运行页面质量检查
7. 计算收益
8. 决定：
   - 采用
   - 继续补证据后再重试
   - 回滚历史最佳版
   - 启用托底版式

---

## 7. 单页重设计与视觉审查如何配合

## 7.1 视觉审查不是只挑错

视觉审查结果应输出两层信息：

### 问题层

- 焦点弱
- 拥挤
- 重叠
- 空洞
- 证据弱

### 设计约束层

- 主视觉建议位置
- 不可再放内容的区域
- 推荐页型
- 建议删减块
- 证据优先区

## 7.2 重设计时应优先用“设计约束层”

也就是说，视觉审查的输出不该只是：

- `repair_instruction`

还应是：

- `layout_constraints`
- `evidence_constraints`
- `focus_constraints`

---

## 8. 单页重设计与素材系统如何配合

## 8.1 先判断这页是否证据驱动

如果是：

- 政策/背景证据页
- 实操步骤页
- 结果证据页
- 创新/价值对比页

则重设计时必须优先考虑：

- 证据位怎么占
- 图怎么成为主视觉

## 8.2 证据缺失时的策略分层

### 测试阶段

- 允许临时演示图
- 允许 warning 下载当前版

### 正式阶段

- 关键证据必须真实
- 若无真实证据，只能停在 `warning`

## 8.3 证据问题不应无限空修

如果当前页根因明确是“缺证据”，而不是“结构坏”，则：

- 不再继续普通 repair
- 进入：
  - `evidence_attach_or_wait`
  - 或证据优先重设计

---

## 9. 单页重设计与收益判断

## 9.1 必须有收益门槛

一次重设计后，至少检查：

- `score_delta`
- `failed_checks` 是否减少
- `primary_issue_resolved`
- `visual_focus_improved`
- `evidence_slot_established`

## 9.2 如果收益不足，不能继续同一路线死修

建议策略：

- 第一次无收益：切换策略
- 第二次无收益：推荐历史最佳版
- 第三次无收益：托底重建

---

## 10. 托底重建设计

对于多次修不好、但又必须交付的页，应允许进入托底模式。

托底模式的特点：

- 强 16:9 契约
- 强标题区
- 强主视觉区
- 强证据区
- 强评分点表达区
- 强留白规则

它的目标不是“最惊艳”，而是：

> 至少稳定、规整、像 PPT、可讲、可交付。

---

## 11. 第一批建议接入的页面类型

如果第一批不能全量做，我建议先接这 5 类：

1. 技术架构页
2. 实操步骤页
3. 结果证据页
4. 创新 / 应用价值页
5. 总结收束页

原因：

- 这 5 类最容易出现“看起来像 HTML，不像 PPT”的问题
- 也是比赛中最关键、最容易拉开专业度差距的页

## 13. 实施顺序建议

### 第一步

先把这份协议转成系统内部结构：

- `root_cause_type`
- `design_context`
- `redesign_plan`
- `redesign_result`

### 第二步

把 prompt 拆成：

- 结构方案 prompt
- HTML 落地 prompt

### 第三步

让视觉审查输出设计约束

### 第四步

把当前 repair 流程接入“先判断是否重设计”

---

## 14. 最终原则

这份单页重设计协议 V1 的核心原则只有一句：

> 不要再把“坏页面”当成“待修的 HTML”，而要把它当成“需要重新设计的一页路演镜头”。

只有这样，系统才会真正减少：

- 模板化页
- 空洞页
- 焦点弱页
- 有 HTML 味的页

并逐步向真正的比赛级 PPT 页面靠拢。
