# 第 02 页｜为什么改变

### 眉题
先问学生有没有真正学会

### 标题
# 材料改了，不等于学生会了。

### 一句结果
真正有底气走上赛场的，不是更漂亮的文件，而是学生知道问题在哪里、为什么这样改，并敢把下一版带回现场验证。

### 正文（建议 80–120 字）
一套更完整的 PPT，可能只是材料更完整；一次更高的分数，也可能只是当轮表现更好。备赛若停在「交了、改了、勾选了」，成长往往还没发生。

启发·竞赛大脑不把「完成」当作终点。它把备赛收成一条可复查的节奏——**备、练、演、评、改**——让每一次关键修改，有机会回到下一轮真实表现中接受检验。

### 三个常见误区（左栏卡片）

| 误区 | 真相 |
|------|------|
| 材料完成度 = 学生能力 | **备**完了材料，未必 **练**会了、也未必 **演**得清 |
| 一次分数 = 问题已解决 | **评**是当轮快照，不是 **改** 已经到位的证明 |
| 任务勾选 = 学习已发生 | 勾选证明执行过，不证明理解与迁移 |

### 我们相信什么（右栏三条）
1. **备得实**：判断能写成可检查的讲稿、材料与版本。  
2. **练得准**：对准项目短板练，而不是盲目加练。  
3. **改得明**：看得懂 **评** 的依据，说得清为何改，再 **演** 一轮验证。

### 页脚短句
金奖是努力方向，不是产品承诺。备赛节奏是 **备-练-演-评-改**，不是「交完即止」。

### 配图说明
- 左：简图「漂亮材料 / 一次高分 / 任务全绿」→ 问号  
- 右：五字节奏条 **备→练→演→评→改→（回）**，或「问题位置 → 修改理由 → 再上场」  
- 或真实备赛场景摄影（讨论、回看录像、改 PPT），避免颁奖堆砌

# 第 03 页｜产品全景（全册核心页）

### 眉题
一条带队老师一听就懂的备赛节奏

### 标题
# 备 · 练 · 演 · 评 · 改

### 副标题（标题下）
同一参赛项目上，把上场前的备、对准短板的练、这一轮的演、有依据的评、改完再验证，收成一条可复查路径。

### 一句结果
人、任务、材料、路演和反馈不再散落在群聊与网盘里，而按 **备-练-演-评-改** 回到同一个项目上下文中被组织、被看见、被再次验证。

### 产品闭环（全页主视觉 · 必须用这五字）

```
        ┌─────────────────────────────────┐
        │         参赛项目（底座）          │
        └─────────────────────────────────┘
    备 → 练 → 演 → 评 → 改 ─┐
    ↑                        │
    └──── 再备 / 再练 / 再演 ─┘
```

| 步 | 字 | 对外标题 | 发生什么 | 产品主要界面 |
|----|----|----------|----------|--------------|
| 1 | **备** | 把成果备齐 | 项目材料、讲稿、待办与协作、备赛日报留痕 | 项目工作台 / 待办 / 日报 |
| 2 | **练** | 对准短板练 | 按训练日学习、提交成果，教师可批改 | 训练营 / 今日学习 |
| 3 | **演** | 真实上场 | 在线路演或上传视频，录制可回看 | 路演会议 / 回放库 |
| 4 | **评** | 反馈有据 | 多维 AI 评分报告，给出依据线索与整改项 | 评分报告 |
| 5 | **改** | 判断后改 | 教师审核建议并发布任务；学生改完再备、再练、再演 | 教师工作台 / 学生待办 |

### 五字各一句（环绕大图，供设计师排字）

- **备** — 该交的、该讲的，备在同一项目里。  
- **练** — 今天该练什么，对着项目来。  
- **演** — 上场不是一次性表演，是可回看的样本。  
- **评** — 不只给分，还给改的线索。  
- **改** — AI 建议，教师裁决；改完，再验证。  

### 机制主句（页底加粗）
**项目是底座；备-练-演-评-改是节奏；路演证据是依据；教师确认的任务是行动接口；下一轮表现是检验。**

### 边界半句（小号）
平台组织的是可复查的备赛路径；学生是否真正形成能力，仍由作品变化、行为记录、专业评价与赛场表现共同证明。

### 配图说明
- **本页必须是一张「备-练-演-评-改」闭环大图**（全册第一视觉资产，后文与展会薄册复用）  
- 每个字下方贴一张实景小图：待办/材料、训练日、路演室、评分报告、教师发布任务  
- 闭环箭头从「改」回到「备」「练」或「演」，标明「多轮」  
- 避免复杂架构图、端口、技术栈

# 第 04 页｜学生获得什么

### 眉题
学生真正带走什么 · 对应节奏：备 / 练 / 改

### 标题
# 不是多做一遍，而是多会一点。

### 一句结果
在 **备-练-演-评-改** 的节奏里，平台为学生形成「把成果备扎实、对准短板练、依据评价再改」创造条件。

### 三个能力方向（三栏等分）

#### 01 备得实 · 把知识做成成果
项目任务推动讲稿、材料与版本向前走。学生不只是「交文件」，而是把项目判断写进可以检查、可以说明的成果里。

- 项目团队内的任务、材料与阶段管理  
- 路演讲稿编辑与备赛材料集中管理  
- 今日待办与备赛日报，把过程备在项目里  

#### 02 练得准 · 围绕真实短板
训练日、学习资源与阶段任务围绕当前项目推进。学生有机会把时间花在眼前要解决的问题上，而不是在课程、文件和通知之间找方向。

- 按训练日查看与完成任务  
- 本地视频、文档与 B 站等课程视频可在平台内学习并留下学习记录  
- 训练成果按日提交，进入教师批改  

#### 03 改得明 · 依据证据再来一轮
路演留下录像与评分报告；问题不再只是一句「还不够好」。学生有机会回看 **评** 的依据、完成 **改**，并准备下一轮 **演**。

- 路演录制回看与历史场次  
- 多维评分报告：结果、依据线索、整改项  
- 改进项可进入任务，在后续训练与路演中继续推进  

### 页脚说明（必留，建立可信）
上述方向是产品希望服务的成长路径。实际学习与能力是否形成，需要学生行动、教师指导、成果变化与迁移表现共同证明。

### 配图说明
- 三栏卡片 + 图标（备 / 练 / 改）；页眉或页脚复述完整五字 **备-练-演-评-改**  
- 每栏底部可放一张对应界面小图：项目材料、训练日、评分报告  
- 不要用「成长曲线冲顶」类空泛插画  

### 页任务
让教师能转述：「我们按备-练-演-评-改带学生，不只堆材料。」

# 第 05 页｜教师如何判断

### 眉题
落在节奏里的「评」与「改」· AI 识别 · 教师裁决

### 标题
# 把有限精力，留给真正需要判断的地方。

### 一句结果
学生侧先 **备** 再 **练** 再 **演**；系统给出 **评** 的线索；**改** 的关键判断在教师——什么值得改、为什么改、改到什么程度、怎样验收。

### 教师工作流（嵌在五字节奏中）

```
备：查看材料、待办与项目进度
        →
练：查看训练提交与学习进度
        →
演：回看路演录制或视频
        →
评：阅读 AI 评分报告（多维分数 / 依据 / 整改项）
        →
改：审核、编辑并发布改进任务 → 学生再备 / 再练 / 再演
```

### 平台为教师提供的直接帮助

1. **备与练可管**  
   配置训练营日程与每日任务书，布置本地与站外学习资源，批改学生提交，查看进度与项目材料。

2. **演可回看**  
   管理路演相关场次与材料，回看录制，查看同源评分报告。

3. **评可对照、改可裁决**  
   将 AI 整理的改进建议，经教师审核后发布给学生执行——AI 不替代专业判断。

4. **整条节奏可统筹**  
   在教师工作台管理参赛项目、成员与路演相关入口，减少指导散落在群聊与口头交接中。

### 可信边界（深色或线框提示块，必放）

| 我们这样用 AI | 我们不这样承诺 |
|---------------|----------------|
| 辅助分析路演表现，生成多维报告与整改线索 | AI 直接作为正式竞赛成绩 |
| 多评委视角的参考意见，供教师对照 | 全自动督学、无人批改结营 |
| 教师审核后再形成学生侧改进任务 | 「有 AI 就等于有名师」 |

### 页脚短句
教师不是被替代的人，而是整条改进路径中不可让渡的判断者。

### 配图说明
- 主图：教师端「批改 / 报告 / 发布任务」界面拼贴  
- 侧图：学生待办中出现教师发布后的任务（体现落地）  
- 流程用线性图标，避免机器人取代教师的隐喻  

### 页任务
消除「又一个 AI 替代老师」的戒心，建立采购与试用信任。

### 4/ 在线路演与回看　｜　节奏：**演**

**图标建议**：视频/舞台

**导语**  
把 **演** 变成可回看的训练样本，而不是一次性的临场发挥。

**要点**

- 路演录制与回放库，历史场次可回看  
- 支持上传路演视频进行评分（非实时会议场景）  
- 教师侧可查看与管理路演相关场次、材料与回放入口  

**谨慎说明（小字）**  
演示前建议预检浏览器权限与网络；长视频处理需预留时间。

### 5/ AI 评分与证据复盘　｜　节奏：**评**

**图标建议**：报告/雷达（克制使用）

**导语**  
基于赛道规则给出多维分析，让 **评** 不止于一个总分。

**要点**
- 会议路演或上传视频后，生成多维度 AI 评分与总结  
- 报告分栏呈现：结果、依据线索、评委视角参考、整改项等  
- 为学生提供结构化改进清单，减少「只知道不够好」  
- 教师与学生查看同源报告，便于对齐问题  

**谨慎说明（小字）**  
分析依赖音视频与文本处理流水线；个别场次锚点密度与完整度可能不一。长视频可能排队，请以成功样例演示。  
**AI 评分为辅助分析，不作为正式竞赛成绩。**

**配图说明**  
评分报告一页长图（结果 + 整改 todos 最清晰的两栏）；避免「100 分奖杯」视觉。

**导语**

**要点**
- 教师配置训练营、批改提交、查看团队进度  
- 阅读 AI 评分报告，把握共性问题与个性问题  
- 将改进建议**整理、审核后发布**为学生可执行任务  
- 学生在待办与后续训练、路演中继续推进，形成再验证条件

# 第 08 页｜组织与过程（教务 / 学院）

### 眉题
给教务与二级学院负责人

### 标题
# 看见备赛是否真正发生，而不只等待最后结果。

### 一句结果
当 **备-练-演-评-改** 被系统承接，学院有机会看见过程，而不只在赛后看见名次。

### 组织侧可观察什么

| 节奏 | 可以看见的过程信号 | 说明 |
|------|-------------------|------|
| **备** | 项目任务、协作、待办与日报 | 减少「只在群里说了」 |
| **练** | 训练日任务、学习记录、成果提交与批改 | 过程可查，不等于能力已成 |
| **演** | 场次、录制回放 | 便于抽查与复盘 |
| **评** | 评分报告是否生成、是否被查看 | 反馈有无据可查 |
| **改** | 教师批改、改进任务发布与跟进 | 强调人工判断环节 |

### 管理与治理（类别级，短列表）
- 学校 / 租户级数据隔离  
- 学生、教师、管理角色分端  
- 用户与组织治理；会议与评分等运营查看  
- 支持容器化部署与校内部署形态（细节见技术方案）  

### 对学院的价值表述（克制）
启发·竞赛大脑帮助学院把「备赛管理」从口头协调与文件收集，部分转为**可检查的过程资产**：谁在练、练到哪、演过几轮、改没改、教师有没有确认。

### 边界
过程可见，不等于育人质量自动提高。质量仍取决于课程设计、教师投入、学生行动与评价体系。

### 配图说明
- 简易「学院视角」示意：多个项目卡片 + 进度/提交/路演次数等过程指标（可用示意数据，标注「示意」）  
- 勿做假大空的「智慧大脑中台」全屏大盘，除非有真实可演示界面  

### 页任务
服务 P1 读者：教务听得懂「为什么值得纳入备赛组织方式」。

# 第 09 页｜学校价值与可信边界（校领导）

### 眉题
给关心人才培养与投入成效的决策者

### 标题
# 一次参赛，应留下可以继续生长的育人方法。

### 一句结果
奖项属于一届比赛；若过程被认真组织，学校更有机会留下可复用的训练方式、指导经验与项目资产。

### 学校可能沉淀什么（四条，机制向）

1. **学生如何从问题出发完成学习、实践与表达**——训练、提交与路演路径可复盘。  
2. **教师如何识别问题、形成判断并设计改进**——报告、批改与任务发布可回溯。  
3. **项目如何从早期版本走到可上场呈现**——材料、任务与场次留在项目上下文中。  
4. **下一届能否少从零开始**——方法与记录有机会被理解、复用与改进。  

### 我们能证明 / 仍需一起证明

| 平台机制可以支撑 | 仍需学校与真实使用证明 |
|------------------|-------------------------|
| 训练、材料、路演、评分、任务被组织与留痕 | 学生能力是否实质提升 |
| 教师判断可以写入改进路径 | 指导质量与效率是否提高 |
| 学院可查看关键过程信号 | 赛场成绩与长期育人成效 |
| 多校租户隔离与分端治理 | 规模化推广中的组织适配 |

### 明确不做的承诺（信任块）
- 不承诺金奖或名次  
- 不以一次 AI 分数代替成长  
- 不把 AI 建议当作教师的最终裁决  
- 不把任务完成或版本更新单独宣传为「已经学会」  

### 品牌承诺（页底大字或引文）
**不替学生赢一场比赛，而是帮助学生长出赢得比赛的能力。**  
这里的「帮助」指创造训练、交付、反馈与复验条件；能力形成仍需学生行动、教师指导与真实证据共同证明。

- 右侧：信任对照表（上表）排版即可，少用奖杯摄影

# 第 10 页｜如何开始 · 合作 · 联系

### 眉题

### 标题
# 带着一个真实项目，走一轮可验证的备赛。

### 一句结果
不从「听完功能」开始，而从「用你们自己的项目跑通一小段 **备-练-演-评-改**」开始。

### 建议试点路径（4 步）

| 步骤 | 做什么 | 建议周期 |
|------|--------|----------|
| 1. 选项目 | 确定 1 个参赛项目、指导教师与核心学生 | 2–3 天 |
| 2. 建节奏 | 先建材料/待办习惯（**备**），再配训练营（**练**） | 3–5 天 |
| 3. 跑五字 | **备** 齐材料与待办 → **练** 提交 → **演** 一场 → **评** 看报告 → **改** 由教师发布任务 → 再推进 | 1–2 周 |
| 4. 复盘 | 对照过程：改了什么、依据是什么、下一轮备/练/演计划 | 1 次工作坊 |

### 三种开始方式

1. **预约演示**  
   按 **备 → 练 → 演 → 评 → 改** 走一遍真界面：待办/日报与材料 → 训练日学习 → 路演或报告 → 教师批改与任务。  

2. **带项目试点**  
   用本校真实备赛项目试跑五字节奏，验证是否减少「找不到依据、改完无法验证」。  

3. **方案与部署沟通**  
   讨论校内部署、账号组织、与现有教学安排的衔接（技术细节另附）。
