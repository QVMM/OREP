## 0. 一句话

老师买的不是「席位好看」，是四件事同时成立：

1. 意见 **对着整场路演和项目本身**，不是只抠评分表空话。  
2. 意见 **能提分**，下场能对照，不是鸡汤。  
3. 同一录像再评 **不会乱飘、不会骗满分**。  
4. 每次评完给出 **任务书级** 的下一步，学生照着做、教师能验收。

**路演评议席** 是把这四件事做成一场正式评议的壳。  
壳本身不是爆点。没有下面第 0.1 节，席位就是皮肤，Claude / Codex 两周就能仿出观感。

对外名称：**路演评议席**。  
对内代号：`Deliberation`。

## 1. 为什么不用「法庭」

「法庭」能讲清程序，但和路演现场是两套语言：

| 法庭说法 | 路演现场实际在说什么 | 问题 |
|----------|----------------------|------|
| 开庭、落槌、呈堂、判决 | 评委入席、质询、教师确认 | 像司法，不像备赛 |
| 主审、书记 | 主评委、记录 | 师生对不上号 |
| 质疑席 | 评委追问 / 质询 | 路演里评委本来就会质询 |
| 决议书 | 本场评议结论 | 「判决」过重，教师也不敢用 |

竞赛大脑的现场是：**学生讲、评委听、教师带、按赛道量表给意见**。修饰词必须从这套现场长出来。

**路演评议席** 三个字各自有用：

- **路演**：场景就是这场展示，不是事后聊天。
- **评议**：评委在做的事，不是判刑。
- **席**：产品差异在「固定席位 + 程序」，不在「又多几个 Persona」。

备选过、本文不用的名字：

| 名字 | 不用的原因 |
|------|------------|
| 路演评委会 | 太像正式竞赛裁判团，对外易越界 |
| 评价议会 | 抽象，学校难开口介绍 |
| 答辩厅 | 只覆盖问答，盖不住上传录像主路径 |

## 2. 现在有什么，差在哪

### 2.1 已有资产（必须复用，禁止推倒）

| 资产 | 现状 | 在评议席里的位置 |
|------|------|------------------|
| 上传 / 会议后出分 | 主路径可用 | **主评草案** |
| 报告五栏：结果 / 为何 / 评委 / 整改 / 对比 | A，完整度看当场流水线 | 降为评议结论的展开页 |
| 证据锚点、转写、关键帧 | B，密度不一 | **质询席弹药**；无有效锚点不得支撑扣分 |
| 9 人 AI 评审团 | B，旁路 Tab，去极值均分 | 收编为 **评议席里的 AI 席**，不再出第二份官方分 |
| 赛道规则 v1.2 | 已接入 | **赛道席** 只读绑定 ruleVersion |
| 整改 todos + 教师审核发布 | B | **本场必做** 的第一落点 |
| 教师确认口径 | 能力真相表红线 | **指导教师席** 终裁 |

### 2.2 结构性问题

1. 叙事仍是「报告阅读器」，评审团是旁边一个 Tab。  
2. 9 个角色并列写评语，任何 Agent 一次 Prompt 就能仿。  
3. 评审团均分容易被看成第二份官方分。  
4. 质询没有强制程序：没有「专人只负责推翻站不住的分」。  
5. 教师终裁不在场上，只在事后看看。  
6. 评议结果几乎不改训练、待办、权限。  
7. 下一场又是一篇新作文，对不上上次承诺。

### 2.3 产品判断（与能力真相表对齐）

| 可写实 | 必须谨慎 | 禁止写 |
|--------|----------|--------|
| 多席位评议、质询、教师确认 | 「接近正式竞赛评委」 | AI 直接出正式竞赛成绩 |
| 辅助建议、教师最终裁决 | 9 席 = 国赛机制（宣传册曾这样写，要改） | 全自动教师裁决 |
| 本场评议结论、承诺对照 | 锚点条条精确 | 任意格式秒出分、100% 稳定 |

## 3. 产品定义

### 3.1 名称与口径

| 项 | 写法 |
|----|------|
| 对外主叙事 | **路演评议席** |
| 一句话 | 路演进入有席位、有质询、有教师确认的正式评议 |
| 学生端入口文案 | 本场评议 / 查看评议结论 |
| 教师端入口文案 | 确认本场评议 / 处理质询 |
| 上传完成态 | 评委入席中… / 主评草案已出 / 待教师确认 |
| 旧名处理 | 对内文档可写「原 Chamber / 法庭隐喻已废」；产品 UI **不得出现** 法庭、开庭、落槌、呈堂、判决 |

### 3.2 用户 30 秒能懂的演示

1. 路演结束或视频上传完成 → 大屏：**本场评议已开始**（计时、席位、量表版本）。  
2. 关键讲解被标成 **评议片段**，可跳回录像。  
3. 主评草案上墙 → **质询席标红 2 条无锚点扣分**。  
4. 教师点「采纳质询」或「维持草案」。  
5. 终局不是长文，而是 **本场评议结论**：分 + 争议点 + 承诺 + 3 天必做。  
6. 下周再来：第一屏是 **「上次承诺兑了几条」**，不是又一篇新报告。

### 3.3 三种评议方式

| 方式 | 场景 | 阶段 |
|------|------|------|
| **送评议** | 现行上传视频 | MVP 主路径。程序按评议席走，流水线不推倒 |
| **对照复评** | 只核承诺和弱项 | 标准版。第二场起才有粘性 |
| **现场评议** | 会议室实时在场 | 完整版。最像真路演，也最重 |

上传链路全部按 **送评议** 的对象模型和界面走，避免「上传是报告、会议是另一套灵魂」。

## 4. 席位

特色来自席位和程序，不来自模型家数。

| 席位 | 职责 | 禁止 | 数据从哪来 |
|------|------|------|------------|
| **记录席** | 冻结本场材料、量表版本、时间线 | 不打分 | Session / 规则 hash |
| **赛道席** | 只引用本赛道本版条款，核证据是否对条款 | 禁止写鸡汤 | 42 赛道规则 + 规则引擎结果 |
| **主评席** | 综合草案、维度分、置信度 | 禁止无证据重判 | 现有评分流水线 finalResult |
| **质询席** | 专攻：证据不足、张冠李戴、过度推断 | 禁止捧场 | 新建质询生成 + 锚点校验 |
| **实质核验席** | 核：是不是套壳开源、有没有先进性证据、对行业/区域有没有可核验价值 | 禁止无出处下判断；未检索必须标「未核验」 | 主张抽取 + 可选联网检索 + 出处 |
| **满分对照席** | 修完旧问题 ≠ 比赛满分；给出满分差距 | 禁止把闭环率加成到 100 | 满分标杆库 / 赛道上限 |
| **指导教师席** | 采信 / 驳回 / 改判，抽检 | 可配置为必经 | 教师端新动作 + 审计 |
| **AI 评议席** | 现有 9 人团并入时间线，出视角差和追问 | 禁止冒充第二官方分 | 现有 jury，输出改写入时间线 |
| （可选）**同伴席** | 有限维度旁听 | 不碰总分 | 后期 |

默认 MVP 只开：**记录席 + 赛道席 + 主评席 + 质询席 + 实质核验席（可降级为未核验标记）+ 满分对照席（最小版）+ 指导教师席**。  
9 人团作为 **AI 评议席** 并行，结果并进时间线，不再单独占一个「第二总分」C 位。

没有实质核验和满分对照，评议席在学校面前站不住。席位再多也只是换皮报告。

## 5. 一场评议怎么走

```text
送评 / 现场结束
    ↓
记录席冻结（材料、量表版本、ruleHash）
    ↓
感知完成（转写 / 抽帧 / 说话人）     ← 现有流水线
    ↓
主评席出草案（维度分 + 扣分动议）
    ↓
质询席扫描并攻击（可与 AI 评议席并行）
    ↓
合议时间线（同意 / 反对 / 少数意见）
    ↓
指导教师确认（采纳质询 / 维持草案 / 改判）
    ↓
冻结本场评议结论
    ↓
下达本场必做 +（可选）改训练状态
    ↓
下场对照复评
```

进度文案只用路演语言：

| 内部状态 | 用户看见 |
|----------|----------|
| sensing | 正在整理本场材料 |
| draft | 主评草案生成中 |
| challenge | 质询席核对中 |
| await_teacher | 待教师确认 |
| frozen | 本场评议已确认 |
| continuance | 对照复评中 |

## 6. 对象模型

一场评议 = 一个评价事件。现有 `AiScoringSession` **不砍**，在其上扩展。

```text
RoadshowDeliberation（本场评议）
  ├── SeatConfig          开哪些席、是否必须教师确认、量表 version
  ├── Docket              卷宗：视频 / 现场流 / PPT / 问答
  ├── Proceedings         过程：时间片、发言、质询片段
  ├── Motions             动议：给某维打分、提出扣分、提出免责
  ├── Challenges          质询：攻击某条动议，必须挂锚点
  ├── Judgment            结论：AI 建议 + 教师确认 + 审计
  ├── Dissent             少数意见，保留不抹
  ├── Commitments         学生 / 队伍当场承诺
  ├── Consequences        触发的必做任务 / 训练动作
  └── Rematch             下场对照议程
```

报告页降级为 **「本场评议结论」的展开**，不再是文章阅读器。

关键约束：

- 每条质询必须带 `targetDimension` / `lossId` / `anchorIds`。  
- 无效锚点（无可靠时间、对不上转写）不得支撑扣分或质询。  
- 全场只有一份权威分：`scoreAuthority`。评审团均分只作对照，文案写死「卷面以本场评议结论为准」。  
- 教师动作全量进审计：采纳质询 / 驳回质询 / 改判 / 撤销某条扣分。

## 7. 质询席：招牌，也是最容易做成玩具的地方

不能做成 Prompt「你唱个反调」。有效质询只能打这三类：

1. **有分无锚点**：该维给了分或扣了分，卷宗里没有可跳转证据。  
2. **锚点对不上**：时间越界、不是这句话、不是这页 PPT。  
3. **条款套不上**：赛道席的量表条款与证据不是同一件事。

生成规则：

- 规则先扫，LLM 只写质询叙述，**不得发明时间戳**。  
- 每条质询默认未决，等教师采纳或驳回。  
- 有效率要可测：一场里 0 条或条条都红，都算失败。目标大约每场 1–4 条可核验质询。

演示句只允许类似：

- 「质询席指出：创新成效扣了 4 分，但没有可跳转的证据。」  
- 「教师已采纳该条质询，草案分已回写。」

## 8. 界面：从报告阅读器到评议现场

### 8.1 学生端 · 本场评议（原报告首页）

首屏只留四块，一屏看完：

1. **本场结论**：权威分、量表版本、是否已教师确认。  
2. **质询条**：N 条，点开跳秒。  
3. **待教师 / 已确认** 状态。  
4. **本场必做**（原整改 todos，强调教师发布后才进待办）。

原「结果 / 为何 / 评委 / 对比」变成结论页的展开，不进一级导航。  
原「多维评委」改名为 **AI 评议席**，首屏禁止放大均分。

### 8.2 学生端 · 评议进行中

不要空白转圈。按席位显示阶段：材料整理 → 主评草案 → 质询核对 → 待教师确认。

### 8.3 教师端 · 确认本场评议

在现有评分报告旁增加「待确认」队列：

- 草案分、质询列表、锚点预览。  
- 每条质询：采纳 / 驳回，可写一句理由。  
- 确认后学生才看到终局结论；未确认时学生看到「草案，待教师确认」（校可配置是否对学生暴露草案）。

### 8.4 现场评议（完整版，非 MVP）

会议室大屏：席位灯、当前片段、质询红条。复用 LiveKit / 录制，不另做一套会议。

## 10. 分期

### 10.1 MVP（送评议能演示）

目标：老板 / 教师 2 分钟看懂「这不是又一份报告」。

必须交付：

1. 文案与信息架构：本场评议、评委入席、质询、教师确认。全站去掉法庭用语。  
2. 状态机：草案 → 质询 → 实质核验标记 → 待确认 → 已确认。Session id 不变。  
3. 质询席：规则扫描「有分无有效锚点」+ 可跳转。  
4. **同一录像冻结复评**：同输入多次分差可展示；超阈值标「本场不稳定」。  
5. **实质核验最小版**：套壳 / 先进性 / 价值 三条主张，每条必须是「有出处」或「未核验」，禁止装成已检索。  
6. **满分差距最小版**：上轮闭环率与本场预测分拆开，禁止修完就满分。  
7. **任务书式必做**：每条有目标、步骤、验收、预计提分、要补的证据；禁止「加强表达」。  
8. 学生端结论首页 + 教师确认与审计。  
9. 权威分单一来源；9 人团均分退出 C 位。

不做：现场实时评议、跨校常模、锁训练日、假装全球产业调研已完成。

### 10.2 标准版

- 承诺写下并在下场对照。  
- 对照复评：整场再评 + 自动差分（先不做局部重算）。  
- 轻量后果：只生成站内必做，不锁权限。  
- 教师抽检队列（低置信 / 高争议自动进）。

### 10.3 完整版

- 现场评议（会议室在场）。  
- 营期分位（单校、样本量不足不展示）。  
- 同伴席、更细的后果编排。

## 11. 技术要点（给研发，不绑死实现）

| 点 | 做法 |
|----|------|
| 兼容 | 不砍 Session；评议是其上的程序层 |
| 质询有效 | 规则先扫，LLM 只写话；禁止发明时间戳 |
| 锚点 | 无效锚点不能支撑结论分和质询 |
| 编排 | 质询与 9 人席并行，超时降级写死：质询失败仍可出草案，标明「本场未完成质询」 |
| 教师 | 乐观锁；操作枚举固定；全量 audit |
| 后果 | 声明式规则；MVP 只写待办；可回滚 |

前端主要改：`AiScoreReportResult.vue` 首屏、`AiScoreReportJury.vue` 降权、教师 `ReviewReportsView` / 新确认页。  
后端主要加：评议状态、质询表、教师确认 API、审计。  
Python 主要加：质询扫描，不重写整条 ASR / 视觉流水线。

## 12. 验收

### MVP 演示脚本（必须一遍走通）

1. 用预置成功样例送评议。  
2. 学生看见「评委入席 / 主评草案 / 质询」而不是空白转圈。  
3. 至少 1 条质询能跳到录像或转写。  
4. 教师采纳 1 条质询，结论分或扣分列表可见变化。  
5. 学生看见「教师已确认」，且只有一份权威分。  
6. 界面无「法庭 / 开庭 / 落槌 / 呈堂 / 判决」。  
7. 对外口头介绍只能说：辅助评议，教师确认。

### 门禁

| 项 | 门槛 |
|----|------|
| 质询可核验率 | 预置样例 ≥ 1 条可跳转；胡编时间戳 = 0 |
| 权威分一致 | 结论页、为何页、教师页同一数字 |
| 教师未确认 | 按校配置：不发布终局，或不进学生待办 |
| 回归 | 现有出分、报告五栏、历史报告不挂 |

## 13. 风险与红线

| 风险 | 处理 |
|------|------|
| 做成皮肤，Agent 仍能仿 | 质询必须可核验，教师动作必须落库 |
| 教师嫌多一步 | 校可配置「自动确认」；默认要确认 |
| 质询条条都红或一场没有 | 调规则阈值；空态写「本场未发现可核验争议」 |
| 宣传越界 | 禁止「正式裁判」「AI 出竞赛成绩」「全自动裁决」 |
| 流水线更慢 | 质询并行；失败降级，不挡草案 |

写作红线（摘自能力真相表，本方案必须遵守）：

- AI 是辅助建议，教师最终裁决。  
- 不要写全自动教师裁决。  
- 不要把 9 席写成国赛正式评审机制。  
- 不要承诺 100% 稳定、任意格式秒出分。

## 14. 对外文案（可用句）

可以用：

- 路演评议席：有席位、有质询、有教师确认。  
- 质询席专门核对站不住的加减分。  
- 本场评议结论由教师确认后生效。  
- 下次路演对照上次承诺。

不可以用：

- 评审法庭 / 开庭 / 判决 / 落槌。  
- AI 评委会直接给出正式竞赛成绩。  
- 一键完美、无需教师。

## 17. 老师真正在问什么（市场质询）

席位和程序是进步，但学校采购时不会问「你们有几个席」。他们问的是下面这些。答不上，评议席在市场上站不住。

### 17.1 你是不是只对着评分表空转？

老师要的不是「技能水平 60 里扣了 8 分」。他们要知道整场路演里这个项目：

| 老师心里的话 | 只对评分表 | 评议席必须做到 |
|--------------|------------|----------------|
| 是不是找个开源项目改了改、加了个 AI | 量表写「创新 10 分」也能给到 7 | **实质核验**：有没有真实运行证据、和原仓库/论文的差异是否讲清 |
| 技术上到底先不先进 | 「提到了大模型」就加分 | 先进性必须有对比、测试、调用或设备证据，否则封顶 |
| 对行业、区域经济有没有用 | 「应用价值」空话 | 主张必须可核验（服务谁、在哪、替代了什么）；核不到就标未核验 |
| 讲得好就能高分吗 | 表达维拉满、项目仍是套壳 | 表达分和项目实质分拆开，不能互相补 |

**口径：量表为主，但量表里的「先进 / 价值 / 创新」必须落到项目实质，不能用讲稿词汇凑。**  
做不到这一条，老师会觉得你是「会打分的 PPT 批改器」。

### 17.2 你联网核过，还是编的？

这是信任总开关。编一次产业判断，比少一个席位更致命。

| 主张类型 | 正确做法 | 错误做法 |
|----------|----------|----------|
| 录像里发生了什么 | 只依据本场转写 / 画面 / PPT | 用模型常识补「他们一定做了实验」 |
| 这技术是不是公开方案改的 | 标「已对照公开资料」或「本场未检索」 | 假装查过 GitHub / 论文 |
| 对某县产业有没有用 | 有出处才写；没有就写未核验 | 生成「赋能当地农业」 |

产品规则：

- 每条实质判断带状态：`本场可见` / `已检索并附出处` / `未核验`。  
- **未核验不得写成肯定句**。  
- 对外禁止说「我们联网审查了所有项目」。MVP 可以先做标记，再做真检索。

### 17.3 评了对提分有没有用？评完会不会给任务书？

「再练表达」没有用。老师要的是训练营里那种任务书：

```text
目标：让评委在 60 秒内看懂你们和开源方案的三条差异
步骤：
  1. 列出原项目能力边界（一页表）
  2. 补一段真实运行录屏（≥30 秒，露出本队环境）
  3. 路演里用「原方案做不到 → 我们做到」句式讲完
验收：录像里能跳到这 30 秒；PPT 上有对比表
预计提分：创新 / 技能水平合计 +3～5（需下场对照，不保证）
```

每条必做必须有：目标、步骤、验收、要补的证据、预计提分区间。  
没有验收标准的建议，不准进学生待办。

### 17.4 同一视频评多次，会不会乱、会不会骗人？

会，如果每次都重新让大模型「再感觉一遍」。老师会拿同一条录像测你。测漂了，就是骗子。

必须做到：

| 规则 | 说明 |
|------|------|
| 冻结输入 | 同文件哈希 + 同量表版本 = 同一场卷宗 |
| 复评可展示 | 同一卷宗连评 3 次，总分 / 维度分差公开 |
| 超阈值标红 | 例如总分波动 > 3 分，写「本场不稳定，请教师复核」 |
| 禁止偷偷改 | 不能这次严、下次松来讨好续费 |

识别率（转写、抽帧、说话人）同样要报：本场转写覆盖、锚点可跳转率。不稳定就写不稳定，不要用流畅报告遮住。

### 17.5 用一两次是不是就满分了，然后不用了、不买了？

这是续费杀手。错误产品是：

```text
第一场 72 → 按待办改 PPT → 第二场 91 → 第三场 98 → 没得练了
```

正确产品必须拆开两个数：

| 数 | 含义 | 能不能到 100 |
|----|------|--------------|
| 上轮问题闭环率 | 上次指出的问题修完了没 | 可以 100% |
| 本场比赛预测分 | 对照赛道满分标杆，现在值多少 | **修完旧问题也不能自动到 100** |

第二场应长这样：

```text
本场预测分 84（+6）
上轮问题闭环率 100%
满分差距 16：现场稳定性、量化对比、区域落地证据仍缺
结论：上次的坑填了，离能打的项目还早
```

没有满分差距，评议席会变成「改稿机器」，两轮用完。

### 17.6 能不能客观给出「所有」意见？

不能，也不许承诺。

客观的上限是：

- **覆盖** 本赛道官方观测点，并列出「本场没看到、因此没评」的项。  
- **分开** 表达分和项目实质分。  
- **标明** 哪些是本场看见的，哪些未核验。  

「所有意见」「完全客观」是假话。老师要的是 **边界清楚的客观**，不是全知。

## 18. 评议席这样改完，市场站不站得住？

### 18.1 只做席位程序：站不住

Claude / Codex 加一个能看视频的模型，一两周就能做出：

- 按评分表打分  
- 多个角色写评语  
- 三条改进建议  
- 一张好看报告  

用户试用这些工具，会觉得「和你们差不多，还不用买平台」。  
**席位皮肤抄起来比抄转写还快。**

### 18.2 加上第 17 节四件事：能站住，但不是「两年抄不了」

两年内 Agent **一定能** 仿：单次看片、套表、写任务书口吻、甚至联网搜一圈。

两年内 Agent **仍然难替代** 的，是绑在学校里的这几样同时成立：

| 老师在意的 | Agent 对话框 | 平台必须做成 |
|------------|--------------|--------------|
| 同一录像评三次一个样 | 每次重生成，分会飘 | 冻结卷宗 + 公开波动 + SLA |
| 是不是套壳、有没有价值 | 可以搜，但无责任、无「未核验」纪律 | 每条主张带出处或未核验；教师可抽检 |
| 练了有没有提分 | 用户自己贴历史 | 跨场对照、闭环率 / 预测分拆开 |
| 会不会两下满分 | 用户让它松一点就松 | 满分标杆锁死，教师锁分 |
| 任务书谁验收 | 学生说做完就算 | 证据回挂、教师发布、营里真正改状态 |
| 谁负责 | 没有 | 审计：哪条质询、谁确认、哪版量表 |

铁律仍是：凡是「一次会话、单用户、复制粘贴就能完成」的，都不是壁垒。  
壁垒是 **同一学生、同一项目、同一量表版本、可复现、可抽检、修完也不封顶** 的组织评价。

所以：

- **不能对外说「两年无法抄袭」。** 这是假话。  
- **能对外说**：单次 AI 看片谁都能做；把「稳、核、对照、任务书、教师锁」做成学校里的评议纪律，对话框替不了。  
- 评议席是这套纪律的名字和界面，不是纪律本身。

### 18.3 爆点该喊哪句

不要喊「我们有五个席」。喊老师听得懂的：

1. **同一条录像，分数经得起复评。**  
2. **先问是不是套壳、有没有真价值，再给表达分。**  
3. **没查过的，会写没查过。**  
4. **评完是任务书，不是鸡汤。**  
5. **上次的改完了，离满分还差哪几块，写得清。**

席位是把这五句变成一场看得见的评议。五句做不到，席位就是包装。

## 19. 对原方案的修正结论

| 原方案 | 修正 |
|--------|------|
| 爆点 = 席位 + 程序 | 爆点 = 可信提分；席位是容器 |
| MVP = 质询 + 教师确认 | MVP 必须加上：复评稳定、未核验标记、满分差距、任务书字段 |
| 质询只打无锚点 | 质询还要打「套壳 / 无先进性证据 / 价值空话」 |
| 后果先做待办 | 待办必须是任务书，否则老师觉得没用 |
| 「两年 Agent 做不到」 | 改为：Agent 做得了单次报告，做不了学校里的复评纪律和满分锁 |

按 1.1 修订后的评议席，**可以作为评分模块的主叙事立项**。  
若只做 1.0 的席位皮肤，**建议不要当核心卖点对外讲。**
