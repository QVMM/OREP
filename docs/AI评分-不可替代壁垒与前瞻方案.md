## 0. 先承认：哪些东西不是壁垒

下列能力 **会变好、会普及、会被 Agent 产品化**，不应再当作「顶级护城河」宣传：

| 能力 | 为何不是顶级壁垒 |
|------|------------------|
| 单次视频 + 量表 → 长报告 | 多模态与长上下文会抹平 |
| 多 Persona 各写一段评语 | 一次 Prompt 多角色即可仿 |
| 时间戳摘录、要点列表 | 视频理解 API 会标配 |
| 「评完给三条建议 / 待办」 | Agent 天然擅长 |
| 同人两次报告对比（用户自己提供历史） | 用户粘贴历史即可 |
| 更漂亮的雷达图与排版 | 无意义差异 |

**铁律：凡是「一次会话、单用户、可复制粘贴完成」的，都不是 1–2 年壁垒。**

前序方案里的证据与闭环 **仍然要做**——那是 ** hygiene（卫生线）与体验及格线**，不是护城河。  
护城河必须落在：**制度、现场、多方、时间、后果、网络** 六类 Agent 不擅长的东西上。

## 1. 核心洞察：Agent 的单位 vs 你们的单位

| | 民用 Agent（含未来升级形态） | 竞赛大脑应成为的单位 |
|--|------------------------------|----------------------|
| 基本对象 | **会话（Session of chat）** | **制度内的评价事件（Institutional Evaluation Event）** |
| 时间 | 分钟～小时 | 天～学期（档案与承诺） |
| 主体 | 一个人 + 模型 | 学生 / 队友 / 教师 / AI 席位 / 规则版本 |
| 输出 | 文本与建议 | **有后果的判定 + 可申诉的记录** |
| 失败 | 再生成一次 | **责任归属与程序正义** |
| 数据 | 用户临时投喂 | **组织持续沉淀、不可被单次对话框搬走** |

AI 评审团之所以「抽象但有特色」，是因为它暗示：

> 评价不是「一个上帝模型说了算」，而是 **一套席位、一套程序、一套可展示的合议。**

我们要的下一代，必须同样 **抽象、可命名、可演示**，并且 **程序与席位本身就是产品**——而不是更长的报告。

## 2. 1–2 年内 Agent 做不到什么（真正的不对称）

下面六条是「即使模型变强，形态上仍难替代」的不对称。**壁垒 = 至少同时占住 3 条以上，并做成用户一眼能懂的产品名。**

### 2.1 现场协议（Live Protocol）——不是事后聊天

| | 说明 |
|--|------|
| 含义 | 评分是 **路演现场的一种仪式/协议**：有开场、有时限、有提问席、有冻结时刻；不是回家后把视频丢进对话框。 |
| 现在就能抓人 | 「今天这场路演，系统在场」——比「上传后出报告」庄重、可传播。 |
| Agent 为何难 | Agent 是 **事后、可反复重试、无现场约束** 的；无法成为 **房间里的公共时钟与公共记录员**（多机位、同刻提问、不可悄悄重录整场当另一次 chat）。 |
| 1–2 年形态 | 即使有实时 Agent，也缺 **与教务/营期绑定的现场席位与冻结规则**；个人 Agent 成不了「本场官方记录」。 |

### 2.2 多方席位与合议程序（Chamber）——评审团的「上位抽象」

| | 说明 |
|--|------|
| 含义 | 评价 = **议会**：固定席位（主审 AI / 质疑席 AI / 赛道规则席 / 教师席 / 可选同侪席），有动议、异议、少数意见、挂起表决，而不是 N 个 Persona 各写一段并列展示。 |
| 与现有评审团关系 | 评审团是雏形；升级为 **程序产品**（可演示「质疑席推翻了一条无证据扣分」）。 |
| 现在就能抓人 | 可视化合议回放：「三席同意、一席反对、教师采纳反对」。 |
| Agent 为何难 | 一次 chat 里模拟多角色 **没有制度效力**；无持久席位权限、无异议归档、无「未达法定人数则不得出分」。 |
| 1–2 年 | 多 Agent 框架会流行，但 **组织级合议卷宗 + 权限 + 终裁权** 仍是平台生意。 |

### 2.3 后果图（Consequence Graph）——分能改命运

| | 说明 |
|--|------|
| 含义 | 分数 **改写系统内权益与路径**：解锁训练日、限制答辩资格、触发导师约谈、生成队内分工建议——评价是 **操作系统事件**，不是附件 PDF。 |
| 现在就能抓人 | 「扣在表达上 → 自动锁死下一项任务是 3 分钟限时再讲」——用户感到系统在管事。 |
| Agent 为何难 | Agent **不拥有** 你们的训练日、营期、权限、资源中心；最多输出「建议你去练」，不能 **默认改状态机**。 |
| 1–2 年 | 除非 Agent 吃掉整个教务 OS（极难、合规重），否则 **后果图只属于平台**。 |

### 2.4 纵向身份与承诺（Longitudinal Identity + Commitment）

| | 说明 |
|--|------|
| 含义 | 同一个人跨月跨场的 **能力轨迹 + 公开/半公开改进承诺**（「我承诺下次逻辑维度 ≥ X」），复评时对照承诺而非对照空气。 |
| 现在就能抓人 | 「你上学期的三个承诺，兑现了两个」——强情绪、强粘性。 |
| Agent 为何难 | 无稳定组织身份；历史在用户磁盘与不同产品间碎裂；**承诺无见证方**。 |
| 1–2 年 | 个人 Agent 可有记忆，但缺 **教师/队友见证的制度承诺** 与跨产品携带的权威档案。 |

### 2.5 对抗与抽检（Adversarial + Sampling）——可信的来源

| | 说明 |
|--|------|
| 含义 | 产品内建 **质疑席 / 红队**：专职攻击「这条分站不住」；低置信与高争议自动进 **教师抽检队列**；形成可信，而不是更顺的吹捧。 |
| 现在就能抓人 | 「我们自己的 AI 在杠自己的评分」——记忆点极强，接近评审团的抽象力。 |
| Agent 为何难 | 用户可要求「唱反调」，但无 **强制双通道、无抽检义务、无机构问责**；高利害场景不敢只靠自说自话。 |
| 1–2 年 | 对抗生成会常见，**强制程序 + 抽检 KPI + 审计** 仍是系统能力。 |

### 2.6 常模网络（Norm Network）——用群体定义「好」

| | 说明 |
|--|------|
| 含义 | 「你的表达在本赛道本营期的分位」来自 **真实群体沉淀**（可脱敏、可租户隔离），不是模型臆测的「一般水平」。 |
| 现在就能抓人 | 「超过本营 72% 的路演」——一句话打败整页空洞评语。 |
| Agent 为何难 | 没有跨用户合法数据飞轮；单用户 Agent **造不出真实常模**。 |
| 1–2 年 | 大厂或有泛化基准，**难有「你们这所学校 / 这个赛道营」的活常模**。 |

## 3. 旗舰抽象：给产品一个「像评审团一样」的名字与内核

### 3.1 旗舰名（建议选定其一作为对外主叙事）

推荐主叙事：

# **评价议会（Evaluation Chamber）**

一句话：

> **路演不是丢给一个 AI 写评语，而是进入一场有席位、有程序、有冻结、有后果的评价议会。**

副能力品牌（可逐步露出，不必一次全做）：

| 名称 | 一句话 | 对应不对称 |
|------|--------|------------|
| **现场书记席** | 本场公共时钟与不可篡改记录 | 现场协议 |
| **质疑席** | 只负责推翻站不住的扣分/加分 | 对抗 |
| **规则席** | 只读本赛道本版本量表，不做散文发挥 | 制度 |
| **见证承诺** | 改进目标被系统与教师共同见证 | 纵向 |
| **后果编排** | 议会结果直接改下周训练与权限 | 后果图 |
| **营期分位** | 活常模，不是模型瞎估 | 网络 |

**AI 评审团** 收编为议会中的 **「AI 席团」**（多 Persona = 议会内若干 AI 席），不再是与主报告平行的「另一份好看输出」。

### 3.2 用户 10 秒能懂的演示脚本（抓人用）

1. 路演开始 → 大屏显示 **本场议会已开庭**（计时、席位、量表版本）。  
2. 过程中关键问答被标成 **庭审片段**（不是事后剪辑玄学）。  
3. 结束后 90 秒内：主审草案上墙 → **质疑席红条挑战 2 处** → 教师一点「采纳质疑」。  
4. 终局：不是长文，而是 **议会决议书**（分 + 争议点 + 承诺 + 自动下达的 3 天任务）。  
5. 下周再来：第一屏是 **「承诺兑现审查」**，不是又一篇新作文。

通用 Agent 可以模仿文案，**模仿不了「开庭—质疑—采纳—后果—兑现」这条公共程序。**

## 4. 评分功能「到底做成什么样」（前瞻规格）

### 4.1 对象模型（抽象层，实现可分期）

```text
EvaluationEvent（评价事件 / 一场庭）
  ├── ChamberConfig（席位、是否现场、是否锁分、量表 version）
  ├── Docket（材料：视频/现场流/问答/PPT）
  ├── Proceedings（庭审过程记录：时间片、发言、提问）
  ├── Motions（动议：给维打分、提出扣分、提出免责）
  ├── Challenges（质疑席攻击）
  ├── Judgment（终裁：AI 建议 + 教师终裁 + 审计）
  ├── Dissent（少数意见，保留）
  ├── Commitments（学生/队伍承诺）
  ├── Consequences（触发的系统状态变更）
  └── Continuance（下次开庭时的对照议程）
```

报告页降级为 **「决议书 UI」**，不再是文章阅读器。

### 4.2 席位职责（产品可配置，默认开启最小集）

| 席位 | 职责 | 禁止 |
|------|------|------|
| 规则席 | 引用量表条款、检查证据是否匹配条款 | 禁止写鸡汤 |
| 主审席 | 综合草案、维度分、置信度 | 禁止无证据重判 |
| 质疑席 | 专攻：证据不足、张冠李戴、过度推断 | 禁止捧场 |
| 教师席 | 采信/驳回/改判、抽检 | 可配置为必经 |
| 书记席 | 记录冻结、版本、哈希 | 不参与打分 |
| （可选）同侪席 | 有限维度、防串通规则 | 不碰总分亦可 |

**特色感来自席位与程序，而不是模型家数。**

### 4.3 三种开庭模式（覆盖现在与未来）

| 模式 | 场景 | 1–2 年 Agent 替代难度 |
|------|------|------------------------|
| **A. 现场庭** | 会议室/教室实时 | 极高 |
| **B. 呈堂庭** | 上传视频（现行主路径）但 UI/程序仍按「开庭」 | 高（程序+后果） |
| **C. 续审庭** | 只审承诺与弱项，不重开全场 | 极高（依赖纵向制度） |

现行上传链路 **全部升级为 B 的仪式与对象模型**，避免两套产品灵魂。

### 4.4 与「可被 Agent 仿的功能」的边界

| 仍要做（及格线） | 不靠它当壁垒 |
|------------------|--------------|
| ASR、锚点、ledger、待办 | 单独拿出来宣传 |
| 多模型 | 「我们模型更多」 |
| PDF 导出 | 「导出更好看」 |

宣传句只允许类似：

- 「本场评价议会决议」  
- 「质疑席已挑战 N 项」  
- 「承诺兑现审查」  
- 「已触发训练后果」  
- 「本营分位」

## 5. 为何这算「长远目光」且 1–2 年仍难被追平

| 技术趋势 | 对「报告生成」 | 对「评价议会」 |
|----------|----------------|----------------|
| 更强视频理解 | 报告更好写 | 只让庭审素材更便宜，**程序仍稀缺** |
| Agent 工作流编排 | 个人自动化更强 | 缺组织席位、缺后果图、缺现场公共记录 |
| 多 Agent 辩论框架 | 可仿评审团文风 | 缺终裁权、审计、抽检义务、营期绑定 |
| 个人永久记忆 | 个人教练变强 | 缺 **见证的承诺** 与 **群体常模** |
| 实时语音 Agent | 可旁路提词 | 难成为 **本场官方书记与冻结机关** |

**结论：**  
1–2 年民用 Agent 会继续碾压「写报告」；  
**不会自然长成「学校/营期里的评价制度器官」。**  
谁先占用这个品类心智，谁就有顶级壁垒。

## 6. 分阶段：先抽象落地，再工程铺开

原则：**先做一个让人记住的「最小议会」**，再填底层能力——避免又做成「更复杂的报告系统」。

### 6.1 Phase α（4–8 周）——只做「记得住」

**目标：一个演示即可融资式讲清差异。**

| 交付 | 说明 |
|------|------|
| 决议书 UI | 上传路径套上「开庭→草案→质疑→（模拟）教师点选→决议」时间线 |
| 质疑席 v0 | 规则化 + LLM：专门输出「可攻击点」列表（最多 3–5 条），主报告必须回应「采纳/驳回」 |
| 席位可视化 | 3 席即可：规则 / 主审 / 质疑（复用现有 jury 数据管线可改造） |
| 文案全面切换 | 去掉「生成报告」主标题 |

**刻意不做：** 大重做流水线、全量常模、完整现场多机位。

**成功标准：** 陌生用户 30 秒内说出与 ChatGPT 的差别里包含「有质疑/有程序/有席位」之一。

### 6.2 Phase β（1–2 季度）——「用得上」

| 交付 | 说明 |
|------|------|
| 呈堂庭对象模型 | Session = EvaluationEvent；决议持久化 |
| 教师席真实终裁 | 采信质疑、改分、审计 |
| 承诺 + 续审庭 | 下次开庭首页 = 兑现审查 |
| 后果图 v1 | 至少 2 类自动后果（解锁训练 / 生成必做任务）接到现有训练或站内任务 |
| 分位 v0 | 单租户营期内分位（数据够才显示） |

### 6.3 Phase γ（2–4 季度）——「离不开」

| 交付 | 说明 |
|------|------|
| 现场庭 | 计时、提问席、冻结、多端同看决议 |
| 抽检队列 | 争议/低置信强制进教师 |
| 常模网络 | 赛道级脱敏分位 |
| 议会回放 | 合议过程可对外（脱敏）展示为品牌 |

## 7. 基准：用「壁垒指标」而不是「报告像不像」

| 指标 | 含义 | α | β | γ |
|------|------|----|----|-----|
| 程序完成率 | 走完草案→质疑→回应 的 session 占比 | ≥80% | ≥95% | ≥95% |
| 质疑有效率 | 教师/规则判定「质疑成立」占质疑条数 | 追踪 | ≥25%* | 稳定区间 |
| 证据跳转率 | 与决议相关的点击 | ≥35% | ≥50% | ≥50% |
| 承诺创建率 | 完成庭后建立承诺占比 | ≥40% | ≥70% | ≥80% |
| 后果触发率 | 产生系统状态变更的决议占比 | ≥30% | ≥70% | ≥85% |
| 续审回访率 | 有承诺者进入续审的占比 | — | ≥40% | ≥60% |
| 盲测差异率 | 用户能指出非 ChatGPT 点 | ≥70% | ≥85% | ≥90% |

\*质疑有效率过低说明质疑席无效；过高说明主审过差——用于调参，不是越高越好。

**明确删除为北向 KPI：** 报告字数、雷达图美观度、与某 LLM 文风相似度。

## 8. 和前序「升级方案」如何分工

| 文档 | 管什么 |
|------|--------|
| 《AI评分功能升级方案》 | 工程债、流水线、证据覆盖率、双引擎收敛——**地板** |
| **本文** | 品类定义、抽象特色、1–2 年不对称、旗舰体验——**天花板与招牌** |

落地顺序建议：

1. **先 α：评价议会最小可用**（特色生死线）  
2. **并行还工程债中的「证据可跳转」**（否则质疑席没有子弹）  
3. 再 β 后果与承诺（粘性）  
4. 再 γ 现场与常模（护城河加深）

没有 α，只做账本闭环 → 仍是「更好的 Agent 套壳」。  
只有 α 没有证据 → 议会变成话剧。  
**两者咬合才是顶级。**

## 9. 战略一句话（请钉在产品墙上）

> **通用 Agent 会成为最好的「写手席」；**  
> **竞赛大脑要成为唯一的「评价议会」——有现场、有席位、有质疑、有终裁、有承诺、有后果。**  
> **写手可替换；议会不可替换。**

| 禁用 | 启用 |
|------|------|
| AI 智能生成评分报告 | 本场评价议会决议 |
