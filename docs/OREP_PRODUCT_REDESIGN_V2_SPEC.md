# OREP 用户端与教师端 V2 产品重构规格

日期：2026-07-16  
状态：已完成产品与视觉审计，作为高保真原型 V2 的实施基线  
范围：学生端、项目队长能力、教师端；管理端沿用逻辑蓝图，本轮不制作页面

## 1. 为什么必须重构

当前问题不是橙色主题，也不是某一张卡片不好看，而是产品骨架失去统一性：

- 现有全局导航把首页、路演、PPT、讲稿、文件、学习、考试、评分、任务、选题平铺为十个一级入口，但这些能力实际属于同一条项目训练闭环。
- 同一个动作常同时出现在悬浮快捷栏、页面主卡、列表和底部控制区，用户无法确认唯一主路径。
- 学生首页与教师首页只是替换文案和数字，教师真正需要的跨项目判断、审核与干预没有形成独立工作模型。
- 单个真实页面已累积到约 2,000–13,000 行，存在多轮样式覆盖；旧原型单个样式文件超过 5,100 行，继续局部修补会放大研发风险。
- 页面同时出现巨型标题、Hero、指标卡、趋势、阶段、任务队列和悬浮操作，形成“页面很空、局部很挤”的矛盾。
- 样式中存在大量 7–10px 字号，桌面端可读性弱，移动端只是桌面卡片纵向堆叠。

因此，旧原型只保留真实业务对象、样本数据、状态和接口映射；页面壳层、信息架构、视觉层级和交互语法全部重建。

## 2. 产品本质

OREP 不是十个并列工具，而是一个以参赛项目为上下文、以路演评分为反馈引擎的训练闭环：

`项目目标 → 任务与交付物 → 教师审核 → 路演评分 → 整改任务 → 再验证`

学习与测评不是孤立内容站，而是当项目任务、错题或评分报告暴露能力缺口时触发的补强路径。

产品对象分为两条相连的链：

1. `项目 → 里程碑 → 任务 → 交付物 → 审核`
2. `路演场次 → 评分报告 → 问题 → 整改任务 → 新证据 → 再验证`

课程、练习、PPT、讲稿和材料都必须能追溯到项目目标、任务或评分问题，不能只作为独立工具存在。

## 3. 重构范围对比

### 方案 A：给现有 44 个页面统一换肤

优点是改动表面较小，旧功能入口保留完整。  
缺点是旧信息架构、重复动作和页面模板仍然存在，只会得到一套更整齐的“工具集合”。

结论：不采用。

### 方案 B：统一项目对象与角色化工作台

学生、队长和教师使用同一套项目事实、状态与导航；角色只改变首页排序、数据范围和可执行动作。先重建六个核心页面和一条完整闭环，再把其余三级页面迁移进同一体系。

优点：

- 适合现有大量三级页面。
- 同一项提交在学生与教师视角下状态一致。
- 队长仍是项目关系角色，不需要复制一套“队长端”。
- 允许保留现有后端数据、接口与业务状态。
- 可以先验证产品骨架，再扩展 PPT、讲稿、题库和会议等复杂页。

代价是必须先冻结导航、对象、权限与状态语义。

结论：采用。

### 方案 C：完全新建前后端产品

自由度最高，但会同时重写路由、状态、权限、接口和页面，交付周期与迁移风险过高。

结论：当前阶段不采用。

## 4. 角色模型

### 4.1 全局身份

- 学生 `STUDENT`
- 教师 `TEACHER`
- 其他管理或评审身份仍由管理端逻辑控制

### 4.2 项目关系角色

- 队长 `CAPTAIN`
- 成员 `MEMBER`
- 导师 `MENTOR`

队长不是全局账号类型。同一学生可以在一个项目中是队长，在另一个项目中是成员。

队长能力继续由项目权限决定：

- 分派任务
- 审核提交
- 审核材料
- 绑定路演

教师可在被授权范围内查看跨项目风险，进入项目后查看任务、提交、材料、路演、问题、能力与备赛度，并执行审核或教学干预。

### 4.3 同一事实，不同视角

| 对象 | 学生 | 队长 | 教师 |
|---|---|---|---|
| 首页优先级 | 我的下一项可执行任务 | 最影响里程碑的团队阻塞 | 最需要教师判断的项目事项 |
| 任务 | 完成与提交 | 分派、协调、项目级审核 | 指导、验收、退回、通过 |
| 评分问题 | 查看、领取整改 | 分配整改与跟进 | 确认证据有效性与干预 |
| 学习 | 继续计划与专项训练 | 查看团队缺口 | 发布、安排、观察与阅卷 |
| 路演 | 参加、上传、查看反馈 | 组织与绑定项目 | 创建、指导、复核 |

## 5. 新信息架构

所有角色固定使用五个一级入口：

1. **工作台**
2. **项目**
3. **学训**
4. **路演**
5. **复盘**

个人资料、通知、全局搜索和帮助属于全局能力，不占一级导航。

### 5.1 工作台

- 学生：首要任务、今日安排、准备度、最近反馈。
- 队长：团队阻塞、任务分工、里程碑、待协调事项。
- 教师：跨项目风险、待审核、今日指导、待跟踪干预。

### 5.2 项目

二级入口：

- 概览
- 任务
- 交付物
- 团队
- 里程碑

原“选题、PPT、讲稿、文件”收进“交付物”上下文，以对象类型或页内标签区分，不再占全局一级导航。

### 5.3 学训

学生二级入口：

- 我的计划
- 课程
- 测评
- 错题与收藏

教师二级入口：

- 教学计划
- 课程管理
- 测评管理
- 人工阅卷

### 5.4 路演

- 场次
- 录制
- 上传评分

会议室、课时播放器和正式考试属于沉浸式三级页。

### 5.5 复盘

- 报告
- 改进任务
- 证据
- 轮次

单场报告内部保留“结果、待办、为什么扣分、多维评委、对比”三级信息，但只使用页内标签，不再增加常驻导航。

### 5.6 三级页面规则

- 三级对象页必须持续显示项目、轮次或当前对象上下文。
- 不新增第三条常驻侧栏。
- 任务页使用“队列 + 详情”时，上下文二级栏自动收起。
- 复杂对象通过页内标签、面包屑、抽屉或沉浸页承载。
- 用户从首页进入三级页后，返回时保留筛选、滚动位置和当前项目。

## 6. 全局壳层

### 6.1 桌面布局

- 一级侧栏：72px。
- 顶部上下文栏：64px。
- 内容最大宽度：1280px。
- 12 栏网格，栏间距 24px。
- 除工作台外，常规页面最多两列。
- 任务或审核页面允许三段式布局，但不得再同时显示二级侧栏。

### 6.2 顶部悬浮快捷栏

快捷栏默认展开、固定悬浮，不做伸缩。

固定结构：

1. 当前页面或对象上下文。
2. 一个主动作。
3. 最多两个次动作。
4. 一个“更多”菜单。

规则：

- 快捷栏是当前页面动作控制器，不是第二套导航。
- 不放五个一级模块入口。
- 主动作由角色、对象状态、权限和前置条件共同决定。
- 动作进入快捷栏后，正文不再重复同名按钮。
- 无可执行动作时显示明确状态，例如“等待教师审核”。
- 沉浸式课程、考试和会议页面切换为任务专用控制条。
- 会议的麦克风、录制和挂断只保留在会议控制区，不在快捷栏重复。
- 移动端快捷栏转为底部行动条。

示例：

| 场景 | 主动作 | 次动作 |
|---|---|---|
| 学生任务草稿 | 提交交付物 | 保存草稿、查看验收标准 |
| 学生等待审核 | 等待教师审核 | 查看提交版本、催办 |
| 队长任务 | 分派负责人 | 调整截止时间、发起团队审核 |
| 教师审核 | 通过并下一项 | 退回修改、查看版本历史 |
| 评分报告 | 创建整改任务 | 轮次对比、询问 AI |

## 7. 六个核心页面

### 7.1 角色首页

首页不是统计看板，五秒内必须回答：

1. 我现在处于哪个项目、哪个阶段，离比赛还有多久？
2. 此刻最应该处理哪一件事？
3. 为什么它排第一，它影响了谁或阻塞了什么？
4. 验收标准是什么，完成后流向哪里？
5. 上次离开后，有什么与我有关的变化？

桌面结构：

- 顶部一条紧凑的项目与阶段状态带。
- 左侧 8 栏：唯一首要行动与最多三项今日安排。
- 右侧 4 栏：比赛日程、准备度、最近反馈。

不再使用四张并列 KPI 卡、巨型评分圆环和多个趋势图抢夺首屏。

角色差异：

- 学生主卡：我的下一项可执行任务。
- 队长主卡：最影响团队里程碑的阻塞。
- 教师主卡：最需要教师判断的事项。

### 7.2 任务工作台

目标：围绕验收标准完成一个交付物，而不是浏览任务数据。

布局：

- 左侧 300px 队列：需要我处理、等待他人、已完成。
- 中央任务详情：目标、负责人、截止时间、验收标准、来源、关联材料。
- 右侧 300px 协作区：活动记录、审核状态、相关人员。

角色主动作：

- 学生：提交交付物。
- 队长：分派负责人或送审。
- 教师：创建指导任务或打开审核。

状态：

`DRAFT → IN_PROGRESS → SUBMITTED → CHANGES_REQUESTED → SUBMITTED → APPROVED`

任务展示状态由提交和审核事实派生，不允许多个组件各自维护不同状态。

### 7.3 提交审核

目标：教师基于交付物和证据做出可执行的判断。

布局：

- 左侧审核队列。
- 中央真实交付物预览或版本差异。
- 右侧验收清单、评分证据、历史反馈和结构化评语。

退回修改必须包含：

- 问题类型。
- 证据位置或验收项。
- 期望结果。
- 截止时间。

审核后必须同步：

- 学生任务状态。
- 教师审核队列。
- 首页首要行动或数字。
- 任务活动记录。

Toast 只作为确认反馈，不能代替状态变化。

### 7.4 学习中心

目标：补齐与当前项目目标相关的能力缺口。

页内标签：

- 我的计划
- 课程
- 练习
- 测评

默认先展示“我的训练计划”，课程目录降为次级入口。

每个推荐项必须说明来源：

- 来自某个评分问题。
- 来自错题统计。
- 来自项目任务或教师安排。

完成课时后直接进入相关练习；完成专项训练后更新掌握度与关联任务状态。

教师的课程发布和测评管理不与学生学习页混在同一交互层。

### 7.5 评分复盘

目标：让用户看懂为什么失分，并把问题转成行动。

布局：

- 顶部紧凑展示总分、提升值、评分来源、评分版本和轮次。
- 左侧问题或评分维度队列。
- 中央证据查看器：视频时间点、讲稿片段、材料证据。
- 右侧评委判断、影响和整改状态。

图表只提供上下文，问题队列是主线。

问题状态：

`NEW → ACCEPTED → TASK_CREATED → EVIDENCE_SUBMITTED → RERUN_PENDING → VERIFIED`

若复评未解决，返回 `ACCEPTED` 并保留轮次记录；规则版本变化导致不可比较时明确显示“不可直接比较”。

### 7.6 教师工作台

目标：从多个项目中快速判断哪里需要介入。

分组：

- 需要判断
- 等待团队
- 已安排跟进
- 已解除

每项必须展示：

- 风险依据。
- 影响范围。
- 正在等待谁。
- 预计处理时间。
- 介入后的跟踪状态。

桌面结构：

- 顶部最多三项概要数据。
- 主区跨项目风险列表。
- 右侧待审核队列与今日指导排期。

教师应能在当前上下文完成审核、退回、创建指导任务或安排彩排，不先跳到另一个信息看板。

## 8. 三条黄金业务链路

### 8.1 学生交付与教师审核

`学生首页 → 任务详情 → 上传或链接交付物 → 提交 → 教师工作台 → 审核通过/退回 → 学生首页与任务状态同步`

这是首轮高保真原型必须完整走通的第一条链。

### 8.2 学习、测评与补弱

`学习计划 → 课时 → 专项练习/正式测评 → 错题与掌握度 → 返回薄弱课程或项目任务`

### 8.3 路演、评分与再验证

`路演/上传视频 → AI 评分 → 选择高影响问题 → 创建整改任务 → 提交新证据 → 教师确认 → 再评 → 轮次对比`

## 9. 真实数据与能力边界

主演示项目：

`智农云眼 · 农业病虫害智能预警系统`

安全样本数据：

- 团队 5 人。
- 比赛日期：2026-07-24。
- 当前阶段：材料与路演准备。
- 最新路演评分：84.2。
- 上一轮评分：76.8。
- 当前准备度：74%。
- 关键问题：成本收益证据缺少统一统计周期和原始记录。

原型可以使用现有后端已经具备的数据与状态：

- 团队、成员、岗位、里程碑、任务、提交、材料、路演、审核问题、能力与教师观察。
- 课程、课时进度、试卷、错题、收藏。
- 会议、录制、AI 评分报告、证据、整改和轮次。

不能在高保真中伪装为已上线能力：

- 当前准备工作区中仍被禁用的选题、PPT、讲稿完整流程。
- 尚未发送后端的会议自动录制、引导评分等设置。
- 被试用版禁用的 AI 报告 PDF。
- 仅保存在本机的课程笔记云协作。
- 考试页中的硬编码分析值。

这些能力可以作为明确标记的未来状态或受限入口，不能表现成已完成业务。

## 10. 视觉系统

视觉方向：克制、温暖、专业、可信。保留参考图的轻盈空间、圆角表面和深色悬浮控制条，但用 OREP 橙色建立品牌识别。

### 10.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#F5F1EC` | 页面背景 |
| `--surface` | `#FFFEFC` | 主表面 |
| `--surface-muted` | `#F0EBE6` | 次级表面 |
| `--ink` | `#171719` | 主文字 |
| `--muted` | `#5F6269` | 次级文字 |
| `--line` | `#E4DDD6` | 分隔与边框 |
| `--orange` | `#E84A1C` | 主品牌与主操作 |
| `--orange-deep` | `#B93612` | 按下与高对比状态 |
| `--orange-soft` | `#FFF0E9` | 轻提示与选中背景 |
| `--success` | `#207A55` | 完成 |
| `--warning` | `#A96512` | 待处理 |
| `--danger` | `#C43F35` | 风险 |
| `--island` | `#171715` | 悬浮快捷栏 |

橙色占页面视觉面积约 8%–12%，只用于当前状态、关键数字和主动作。

### 10.2 字体

- 页面标题：32–36px，移动端 26px。
- 区块标题：20–22px。
- 卡片标题：16px。
- 正文：14px。
- 辅助文字：12–13px。
- 禁止出现小于 12px 的界面文字。
- 中文标题字距控制在 `0` 到 `-0.01em`。

### 10.3 表面与圆角

- 控件圆角：12px。
- 卡片圆角：16px。
- 首要行动或特殊主表面：24px。
- 胶囊只用于状态、筛选和悬浮快捷栏。
- 阴影只保留普通浮层与快捷栏两个等级。
- 卡片最多一层，行项目优先使用分隔线而不是“卡片套卡片”。

### 10.4 图标

- 使用统一的线性 SVG 图标。
- 不混用字符箭头、Emoji、字母缩写和不同描边体系。
- 图标只辅助识别，不替代清晰文字。

## 11. 动效与反馈

- 页面内容切换：140–180ms 淡入。
- 列表选中与详情切换：160–200ms。
- 抽屉与弹窗：220–260ms。
- 进度和评分绘入：420–600ms。
- 快捷栏不伸缩，不做弹跳或夸张位移。
- 每页最多一个持续环境动效。
- 支持 `prefers-reduced-motion`，减少动效时取消位移、自动播放与持续动画。
- 保存使用局部状态反馈；提交、审核和状态迁移必须同步更新相关页面。

## 12. 响应式

### 桌面 `>= 1280px`

- 完整一级侧栏、悬浮快捷栏和两列/任务三段式布局。
- 1440×900 首屏完整展示首页首要行动与今日安排。

### 平板 `768–1279px`

- 一级导航缩为图标栏。
- 任务详情的协作区转为抽屉。
- 快捷栏宽度跟随内容区，但仍保持固定高度。

### 手机 `< 768px`

- 一级导航转为五项底部导航。
- 快捷栏转为底部主行动条，并与底部导航错层显示。
- 首页顺序固定为：项目状态 → 首要行动 → 今日安排 → 最近反馈。
- 列表与详情拆成两个视图，不纵向堆叠三栏。
- 弹窗优先使用全屏工作面。

## 13. 首轮原型交互

首轮必须真实同步以下状态：

1. 学生打开任务并上传或填写交付物。
2. 学生提交后，任务进入“待审核”，首页主动作改为等待状态。
3. 切换教师视角后，审核队列出现该提交。
4. 教师结构化退回后，学生任务进入“需修改”，并显示问题与期望结果。
5. 学生返修再次提交。
6. 教师通过后，任务进入“已完成”，队列和首页同步更新。
7. 评分问题可以生成整改任务，并立即进入任务工作台。
8. 学习计划可以完成一个课时或训练，掌握度和关联任务同步更新。

角色切换只用于原型演示；正式产品只能切换账号已被授予的身份和项目关系。

## 14. 验收标准

### 产品

- 每页只有一个明确主行动。
- 关键工作最多两次点击进入。
- 学生、队长和教师看到同一业务事实。
- 所有等待状态说明“正在等待谁”和“下一步何时可做”。
- 权限受限动作显示原因，不只隐藏入口。
- 三级页持续保留项目或对象上下文。

### 视觉

- 1440×900 首屏不出现卡片墙和大面积无意义留白。
- 页面标题、正文、状态和动作形成稳定层级。
- 全站不出现小于 12px 的文字。
- 橙色只用于品牌与关键动作，不大面积铺色。
- 不出现同名主动作重复。
- 六个核心页面使用同一组 Token、组件和间距规则。

### 交互

- 前进、后退和深链可用。
- 筛选、当前任务、当前项目与角色上下文可恢复。
- 提交、审核、整改和学习进度跨页面同步。
- 弹窗、菜单和抽屉支持键盘与焦点管理。
- 触控目标不小于 44×44px。
- 支持减少动效。

### 技术

- V2 代码独立于旧原型的样式补丁。
- 业务数据、视图和交互状态分层。
- 禁止继续在旧的 5,100 行样式文件后追加覆盖。
- 核心链路具备自动化浏览器测试。
