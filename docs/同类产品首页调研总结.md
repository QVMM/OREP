# 同类 / 近类产品「登录后首页」调研总结

> **目的**：回答「为什么我们现在的分屏舞台还不像一个产品首页」，以及同类产品用什么理念做首页。  
> **范围**：登录后的 **App/Web 主入口（Home）**，不是官网营销页。  
> **方法**：公开文档、产品站、支持中心、设计复盘与常见使用描述；国内双创备赛评分工具几乎无成熟对标，故以 **练→评→改→再练** 闭环近类为主。  
> **日期**：2026-07-10

---

## 0. 先给结论：你感觉「不像产品首页」通常卡在哪

调研后共性很清楚——**像产品首页的，几乎都不是「信息展览」**，而是：

| 共性 | 一句话 |
|------|--------|
| **1. 主动词唯一** | 首页先让你 **开始/继续一件事**，不是先让你读懂整站 |
| **2. 结果贴在任务上** | 分数/反馈是 **某一次练习的产物**，很少单独做成「指挥台 KPI 墙」当主叙事 |
| **3. 下一动比全貌重要** | 给「下一步」，不全量功能入口 |
| **4. 风格服务闭环** | 教练产品偏干净、大主按钮；数据产品偏列表/图表——**风格跟着任务走** |
| **5. 壳很克制** | 侧栏/底栏管导航；**主区不重复导航职责** |

我们当前分屏舞台更像 **「左右两块说明面板」**：左右都有字、都有行动，信息量全，但 **「这是打开 App 后必须完成的那一下」不够硬**——所以会像杂志/报表，而不像「每天打开就练」的产品。

## 1. 样本池（近类优先）

### 1.1 强近类：说话 / 路演 / 反馈闭环

| 产品 | 闭环 | 首页像什么 |
|------|------|------------|
| **Yoodli** | 选场景 → 开口练 → 看分析报告 → 再练 | **Practice 入口** + 练习库；反馈在「练完之后」；另有 Dashboard 看趋势（偏二级） |
| **Orai** | 每日小场景 → 即时打分 → 给一条 next tip | **今日练习 + 分数卡 + 连续天**；「Try this next」极短 |
| **Grammarly Editor** | 打开文档 → 边写边改 → Overall score | 登录先进 **文档列表/新建**；分数贴在 **文档编辑态**，不是独立大看板 |

### 1.2 强近类：闯关 / 备考

| 产品 | 闭环 | 首页像什么 |
|------|------|------------|
| **Duolingo** | 沿路径上课 → 完成关卡 → 连胜 | 首页 = **路径**；当前关唯一高亮；任务/练习进 Tab |
| **LeetCode** | 选题 → 提交 → 通过 | 更像 **题库/探索**，进度在 Profile；**不是 KPI 指挥台当唯一 home** |
| **Khan / Coursera** | 继续课程 → 完成模块 | **Continue learning** + 进行中课程卡；进度条服务「接着学」 |

### 1.3 教练 vs 数据（对照用）

| 产品 | 首页理念 |
|------|----------|
| **Nike Training / Run Club** | **今天练什么 / 开跑**；教练感、主 CTA 极大 |
| **Strava** | **Feed + 数据 + 社群**；记录与比较，不是「今天只练一项」 |

### 1.4 习惯/今日一条（气质参考）

| 产品 | 首页理念 |
|------|----------|
| **Headspace / Calm** | **Today / 今日推荐** 一条主内容 + 大播放；库在二级 |

### 1.5 国内语境

双创备赛线下流程普遍是：**模拟路演 → 评委打分/点评 → 改稿 → 再模拟**。  
几乎没有「评分大脑」成熟消费级首页可抄，但 **用户心智更接近 Orai/Yoodli/Duolingo 的闭环**，而不是 Stripe/Linear 商户后台。

## 2. 逐产品：约束 · 信息 · 形式

### 2.1 Duolingo（路径型首页的教科书）

| 维度 | 内容 |
|------|------|
| **设计约束** | 必须让用户知道「正确用法」= 沿路径走；减少自由跳技能树带来的选择焦虑；娱乐化但不抢主任务 |
| **页面信息** | 当前单元名、关卡节点状态（完成/当前/锁定）、开始当前课、连胜/生命等轻状态；任务/练习/商店进底栏 |
| **呈现形式** | **竖向路径节点** + 当前关大按钮；非 KPI 卡片墙；角色作情绪装饰 |
| **理念一句话** | 首页是 **课程本身**，不是关于课程的说明 |

### 2.2 Orai（说话教练 · 与竞赛大脑最近）

| 维度 | 内容 |
|------|------|
| **设计约束** | 几分钟可完成；即时、无评判感；每天一点即可 |
| **页面信息** | 今日练习主题、关键指标（filler / pace / clarity）、连胜、周进步；**一条「下次试这个」** |
| **呈现形式** | **今日卡 + 分数卡 + 短建议**；主 CTA = 开始今日练习 |
| **理念一句话** | 首页 = **今日一练 + 上一练结果摘要**，不是功能目录 |

### 2.3 Yoodli（路演/角色扮演教练）

| 维度 | 内容 |
|------|------|
| **设计约束** | 像运动员训练：大量重复 + 看回放；企业侧还要认证/报告 |
| **页面信息** | 练什么（场景库）、开始练、练完报告（内容/表达指标）、进度趋势（Dashboard 常为独立视图） |
| **呈现形式** | 导航进 **Practice**；结果页/报告页承担「分数叙事」；首页少「长文案展览」 |
| **理念一句话** | **入口是 Practice，价值在 Results**——首页不背全部叙事 |

### 2.4 Grammarly（文档 + 分数贴对象）

| 维度 | 内容 |
|------|------|
| **设计约束** | 分数服务写作对象；登录后先能干活 |
| **页面信息** | 文档列表、新建/上传；进文档后才是 Overall score + 建议列表 |
| **呈现形式** | **列表/工作台 → 对象内评分**；分数不脱离文档单独当首页主角 |
| **理念一句话** | 分数是 **文档属性**，不是全站 KPI 墙 |

### 2.5 Coursera / Khan（继续学习）

| 维度 | 内容 |
|------|------|
| **设计约束** | 降低「找回上次学到哪」的成本 |
| **页面信息** | 进行中课程、进度条、下一讲/作业、Continue |
| **呈现形式** | **横向/纵向课程卡 + 进度 + Continue 按钮**；发现课在 Explore |
| **理念一句话** | 首页 = **接着学**，发现是另一条导航 |

### 2.6 Nike Training / Run Club vs Strava

| 维度 | Nike（教练） | Strava（数据/社群） |
|------|--------------|---------------------|
| **约束** | 感觉、坚持、今日可完成 | 轨迹、比较、Feed |
| **信息** | 今日推荐训练/开跑、计划 | 动态流、配速、段排名 |
| **形式** | 大封面/大 CTA「开始」 | 列表 Feed + 数据模块 |
| **对 OREP** | 更贴近「打磨」 | 更贴近「备赛动态墙」（可辅不可主） |

### 2.7 Headspace / Calm

| 维度 | 内容 |
|------|------|
| **约束** | 低摩擦；今日一条；氛围统一 |
| **信息** | 今日推荐、时长、开始；库在 Library |
| **形式** | 大主卡片/大播放钮；极简层级 |
| **对 OREP** | 可学「今日一条」的极简，但竞赛场景需要 **上一场分数** 作依据 |

## 3. 横切统计：设计风格约束（共性）

| # | 约束 | 出现频率 | 说明 |
|---|------|----------|------|
| 1 | **一个主 CTA**（开始/继续/练习） | 极高 | 教练/学习类几乎必有 |
| 2 | **主区不重复全站导航** | 极高 | 功能进侧栏/底栏 |
| 3 | **结果与任务绑定** | 高 | 报告/分数跟 session 或文档 |
| 4 | **下一动优先于全貌** | 高 | Duolingo 甚至去掉「自己选最优用法」 |
| 5 | **情绪/品牌装饰服从任务** | 中高 | 吉祥物/插画不抢 CTA |
| 6 | **数据可二级** | 中高 | 趋势 Dashboard 常不是 Home 唯一形态 |
| 7 | **视觉：干净、大按钮、少线框噪声** | 高 | 消费级教练；企业后台才密 KPI |
| 8 | **进度可感知但轻** | 高 | 条/连胜/完成态，不做 8 个同权指标 |

**我们容易违反的**：在同一首屏同时做「成绩单 + 引擎说明 + 项目台 + 训练入口 + 左右双行动」→ 像门户，不像产品。

## 4. 横切统计：首页上通常有什么信息

按「是否出现在 Home 首屏」粗分：

### 4.1 几乎总在首屏（近类共识）

| 信息 | 形式 |
|------|------|
| **现在该做什么** | 大按钮：继续 / 开始今日练习 / 开一场 |
| **进行中的对象** | 当前课/当前路径节点/今日场景名 |
| **轻进度** | 连胜、进度条、完成勾选 |
| **（教练类）最近结果摘要** | 一两个关键分 + 一句建议（Orai） |

### 4.2 常有，但形态克制

| 信息 | 形式 |
|------|------|
| 历史练习 | 列表缩略，点进报告 |
| 多指标 | **练完结果页**展开，Home 只留 2～4 个 |
| 激励 | 连胜、周进步 % |

### 4.3 很少当 Home 主角（或放二级）

| 信息 | 常见位置 |
|------|----------|
| 产品能力说明（「我们能做什么」） | Onboarding / 空状态 / 帮助，**不是每日 Home** |
| 全站功能平铺 | 导航，不是主区 |
| 完整项目协作台 | Project 页 |
| 完整分析看板 | Analytics / Dashboard Tab |

**对照 OREP 现状信息包**：本场分、读后感、下一刀、评委差、五维、引擎能力、项目、事项、训练——**同类几乎不会全部堆在 Home 首屏**；通常拆成：

- Home：对象 + 结果摘要 + 下一动 + 主 CTA  
- 总结/报告：五维与依据  
- 项目：协作与材料  
- 训练：课/会

## 5. 横切统计：信息以什么形式体现

| 形式 | 谁在用 | 承载什么 | 是否「像产品」 |
|------|--------|----------|----------------|
| **路径/节点** | Duolingo | 进度与当前关 | 极强（任务=页面） |
| **今日任务卡 + 大 CTA** | Orai、Nike、Headspace | 今天练什么 | 极强 |
| **Continue 课程卡** | Coursera、Khan | 接着学 | 强 |
| **练习库 + 开始** | Yoodli | 选场景开练 | 强 |
| **对象列表（文档/题）** | Grammarly、LeetCode | 打开对象干活 | 强（工作台感） |
| **结果报告页** | Yoodli、Orai 练后 | 分数与建议 | 强（但是二级） |
| **Feed** | Strava | 动态 | 强（但另一类产品） |
| **左右分屏叙事+分** | 少见作消费级 Home | 说明感重 | 易像「介绍页/报表」 |
| **多 KPI 卡片墙** | 企业后台 | 监控 | 像 B 端后台，不像教练 |

**关键洞察**：  
「分屏舞台」在 **结果页/报告页** 很常见（左文案右分数），但在 **每日 Home** 上，近类更常是：

> **上：主任务/继续 · 中：最近一场摘要 · 下：轻入口**  
> 或  
> **整页路径 + 底栏导航**

## 6. 四类「首页产品理念」归类（供选型）

| 理念 | 代表 | Home 回答的问题 | 适合 OREP？ |
|------|------|-----------------|-------------|
| **A. 继续任务** | Coursera、Khan | 接着学哪门？ | 中（若项目=课程） |
| **B. 今日一练** | Orai、Nike、Headspace | 今天练什么？ | 高（教练感） |
| **C. 路径闯关** | Duolingo | 下一关是什么？ | 高（备赛闭环） |
| **D. 打开对象** | Grammarly、题库 | 打开哪份稿/哪场？ | 高（本场/最近一场） |
| **E. 数据/社群** | Strava | 发生了什么？ | 低作主，可辅 |
| **F. 功能门户** | 能力墙 | 有什么功能？ | **低**（销售页不是 Home） |

当前分屏更接近 **「报告页布局放在了 Home」**（D 的结果形态 + 说明文案），缺少 B/C 的 **「打开就干」产品感**。

## 7. 对竞赛大脑的启示（可执行，仍不直接改代码）

### 7.1 若要「像产品首页」

优先满足这 5 条（来自统计，不是审美口号）：

1. **首屏 3 秒只回答一个问题**  
   例：「继续改这一刀 / 打开最近一场 / 开始一场评分」三选一做主，不要三个同权。  
2. **主 CTA 唯一且像按钮**（大、实心、固定位置）。  
3. **分数=某场的属性**，带场次时间/标题；不是悬浮 KPI。  
4. **能力说明、项目、训练** 默认不进首屏主叙事（导航或「更多」）。  
5. **风格统一成「教练工作台」**：干净、任务卡/对象卡、少分屏说明文。

### 7.2 三种更「像产品」的 Home 信息架构（只定 IA，不定皮肤）

| 方案 | 首屏结构 | 像谁 |
|------|----------|------|
| **H1 最近一场工作台** | 场次标题 + 本场分 + 一句判断 +【打开总结】【再练】；下一刀一条 | Grammarly 对象感 + Orai 摘要 |
| **H2 今日备赛** | 今日任务（来自下一刀）+ 依据（本场分旁证）+ 开始 | Nike / Orai |
| **H3 备赛路径** | 交稿→出分→总结→改→复测节点 + 当前关 CTA | Duolingo |

分屏舞台可作为 **H1 的一种视觉变体**，但需改成：  
**右=对象（场+分+主按钮）硬焦点；左只服务该对象的「下一步」**，而不是左右各讲一套故事。

### 7.3 明确不建议当每日 Home 主层

- 「引擎能做什么」四格说明  
- 与主 CTA 同权的多入口  
- 五维完整条形图（更适合总结页）  
- 项目/课/考/练完整工作台  

---

## 8. 建议的下一步（仍走原型）

1. 你先选 **H1 / H2 / H3** 哪一种「首页问题」最想产品化。  
2. 再出 **1～2 个高保真原型**（只表达该 IA，不落 Dashboard）。  
3. 确认后再进代码。
