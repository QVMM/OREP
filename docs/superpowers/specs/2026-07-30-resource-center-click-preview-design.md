# 资源中心点击预览与只读状态设计

## 目标

将资源中心文件预览从悬停触发改为明确的点击触发，并消除公共资源操作栏中“只读”伪按钮造成的误解。

## 当前问题

- 鼠标经过文件行会在 `150ms` 后加载预览，容易在浏览目录时频繁切换和发起无意加载。
- 预览栏文案强调“悬停切换”，与用户希望主动点击查看的操作方式不一致。
- 公共资源操作栏中的“只读”外观接近禁用按钮，但它并不是可执行操作。

## 交互设计

### 文件预览

1. 单击文件行，将该文件设为当前文件并在右侧预览。
2. 单击其他文件行，切换右侧预览。
3. 双击文件行或点击预览栏“展开”，进入沉浸式预览。
4. 文件行获得焦点时不自动加载预览。
5. 键盘 `Enter` 或 `Space` 等同于单击，选择文件并在右侧预览。
6. 已选择文件按 `Enter` 时仍保持行内预览，不因重复按键意外展开。
7. 下载、移动下拉框等行内操作继续阻止事件冒泡，不触发预览切换。

### 只读状态

1. 公共文件操作栏仅保留“下载”，删除“只读”伪按钮。
2. 文件名称下方继续显示“公共只读”，用于解释权限状态。
3. 公共资源文件夹继续显示“公共只读”属性。
4. 只读含义保持不变：可以预览和下载，不能移动、重命名或删除。

### 引导文案

- 预览栏有文件时显示“点击文件切换预览”。
- 空预览状态改为“点击文件即可在这里预览 PDF、Word、Excel、PPT、图片和音视频”。
- 键盘提示改为“支持 Enter 或 Space 预览，双击展开”。

## 实现边界

- 移除 `hoveredFile`、悬停定时器及相关调度函数。
- `previewFile` 仅由 `selectedFile` 决定。
- 保留现有沉浸式预览、下载、移动、拖放和真实文件渲染逻辑。
- 不修改后端接口或文件权限模型。

## 验收标准

- 悬停或单纯聚焦文件行不会加载或切换预览。
- 单击、Enter、Space 均能在右侧显示所选文件。
- 双击和“展开”按钮能打开沉浸式预览。
- 公共资源操作栏不再出现“只读”按钮，仅显示下载操作。
- 页面仍清楚说明公共资源为只读。
- 前端契约测试、完整测试和生产构建通过。

## 范围外

- 不增加批量选择。
- 不改变文件夹悬浮展开动画。
- 不改变公共资源的权限配置。
