# 已有 PPT 全链条（怎么交来、怎么认、怎么改、怎么还）

> 日期：2026-08-18  
> 状态：补上主规格里被写轻的右门  
> 主规格：`2026-08-18-judge-path-roadshow-design.md`  
> 界面：`docs/superpowers/mocks/judge-path-hifi/index.html`  
> 本篇只解决一件事：**用户手里已经有一份 PPT，从交到还，中间每一步用什么、做不到什么、失败怎么办。**

上一版把「抽文字 / 改不了就换页 / 导出用图」一笔带过，这不够。右门不是 MVP 附件，是和左门同等的主路径。

---

## 0. 先把三句假话拿掉

1. **不能 100% 识别。** 谁说能 100% 读懂每一页在讲什么，就是在糊弄。系统保证的是：原生文字框里的字能原样抽出；页和「这场要讲的事」对不上时必须人点一下；读不全的页必须标出来，不许装懂。  
2. **不能用 Collabora 当 AI 改稿容器。** 启发 Office 的 Collabora 没有「改第 6 页第 2 个文本框」的稳定接口。人决赛前自己拖排版可以进 Collabora。AI 不进 iframe 改。  
3. **不能把整页做成图片再塞回 pptx 交给用户。** 那不是标准 PPT。WPS / PowerPoint 里不能改字，评委要的也不是一叠图。新页、换页、改字，交出去都必须是可选题、可改字的 OOXML。

## 1. 用户怎么把 PPT 给你

四个来源，一个收口。收口之后都变成同一份 `legacy_deck`。

### 1.1 来源

| 来源 | 用户怎么做 | 系统怎么拿文件 |
|---|---|---|
| 项目里已经有 | 右门列出：启发 Office 演示、资源中心 PPT、团队文件、上次路演绑过的稿 | 走已有 `storage_path` / `file_key`，不让人再传一遍 |
| 本机文件 | 拖进右门，或点选 | 上传到启发 Office（团队范围），再纳入 `legacy_deck` |
| 别人发来的 | 微信 / 网盘先存到电脑，再拖。我们不接微信、不接网盘账号 | 同上 |
| 只有 PDF | 可以分析（当片子看），**不能按原件改字还回去** | 另存分析副本；交付只能是「按这场提纲新做的 pptx」，并说清楚原 PDF 没被改 |

同时有多份：列出文件名、页数、更新时间、谁传的。默认勾最新一份。用户可换。不允许静默拿错文件。

### 1.2 收什么、拒什么

收：`.pptx`（主）、`.ppt`（先转成 pptx 再干）、`.odp`（先转）。

拒，并说人话：

| 情况 | 对用户说 | 系统做 |
|---|---|---|
| 带密码 | 这份加了密码，解开再传 | 不收 |
| 损坏 / 不是 zip 包 | 文件打不开 | 不收 |
| 大于 80MB 或超过 80 页 | 太大了，先删附录再传，或拆开 | 不收 |
| `.key` / 在线链接 | 请另存为 pptx | 不收 |
| 宏 / `.pptm` | 宏会去掉，只留页面 | 转成无宏 pptx，告知 |
| 转换 `.ppt` 失败 | 请用 WPS 另存为 pptx 再传 | 停在这一步 |

转换用服务器上的 LibreOffice 无头。转换后的 pptx 当工作副本。原 `.ppt` 原样存档，不覆盖。

### 1.3 原件保护

收到后立刻：

1. 算 sha256，落 `legacy_deck.original_hash`  
2. 原件只读存档  
3. 所有改动打在**副本**上  
4. 没有用户确认，不覆盖启发 Office 里的原文档

## 2. 你怎么分析

分析是结构读取 + 预览图，不是「看懂设计」。

### 2.1 步骤（必须按这个顺序）

1. **归一**：`.ppt` / `.odp` → pptx 工作副本。  
2. **拆包**：用 OOXML（python-pptx 或等价）读每页。  
3. **抽结构**：每个形状记下 `shapeId`、类型（文本框 / 表格 / 图 / 组合 / 图示 / 图表）、文字、字号、框的位置大小、是否在母版。演讲者备注单独存。  
4. **出预览图**：每页一张 PNG，只给人看，不当交付。用 LibreOffice 渲页；失败则用形状粗绘，并标「预览不准」。  
5. **定阅读档**：见 2.2。  
6. **对齐提纲**：见第 4 节。  
7. **出改稿清单**：改字 / 换这一页 / 拿掉 / 补一页 / 不动。每一条带阅读档和把握。

整份分析目标：28 页 < 20 秒出列表；预览图可后到，先出文字。

### 2.2 每一页的阅读档（不是 100%，是分档）

| 档 | 什么情况 | 能抽出什么 | 能不能改字 |
|---|---|---|---|
| 能改字 | 标题、正文在真实文本框里 | 字和框的位置 | 能。按原框改 |
| 只能部分改 | 有文本框，也有组合、图示、SmartArt、图表标题 | 普通文本框里的字 | 只能改普通框；图示里的字标「改不了」 |
| 读不全 | 整页是一张导出图、扫描件、照片墙 | OCR 顶多猜，默认不做 | 不能改原字。只能换页或不动 |
| 空页 / 失败 | 没形状，或这页 XML 坏了 | 无 | 只能拿掉或换页 |

**默认不做 OCR。** OCR 不是 100%，还容易把图上的装饰字读进来。读不全的页让人看预览，自己选：换掉 / 不动 / 拿掉。

### 2.3 什么叫「识别」——必须拆开，不许混

| 识别什么 | 能否接近 100% | 实际保证 |
|---|---|---|
| 文件是不是这份 pptx | 能 | hash |
| 有几页、每页有哪些文本框、框里写了什么 | 原生框能 | 按 OOXML 原样抽出，抽到的和 WPS 里选中看到的一致 |
| 这页在讲什么（意思） | 不能 | 用抽出的字去对讲稿和这场要讲的事，给出建议，**人确认** |
| 图里的字、艺术字、拆散的字 | 不能 | 标读不全，不装懂 |
| 评委看了会不会信 | 不能 | 那是提纲和评分的事，不是读文件的事 |

所以产品上禁止出现「已智能识别全部内容」。改成：「28 页里，22 页能改字，4 页是图读不全，2 页是空的。」

## 3. 识别过后该怎么做

先有「这场要讲清的几件事」（左门同一条提纲）。没有提纲，不许改旧 PPT。

然后每一页对上至多一件要讲的事。

| 对上的结果 | 建议动作 | 人对用户说 |
|---|---|---|
| 字对得上，原框塞得下新字 | **改字** | 只改这页上的字，样子不变 |
| 字对得上，但原页是清单/模块墙，要讲的是一个数 | **换这一页** | 改几个字不够，要换成另一张 |
| 这页和任何要讲的事都对不上 | **拿掉** 或挪到最后「不讲的页」 | 台上翻到这里会断 |
| 有要讲的事，旧稿没有对应页 | **补一页** | 在第 N 页后面加一页 |
| 页上出现这场说好不写的词（假金额、姓名） | **改字删掉** 或拿掉 | 这场不要写这个 |
| 读不全 | 人看图选：换掉 / 不动 / 拿掉 | 这页基本是图，我改不了上面的字 |
| 把握不够 | 停住问人 | 吃不准这页是不是在讲损耗，请点一下 |

「塞得下」：新字数 ≤ 原框可见字数 × 1.1，且行数 ≤ 原行数。否则不能走改字。

把握不够的规则（必须问人）：

- 一页对上两件要讲的事，分差 < 20%  
- 抽出的字少于 8 个汉字  
- 阅读档是「读不全」或「只能部分改」  
- 要改的框找不到原文（别人中途改过文件）

问的时候把预览图、抽出的字、建议动作摊开。不许后台猜完就改。

## 4. 用什么容器改

### 4.1 唯一的 AI 改稿容器

**服务端对 pptx 工作副本做 OOXML 手术。**  
实现可以是 python-pptx，或直接改 `ppt/slides/slideN.xml`。  
这是唯一写回文件的地方。

不是：

- Collabora / WOPI  
- 学生端画布随便拖  
- 整页截图贴回去  
- 启发 Office 里模拟键盘  

### 4.2 五种动作怎么落到文件上

**改字**

1. 用分析时记下的 `shapeId` + 原文定位文本框。  
2. 原文对不上（人中途改过）：这页升成「吃不准」，停止改，问人。  
3. 原文对得上：换文字，尽量保留原 run 的字体、字号、颜色。字变长就还在原框里换行，不改框大小，不改别的形状。  
4. 一页只动清单里写明的那些框。

**换这一页**

1. 记下原页尺寸（16:9 或 4:3），新页必须同尺寸。  
2. 删掉该 index 的旧页。  
3. 按页型用**真实形状**插入新页：标题框、数字框、一句框、图，不是一张图。  
4. 颜色只取原稿三色：底、标题、强调。字号走页型。  
5. 标「换过」。人和前后页并排会看出来。这个要在确认卡上写明。

**拿掉**

默认移到文稿末尾一节「这次不讲」，不物理删除。人也可以选「真删」。默认可找回。

**补一页**

在指定页后插入一页真实形状的页型页。标「新加」。

**不动**

工作副本里该页字节级保持（至少 XML 等价）。验收时 hash 或规范化 XML 对比。

### 4.3 Collabora 放哪

交付之后，用户在启发 Office 打开**新版本**，自己微调。  
AI 不通过 WOPI PutFile 改。  
人在 Collabora 里改完，那是人的版本，和下一次「按提纲再改」是两回事：再改必须基于最新人存的版本重新分析，不能拿旧工作副本覆盖人的修改。

### 4.4 路演台中栏

对照和确认用。中栏是预览 +「这页只写这些」。  
**中栏改字如果发生，先写回提纲上的「这页只写」，再走 4.2 打进 pptx。** 中栏不是文件容器。

## 5. 改的是否标准

标准交付的定义（验收就按这个）：

1. 扩展名 `.pptx`，是合法 OOXML，能被 PowerPoint、WPS、启发 Office（Collabora）打开。  
2. 改过的字是文本，能选中、能继续改，不是图片。  
3. 没动过的页，打开后和原件看起来一样，文字仍能改。  
4. 幻灯片尺寸和原件一致。  
5. 字体：优先保留原字体；服务器没有的字体，回退到「微软雅黑 / 思源黑体」，并在交付说明里写「有 3 页字体换成了某某」。禁止乱码方框。  
6. 不带宏。不改母版主题名，除非换页时写了要换。  
7. 原件 hash 仍在，随时可对照。

不标准、禁止当交付：

- 每页一张图的 pptx  
- PDF 改后缀  
- 只有链接、打开还要联网的文件  

左门新做的那套，同样遵守这一条。上一版写「先导出 PNG 再打进 pptx」**作废**。新页也用真实形状拼。预览可以用 PNG，下载不行。

## 6. 怎么给用户

做完后同时给三样，缺一不可：

1. **启发 Office 里的新版本**  
   名称：`原文件名 · 路演改过`。原文件还在，多一个版本记录（已有 versions API）。  
   默认不替换原文件。用户可点「用这个当现在用的稿」。  

2. **下载 pptx**  
   就是这份新版本的字节。  

3. **改了什么的清单**  
   第 6 页：模块介绍 → 损耗 23%（换过）  
   第 12 页：18% 改成 9%（只改字）  
   第 18 页：拿掉（这次不讲）  
   补了：实操五步  

清单上每条能点回预览。人可以「撤回第 6 页」（从副本再打一遍，或从修订记录回退该页）。

团队：谁点的确认，记在版本备注。本期仍按讲稿同样的人：能改这份 Office 文档的人。

## 7. 失败和边角（必须都能走下去）

| 情况 | 系统 | 对人说 |
|---|---|---|
| 分析到一半崩溃 | 已出的页保留，可续 | 看到第 11 页停了，点继续 |
| 工作副本写到一半失败 | 丢掉副本，原件不动 | 没改成功，原件还在 |
| 改字时原文对不上 | 这页跳过，其余继续 | 第 6 页你中途改过，我没动它 |
| 转换 .ppt 版式跑了 | 分析仍做，交付前警告 | 从旧版 ppt 转过来的，个别页可能歪，建议用 WPS 另存 pptx 再来一次 |
| 16:9 和 4:3 混在同一份（极少） | 按每页自己的尺寸插页 | — |
| 人在 Collabora 正开着原件 | 仍只写新版本，不抢原件锁 | 原件你开着没关系，改动在新文件里 |
| 没有讲稿也没有八句 | 不分析改稿 | 先写这场要讲什么，或先写八句 |
| 只有 PPT 没有评分 | 仍可按讲稿改，不装覆盖了评分 | 没用评分，只按讲稿看对不对得上嘴 |
| 两个人同时点「做成 PPT」 | 第二个 409 | 队友正在出，稍等或打开他那一版 |

## 8. 数据

`legacy_deck`：

- id, team_id, source（office / resource / upload / convert）  
- original_document_id, original_hash, original_ext  
- work_pptx_path, work_hash  
- page_count, slide_size  
- status: received / analyzing / analyzed / applying / applied / failed  
- analysis_json（每页：preview、shapes、grade、match、action、confidence）  
- output_document_id（新版本）  

`legacy_deck_page` 可拆表，便于按页重试。

分析、应用都写进度。应用按页提交，一页失败不影响已成功的页（已成功的在工作副本里，输出仍等到整份结束或人点「先交出已改的」）。

## 9. 接口（右门）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/roadshow/legacy/candidates` | 项目里能选的 PPT 列表 |
| POST | `/api/roadshow/legacy/ingest` | `{documentId}` 或上传文件 |
| GET | `/api/roadshow/legacy/{id}` | 状态 + 每页阅读档 |
| POST | `/api/roadshow/legacy/{id}/analyze` | 依赖已确认的 `judge_path` |
| POST | `/api/roadshow/legacy/{id}/resolve` | 人点：这页是改字/换/拿掉/不动 |
| POST | `/api/roadshow/legacy/{id}/apply` | 打进工作副本，出新版本 |
| GET | `/api/roadshow/legacy/{id}/diff` | 改了哪些页 |
| POST | `/api/roadshow/legacy/{id}/revert-page` | 撤回一页 |

确认仍走小启卡。不确认不打进文件。

## 10. 和主规格怎么接

- 右门点下去：先选/交 PPT（本章 1）→ 分析出阅读档（本章 2）→ 若还没有提纲，先走「这场怎么讲」→ 对齐（本章 3）→ 确认后 apply（本章 4）→ 交付（本章 6）。  
- 主规格第 5.4「PNG 打进 PPTX」作废，左右门交付都改走真实形状。  
- 主规格第 6 节整节以本文为准。  
- Collabora 仍是人用的 Office，不是 AI 改稿引擎。  
- C 期验收加上：原件 hash 不变；下载的 pptx 能在 WPS 里改字；未动页可继续编辑。

## 11. 对人说的词（不要内部词）

| 内部 | 界面 |
|---|---|
| ingest | 用这份 PPT / 把文件拖进来 |
| parse grade native | 能改字 |
| parse grade picture | 这页是图，改不了字 |
| apply L1 | 只改这页上的字 |
| apply L2 | 换成另一张 |
| output version | 新文件已放进文档库，原件还在 |

禁止：令牌、OOXML、WOPI、阅读档（对用户说「能改字 / 改不了字」即可）。
