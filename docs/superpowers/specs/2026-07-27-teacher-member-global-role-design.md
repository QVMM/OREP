# 教师端成员全局角色联动设计

## 目标

教师端的团队成员管理以 `users.role` 为唯一身份来源。教师在任何团队中都保持教师身份，学生也保持学生身份；团队内角色只表达团队关系，不再另造一套互相冲突的身份。

## 角色规则

- `users.role = TEACHER`：加入团队时自动设置 `project_team_member.role_in_team = MENTOR`。
- `users.role = STUDENT`：加入团队时自动设置 `project_team_member.role_in_team = MEMBER`。
- 团队队长必须保持学生身份，团队角色为 `CAPTAIN`。
- `ADMIN` 和 `SCHOOL_ADMIN` 不通过团队成员管理加入普通团队，也不能在此入口改成学生或教师。
- 教师端允许手动把普通成员的全局角色在 `STUDENT` 与 `TEACHER` 间切换。
- 手动切换会同步 `users.role` 和团队内角色；新权限在该成员下次登录后生效，因为登录令牌包含全局角色。
- 主指导教师降级为学生前，必须先有另一位指导教师可接替；否则拒绝操作。
- 普通教师加入后，如果团队尚无主指导教师，则自动设为主指导教师。

## 界面

- 候选成员显示系统识别到的全局身份。
- 每位候选成员可保持“自动识别”，也可手动选择“学生”或“教师”。
- 已加入成员列表增加“系统角色”选择框，并继续保留“团队角色”和“岗位”。
- 队长的系统角色不可直接切换。
- 成功修改角色后提示“该成员重新登录后权限生效”。

## 安全边界

- 所有身份变更仍经过租户、学校和学院范围校验。
- 只有该团队指导教师、管理员或具备成员管理权限的队长能执行成员管理；全局角色变更进一步限制为教师或管理员操作。
- 服务端不信任前端传入的团队角色，而是根据最终全局角色推导。
