# 上传评分页精简与持久任务队列设计

日期：2026-07-30  
状态：已确认方向，待书面审阅  
范围：用户端上传评分页、上传评分任务查询接口与相关测试

## 1. 背景

当前 `/ai-score-upload` 同时展示上传表单、当前状态、处理流程、上传进度、评分会话和分析进度，多处信息重复，页面视觉重心分散。用户完成上传后，页面仅把新建评分会话保存在 `VideoScoreUpload.vue` 的组件内存中；刷新页面或重新登录后，前端不会重新读取该用户的上传评分会话，因此正在分析的任务从页面消失。

评分会话和分析进度已经持久化在 `ai_scoring_session`，视频文件信息已经持久化在 `ai_score_media_asset`。根因不是后台任务丢失，而是缺少“当前用户上传评分任务列表”接口，以及上传页没有恢复、轮询和展示该队列的逻辑。

## 2. 目标

1. 将页面重构为“紧凑上传区 + 全宽持久任务队列”。
2. 清除重复状态卡、处理流程卡和大块进度说明。
3. 将浏览器上传进度与服务器分析进度分成两个真实阶段。
4. 展示当前用户全部非终态任务，并附最近完成或失败的 10 条任务。
5. 页面刷新、离开后返回、退出登录后重新登录，都能从服务器恢复分析任务与进度。
6. 完全复用平台现有工作区布局、`--ds-*` 设计令牌、基础按钮和响应式规范。
7. 保持评分流水线、报告路由和现有上传限制不变。

## 3. 非目标

- 第一版不实现分片上传、断点续传或浏览器刷新后的本地文件续传。
- 本地文件仍在单次 HTTP 上传完成后才进入持久服务器任务队列；刷新发生在本地传输阶段时，需要重新选择文件。
- 不新增批量上传、任务暂停、任务取消或任务删除。
- 不改变 AI 评分算法、流水线阶段或报告内容。
- 不把会议录制评分任务混入本页；队列只展示 `uploaded_video`。
- 不为本页创建独立主题、配色、字体、圆角或阴影。

## 4. 已确认产品决策

### 4.1 页面模式

采用 B+：

1. 页头；
2. 紧凑上传卡；
3. 上传期间的轻量本地进度；
4. 全宽持久任务队列。

不采用左右常驻双栏。任务名称、团队、赛道、阶段、时间、进度和操作需要完整横向空间；左右双栏会压缩任务信息，并在移动端产生额外重排。

不采用纯任务中心优先。用户从评分报告点击“上传评分”进入，首要意图是立即上传，不应再多点击一次才能看到表单。

### 4.2 队列范围

- 全部非终态上传任务置顶。
- 终态任务只保留最近 10 条。
- 非终态包括 `created`、`scoring`、`processing` 及未来新增但不属于终态集合的状态。
- 终态集合为 `completed`、`failed`、`cancelled`。
- 同一组内按 `created_at DESC, id DESC` 排序。

### 4.3 两段式进度

#### 本地上传

由浏览器上传事件提供真实数据，只在传输期间展示：

- 文件名；
- 百分比；
- 已上传 / 总大小；
- 上传速度；
- 预计剩余时间；
- 4px 纤细进度条。

上传完成后，本地进度从页面退出，不把 82% 或 92% 映射成服务器分析进度。

#### 服务器分析

服务器返回的 `progressPercent` 是唯一权威值。任务进入队列后，由队列展示：

- 当前阶段；
- 服务器进度；
- 完成、失败或排队状态；
- 对应操作。

排队阶段没有可信百分比时只展示“排队中”，不伪造增长动画。

## 5. 平台设计规范

### 5.1 外部间距只有一个所有者

- `.workspace-main` 是页面上、下、左、右外部间距的唯一所有者。
- `.video-score-page` 不设置页面级 `padding`、`margin`、背景或独立最大宽度。
- 桌面沿用全局 `--ds-page-margin-x: 40px` 与 `--ds-page-margin-y: 40px`。
- 平板和手机间距由全局工作区断点统一缩减，业务页不得单独写另一组视口边距。
- 页头首行必须与首页、训练营、路演训练和评分报告的内容起始线一致。
- 页面底部留白使用工作区公共页面容器规则，不额外增加孤立数值。

### 5.2 令牌与组件

- 页面标题使用 `--ds-text-h1`、`--ds-weight-bold`。
- 说明文字使用 `--ds-text-caption` 或平台页面说明样式。
- 卡片使用 `--ds-card-bg`、`--ds-card-border`、`--ds-card-shadow` 和 `--ds-radius-lg`。
- 主操作使用 `BaseButton` primary；返回和次操作使用 secondary 或 text。
- 输入框、选择器和文件控件复用 `--ds-input-*`。
- 主进度使用 `--ds-orange-500`；完成、等待、失败分别使用现有绿色、中性、红色状态令牌。
- 间距只使用 4px 阶梯 `--ds-space-*`。
- 不新增大面积渐变、彩色光斑、强阴影、环形进度或玻璃叠层。

### 5.3 响应式

- 桌面上传卡为紧凑两行布局。
- 900px 以下切换为单列。
- 手机端字段、文件选择、按钮和任务信息按阅读顺序垂直排列。
- 任务行顺序固定为：名称与元数据 → 状态 → 进度 → 操作。
- 所有断点不得产生横向滚动。

## 6. 页面结构

### 6.1 页头

- 标题：上传评分。
- 说明：上传完整路演视频，系统将生成评分报告。
- 操作：返回评分报告。

删除对“内部评分规则”的说明。

### 6.2 紧凑上传卡

第一行：

- 项目团队；
- 赛道。

第二行：

- 路演视频，必选；
- 佐证材料，可选。

底部：

- 默认折叠的“评分偏好”，容纳“引用历史评分记忆”和“AI 评审团复核”；
- 唯一主操作“开始上传评分”。

文件选择行显示文件名、大小和更换操作，不再使用两张大面积上传盒。

### 6.3 本地上传进度

上传开始后在上传卡底部展开一条轻量区域：

- 文件名和百分比同一行；
- 4px 进度条；
- 大小、速度、预计剩余时间放在一行次要文本中；
- 上传失败在相同位置显示错误和重试提示。

页面不再渲染独立的“当前状态”卡、“处理流程”卡或第二条上传进度。

### 6.4 持久任务队列

队列标题：

- 评分任务；
- 进行中数量；
- 轻量同步状态。

每个任务行包含：

- 视频文件名；
- 项目团队、赛道、创建时间；
- 中文阶段；
- 服务器分析进度；
- 任务操作。

状态与操作：

- `created/uploaded/queued`：等待处理，无虚假百分比；
- `scoring/processing`：显示橙色细进度与百分比；
- `completed`：绿色“已完成”，操作“查看报告”；
- `failed`：红色“失败”、简短错误，操作“重新上传”；
- `cancelled`：中性“已取消”。

“重新上传”只恢复团队、赛道与评分偏好，并滚动聚焦上传卡；浏览器安全限制决定本地文件必须重新选择。

队列空状态只保留一句说明，不再重复放置上传按钮。

## 7. 服务端架构

### 7.1 新任务响应

新增 `AiScoreUploadTaskResponse`，仅包含用户需要的字段：

- `sessionId`
- `sessionNo`
- `fileName`
- `fileSize`
- `projectId`
- `teamId`
- `teamName`
- `trackName`
- `status`
- `currentStage`
- `progressPercent`
- `useHistoryMemory`
- `juryEnabled`
- `reportId`
- `errorMessage`
- `createdAt`
- `updatedAt`

不得返回文件绝对路径、评分规则、rubric 哈希、内部版本或证据配置。

### 7.2 查询接口

新增：

```text
GET /api/ai-score/upload-tasks?completedLimit=10
```

接口从请求上下文读取当前 `userId` 和 `tenantId`，不接受客户端指定用户。查询限定：

```text
source_type = uploaded_video
AND created_by = current_user
```

结果由“全部非终态任务 + 最近 N 条终态任务”组成。`completedLimit` 默认 10，服务端限制在 1–50 之间。

文件名和大小来自该会话的 `video` 媒体资产；团队名称来自项目团队。缺少媒体资产时回退到会话编号，不暴露内部路径。

### 7.3 服务边界

- `AiScoreUploadTaskService` 负责安全查询、排序和响应映射。
- `AiScoreUploadController` 只负责请求参数、登录上下文和结果包装。
- 现有 `AiScoringSessionService` 继续负责会话创建与状态更新，不承担页面展示拼装。
- 现有上传接口和流水线回调保持不变。

## 8. 前端架构与数据流

### 8.1 文件职责

- `VideoScoreUpload.vue`：页面编排、上传状态与队列组合。
- `VideoScoreUploadForm.vue`：字段、文件选择、校验和浏览器上传进度。
- `AiScoreUploadTaskQueue.vue`：任务列表、状态表达和任务操作。
- `useAiScoreUploadQueue.js`：队列获取、轮询、前后台切换恢复与即时合并。
- `aiScoreUpload.js`：上传和任务队列 API。

### 8.2 恢复流程

1. 页面挂载后立即请求上传任务队列。
2. 如果队列存在非终态任务，每 3 秒刷新一次。
3. 页面隐藏时停止轮询。
4. 页面重新可见或窗口重新聚焦时立即刷新。
5. 没有非终态任务时停止定时轮询，只保留可见性恢复刷新。
6. 新上传成功后，把返回会话即时合并到队列头部，再从服务器刷新补齐文件和团队信息。
7. 页面卸载时释放所有定时器与事件监听。

### 8.3 路由

- 完成任务的“查看报告”进入 `/ai-score/report/{sessionId}`。
- “返回评分报告”直接进入当前统一入口 `/online-meeting?tab=reports`，不再先经过 `/statistics` 兼容重定向。

## 9. 错误处理

- 队列首次读取失败：上传功能仍可用；队列区域显示“任务暂时无法读取”和“重新加载”。
- 轮询单次失败：保留已有任务，不把任务错误标记为失败；下一轮继续尝试。
- 连续轮询失败：停止高频重试，等待用户点击或页面重新可见再刷新。
- 上传失败：只影响当前本地上传，不清空服务器已有队列。
- 流水线失败：以服务器持久状态展示，刷新后仍可看到原因。
- 错误文本做长度限制，完整内部异常不直接暴露给学生。
- 未登录或身份失效继续由全局请求拦截器处理。

## 10. 可访问性

- 本地上传进度和服务器分析进度使用原生或等价 `role="progressbar"`，提供 `aria-valuenow`。
- 队列更新使用克制的 `aria-live="polite"`，不在每次轮询时重复朗读整张列表。
- 状态不能只依赖颜色，必须有中文标签。
- 折叠的评分偏好提供 `aria-expanded`。
- 文件选择、重新加载、查看报告和重新上传均有明确可访问名称。
- 键盘焦点样式复用平台统一焦点环。

## 11. 测试与验收

### 11.1 服务端

- 当前用户只能读取自己创建的 `uploaded_video` 任务。
- 不返回其他用户、会议录制或其他租户任务。
- 所有非终态任务都返回，终态只返回最近 10 条。
- 排序稳定。
- 文件名、团队、进度和报告 ID 映射正确。
- 响应不泄露路径、rubric 或内部版本。

### 11.2 前端

- 页面加载时请求任务队列。
- 刷新页面后仍恢复正在分析的任务。
- 新上传成功后任务立即出现在队列，并继续轮询。
- 服务器进度更新后界面同步。
- 完成后停止轮询并出现“查看报告”。
- 失败任务刷新后仍存在，并能恢复上传上下文。
- 上传进度和分析进度不会混用或倒退。
- 空闲时不存在重复状态卡、处理流程卡和空进度条。

### 11.3 视觉合同

- `.workspace-main` 是唯一外边距来源。
- 上传页根容器四周没有额外页面 padding。
- 页头与首页、训练营、路演训练的内容起始线一致。
- 桌面使用全宽上传卡和全宽队列。
- 390px、900px 和桌面宽度均无横向溢出。
- 进度条高度为 4px，未出现环形或厚重进度组件。
- 按钮、输入、状态色、圆角和阴影来自现有 `--ds-*` 令牌。

## 12. 成功标准

- 用户上传完成后，无论刷新、离开页面还是重新登录，都能恢复正在分析的任务。
- 页面首屏只保留上传所需信息和可理解的任务状态。
- 上传与分析进度在视觉和数据上清晰分离。
- 页面外部上下左右间距与平台其他工作区页面完全一致。
- 桌面和移动端都没有重复信息、横向滚动或拥挤的进度卡。
