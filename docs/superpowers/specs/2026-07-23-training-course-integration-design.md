# 课程学习与训练任务融合设计

日期：2026-07-23  
状态：已确认  
范围：学生端、教师端、训练营接口与数据结构

## 1. 背景

当前“课程学习”和“训练任务”是两个相互独立的功能入口。学生需要先判断去哪里学习，再返回训练任务完成交付；教师也需要先创建完整课程，再将课程与训练安排关联。这个结构增加了路径判断和维护成本，也削弱了“每日训练”作为核心工作流的产品心智。

本次调整将课程从独立业务模块改为训练日中的“学习环节”。教师按训练日直接上传或添加学习内容，学生在当天任务详情中依次完成学习、任务和提交。

## 2. 设计目标

1. 训练任务成为学生端训练营的唯一入口。
2. 学习内容直接服务于当天任务，不再要求先创建完整课程。
3. 学生能明确理解“先学、再做、再提交”的顺序。
4. 教师在同一个日任务编辑器中完成内容编排和发布。
5. 学习进度用于提示和统计，不阻断任务提交。
6. 保留历史课程与学习记录，避免数据丢失。

## 3. 非目标

1. 本次不删除原课程表、课程文件或历史学习进度。
2. 本次不改造管理员端的历史课程管理能力。
3. 本次不提供跨训练营的课程商城或公共课程库。
4. 本次不通过学习完成状态强制锁定成果提交。
5. 本次不恢复已停用的练习考试功能。

## 4. 已确认的产品决策

### 4.1 学习内容规则

- 教师可为每个训练日添加零条或多条学习内容。
- 支持视频、文件和外部链接三种类型。
- 文件类型支持 PDF、PPT、PPTX、DOC、DOCX。
- 每条内容可设置必学或选学、标题、说明和预计时长。
- 内容支持排序、预览、替换和删除。
- 必学内容未完成时仅提示，不禁止学生提交成果。

### 4.2 学生端布局

采用三步纵向流程：

1. 今日学习
2. 今日任务
3. 成果提交

学习内容直接内嵌在任务详情页，不再跳转独立课程详情页。

### 4.3 教师端布局

采用“日编辑器内联区块”：

- 在现有“计划与日任务”编辑器内增加“今日学习”区块。
- 教师选定训练日期后，在同一页面配置学习内容、任务书、交付要求和截止时间。
- 学习内容与日任务一起保存草稿、预览和发布。

## 5. 信息架构

### 5.1 学生端

训练营二级导航只保留：

- 训练任务

移除：

- 课程学习
- 练习考试
- 选题策划

旧 `/course-learning`、课程详情和课时播放地址统一跳转到 `/training/today`。历史学习数据保留，不再通过学生端独立页面访问。

### 5.2 教师端

教师端训练营以“计划与日任务”为主要内容编排入口。

独立“课程”入口从训练营导航中移除，旧 `/camp/courses` 地址重定向到“计划与日任务”。教师不再先创建课程，再关联训练日，而是在训练日内直接添加学习资源。

## 6. 学生端详细设计

### 6.1 训练任务列表

每日任务区域仍以正式任务为主体，在日期区域或任务组头部增加紧凑摘要：

`2 项学习 · 1 项任务 · 预计 35 分钟`

规则：

- 不在列表页展开学习资源明细。
- 没有学习内容时不显示“0 项学习”。
- 预计时长为学习内容预计时长与任务预计时长之和；任务未设置时长时只展示学习时长。
- 筛选状态仍以任务提交状态为准，不把单条学习资源加入任务数量。

### 6.2 任务详情

页面内容顺序：

1. 页面标题与当天上下文
2. 今日学习
3. 今日任务
4. 成果提交与反馈

“今日学习”规则：

- 存在学习内容时默认展开。
- 全部必学内容完成后，自动收起为摘要，可再次展开。
- 没有学习内容时整个区块不渲染。
- 每条资源展示类型、标题、说明、必学/选学、预计时长和完成状态。
- 同一天的内容按教师排序展示。

“今日任务”沿用现有任务书结构：

- 任务主题
- 任务概要
- 正式任务描述
- 交付要求
- 同日其他任务

“成果提交”沿用现有提交与反馈逻辑。若存在未完成必学内容，在提交区域上方显示非阻断提示：

`还有 1 项必学内容未完成，建议学习后再提交。`

### 6.3 资源交互

视频：

- 在当前任务详情页内展开播放器。
- 播放进度达到 90% 时自动标记完成。
- 记录最近播放位置，重新进入时可继续播放。

文件：

- 使用现有文件预览能力。
- 文件成功打开后允许学生点击“标记已学”。
- 下载不是完成条件。

外部链接：

- 新窗口打开。
- 学生返回后手动点击“标记已学”。
- 链接不可访问时显示错误，不影响任务书和提交区域。

### 6.4 窄屏适配

- 三步流程保持单列顺序。
- 学习资源操作按钮收拢为“打开”和更多菜单。
- 视频播放器使用 16:9 自适应宽度。
- 不使用固定宽度侧栏，不产生横向滚动。

## 7. 教师端详细设计

### 7.1 日任务编辑器

“编辑日任务”表单顺序：

1. 任务标题
2. 训练说明
3. 今日学习
4. 详细任务说明
5. 截止时间
6. 任务附件
7. 交付要求
8. 发布说明

“今日学习”头部展示资源数量、必学数量和预计总时长。资源列表采用紧凑行布局，不展示大封面。

### 7.2 添加学习内容

点击“添加学习内容”打开统一弹窗。

公共字段：

- 内容类型
- 标题
- 补充说明
- 必学或选学
- 预计时长

按类型增加：

- 视频：选择本地视频文件。
- 文件：选择 PDF、PPT、PPTX、DOC、DOCX。
- 外部链接：填写 HTTPS 地址。

保存成功后将内容加入当前训练日列表。支持拖拽排序、预览、替换和删除。

### 7.3 草稿与发布

- 新上传资源先处于待发布状态。
- 保存草稿不会影响学生端。
- 发布日任务时，同时激活上传成功的学习资源。
- 存在上传失败、标题为空或无效链接时阻止发布，并定位到具体资源。
- 已发布训练日修改后再次发布，学生端读取最新内容。
- 更新资源不清除其他资源的学生学习进度。
- 删除已产生学习记录的资源时，教师端显示二次确认；历史进度保留为归档记录。

### 7.4 页面长度控制

- 今日学习区块头部始终可见。
- 已添加资源可折叠为摘要。
- 发布操作栏在编辑器底部保持可见。
- 发布栏显示缺项检查，例如“2 项学习内容已就绪，1 项任务要求待补充”。

## 8. 数据模型

### 8.1 训练日学习内容

新增 `training_day_learning_resource`：

- `id`
- `training_day_id`
- `resource_type`：VIDEO、DOCUMENT、LINK
- `title`
- `description`
- `resource_url`
- `file_name`
- `file_size`
- `mime_type`
- `duration_seconds`
- `is_required`
- `sort_order`
- `status`：PENDING、ACTIVE、ARCHIVED
- `created_by`
- `created_at`
- `updated_at`

索引：

- `training_day_id + status + sort_order`

### 8.2 学生学习进度

新增 `training_learning_progress`：

- `id`
- `user_id`
- `learning_resource_id`
- `learned_seconds`
- `progress_percent`
- `status`：NOT_STARTED、IN_PROGRESS、COMPLETED
- `last_learned_at`
- `completed_at`
- `created_at`
- `updated_at`

唯一约束：

- `user_id + learning_resource_id`

资源被归档后，进度记录继续保留。

## 9. 接口设计

### 9.1 教师端

- 获取训练日时返回 `learningResources`。
- 新增视频或文件上传接口。
- 新增外部链接创建接口。
- 新增学习内容更新接口。
- 新增归档接口；前端使用删除动作，服务端保留资源与历史进度记录。
- 新增排序接口。
- 发布训练日时校验并激活待发布资源。

上传接口沿用现有训练日权限校验，确保教师只能编辑自己可访问团队的训练日。

### 9.2 学生端

训练计划接口增加每日摘要：

- `learningResourceCount`
- `requiredLearningCount`
- `estimatedLearningMinutes`
- `completedLearningCount`

训练日详情接口增加：

- `learningResources`
- 每条资源对应当前用户的学习进度

新增学习进度接口：

- 更新视频播放进度
- 手动标记文件或链接完成

服务端限制进度百分比范围，完成状态只允许按当前资源类型的规则写入。

## 10. 文件与安全规则

- 视频和文档必须校验扩展名、MIME 类型和文件签名。
- 文件名只用于展示，存储使用随机文件名。
- 文件路径必须限制在训练资源目录内。
- 外部链接只接受 HTTPS。
- 学生端渲染教师说明时继续使用 HTML 清理规则。
- 资源下载和播放必须经过现有身份与团队访问校验。
- 单条资源上传失败不回滚其他已上传成功资源。

## 11. 异常与空状态

- 无学习内容：不显示学习区块。
- 上传失败：资源行显示失败原因并允许重试或移除。
- 文件预览失败：提供下载入口，不影响任务提交。
- 外部链接失效：提示教师更新；学生端显示“资源暂不可用”。
- 视频进度同步失败：保留本地播放位置并在恢复网络后重试。
- 训练日更新：学生端重新进入时获取最新资源列表。
- 已完成资源被替换：保留原进度，但新资源显示“内容已更新”，允许重新学习。

## 12. 历史数据与迁移

- 保留 `course`、`course_lesson`、`course_attachment` 和 `course_learning_progress`。
- 不自动把全部历史课程分配到训练日。
- 原课程页面关闭访问，旧地址跳转到训练任务。
- 历史课程学习时长仍可计入个人中心汇总。
- 新的训练日学习内容使用独立进度表，避免与历史课程进度互相覆盖。

## 13. 测试与验收

### 13.1 学生端

- 训练营侧栏不再显示课程学习。
- 旧课程地址正确跳转训练任务。
- 训练列表正确展示学习摘要。
- 有学习内容时显示三步流程。
- 无学习内容时不显示空学习模块。
- 视频、文件、链接的完成逻辑正确。
- 必学未完成时显示提示但不阻断提交。
- 已完成学习区块自动折叠且可重新展开。
- 窄屏无横向滚动。

### 13.2 教师端

- 训练日可添加三种学习内容。
- 上传格式、大小和链接校验正确。
- 必学设置、预计时长和排序可保存。
- 草稿内容学生不可见。
- 发布后学生端可见。
- 上传失败资源阻止发布并正确定位。
- 修改已发布资源不清除其他学习进度。
- 删除已有进度资源显示二次确认。

### 13.3 后端

- 权限隔离覆盖教师、团队和学生。
- 资源发布状态过滤正确。
- 学习进度唯一约束和并发更新正确。
- 文件路径与内容校验正确。
- 历史课程数据保持不变。

## 14. 上线顺序

1. 新增数据表与后端资源、进度接口。
2. 扩展教师端日任务编辑器。
3. 扩展学生端训练计划和任务详情。
4. 迁移导航和旧课程路由。
5. 完成端到端测试与窄屏验证。
6. 关闭独立课程入口并观察上传、学习和提交数据。

## 15. 成功标准

- 学生无需离开训练任务即可完成当天学习和交付。
- 教师无需进入独立课程模块即可发布每日学习内容。
- 每日学习资源的上传、打开和完成状态可追踪。
- 未完成学习不阻断关键的成果提交路径。
- 所有历史课程数据和学习时长保持可查询。
