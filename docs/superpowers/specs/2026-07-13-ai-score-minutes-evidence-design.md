# AI 评分纪要式依据页正式设计

## 1. 决策结论

评分总结继续保留“结果 / 待办 / 依据”三级结构。本次只重构“依据”页，使它成为可回看、可定位、可核验的路演复盘工作台。

页面采用“左侧固定复盘台 + 右侧独立滚动信息流”：

- 左侧在一个可用视口内同时容纳完整视频、原生播放控制、事件时间轴和当前事件摘要，不产生纵向滚动。
- 右侧承载评分事件、人物转写和路演章节，只有右侧内容区可纵向滚动。
- 视口高度不足时，优先等比例压缩视频和间距；不能把时间轴挤出视口，也不能通过裁切视频换取空间。
- 页面继续只展示一个正式 AI 分数；诊断建议不得伪装成正式扣分。

## 2. 产品目标

用户需要在同一个上下文中回答三个问题：

1. 当时发生了什么？
2. 为什么影响评分？
3. 我应该从哪里开始复核或整改？

视频负责还原现场，转写负责定位发言，时间轴负责建立整场结构，评分事件负责解释分数。四者必须共享同一播放时间，点击任意真实时间锚点都能跳到对应视频位置。

## 3. 页面信息架构

### 3.1 左侧固定复盘台

左侧从上到下分为两行：

- 视频舞台：`minmax(0, 1fr)`，视频使用 `object-fit: contain`，完整画面始终可见。
- 时间轴区：内容自适应高度，包含章节带、评分事件点、当前时间和当前事件摘要。

容器使用 `overflow: hidden`，禁止左侧产生纵向滚动。播放器使用浏览器原生媒体控制，首期不重写播放、音量、全屏和倍速能力。

### 3.2 右侧复盘信息流

右侧顶部工具栏固定，内容区独立 `overflow-y: auto`。提供三个真实数据视图：

- 评分事件：正式扣分、证据限制、表现差距及其证据锚点。
- 人物转写：按时间排序的 ASR 片段，点击时间跳转视频。
- 路演章节：来自真实结构分析的章节区间，点击章节跳转视频。

右侧滚动不改变左侧视频、时间轴和当前事件的可见性。

## 4. 数据真实性原则

- 不伪造人物。原始 ASR 只有 `SPEAKER_0` 时，页面显示“发言人待确认”或原始标签，不凭空拆成多人。
- 团队角色映射与原始说话人标签分离保存。人工修正只改变展示映射，不覆盖原始 ASR。
- 不伪造章节。没有结构分析时展示明确空状态。
- 不伪造分值。只有能关联到正式评分规则和结构化扣分记录的事件展示扣分或保守可追回区间。
- 诊断性问题展示验收标准，但不承诺提分。
- 展示分数以 Java 报告 API 的最终权威分为准，不使用 Python 原始模型分覆盖。

## 5. 数据契约

报告 API 增加只读 `mediaPlayback`：

```json
{
  "assetId": 123,
  "contentType": "video/mp4",
  "sizeBytes": 496000000,
  "durationSeconds": 3270.592,
  "streamUrl": "/api/ai-score/sessions/26/media/video"
}
```

字段缺失时前端显示“视频暂不可用”，不得猜测地址。

视频流接口：

```http
GET /api/ai-score/sessions/{sessionId}/media/video
Range: bytes=0-1048575
```

契约要求：

- 与报告接口执行同一会话访问控制。
- 支持 `HEAD`、完整 `GET` 和单段 `Range GET`。
- 合法 Range 返回 `206`、`Content-Range`、`Accept-Ranges: bytes`、准确 `Content-Length`。
- 非法或越界 Range 返回 `416` 和 `Content-Range: bytes */{size}`。
- 流式读取指定区间，不把 496MB 视频整体载入 JVM 内存。

人物转写和章节首期兼容现有真实结果字段：

- `asr.segments[]`: `start/end/text/speaker`
- `pitch_structure_benchmark[]` 或等价真实结构字段
- `structuredDeductions[]` + `evidenceAnchors[]`

后续持久化为原生表时保持相同前端展示模型，不改变页面组件契约。

## 6. 交互规则

- 播放器 `timeupdate` 驱动当前时间、当前转写、当前章节和当前评分事件高亮。
- 点击时间轴事件、转写时间或章节，统一调用播放器 seek。
- 正式扣分事件显示扣分值、原因、规则维度和证据摘要。
- 没有时间锚点的扣分仍进入评分事件列表，但不在时间轴上制造虚假位置。
- 角色修正入口仅在存在可持久化说话人记录时启用；保存后后续报告复用，原始 speaker 标签保留用于审计。

## 7. 响应式与可访问性

- 桌面宽屏采用左右双栏。
- 宽度不足时切为上下结构，此时整页允许正常文档滚动；“左侧一屏全显”约束只针对产品主要桌面工作区。
- 时间点按钮可键盘聚焦，并提供可读的时间与事件标题。
- 使用原生 `<video>`，支持字幕轨道扩展、全屏和系统媒体快捷键。
- 右侧滚动条始终可发现，当前条目使用颜色加左边线双重提示，不只依赖颜色。

## 8. 空态与失败态

- 视频缺失：保留舞台尺寸，说明“当前报告未关联可播放视频”。
- 视频加载失败：提供重试按钮和明确错误，不退回静态关键帧冒充视频。
- 转写缺失：显示“尚无可用转写”，评分事件仍可查看。
- 人物未识别：显示原始 speaker 或“发言人待确认”。
- 事件无时间锚点：显示“未定位到视频时间”，仍保留扣分解释。
- Range 失败：播放器显示可恢复错误，服务端记录请求范围和资产 ID，日志不输出敏感文件绝对路径。

## 9. 验收标准

1. 在常用桌面视口内，左侧视频、控制条、时间轴、当前事件同时可见，左侧无纵向滚动条。
2. 右侧列表可独立滚动，左侧位置不移动。
3. 会话 26 使用真实 54 分 30 秒视频，拖动到后半段无需顺序下载完整文件。
4. 点击评分事件、转写或章节后，播放器跳转到真实时间。
5. 会话 26 当前只有单一原始说话人标签时，页面不显示虚构的四位发言人。
6. 正式分数和扣分值来自报告 API；诊断建议不显示承诺分数。
7. Java Range 单元/控制器测试、前端展示模型测试和生产构建均通过。
