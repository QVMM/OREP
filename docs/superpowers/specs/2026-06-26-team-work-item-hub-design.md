# OREP 团队项目管理页工作项中枢设计

## 背景

当前团队项目管理页已经有成员、资料、任务、作品版本、路演复盘、AI 评分入口等能力，但它们以模块方式并列展示。用户进入页面后，需要自己判断下一步该做什么、哪个资料关联哪个任务、AI 评分扣分如何转成团队行动、谁负责推进。这导致页面虽然功能多，但不够好上手、关联性弱、视觉焦点不清晰。

这次设计目标不是继续追求 `https://linear.app/` 的外观相似，而是参考 Linear 的产品逻辑：把团队协作对象统一成可分配、可筛选、可追踪、可关联上下文的工作项，让团队每天进入页面就能处理最重要的事项。

## 设计目标

1. 页面主视觉聚焦在“当前最该处理的工作项”，而不是项目阶段、资料卡片、任务卡片等并列信息块。
2. 将任务、资料、AI 评分扣分、路演复盘建议和系统建议统一进入收件箱。
3. 用户可以按工作视图和项目阶段快速筛选工作项。
4. 用户点击任一工作项后，在右侧看到完整上下文：负责人、状态、阶段、截止时间、关联资料、关联评分、关联复盘和下一步动作。
5. 保留 OREP 的路演训练业务特征，但交互组织方式接近 Linear 的工作台体验。

## 核心产品模型

### 工作项

工作项是团队页的一等对象。它可以来自已有任务、资料审核、AI 评分扣分、复盘建议或系统建议。

每个工作项至少包含：

- 类型：任务、资料、评分、复盘、系统建议。
- 标题：用户一眼能理解要处理什么。
- 摘要：说明来源和处理目的。
- 状态：未开始、进行中、待审核、需修改、已完成、阻塞。
- 优先级：高、中、低。
- 负责人：成员、队长、老师或系统。
- 阶段：课程学习、能力测评、材料准备、路演展示、复盘提升。
- 截止时间：可为空。
- 来源对象：原始任务、资料、评分报告、复盘记录或系统事件。
- 关联对象：资料、PPT 版本、视频评分会话、复盘建议、任务提交记录等。

### 首版收件箱来源

第一版支持 5 类自动进入收件箱的事项：

1. 普通任务：已有任务、逾期任务、待完成任务。
2. 资料事项：新上传资料、待审核资料、需修改资料。
3. AI 评分扣分项：评分报告中的扣分原因自动形成待处理项。
4. 路演复盘建议：复盘中的改进建议自动形成待处理项。
5. 系统建议：如已上传视频建议发起评分、资料更新后建议同步 PPT。

## 页面结构

### 左侧：工作视图和阶段筛选

左侧不再只是模块入口，而是类似 Linear 的工作视图。

第一组为工作视图：

- 收件箱：所有需要处理的新事项。
- 我的工作：当前用户负责的事项。
- 待审核：需要队长或老师确认的事项。
- 评分扣分项：来自 AI 评分报告的扣分和改进点。
- 逾期/阻塞：超期或依赖未解决的事项。

第二组为阶段筛选：

- 课程学习。
- 能力测评。
- 材料准备。
- 路演展示。
- 复盘提升。

阶段只作为筛选条件，不再作为首页大卡片出现。

### 中间：统一工作项列表

中间是页面主视觉，只显示当前视图下的工作项列表。

列表字段建议为：

- 类型。
- 标题。
- 负责人。
- 截止时间。
- 状态。

排序规则：

1. 阻塞和逾期优先。
2. 高优先级优先。
3. 待审核优先于普通未开始任务。
4. 最近产生的系统建议和评分扣分项靠前。

列表不再拆成“项目阶段 / 最近资料 / 任务推进”多个卡片。资料、任务、评分和复盘都以工作项形式进入同一个列表。

### 右侧：工作项详情

右侧详情面板只展示当前选中的工作项。

详情内容包括：

- 标题和摘要。
- 状态、负责人、阶段、优先级、截止时间。
- 来源：任务、资料、AI 评分报告、复盘或系统建议。
- 关联内容：资料文件、PPT 版本、视频评分会话、评分报告、复盘记录、任务提交记录。
- 下一步动作：拆成子任务、打开资料、发起评分、提交审核、标记完成、进入准备页等。
- 活动记录：谁创建、谁修改、谁提交、谁审核。

阶段信息只在右侧详情中作为上下文字段出现，不占主视觉。

## 视觉原则

1. 删除首页大面积“项目阶段”卡片。
2. 删除“最近资料 / 任务推进”双卡片作为首页主体的结构。
3. 减少大圆角、大阴影、大留白和大进度条。
4. 主列表使用高密度行式信息，突出优先级和状态。
5. 只有高优先级、逾期、阻塞事项使用橙色强调。
6. 普通信息使用灰色、细边框和低饱和背景，避免审美疲劳。
7. 页面视觉焦点只允许一个：当前工作项列表。

## 用户流程

### 成员处理事项

1. 成员进入团队页。
2. 默认看到“收件箱”或“我的工作”。
3. 先处理高优先级、逾期或待审核事项。
4. 点击工作项，在右侧查看关联资料和来源。
5. 根据动作按钮进入资料、准备页、评分页或提交完成。

### 队长审核资料

1. 队长进入“待审核”。
2. 看到所有待审核资料、任务提交和版本更新。
3. 点击某一工作项，右侧显示提交人、资料版本、关联任务和审核动作。
4. 队长选择通过、退回修改或拆成新任务。

### AI 评分转行动

1. 用户上传视频并生成评分报告。
2. 系统将扣分项和关键建议转成评分类工作项。
3. 工作项进入“收件箱”和“评分扣分项”。
4. 团队成员可分配负责人、关联 PPT 或讲稿资料，并追踪是否完成。

### 复盘建议转行动

1. 路演复盘完成后，系统抽取或展示改进建议。
2. 建议进入收件箱，类型为“复盘”。
3. 队长可以将建议拆成具体任务或分配给成员。

## 现有功能映射

- 任务推进：变成任务类工作项来源。
- 最近资料：变成资料类工作项来源。
- 项目阶段：变成左侧筛选和右侧详情字段。
- 团队成员：保留为独立视图，但不作为默认首页主体。
- 作品版本：作为资料/审核类工作项的关联对象。
- 路演复盘：作为复盘类工作项来源。
- AI 评分报告：作为评分类工作项来源。
- 视频评分入口：作为右侧详情动作或左侧快捷入口。

## 首版边界

首版以重组现有数据为主，尽量不引入复杂后端表结构变更。

可接受的首版实现方式：

- 前端基于已有任务、资料、评分、复盘数据聚合生成工作项视图。
- 如果后端已有足够字段，则直接映射。
- 如果某些来源缺字段，先以系统建议或只读工作项展示。
- 对真实写入动作保持克制，优先复用已有任务创建、资料审核、评分跳转和完成状态接口。

首版不做：

- 完整评论系统。
- 全量工作项数据库模型迁移。
- 复杂自定义工作流。
- 多团队跨项目路线图。
- 类 Linear 的快捷键系统。

## 风险与处理

- 风险：现有 `ProjectTeam.vue` 文件过大，继续堆逻辑会降低可维护性。
- 处理：实现时优先抽出工作项聚合 computed 和展示区块，但不做无关重构。

- 风险：AI 评分扣分项和复盘建议的数据结构可能不稳定。
- 处理：先做容错映射，缺字段时以标题、摘要和来源类型兜底。

- 风险：用户可能仍需要查看完整资料库、成员列表和版本列表。
- 处理：这些保留为左侧低优先级视图，但默认首页不展示它们的大卡片。

## 验收标准

1. 进入团队页默认看到统一工作项列表，而不是项目阶段大卡片。
2. “项目阶段 / 最近资料 / 任务推进”不再以首页主体卡片形式出现。
3. 左侧可以切换收件箱、我的工作、待审核、评分扣分项、逾期/阻塞。
4. 左侧可以按课程学习、能力测评、材料准备、路演展示、复盘提升筛选。
5. 点击工作项后，右侧显示该事项的负责人、状态、阶段、来源、关联内容和下一步动作。
6. 任务、资料、AI 评分扣分项、复盘建议和系统建议至少能以只读或可跳转形式进入列表。
7. 高优先级、逾期、阻塞事项在列表中有明确但克制的视觉强调。
8. 用户端构建通过。
