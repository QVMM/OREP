# AI 评分待办页固定工作区设计

## 目标

待办页在桌面端始终占满评分报告可用高度，不再随着待办数量和详情内容拉长整张页面。用户无需滚动整页即可持续看到页面标题、完整性统计和待办工作台。

## 已确认交互

- `AiScoreSummaryChrome` 保持在报告顶部，不进入内容滚动区。
- 待办页正文占据剩余可用高度，正文自身不产生纵向页面滚动。
- 标题、完整性统计、覆盖说明和复评摘要固定在正文顶部。
- 待办工作台填满剩余高度。
- 左侧待办队列独立纵向滚动；筛选器和队列标题保持可见。
- 右侧选中待办详情独立纵向滚动。
- 桌面端用单一固定工作区；宽度不超过 900px 时恢复自然页面滚动，避免移动端嵌套滚动。

## 布局约束

桌面端高度链路必须连续：`report-shell` → `report-main` → `todos-page` → `todos-scroll` → `page` → `todo-layout`。每个可收缩容器都设置 `min-height: 0`，只有 `.todo-list` 和 `.todo-main` 拥有 `overflow-y: auto`。

`.todos-scroll` 保留现有命名以降低改动风险，但桌面端改为不滚动的内容容器。`.page` 改为纵向 Flex 容器，`.todo-layout` 使用 `flex: 1` 获取剩余高度并移除强制的 520px 最小高度。

低高度桌面窗口压缩标题、统计和工作台间距，但不隐藏评分信息。滚动条使用稳定 gutter，避免左右内容因滚动条出现而跳动。

## 响应式与边界

- 桌面端：页面固定，队列和详情分别滚动。
- 短屏桌面：压缩垂直间距，保证工作台仍有可操作高度。
- 平板和移动端：`.todos-page` 恢复纵向自然滚动，工作台改为单列；列表限定合理高度，详情完整展开。
- 空待办：空状态占据剩余区域，不制造无意义滚动条。

## 验收标准

在真实会话 26、Playwright 默认桌面视口中：

1. 待办正文容器 `scrollHeight <= clientHeight + 1`。
2. 待办工作台底部不超过正文容器可视底部。
3. 左侧队列内容超过可视高度时，队列自身可滚动。
4. 右侧详情内容超过可视高度时，详情自身可滚动。
5. 页面仍显示完整的真实待办数量和既有评分信息。
