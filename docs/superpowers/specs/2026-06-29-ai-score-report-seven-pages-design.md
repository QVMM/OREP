# OREP AI 评分报告 7 页面拆分设计

## 背景

当前用户端 AI 评分报告由 `frontend/user/src/views/AiScoreResult.vue` 承载。该文件同时负责数据请求、加载态、评分进度、七个报告分区、图表、证据链、团队任务生成、AI 评审团复核和页面样式，文件体量超过 6000 行。

现有页面的问题不是单纯视觉丑，而是用户阅读路径不清晰：上来看到大量分析模块、深色驾驶舱风格和技术指标，难以快速理解“我得了多少分、为什么扣分、AI 根据什么判断、接下来怎么改”。

本次改版依据用户提供的 7 张 UI 原型图，将 AI 评分报告改为浅色、清晰、任务闭环型的报告工作台，并拆成 7 个可维护页面。

## 目标

1. 把单个大页面拆成 7 个报告页面，降低维护成本。
2. 保留现有后端接口和核心业务能力，不要求后端先改字段。
3. 让用户按“总览 -> 五维 -> 证据 -> 表达 -> 现场 -> 改进 -> 评审团”的路径理解报告。
4. 每个页面都回答一个明确问题，避免信息堆叠。
5. 页面视觉统一为 OREP 浅色专业工作台风格。
6. 保留旧入口，避免已有链接失效。

## 非目标

1. 不在本轮重写 AI 评分后端。
2. 不改变 AI 评分结果的数据协议。
3. 不强行实现原型图里当前后端没有的数据字段。
4. 不把 AI 助手、团队任务、评审团逻辑拆成新业务系统。
5. 不追求一次性完成所有动画和高级交互。

## 推荐架构

采用“公共报告壳 + 共享数据层 + 7 个子页面”的架构。

### 目录建议

```text
frontend/user/src/views/ai-score-report/

  AiScoreReportOverview.vue
  AiScoreReportDimensions.vue

frontend/user/src/components/ai-score/report/
  AiScoreReportShell.vue
  AiScoreReportNav.vue
```

`views/ai-score-report` 放页面级组件；`components/ai-score/report` 放报告 UI 组件；`useAiScoreReport.js` 负责共享数据和操作。

## 路由设计

新增或调整用户端路由：

```text
/ai-score/report/:sessionId
/ai-score/report/:sessionId/overview
/ai-score/report/:sessionId/dimensions
/ai-score/report/:sessionId/evidence
/ai-score/report/:sessionId/voice
/ai-score/report/:sessionId/presentation
/ai-score/report/:sessionId/actions
/ai-score/report/:sessionId/jury
```

兼容现有入口：

```text
/ai-score/report-id/:reportId
/ai-score/:meetingId
```

兼容策略：

1. `/ai-score/report/:sessionId` 默认跳转到 `/overview`。
2. `/ai-score/report-id/:reportId` 使用同一个 Layout，但由 composable 按 `reportId` 加载。
3. `/ai-score/:meetingId` 保留旧会议入口，使用同一个 Layout，但由 composable 按 `meetingId` 加载。
4. 旧的 `AiScoreResult.vue` 在迁移期间保留为兼容入口或包装层，不立即删除。

## 共享数据层

新增 `useAiScoreReport.js`，从现有 `AiScoreResult.vue` 迁移可复用的数据逻辑。

### 职责

1. 根据路由参数识别加载方式：`sessionId`、`reportId`、`meetingId`。
2. 加载评分结果、进度状态、关键帧、证据包、表达建议、现场建议、改进方案、评审团结果。
3. 暴露通用状态：`loading`、`error`、`isSessionProgressView`、`sessionStatus`、`sessionProgress`、`sessionStage`。
4. 暴露通用计算属性：总分、原始分、评分等级、五维、扣分项、证据锚点、语音数据、视频数据、改进任务、评审团状态。
5. 暴露通用操作：返回、返回会议、下载 PDF、准备证据链、生成团队任务、启动评审团复核。
6. 统一兜底文案，避免每个页面重复处理空数据。

### 数据加载原则

7 个页面不各自重复请求完整报告。Layout 初始化共享状态，子页面通过 composable 读取同一份状态。

若 Vue 组件树中需要避免重复实例，可使用 provide/inject 或模块级缓存。优先选择可读性更好的 provide/inject：

1. `AiScoreReportLayout.vue` 调用 `useAiScoreReport()`。
2. Layout 通过 `provide` 提供报告上下文。
3. 子页面通过 `inject` 或封装的 `useAiScoreReportContext()` 读取上下文。

## 公共布局

### `AiScoreReportLayout.vue`

负责：

1. 处理加载态、失败态、评分进度态。
2. 渲染报告公共 Shell。
3. 提供报告上下文。
4. 承载子路由 `<router-view />`。
5. 控制 AI 助手收起状态。

### `AiScoreReportShell.vue`

负责视觉结构：

1. 左侧报告导航。
2. 顶部页面标题、会话信息、项目状态。
3. 右侧通用操作：同步团队看板、下载 PDF、返回会议等。
4. 主内容插槽。

### 左侧导航

导航项：

1. 总览
2. 五维评分
3. 证据链
4. 表达节奏
5. 现场呈现
6. 改进方案
7. AI评审团

导航展示：

1. 当前 AI 评分会话编号。
2. 完成状态。
3. 评分时间。
4. 每个页面的关键数量，例如证据点、表达问题、现场风险、改进任务、评审人数。
5. 恢复周期进度，例如今天、Day1、Day2、Day3、重评。

## 七个页面设计

### 1. 总览页

页面问题：用户现在多少分、主要问题是什么、第一步应该改什么。

主要模块：

1. 顶部指标条：当前分、目标分、可追回分、未解决 P0、证据置信度、评审团共识。
2. 评分结论卡：用一句业务语言解释当前报告。
3. 五维概览：展示各维度得分和当前最大短板。
4. 最影响得分的 3 个问题：按提分优先级排序。
5. 证据摘要：展示关键证据是否充分。
6. 下一步行动：进入改进方案或创建团队任务。

核心原则：总览不做复杂分析台，重点是“看懂结论”。

### 2. 五维评分页

页面问题：每个维度为什么扣分，应该优先修哪个维度。

主要模块：

1. 顶部指标条：当前评分、目标评分、最大差距、最易追回、待验收维度。
2. 五维能力地图：项目价值、商业逻辑、技术可行性、表达节奏、评委说服力。
3. 维度整改周期：将维度问题映射到今天、Day1、Day2、Day3、重评。
4. 当前维度详情：得分、扣分、证据置信度、核心瓶颈、关键影响。
5. 评分项任务映射表：评分项、当前得分、扣分原因、对应任务、验收标准。

核心原则：从“分数表”变成“维度修复路线图”。

### 3. 证据链页

页面问题：AI 根据什么判断，哪些证据不足阻碍提分。

主要模块：

1. 顶部指标条：证据快照、转写片段、关键帧、证据锚点、媒体资产、弱证据阻塞。
2. 证据时间线：按时间和影响排序展示证据点。
3. 当前证据详情：关键帧、OCR、转写片段、证据置信度、影响维度、AI 结论、需要补充。
4. 技术校准：展示技术上限、现场演示、修正幅度和修正原因。
5. 证据覆盖矩阵：维度 x 证据类型，标出强、中、弱、缺失。
6. 底部瓶颈提示：哪些证据补齐后可覆盖多少可追回分。

核心原则：让用户相信评分可复核，同时知道该补什么材料。

### 4. 表达节奏页

页面问题：讲得哪里不稳，具体哪句话要改。

主要模块：

1. 顶部指标条：表达稳定性、平均语速、严重停顿、最长停顿、口头禅、可追回分。
2. 表达问题排期：按开场、技术讲解、商业闭环、转场、结尾归类。
3. 当前选中句段：时间点、视频片段、影响分值、证据置信度、问题描述。
4. 原句转写与教练建议：给出可直接替换的话术。
5. 需要回练的句段列表：按风险排序。
6. 语音节奏轨迹：作为复盘依据，不喧宾夺主。

核心原则：少讲指标，多给可练的话术。

### 5. 现场呈现页

页面问题：画面、屏幕、首画面和讲解是否支撑评分。

主要模块：

1. 顶部指标条：视觉综合、音画冲突、关键帧、主要屏幕类型、可追回分。
2. 当前选中现场片段：关键帧、风险等级、评委视角、下一步动作、建议话术。
3. 现场呈现整改周期：开场定位、方案演示、商业说明、总结答辩。
4. 动作处方：每个场景的标准动作和建议话术要点。
5. 音画融合窗口：展示音频表达强度、视觉信息强度、冲突窗口。
6. 下一轮彩排计划：可直接加入训练日程。

核心原则：把“视觉分析”转成“下一轮彩排动作”。

### 6. 改进方案页

页面问题：报告如何变成团队任务，三天内怎么改。

主要模块：

1. 顶部指标条：预计追回分、已选工作项、P0 任务、今日应完成、重评时间、证据置信度、评审团共识。
2. 团队工作项生成器：支持勾选扣分项、训练项、材料项，生成团队工作项。
3. 三天整改周期：按 Day1、Day2、Day3、重评组织任务。
4. 提分优先级：影响力、难度、依赖、预计提分。
5. 话术与材料修改：原句替换、PPT 材料清单。
6. 重评前验收清单：明确完成标准。
7. 60 分钟彩排排期：把训练安排落到时间段。

核心原则：这是报告闭环页，不只是建议页。

### 7. AI 评审团页

页面问题：不同评委怎么看，哪些问题是共识，哪些是分歧。

主要模块：

1. 顶部说明：评审团只做复核，不修改基础分。
2. 顶部指标条：官方评分、评审团均分、分差、评委数、共识度。
3. 评委分数尺：展示最高/最低剔除、计入分、官方分。
4. 九位评委视角表：角色、评分、相对官方、核心关注点、训练建议。
5. 共识与分歧：共识问题、分歧焦点、下一轮训练优先级。
6. 答辩追问题库：由评审团生成的问题和关联证据。

核心原则：评审团不是炫技模块，而是帮助用户预判真实评委质疑。

## 视觉规则

1. 使用浅色工作台风格，主背景接近 `#f6f8fc`，卡片为白色。
2. 主色使用 OREP 蓝，重点行动按钮使用蓝色实心。
3. 风险、P0、扣分使用橙红色；可追回分和完成状态使用绿色。
4. 减少大面积渐变、强阴影和过度圆角。
5. 卡片边框清晰，层级靠留白、标题和表格结构表达。
6. 所有页面保持统一：顶部指标条 + 主分析区 + 右侧行动区。
7. 移动端优先保证不横向溢出，复杂表格可横向滚动或改卡片。

## 迁移顺序

1. 新建共享数据层 `useAiScoreReport.js`，迁移现有请求、状态、核心计算属性和通用操作。
2. 新建报告 Layout 和公共 Shell，跑通一个空的 7 页面子路由结构。
3. 迁移总览页，验证旧入口、数据加载、下载 PDF、返回会议。
4. 迁移五维评分页和证据链页，验证评分和证据数据映射。
5. 迁移表达节奏页和现场呈现页，验证语音、视频、图表和空状态。
6. 迁移改进方案页，验证团队任务生成。
7. 迁移 AI 评审团页，验证复核启动、加载、失败、完成状态。
8. 将旧 `AiScoreResult.vue` 改成兼容跳转或轻包装层。
9. 清理重复样式和未使用代码。

## 风险与控制

### 风险：现有页面逻辑过度耦合

控制：先迁移共享数据层，再迁移页面；每次只迁移一个分区，保留旧文件作对照。

### 风险：7 个页面重复请求报告

控制：Layout 层统一加载，通过 provide/inject 共享上下文。

### 风险：原型字段与现有接口不一致

控制：只用现有字段映射，缺失内容使用兜底状态，不要求后端立即改造。

### 风险：团队任务和评审团属于有副作用操作

控制：最后迁移这两个页面，并在迁移时保留原函数逻辑。

### 风险：一次性改动过大

控制：按页面分阶段提交和验证；旧入口保留到新页面验证完成后再清理。

## 验收标准

1. AI 评分报告由 7 个独立页面组成，单个页面职责清晰。
2. 用户进入总览后，能在第一屏理解分数、扣分原因和下一步行动。
3. 每个页面都能解释一个业务问题，而不是堆叠技术指标。
4. 原有关键能力不丢失：下载 PDF、证据链、表达建议、现场建议、改进任务、AI 评审团。
5. 页面视觉与用户提供的原型图方向一致：浅色、专业、结构清晰。
6. 前端构建通过，主要路由可访问。
