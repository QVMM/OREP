# 竞赛大脑研发驾驶舱设计

日期：2026-08-13  
位置：`project management/`（独立站点，不接入竞赛大脑正式前后端）  
状态：已通过对话确认；实现计划见 `docs/superpowers/plans/2026-08-13-competition-brain-rd-cockpit.md`

## 1. 背景

竞赛大脑（OREP）已是多端产品：学生端、教师端、管理端、路演、训练营、AI 评分、小启、PPT/讲稿、资源、学情。教师端已有面向备赛项目的「项目管理」，那是给学生和老师管参赛项目用的。

研发团队和老板缺少一张只回答「这个产品做到哪了」的作战图。现有 TASK.md、WORK_LOG、文档和代码分散，进度靠口头，判断和仓库真相容易打架。

本设计做给 **竞赛大脑研发团队和老板** 的内部驾驶舱，不是参赛师生的项目管理，也不替换教师端已有功能。

## 2. 目标与非目标

### 目标

1. 老板打开首页 30 秒看懂：11 个产品模块各自做到哪了。
2. 每张模块卡同时显示负责人标定的产品判断，和系统扫到的证据；两边打架必须可见，且任何一侧都不被自动改写。
3. 老板能指挥：改优先级、换负责人、写批示、标风险。研发能报进度：改判断、完成度、任务状态。自动证据只读。
4. 任务流完整：模块下的任务、本周交付、人员负荷、风险列表、任务总表，同一条任务只有一份进度。
5. 多人同时打开同一地址，写操作和扫描结果经 WebSocket 实时同步。
6. 全部代码和数据留在 `project management/`，不向正式产品加菜单、加表、加路由。

### 非目标

- 正式账号 / SSO / 权限系统
- 移动端适配作为第一版验收项
- 与教师端项目管理、学生任务打通
- 扫描器自动改产品判断或完成度
- 给参赛师生使用
- 把驾驶舱嵌进 `frontend/admin` 或 `frontend/teacher`

## 3. 用户与权限

登录很轻：选角色 + 填显示名。服务端每次写操作校验角色。

| 动作 | 老板 | 研发 |
|------|------|------|
| 看全部页面、证据、时间线 | 是 | 是 |
| 改产品判断、完成度 | 否 | 是 |
| 新建任务、改任务状态、写进度说明、认领 | 否 | 是 |
| 改优先级、换负责人、写批示、标/取消风险 | 是 | 否 |
| 手动触发扫描 | 是 | 是 |
| 改自动证据、改自动任务的证据摘要 | 否 | 否 |

越权时按钮仍显示，点了就地说明规则，服务端同样拒绝。不藏按钮，不静默失败。

## 4. 信息架构

### 一级导航（4 个）

1. **产品全貌**（默认首页）
2. **本周交付**
3. **风险**
4. **人员**

### 深链，不进一级导航

- **任务总表**：全部 / 我的 / 阻塞 / 待指派 / 老板批示
- **模块详情**：从首页卡片进入
- **任务抽屉**：从任何任务行打开

任务流完整存在，但不和「产品做到哪了」抢首页。

## 5. 首页模块图

按产品能力分组，不按代码仓库分组。第一版固定 11 张卡：

| 组 | 模块 |
|----|------|
| 两端工作台 | 学生端、教师端 |
| 备赛闭环 | 项目管理、训练营、路演、资源中心 |
| 智能与裁决 | 小启 AI、PPT/讲稿、AI 评分 |
| 治理与学情 | 学情分析、管理端 |

每张卡自上而下四层，顺序固定：

1. 模块名 + 产品判断（已上线 / 可用不完整 / 做到一半 / 未开始）
2. 一行证据：页面 · 接口 · 服务，各为「在 / 缺 / 不通 / 过期」
3. 负责人、完成度、未完成任务数
4. 有则显示的警报底条：判断与证据不一致 / 阻塞 / 本周超期 / 老板批示未回

首页顶部一条窄摘要，不是图表墙：已上线数、打架数、未指派数、本周超期数、当前阻塞数。点数字分别进入风险 / 本周 / 人员。

老板在卡上可换负责人、标风险、写批示。研发在卡上可改产品判断、完成度。点卡片空白进详情。

判断与证据不一致时，使用固定句式，例如：「负责人标『已上线』，但评分服务探活失败。」系统不算胜负，只逼人处理。

## 6. 其他页面

### 模块详情

上半左右对照：

- 左：产品判断、完成度、负责人、老板优先级、风险、批示时间线
- 右：只读证据（目录、关键页、接口、服务、上次成功扫描、失败原因、最近相关提交）

下半：该模块任务列表，未完成在上。点行打开右侧抽屉。

### 本周交付 / 风险 / 人员 / 任务总表

统一「左筛 + 中列表 + 右抽屉」。

- 本周：`due` 落在本周或被标「本周」的任务；超期置顶；按模块分组
- 风险：五类合一个列表（阻塞、打架、无人认领、老板标风险、本周超期），用类型标签区分
- 人员：每人一张负荷卡（负责模块数、进行中、阻塞、本周超期）；点人只看他的任务
- 任务总表：不进一级导航；视图为全部 / 我的 / 阻塞 / 待指派 / 老板批示

同一任务在模块、本周、风险、人员、总表中是同一条记录，进度不得分叉。

## 7. 数据模型

三种一等对象，外加只读派生。

### Module

人写：

- `id`：稳定键，如 `student`、`teacher`、`project`、`camp`、`roadshow`、`resources`、`xiaoqi`、`ppt`、`scoring`、`analytics`、`admin`
- `name`、`group`
- `judgment`：`shipped` | `usable_incomplete` | `in_progress` | `not_started`
- `progressPercent`：0–100，仅研发可写
- `ownerName`
- `priority`：老板可写
- `riskFlag`、`riskNote`：老板可写
- `briefs[]`：老板批示（作者、时间、正文）

机器写（人不可写）：

- `evidence.pages` / `evidence.apis` / `evidence.service`：`present` | `missing` | `down` | `stale`
- `evidence.detail`：路径、URL、失败原因
- `evidence.scannedAt`、`evidence.lastSuccessAt`
- `evidence.recentCommits[]`：路径相关的最近提交摘要
- `divergence`：由判断与证据算出，不手勾

### Task

- `id`、`moduleId`、`title`
- `status`：`todo` | `doing` | `blocked` | `review` | `done`
- `ownerName`、`dueAt`、`thisWeek`、`priority`
- `blockedReason`、`progressNote`（研发）
- `briefs[]`（老板）
- `source`：`manual` | `scan`
- `evidenceSummary`：仅 `scan` 任务有；只读；说明这条为什么存在

### Person

- `displayName`、`role`：`boss` | `dev`
- 负荷由模块负责人和任务负责人聚合，不单独维护编制表

### 派生（不提供编辑页）

- 本周交付 = 本周到期或 `thisWeek=true` 的任务
- 风险 = 阻塞任务 ∪ 打架模块 ∪ 无负责人模块 ∪ 老板标风险 ∪ 本周超期任务

## 8. 自动扫描

服务端持有「模块 → 探针」对照表（配置文件，不写死在卡片文案）。第一版探针：

| 模块 | 仓库证据 | 存活证据 |
|------|----------|----------|
| 学生端 | `frontend/user/src` 工作台路由 | 学生端页面可访问 |
| 教师端 | `frontend/teacher/src` 工作台/项目/训练营 | 教师端页面可访问 |
| 项目管理 | `ProjectsView` + 后端 Project API | 列表接口通 |
| 训练营 | camp 视图 + camp API | 营接口通 |
| 路演 | roadshow 视图 + 会议/录制相关 | 相关接口通 |
| 资源中心 | resources 视图 + 文件 API | 接口通 |
| 小启 AI | assistant 相关前端 | 助手接口通 |
| PPT/讲稿 | ppt/script 视图 + banana-slides / 生成服务 | 生成服务探活 |
| AI 评分 | 评分报告页 + `ai-scoring` | 评分服务探活 |
| 学情分析 | analytics 视图 | 学情接口通 |
| 管理端 | `frontend/admin` | 管理端可访问 |

规则：

- 默认每 30 秒扫一轮；老板和研发都可点「立即扫描」
- 只更新证据层；判断、完成度、负责人、批示一律不动
- 证据从有到无或从无到有时写变更；必要时自动生成一条 `source=scan` 的待认领任务
- 扫描失败：证据标 `stale`，保留上次成功快照和失败原因，**不得变绿**
- 探活超时：标 `down`，不是 `missing`
- 仓库路径被挪走：`present` → `missing`，可自动建待认领任务，不改产品判断
- 探活目标来自驾驶舱本地配置（端口、基址），缺省指向本机常见 OREP 端口；配不到就该项为 `stale`，并写明未配置

第一版打开时空库：11 张模块卡都在，判断默认 `not_started`，证据按当场扫描填。不塞演示假数据。

## 9. 实时同步与冲突

独立 Node 服务 + SQLite + WebSocket。

- 人改任务 / 负责人 / 批示 / 判断 / 完成度 / 优先级 / 风险：先落库再广播增量
- 扫描结束：只广播证据层和新建的自动任务
- 所有打开的页面（首页卡、详情、本周、风险、人员、抽屉）吃同一份增量
- 后写覆盖先写；每条变更记录操作者和时间
- 老板批示与研发进度说明分字段，互不覆盖
- WebSocket 断开：顶栏「实时已断开，正在重连」；仍可看最后一份数据；写操作禁用；重连后拉增量，不整页刷新冲掉抽屉
- 别人改了当前抽屉里的任务：顶栏「刚刚由某某更新」，内容直接换新，不弹打断式对话框
- 自己被覆盖：一句「已被某某覆盖」，时间线能看到两次

## 10. 视觉与交互原则

- 浅色工作台，清楚、克制、可信。不做彩虹 KPI、赛博黑、玻璃拟态
- 状态不只靠颜色：判断和证据都有文字
- 证据用人话（在 / 缺 / 不通 / 过期），不堆技术指标
- 三个二级页和任务总表同一套列表 + 抽屉，避免每页一种交互
- 空：未指派就写「未指派」并进风险，不假装有人在做
- 动效只用于状态切换和列表插入；尊重 `prefers-reduced-motion`
- 键盘：Tab 选卡，Enter 进详情，抽屉 Esc 关闭
- 触控目标至少 40×40px；正文桌面不小于 13px

## 11. 技术边界

```
project management/
  web/          Vue 3 + Vite 前端
  server/       Node 服务：REST + WebSocket + SQLite + 扫描器
  data/         SQLite 文件与本地配置（探针、探活基址）
  README.md     如何启动给老板和研发用
```

- 前端不复用 `frontend/user` 或 `frontend/teacher` 的路由壳，避免和正式产品耦合
- 视觉语言对齐 PRODUCT.md（克制工作台），但独立样式表
- 仓库扫描只读 OREP 源码树，不写回正式产品文件
- 启动方式：一条命令同时起服务和前端；默认局域网可访问，方便老板另开浏览器

## 12. 验收

1. 老板和研发两个浏览器同时打开，改负责人 / 批示 / 完成度，对面 2 秒内看到；越权写入被挡住并就地说明。
2. 首页 11 张卡都能对上真实仓库或服务探针；人为停掉评分服务后，AI 评分卡证据变「不通」，产品判断不变，出现打架警报。
3. 标一条本周超期、一条阻塞、一个模块不指派：风险页能看到这三类，首页摘要数字一致。
4. 从模块卡进详情改任务，从人员能看到同一条；不出现两份进度。
5. 扫描失败或 WS 断开时有人话状态，无假绿、无假成功。
6. 键盘能完成：首页 → 详情 → 任务抽屉 → Esc。
7. 不向竞赛大脑正式前端/后端加菜单或表。

## 13. 明确不验收

正式账号体系、移动端、和教师端项目管理打通、自动改产品判断、做给参赛师生用。
