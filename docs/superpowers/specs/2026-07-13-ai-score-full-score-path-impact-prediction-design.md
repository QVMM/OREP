# AI 评分满分路径与待办提分预测设计

日期：2026-07-13  
状态：待用户确认  
适用范围：Python 主评分流水线、Java 回调与报告 API、用户端评分结果页和待办页

## 1. 背景与问题

现有报告存在两个产品问题：

1. 当报告没有显式目标分时，前端按照 `60 / 70 / 85 / 100` 自动选择下一档，导致 49.5 分报告显示“目标 60 分”。这只是页面回退值，不是赛事目标，也不符合用户冲击满分的心智。
2. 当前只有与结构化扣分成功关联的任务能显示“最高可追回约 X 分”。行动计划中的其他整改项虽然有问题、方法和验收标准，但没有经过评分规则情景复算，因此页面无法说明“改好后大约影响多少分”。

产品必须同时满足可理解和可信：用户要看到从当前分到 100 分的完整差距，也要看到每项整改的保守提分区间；系统不能让大模型自由编造分数，也不能把多个相互重叠的任务直接相加。

## 2. 已确认的产品决策

1. 删除“下一档定位线”和阶段目标。
2. 所有报告永远以 100 分作为满分参照，显示当前完整差距。
3. 保留“本轮优先事项”，但它只表示执行顺序，不表示平台把本轮目标限制在某个分数档位。
4. 所有正式计分待办都必须计算保守提分区间。
5. 报告顶部显示“本轮全部整改通过验收”后的整体预测区间。
6. 无法关联评分规则、评分维度或观测点的建议不得承诺分数。

## 3. 用户端信息模型

### 3.1 顶部满分路径

结果页顶部固定展示：

- `当前 AI 分数`：当前正式分，例如 `49.5 / 100`；
- `满分目标`：固定为 `100`；
- `距离满分`：`100 - 当前正式分`，例如 `50.5`；
- `本轮全部通过后的预测`：组合情景复算区间，例如 `预计 61.0～67.5`；
- `本轮预计提升`：组合情景相对当前分的差值区间，例如 `+11.5～18.0`；
- `本轮优先事项`：统一待办队列中优先处理的数量。

顶部不再出现“下一档”“及格线”“本周目标 60 分”等系统替用户设定的阶段目标。若组合情景无法计算，预测区域显示“待评分规则测算”，不得回退到下一分档。

页面固定保留一句解释：

> 预测基于当前评分规则和全部验收情景，最终以重新路演评分结果为准。

### 3.2 单项待办

每条待办必须展示：

- 问题；
- 关联评分点；
- 怎么改；
- 怎样算好了；
- 分值影响；
- 负责人和建议时间（有数据时）。

根据影响类型使用不同语言：

| 影响类型 | 用户端文案 |
| --- | --- |
| 撤销独立扣分 | `最高可追回约 2.0 分` |
| 解锁证据等级 | `补证并核验通过后，预计可争取 1.0～2.0 分` |
| 改善现场表现 | `达到验收标准后，预计可提升 2.0～4.0 分` |
| 无规则关联 | 不显示分数，标记为“额外训练建议” |

不得使用“改完必得”“保证增加”“完成后直接加分”等确定性承诺。

### 3.3 正式计分待办与额外建议

- `正式计分待办`：至少关联一个有效的 `observationCode`、`criterionCode` 或 `dimensionCode`，并且能由当前版本评分规则完成情景复算。只有这类任务进入提分预测。
- `额外训练建议`：有训练价值但无法与当前评分规则建立稳定关联。它可以保留问题、方法和验收标准，但不进入单项或整体提分预测。

统一队列仍可同时展示两类内容，但顶部的“预计提升”和“预测分”只统计正式计分待办。顶部待办数量仍按去重后的完整队列统计，卡片应清楚区分“计分待办”和“额外建议”。

## 4. 提分区间计算

### 4.1 唯一计算权威

大模型只负责识别问题、提出整改方法和验收标准，不得产生最终展示分值。所有提分区间由 Python 评分规则引擎使用当前报告的同一套赛道、赛事、组别、规则版本和评分指纹计算。

### 4.2 三种情景

#### A. 独立扣分恢复

适用于 `hard_violation` 等已实际扣分且允许恢复的规则：

- 情景输入只撤销该独立违规；
- 重新运行同一规则引擎；
- `delta = 情景分 - 当前分`；
- 二元验收任务可返回相同上下界，例如 `2.0～2.0`，用户端仍表达为“最高可追回约 2.0 分”；
- 上限不得超过该扣分的 `maxRecoverablePoints`。

#### B. 证据等级解锁

适用于因证据等级不足而受限的评分点：

- 保守情景：证据提升到满足最低验收的下一级；
- 目标情景：证据提升到验收标准明确要求的等级；
- 两个情景分别通过规则引擎复算得到区间；
- 预测分不得超过当前表现所允许的能力上限，补材料不能伪装成现场表现提升。

#### C. 表现改善

适用于表达、节奏、演示稳定性、说服力、临场表现等：

- 待办必须绑定可评分的观测点或维度等级；
- 保守情景：相关观测点提升一个有效等级；
- 目标情景：提升到验收标准对应的目标等级；
- 两个情景分别复算，不允许直接使用大模型输出的 `expected_gain`；
- 若规则没有等级、权重或情景复算能力，该任务只能作为额外训练建议，不得显示分数。

### 4.3 单项区间

单项待办使用“只应用当前任务”的边际情景：

```text
taskLower = score(apply(task.minimumAcceptedState)) - currentScore
taskUpper = score(apply(task.targetAcceptedState)) - currentScore
```

约束：

- `0 <= taskLower <= taskUpper`；
- 预测总分不得超过 100；
- 区间保留一位小数；
- 规则复算结果小于 0 时按 0 处理；
- 相同观测点或同一来源问题先合并，再计算一次。

### 4.4 整体预测区间

整体预测必须将全部正式计分待办同时应用到一份评分输入副本，再执行一次完整复算：

```text
portfolioLowerScore = score(apply(all minimum accepted states))
portfolioUpperScore = score(apply(all target accepted states))
portfolioGainLower = portfolioLowerScore - currentScore
portfolioGainUpper = portfolioUpperScore - currentScore
```

整体预测禁止使用 `currentScore + 所有单项上限之和`。这样可以处理多个任务共同影响同一维度、封顶规则、证据上限和任务交互，避免重复计分。

## 5. 关联、去重与分值归属

每条任务增加稳定关联字段：

- `observationCodes`；
- `criterionCodes`；
- `dimensionCode`；
- `sourceIssueKey`；
- `scoreBudgetKeys`；
- `scoreLinkStatus = linked | unlinked`。

处理顺序：

1. 相同 `observationCode` 合并；
2. 否则相同 `sourceIssueKey` 合并；
3. 否则相同 `scoreBudgetKey` 不合并任务内容，但必须共享同一分值预算，组合复算时只占用一次；
4. 旧数据缺少结构化字段时，可用标题和问题指纹辅助找候选，但只有规则引擎确认关联后才能显示分数；
5. 不能确认关联的任务设置为 `unlinked`，不得进入提分预测。

## 6. 数据契约

### 6.1 单项分值影响

行动计划和训练任务统一增加：

```json

    "upper": 4.0,
```

## 7. 系统改造范围

### 7.1 Python 主评分逻辑

新增独立的分值影响服务，职责包括：

1. 从正式失分账本、观测点、维度分和行动计划建立关联；
2. 将行动计划分为正式计分待办和额外建议；
3. 为三种影响类型构造保守、目标情景；
4. 调用同一评分规则引擎进行单项和组合复算；
5. 生成版本化 `scoreImpact` 和 `scoreProjection`；
6. 将结果写入完成回调。

不得在前端或 Java 层根据标题、优先级、时长自行推断分数。

### 7.2 Java 数据库与报告 API

- `ai_score_report` 新增 `score_projection_json`；
- `action_plan_json` 中保留每条任务的 `scoreImpact`；
- 完成回调同时保存整体预测和单项影响；
- 报告 API 返回原始 JSON 和解析后的 `scoreProjection`；
- 非法或缺失 JSON 返回空对象，不影响历史报告读取；
- 数据库迁移保持幂等，并同步部署目录中的建表脚本。

### 7.3 用户前端

- 删除 `resolveNextBandTarget` 以及所有“下一档定位线”回退；
- 目标固定为 100，完整差距固定按 `100 - currentScore` 计算；
- 顶部读取后端 `scoreProjection`，不得由单项任务求和；
- 正式计分待办展示对应的区间文案；
- 未关联建议隐藏分数并显示“额外训练建议”；
- “本轮优先事项”继续按 P0/P1/P2 和影响区间排序，但不再表达为阶段目标；
- 结果页仍展示前三项，待办页展示完整去重队列。

## 8. 兼容与失败处理

- 历史报告没有 `scoreProjection` 时，仍显示当前分、满分 100 和完整差距；预测区域显示“待规则测算”，不得恢复成 60/70/85 分档。
- 单项 `scoreImpact` 缺失时不显示分数，不从标题或旧 `expected_gain` 猜测。
- 若评分规则复算失败，报告主分仍可正常展示，预测区域明确显示“提分预测暂不可用”。
- 规则版本、规则哈希或评分指纹变化后必须重新计算，不能沿用旧预测。
- 当前报告的预测不能直接带入下一轮；下一轮必须使用新视频、新证据和当时绑定的规则重新评分。

## 9. 测试与验收

### 9.1 Python

- 独立扣分恢复不能超过原扣分上限；
- 证据解锁不能突破表现上限；
- 表现改善必须来自观测等级情景，而不是模型 `expected_gain`；
- 无关联建议输出 `unlinked` 且无分数；
- 相同观测点只计算一次；
- 组合预测通过整体复算产生，证明它不等于单项上限简单求和；
- 所有输出包含计算版本、规则哈希和评分指纹。

### 9.2 Java

- 回调完整保存 `score_projection_json` 和行动计划内的 `scoreImpact`；
- 报告 API 返回解析后的整体预测；
- 空值和非法 JSON 兼容；
- 迁移脚本可重复执行。

### 9.3 前端

- 49.5 分报告固定显示满分 100、完整差距 50.5，不显示目标 60；
- 有整体预测时显示预测总分区间和预计提升区间；
- 没有整体预测时显示待测算，不生成阶段目标；
- 三种影响类型使用各自文案；
- `unlinked` 建议没有任何分数承诺；
- 结果页前三项、待办页全量和顶部完整计数保持正确；
- 所有分数展示均来自后端契约，前端不自行相加。

### 9.4 会话 26 回归

完成实现后使用现有结果数据重放，不重新分析视频：

- 顶部不再显示 60 分目标；
- 显示 49.5 / 100 和距离满分 50.5；
- O02 独立扣分任务继续显示最高可追回约 2 分；
- 其余行动计划只有在成功关联评分规则并完成情景复算后才显示区间；
- 无法关联的计划保留验收标准，但不显示分数；
- 顶部整体预测只能来自新组合情景结果。

## 10. 销售口径

对客户统一解释为：

> 平台始终按照 100 分展示完整提升路径。每个正式整改项都对应真实评分点，并给出达到验收标准后的保守提分区间；全部整改的预测分由同一赛事规则整体复算，不是把建议分数简单相加。预测用于指导训练，最终结果以重新路演后的正式评分为准。

## 11. 非目标

- 不承诺完成整改后必然达到某个分数；
- 不把 100 分描述成可保证兑现的结果；
- 不用大模型自由生成最终展示分值；
- 不向普通用户暴露后台原始模型分、影子分或复杂评分结构；
- 本次不改变 42 个赛道现有规则内容，只增加基于已绑定规则的情景复算和展示契约。
