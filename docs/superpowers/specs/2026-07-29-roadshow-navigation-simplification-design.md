# 路演页面导航简化设计

## 背景

在线会议和会议回放目前同时出现在主侧栏与“路演中心”二级菜单中，入口重复，并占用 230px 横向空间。用户希望路演相关页面只保留主侧栏入口，再通过页面内按钮完成在线会议与会议回放之间的切换。

## 目标

- 移除路演模块的整块二级菜单，让在线会议和会议回放内容区直接使用主侧栏右侧空间。
- 保留复盘改进、团队协作等其他模块的二级菜单。
- 在线会议页通过“查看回放”进入会议回放列表页。
- 会议回放列表页提供明确的“返回在线会议”按钮。
- 保持现有主侧栏当前态、会议业务流程、录制列表与回放详情路由不变。

## 已确认方案

采用工作区壳层按模块控制的方案：

- `WorkspaceShell.vue` 不再为 `roadshow` 模块渲染 `WorkspaceModuleNav`。
- `review` 与 `collaboration` 模块继续显示现有二级菜单。
- 路演相关路由不再获得 `has-module-nav` 布局类，顶部栏和内容区自动回到第二列，不留下空白栏。
- `OnlineMeeting.vue` 现有“查看回放”按钮继续跳转 `/my-recordings`，并通过自动化测试锁定该行为。
- `MyRecordings.vue` 页头操作区增加“返回在线会议”入口，跳转 `/online-meeting`。

## 页面与组件边界

### `WorkspaceShell.vue`

- 将 `hasModuleNav` 的显示范围收窄为 `review` 与 `collaboration`。
- 不改 `moduleGroup` 推断，因为主侧栏仍需把在线会议、会议回放和详情路由归入“现场讲解”当前态。
- 不用 CSS 隐藏二级菜单，避免保留不可见节点或 230px 空白列。

### `OnlineMeeting.vue`

- 保留现有页头“查看回放”按钮、文案和视觉样式。
- 保留现有 `goRecordings()` 方法及 `/my-recordings` 目标路由。
- 新增回归测试验证点击后确实到达会议回放列表页。

### `MyRecordings.vue`

- 在页头右侧操作区加入“返回在线会议”入口。
- 入口使用次级按钮视觉，与“刷新”按钮保持同一控件语言，但不与刷新状态绑定。
- 使用路由链接直接跳转 `/online-meeting`，支持键盘操作并保留准确的可访问名称。
- 窄屏下与现有页头操作区一起换行，不遮挡状态提示和刷新按钮。

## 路由结果

| 起点 | 操作 | 目标 |
| --- | --- | --- |
| `/online-meeting` | 点击“查看回放” | `/my-recordings` |
| `/my-recordings` | 点击“返回在线会议” | `/online-meeting` |

会议回放详情页 `/meeting-history/:id` 继续使用现有返回会议回放列表的入口，不新增重复按钮。

## 不在本次范围

- 不删除 `WorkspaceModuleNav.vue`，因为复盘与协作仍在使用。
- 不修改会议创建、加入、历史记录、录制加载或播放逻辑。
- 不修改会议回放详情页的返回逻辑。
- 不修改移动端底部导航、主侧栏导航名称或路由地址。

## 验证标准

1. `/online-meeting` 与 `/my-recordings` 均不渲染 `.workspace-module-nav`，工作区不包含 `has-module-nav` 类。
2. `/statistics` 与 `/project-team` 仍显示各自的二级菜单。
3. 在线会议页点击“查看回放”后到达 `/my-recordings`。
4. 会议回放页点击“返回在线会议”后到达 `/online-meeting`。
5. 两页主侧栏“现场讲解”仍保持当前项状态。
6. 页面没有新增横向滚动，桌面和窄屏页头操作区均可完整访问。
7. 相关自动化测试与生产构建通过。
