# 评分总结 · 全套信息架构与交互设计

> 在已确认的编辑叙事风格（Grok 风）之上，覆盖「评分总结」模块的**完整能力面**：主台、子页、抽屉、弹窗、状态机、与 AI 评分流的衔接。  
> **原则**：行动闭环为主、分数定心为辅；真数据不 invent；**少页面、人话标签**；深能力下钻而非能力平权导航。

---

## 0. 模块定位

**评分总结**不是七个报表页，而是备赛闭环里的一份「结果 + 待办」体验：

```
结果（我怎么样）→ 待办（先改什么 / 谁改）→ 依据（为什么这么判，按需）
  模拟评委 / 比上一轮 → 入口级，不是并列顶栏
```

### 0.1 对「8 分段」的否定（2026-07-09 修订）

原方案顶栏：总结 · 理解 · 证据 · 表达 · 现场 · 行动 · 评审团 · 对比 —— **不可取**。

| 问题 | 说明 |
|------|------|
| 能力平权 | 把后端模块名摆成导航，用户要先学系统语言 |
| 学习成本 | 8 个去处 ≈ 8 次决策；用户反感「页面多」 |
| 路径重复 | 表达/现场本质是「某条待办怎么练」，不该与「待办」并列 |
| 证据/理解 | 都是信任层「凭什么」，应合并 |
| 机器味文案 | 「证据链 / 规则观测 / 处方」不像学生备赛用语 |

**合并原则（营销 JTBD）**

1. 打开报告 5 秒：我怎么样？（结果）  
2. 接下来 10 分钟：改哪几件、谁改？（待办）  
3. 不服或要交差时：凭什么给这个分？（依据）  
4. 可选：换几位「评委人格」独立打分，和官方分差多少？（多维评委，入口不是顶栏主项）  
5. 有历史时可选：比上一轮好了吗？（对比，条件出现）

### 0.2 推荐顶栏：最多 3 项（已确认方向）

| 顶栏（人话） | 吞并的旧能力 | 不单独成页 |
|--------------|--------------|------------|
| **结果** | 原总结 + 画像摘要 + 关键时刻入口 + 比上一轮入口 | — |
| **待办** | 原行动 + 表达 + 现场（练法挂在每条待办上） | 表达页、现场页 |
| **依据** | 原理解（五维/规则）+ 证据 | 独立「证据链」顶栏 |

**非顶栏入口（卡片 / 按钮 / 条件显示）**

- **多维评委**（原 AI 评审团，见 §0.3.1）：结果页入口，**不是**模拟现场问答  
- **比上一轮**（原对比）：仅有 recovery / 历史分差时出现在结果页  
- **单条深潜**：抽屉（改法、录像片段、话术、站位）  
- **同步任务**：结果/待办上的主按钮 + 弹窗  

### 0.3 文案原则（去 AI 味）

| 避免（系统/AI 味） | 改用（大众备赛语境） |
|--------------------|----------------------|
| 证据链 / 锚点 | 录像片段 / 发言记录 / 评分依据 |
| 规则引擎观测点 | 评分卡在哪 / 这一项为什么扣分 |
| 处方 / 闭环工厂 | 待办 / 先改这几件 |
| 表达节奏 / 现场呈现 | 话怎么说 / 台上怎么演（作为待办里的「练法」） |
| AI 评审团 / 预演质疑 / 答辩题库（误解） | **多维评委** / 九位评委怎么看（见下） |
| 可追回分 | 大约还能涨 X 分（有数才说） |
| 结构化扣分 | 主要问题 |

### 0.3.1 AI 评审团 · 正确产品定义（以代码为准）

**不是**模拟现场问答、追问答辩。  
**是**多人格独立评分复核层。

| 机制 | 代码事实 |
|------|----------|
| 人格池 | 16 种评委人格（MBTI 码：ISTJ…ENTJ），见 `ai-scoring/app/services/jury/personas.py` `PERSONAS` |
| 抽取 | `select_personas(seed, count=9)`：按会话 seed 稳定随机，从池中抽 **9** 位（`AI_JURY_COUNT` 默认 9） |
| 评分方式 | 每位人格 **独立** 打分（各自 focus_dimensions + prompt_modifier），互不参考 |
| 汇总 | 去掉最高分与最低分后取 trimmed average（`aggregate_service.aggregate_judge_reports`） |
| 与官方分关系 | **不修改** 规则引擎/官方基础分；只给出评委均分与分差 |
| 附带输出 | 各人格关注点、共识问题、训练建议、维度分歧统计 —— 用途是「多角度怎么看这份路演」，不是生成现场问答剧本 |

**结果页入口文案建议（人话）**

- 标题：**多维评委**  
- 副文：从 16 种评委视角里抽 9 位，各自独立打分；官方分不变。  
- 页内结构：官方分 vs 评委均分（去极值）→ 9 位是谁、各打几分 → 他们共同卡住的问题 →（可选）训练建议  

**结果页位置（特色突出，不沉底）**

- **不要**放在结果页最底部 Explore 三卡之一（权重被稀释）  
- **不要**强行加第 4 个顶栏主项（会回到「标签太多」）  
- **推荐**：结果页叙事中前部——在「先改这三件」**之后**、能力画像**之前**，用整宽 **特色模块卡**（深色/强对比）展示：  
  - 平台特色标签  
  - 官方分 / 九位均分 / 分差  
  - 9 人格缩略 + 主 CTA「查看九位评委」  
- 理由：用户先定心、先看见行动，紧接着被特色能力「接住」；首屏滚动一小段即可看到，而非滚到页脚  

**禁止再写进设计/原型的误解**

- 「预演质疑 / 模拟答辩 / 答辩题库为主叙事」  
- 把评审团说成「模拟现场问答」

## 0.4 用户路径（收敛后）

```
定心（结果）→ 待办（改什么/谁改/怎么练）→ 依据（不服再看）
  → 可选：模拟评委、比上一轮、同步到任务
```

它承接三条上游入口，输出两条下游动作：

| 上游入口 | 路径 |
|----------|------|
| 上传视频评分 | `/ai-score-upload` → session → 报告 |
| 会议路演评分 | 会议结束 / AiScoreControl → session 或 meeting 报告 |
| 历史报告列表 | Statistics / ProjectTeam → by-session / by-report / by-meeting |

| 下游动作 | 去向 |
|----------|------|
| 同步团队任务 | `/project-team?workView=score` |
| 重新评分 / 再上传 | restart session 或 upload 新一轮 |

## 2. 信息架构（替换七 Tab 平权）

### 2.0 壳层决策（已确认 · 方案 B）

OREP 全局已是工作台（`WorkspaceShell` 左侧产品导航）。评分总结**不再**做「台中台」二级侧栏。

| 层级 | 职责 | 形态 |
|------|------|------|
| 全局侧栏 | 产品模块：首页 / 路演 / **评分总结** / 任务… | 唯一侧栏 |
| 报告情境顶栏 | 本份报告内：总结 · 理解 · 证据 · 表达 · 现场 · 行动 · 评审团 · 对比 | **分段胶囊**（非工具七 Tab、非第二侧栏） |
| 主内容区 | 满幅叙事（总结）或页内 master-detail（行动/证据等） | 无永久模块侧栏 |
| 深潜 | 单条处方、证据帧 | **抽屉** |

### 2.1 路由建议（兼容旧链接）

```
/ai-score/report/:sessionId
  /summary          ← 主台（原 overview，可 redirect）
  /understand       ← 能力与规则（原 dimensions 升级）
  /evidence         ← 证据时刻
  /train/voice      ← 表达训练
  /train/stage      ← 现场训练（原 presentation）
  /act              ← 行动工作台（原 actions）
  /jury             ← 评审团
  /compare          ← 轮次对比（新增，有数据才入口）
```

兼容：`/overview` → `/summary`；旧七 path 全部 301/redirect 到新 path。  
`report-id`、`meeting` 三套父路由保持。

### 2.2 导航模型（方案 B）

```
┌──────────┬──────────────────────────────────────────────┐
│ 全局侧栏  │  评分总结  62.3  项目名     [同步] [···]     │
│ 首页     │  (总结)(理解)(证据)(表达)(现场)(行动)(评审团)  │ ← 情境分段
│ 路演     ├──────────────────────────────────────────────┤
│ PPT      │                                              │
│ 评分总结 │           满幅主内容（叙事 / 页内分栏）          │
│ 任务…    │           抽屉从右侧滑出，不占导航              │
└──────────┴──────────────────────────────────────────────┘
```

- **只有一层产品导航**；报告内是「情境」不是「第二个 OS」
- 总结页吃满内容区，保持大字留白
- 理解/证据/行动等可用页内左右栏（内容布局 ≠ 导航侧栏）
- 主台 Explore / 处方操作 = 切分段或开抽屉
- 移动端：全局底栏 + 报告分段横滑

### 2.3 用户主路径（营销漏斗感）

1. **落地 5 秒**：分数 + 一句话 + 今日 3 处方  
2. **10 分钟行动**：按教练改 / 派任务  
3. **需要信服时**下钻证据与规则  
4. **彩排前**进训练与评审团  
5. **改完后**复评对比  

禁止默认路径：先看 KPI 墙 → 再找问题。

## 6. 理解域

### 6.1 能力与规则 · `/understand`（原五维）

**布局（Workbench）**

```
左：维度列表（名 · 分/满分 · 短板标记）
主： 
  Chapter「当前维度」
  一句短板叙事（取 dimension.improvement 首条，无则隐藏）
  规则观测点（编辑列表，非密表）：名称 · 证据等级 · 是否封顶 · 理由

```

**呈现差异（相对现状）**

- 去掉 8 列表格墙 → **折叠编辑行**  
- 观测点用 E 级标签 + 一句话 modelReason

**交互**

| 操作 | 行为 |
|------|------|

### 6.2 证据时刻 · `/evidence`

**页面问题**：「AI 凭什么判，我缺什么证据。」

**布局**

## 7. 训练域

### 7.1 表达 · `/train/voice`

**页面问题**：「哪句话不稳，换成什么说，怎么算练完。」

**布局**

```
左：问题句队列（来自 speech pauses/fillers + coaching moments；无 coaching 仍可显示 speech 结构化问题）
主：原句 | 建议话术（仅真实 coaching/字段；无则「待生成训练建议」+ 生成按钮）
   节奏提示：仅当 coaching 返回节奏字段时展示，否则不写死 20 秒剧本
下：验收（真实 acceptance，否则隐藏）
侧：训练仪表盘摘要（语速/停顿/口头禅 — 真实 speech_quality）
```

**交互**

| 操作 | 行为 |
|------|------|
| 生成/刷新表达训练 | `loadExpressionCoaching(true)`；meeting 缺失时说明限制 |
| 复制话术 | clipboard |
| 加入行动 | TeamSync 或写入 act 列表 |
| 看证据 | EvidenceDrawer 按时间 |

**禁止**：用 index%N 硬编码问题类型装真；无数据就空。

### 7.2 现场 · `/train/stage`

**页面问题**：「哪个镜头有问题，站位/屏幕/互动怎么改。」

**布局**

```
左：问题镜头队列（contradictions + per_frame 风险 + presentation coaching）
主：大图舞台 + 诊断（原因/改法）+ 验收
侧：音画冲突摘要（fusion，有则显）
```

**交互**：同表达 — 生成呈现训练、复制、推入行动、证据关联。

## 8. 行动域 · `/act`

**这是闭环页，不是建议页。**

**布局**

## 9. 预演域 · `/jury`

**页面问题**：「不同评委会盯什么，共识质疑是什么，答辩怎么准备。」  
**硬规则**：评审团**不修改**官方分；文案必须始终可见。

**状态**

| 状态 | UI |
|------|-----|
| empty | 大标题 + 「生成评审团复核」 |
| processing | State 文案 + 禁用按钮 |
| error | 原因 + 重试 |
| ready | 完整预演台 |

**ready 布局**

```
上：官方分 vs 评审均分 vs 分差（真字段；缺则隐藏均分）
   争议触发原因列表
中左：评委人格列表（分 · 立场标签来自真实字段，避免纯启发式时用中性「已复核」）
中主：当前评委 — 关注点 / 风险 / 训练建议 / 证据关切
下：共识问题 · 分歧焦点 · 答辩题清单
```

**交互**

| 操作 | 行为 |
|------|------|
| 生成复核 | startJuryReview + 轮询 |
| 切换评委 | 更新主区 |
| 某共识 → 行动 | 深链 `/act` 搜索 |
| 答辩题复制 | clipboard |

**不做**：未接线的「查看示例」「生成回应话术」除非接 API；勾选清单不持久则标明「仅本页备忘」。

## 12. 与 AI 评分流的衔接图

```
[上传/会议] → create+start session
      → status 轮询（State Stage）
      → completed + reportId
      → GET reports/by-session  ──► 主台 & 全站数据
      → visual-frames / evidence-bundle
      → coaching（meeting 键，可空）
      → jury 可选（异步，不挡主台）
      → 用户行动 createTeamTasks
      →（可选）restart / 新 upload → compare
```

**前端数据层不变**：继续 `useAiScoreReport` 单例 provide；各页 presentation 函数只做映射。  
建议扩展：

- `buildUnderstandPresentation`  
- `buildEvidencePresentation`  
- `buildTrainPresentation`  
- `buildActPresentation`  
- `buildJuryPresentation`  

规则同 overview：**不 invent**。

## 13. 逐页「首屏必须有 / 禁止有」

|----|----------|------|

## 15. 验收标准（完整功能）

1. 用户从上传/会议进入，评分中看到阶段叙事，完成后落主台。  
2. 主台 30 秒内能说出「分 + 今天三件事」。  
3. 任意处方可：看证据、看详情、派任务（真 API）。  
4. 理解/证据可互相跳转，证据可复制。  
5. 训练页在无 coaching 时不伪造建议。  
6. 评审团明示不改官方分；生成/轮询/失败完整。  
7. 旧七 URL 可进；无顶栏七 Tab 平权。  
8. 全路径无硬编码示范项目文案。

## 16. 设计哲学备忘（给实现的人）

- **少即是多**：一章一意；指标是配角。  
- **问题是原子**：不是「字段页」。  
- **信任可下钻**：证据与规则在需要时出现。  
- **行动可协作**：个人处方 → 团队任务一键。  
- **诚实空态**：比假智能更像专业产品。
