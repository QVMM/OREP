# 训练详情任务书与右侧行动栏设计

## 目标

把训练详情页从“任务内容、流程状态和辅助入口混排”重构为清晰的双栏结构：左侧专注阅读任务书，右侧只负责附件操作和当前提交行动。

## 左侧任务书

主卡标题由“训练任务”改为“任务书”，移除训练进度步骤条和提交状态横幅。

内容顺序固定为：

1. 任务标题：使用训练日标题 `data.title`。
2. 任务概要：明确标注“任务概要”，展示 `data.summary`，为空时使用现有兜底文案。
3. 正式任务描述：明确标注“正式任务描述”，优先展示净化后的 `data.contentHtml`；为空时展示 `primaryTask.description`；两者都为空时显示明确空状态。
4. 交付要求：保留必交和可选状态；为空时保留说明性空状态。
5. 同日其他任务：维持当前条件展示，位于任务书末尾。

任务概要、正式任务描述和交付要求使用分节与分隔线，不增加嵌套卡片。

## 右侧任务附件

移除整张周导航卡，将任务附件从左侧任务书移动到右侧首张卡，标题为“任务附件”。

附件列表每行包含文件类型、文件名和文件大小，并提供两个含义明确的独立操作：

- “预览”：沿用现有 `FilePreview`，在当前页面打开附件预览。
- “下载”：使用附件 `fileUrl` 和原始 `fileName` 下载文件；文件地址缺失时不提供可点击的下载入口。

附件为空时保留简短空状态“老师暂未上传任务附件。”，避免右侧结构跳变。

删除：

- 周标题、日期范围和 7 天日期切换。
- “训练计划”入口。

## 右侧提交行动

“任务与提交”改为更直接的“提交成果”。仅保留：

- 当前提交状态。
- 截止时间或提交时间。
- 一句当前状态说明。
- 与当前状态匹配的主要操作。

操作规则：

- 未提交：主按钮“去提交成果”。
- 已提交、等待批改：主按钮“查看我的提交”。
- 已有反馈且无需修改：主按钮“查看老师反馈”，次按钮“查看我的提交”。
- 需要修改：主按钮“提交新版本”，次按钮“查看老师反馈”和“查看我的提交”。

删除：

- 右侧交付要求、已提交材料明细。
- “查看完整任务说明”。
- “先看课程”。
- 独立“老师反馈”卡片。
- 独立“接下来可以做”卡片及“去练一场路演”。

## 数据与降级

- 不修改后端接口或数据库。
- `contentHtml` 继续经过 DOMPurify 净化。
- 正式任务描述为空时使用纯文本任务描述，再为空时显示“老师暂未填写正式任务描述。”。
- 附件、交付要求和反馈均按现有数据条件显示，不虚构内容。
- 附件预览和下载共用现有 `fileUrl`，下载文件名优先使用 `fileName`。

## 响应式

- 桌面端保持主区和窄右栏。
- 桌面端右侧“任务附件 + 提交成果”作为一个整体保持吸顶。内容滚动区已有 40px 顶部内边距，因此侧栏使用 `top: 0`，最终与顶部栏底部保持 40px 视觉间距，不重复叠加偏移。
- 右侧最大高度按可用视口计算；内容超过可用高度时仅右侧区域内部滚动。
- 1080px 以下按现有规则变为单列，任务书在前，任务附件和提交行动在后。
- 1080px 以下取消右侧吸顶与内部滚动，恢复普通文档流。
- 不引入新的横向滚动区域。

## 验收标准

- 主任务卡标题为“任务书”，页面不存在训练进度步骤条。
- “任务概要”和“正式任务描述”标签均清晰可见。
- 交付要求只在左侧任务书出现，任务附件只在右侧出现。
- 右侧只有任务附件和提交行动两张卡。
- 每个具备文件地址的附件都能独立预览和下载。
- 右侧不存在周导航、训练计划、完整任务说明、先看课程、独立反馈卡和接下来行动卡。
- 桌面端滚动页面时，右侧区域顶部与顶部栏底部保持 40px 间距。
- 900px 宽度下右侧不吸顶且页面无横向溢出。
- 未提交状态下只有一个主行动“去提交成果”。
