# 教师端真实批改队列设计

## 目标

将教师工作台当前演示批改队列接入真实项目任务提交数据，形成“查看待批 -> 阅读提交与历史版本 -> 给出审核意见 -> 自动进入下一条”的完整闭环。

本阶段只解决项目任务提交审核，不扩展路演、AI 待办或未交提醒的真实数据接口。

## 业务规则

### 队列范围

- `TEACHER` 只查看本人指导团队的提交。
- 团队满足任一条件即归当前教师指导：
  - `project_team.mentor_id = 当前用户`。
  - 当前用户在 `project_team_member` 中的角色为 `MENTOR`。
- `ADMIN` 和 `SCHOOL_ADMIN` 可查看当前租户全部团队的提交。
- 所有查询必须通过 `project_team.tenant_id` 做租户隔离。

### 版本规则

- 同一任务只有最新提交版本可以进入待批队列。
- 详情页展示同一任务的历史版本，按版本号和提交时间倒序排列。
- 历史版本只读，不允许审核。
- 最新版本只有状态为 `PENDING_REVIEW` 或 `REVIEWING` 时可以审核。
- 已审核版本不可重复审核，防止重复点击覆盖结果。

### 审核结果

- `APPROVED`：提交状态变为已通过，任务状态变为 `DONE`。
- `CHANGES_REQUESTED`：提交状态变为需修改，任务状态变为 `CHANGES_REQUESTED`。
- `REJECTED`：沿用现有行为，任务状态变为 `CHANGES_REQUESTED`。
- 审核成功后保留现有能力画像刷新和项目阶段同步行为。

## 接口设计

### 获取教师待批队列

`GET /api/teacher/review-queue`

返回当前身份可见范围内，每个任务最新且待审的提交。队列按最早提交优先排列，便于教师先处理等待最久的内容。

每项至少包括：

- 提交 ID、状态、版本、类型、正文、提交时间。
- 附件和链接数量。
- 任务 ID、标题、类型、优先级、截止时间。
- 团队 ID、团队名称。
- 提交人 ID、姓名。
- 可选的集训营和训练日信息。

### 获取提交详情

`GET /api/teacher/submissions/{submissionId}`

返回：

- 当前提交完整信息。
- 附件和链接。
- 任务交付要求。
- 团队、提交人、审核人信息。
- 可选的集训营和训练日信息。
- 同一任务的历史版本摘要。
- `canReview`，由后端根据身份、最新版本和状态统一计算。

跨租户或不属于当前教师指导范围的提交统一按不存在处理，避免泄露记录是否存在。

### 审核提交

继续使用：

`POST /api/project-teams/submissions/{submissionId}/review`

服务层增加约束：

- 只能审核当前任务最新版本。
- 状态必须为 `PENDING_REVIEW` 或 `REVIEWING`。
- 教师只能审核本人指导团队；管理员可审核租户内全部团队。
- 原有具备 `REVIEW_SUBMISSION` 权限的队长行为保持不变，但同样受最新版本和待审状态约束。

## 代码结构

### 后端

- 新增 `TeacherReviewController`，负责 `/api/teacher/**` 的读取接口。
- 在 `ProjectTeamService` 增加教师队列和详情查询，复用现有提交 SQL、附件和链接组装逻辑。
- 在现有 `reviewSubmission` 中增加最新版本、待审状态和教师指导范围校验。
- 不新建独立 Service，避免为单一闭环重复提交数据访问逻辑。

### 教师端

- 在现有 API 层增加待批队列和提交详情请求。
- `WorkbenchView.vue` 登录后优先加载真实待批队列。
- 未登录或明确演示模式继续使用现有 mock，确保展示环境可用。
- 选择队列项时加载真实详情和历史版本。
- 审核成功后从当前队列移除该项并自动选中下一项。
- 请求失败时保留当前输入并显示错误，不提前从队列移除。

## 错误处理

- 非教师、非管理员调用教师读取接口返回 403。
- 提交不存在、跨租户或不在教师指导范围内返回 404。
- 审核旧版本返回 409。
- 重复审核已完成版本返回 409。
- 非法审核状态返回 400。
- 队列为空返回空数组，不视为错误。

## 测试策略

### 后端测试

- Controller 正确传递 `tenantId`、`userId` 和 `role`。
- 教师只获得本人指导团队数据。
- 管理员获得租户内全部数据。
- 跨租户数据不可见。
- 同一任务只有最新待审版本进入队列。
- 详情返回附件、链接、要求和历史版本。
- 旧版本不可审核。
- 已审核版本不可重复审核。
- 最新待审版本审核后正确更新提交和任务状态。

### 前端验证

- 登录状态加载真实队列，演示状态继续加载 mock。
- 队列为空、加载失败和详情失败均有明确状态。
- 审核成功后自动进入下一条。
- 审核失败时当前项和教师意见不丢失。
- `npm run build` 通过。
- 浏览器完成真实队列的桌面和移动端回归，无控制台错误和横向溢出。

## 风险与兼容

- 历史团队可能只维护 `mentor_id` 或只维护 `MENTOR` 成员关系，查询同时兼容两种归属，不执行数据迁移。
- 一个项目任务可能映射多个训练日。接口把训练信息作为可选上下文，不让重复映射产生重复队列记录。
- 本阶段不修改数据库结构。若实际数据量导致队列查询变慢，再单独增加 `(team_id, status, created_at)` 索引。

## 验收标准

1. 教师登录后只看到本人指导团队的最新待审提交。
2. 教师可在工作台查看提交正文、附件、链接、交付要求和历史版本。
3. 审核成功后该提交离开队列，下一条自动选中。
4. 教师无法审核其他教师团队、旧版本或已审核版本。
5. 管理员仍能处理当前租户全部团队。
6. 未登录演示页面不受影响。
