# OREP 用户前端重设计方案

日期：2026-06-25

## 目标

在现有用户端功能基础上，重设计 OREP 用户前端。第一阶段覆盖主入口和一级主流程页面：首页、课程学习、考试系统、在线会议、项目团队、智能PPT、数据分析。会议房间、AI评分报告、PPT编辑器等复杂工作台暂不做完整重绘，但继承新的导航、色彩、按钮、卡片和状态规范。

设计方向已确认：

- 双品牌过渡：保留 OREP 系统识别，用户侧主心智强化“竞赛备赛大脑”。
- 主色使用橙色，参考“启发&继学”的高能橙，但只做品牌和状态点睛。
- 页面气质为规范、简约、精细、大气，不做游戏化地图和过度装饰。
- 所有页面取消英文标题。页面标题、分区标题、状态文案统一中文。
- 首页采用已确认的 `homepage-final-v1.html` 作为设计基准。

## 现有项目理解

用户端位于 `frontend/user`，技术栈为 Vue 3、Vite、Pinia、Vue Router、Element Plus，并混有 React/Konva 的 PPT 编辑能力。当前路由已覆盖首页、课程、考试、会议、团队、脚本、PPT、数据、个人中心等功能。

当前 UI 已有 `OrepTopNav`、`OrepPageShell`、`OrepMobileNav`、`BaseCard`、`BaseButton` 和一套 `apple` 组件，但视觉风格混杂：部分页面偏 Apple/蓝色 SaaS，部分页面偏深色科技感，部分复杂页面单文件过大。重设计应优先建立统一设计系统和页面模板，再逐页迁移。

## 视觉系统

### 品牌

顶部品牌显示：

- 主标题：竞赛备赛大脑
- 辅助识别：OREP / AI 路演训练与成长平台
- Logo：橙色 OREP 标记，保留 OREP 连续性

导航保留完整一级入口：

- 首页
- 课程学习
- 考试系统
- 在线会议
- 项目团队
- 智能PPT
- 数据分析

现有“准备”导航不再作为一级抽象词出现。脚本、资源、PPT 历史等归入智能PPT或相关页面内部入口。

### 色彩

核心色彩：

- 主橙：`#F36B17`，用于 Logo、当前状态、重点进度、轻量提示。
- 主文本：接近黑色 `#151515`。
- 主操作按钮：黑色背景、白色文字。
- 背景：白色为主，局部使用 `#FFF8F3` 作为当前状态浅橙底。
- 边框：浅灰 `#E9E9E9`。
- 成功：绿色，仅用于在线、完成、正常状态。
- 风险：红色，仅用于待处理、告警、错误状态。

橙色不得大面积铺满页面。它是品牌点睛，不是整页背景。

### 组件规则

卡片：

- 白底、细边框、低阴影。
- 圆角以 12px 到 18px 为主。
- 内容密度适中，不做大面积空白。
- 当前项可使用浅橙背景。

按钮：

- 主按钮：黑底白字。
- 次按钮：白底灰边框。
- 当前状态或轻提示使用橙色，不用橙色替代所有主按钮。

状态标签：

- 当前/进行中：橙色文字 + 浅橙底。
- 已完成：绿色。
- 未开始/待处理：灰色或红色，按业务严重程度区分。

文本：

- 全站取消英文 eyebrow 标题。
- 页面标题使用中文大标题。
- 分区标题短而具体，如“继续学习”“今日学习计划”“备赛路径”。

## 首页设计

首页基准文件：

`/Users/liuyixing/项目/OREP/.superpowers/brainstorm/7346-1782323770/content/homepage-final-v1.html`

首页结构：

1. 顶部导航
2. 运营轮播
3. 下一步推荐
4. 通知条
5. 三块概览：我的进度、本周计划、团队协作
6. 备赛路径

### 运营轮播

轮播承担运营宣传职责，不直接替代任务推荐。内容包括训练营、赛事阶段、平台能力、活动通知。轮播图应有真实或拟真的白色办公备赛场景，避免抽象渐变和过度科技感。

轮播包含：

- 中文活动标签
- 大标题
- 简短说明
- 黑色主按钮
- 白色次按钮
- 关键业务标签，如团队任务、待复盘、路演评分
- 分页点
- 右侧图像或拟真设备区域

### 下一步推荐

下一步推荐紧接轮播下方，是首页最重要的行动入口。推荐对象可以是课程、测评、团队任务、PPT、复盘。推荐条展示：

- 标题：下一步推荐
- 辅助说明：Agent 已排序
- 推荐动作名称
- 进度或上下文
- 预计用时
- 开始按钮

### 通知条

通知条用于轻量赛事或团队提醒。它不是公告栏，不堆叠多条。首页只展示一条最重要通知，可跳转详情。

### 三块概览

我的进度：

- 圆形总进度
- 已完成模块
- 学习时长
- 距阶段目标天数
- 底部进度条

本周计划：

- 周一到周五五列
- 彩色小点表示类型
- 每天展示任务名和时间
- 右上角“查看全部”

团队协作：

- 团队成员数
- 任务总数
- 待处理数
- 底部显示材料待审核、会议待确认等轻量状态

### 备赛路径

备赛路径保留为规范模块，不做复杂连线和游戏化地图。四个阶段：

1. 学习
2. 测评
3. 协作
4. 交付

每张阶段卡片：

- 左上角阶段编号
- 右上角阶段状态
- 中部标题和描述
- 左下角业务摘要，如 `3 个资源 · 1 个未完成`
- 右下角圆形箭头入口
- 当前阶段使用浅橙底和橙色入口

## 课程学习模块

课程模块需要按完整学习产品设计，不能只做课程卡片列表。基准文件：

`/Users/liuyixing/项目/OREP/.superpowers/brainstorm/7346-1782323770/content/course-module-full-design.html`

### 课程列表页

布局：

- 保留全站导航栏。
- 顶部继续学习区优先展示当前课程。
- 左侧为可滚动、可折叠分类树。
- 右侧为筛选条和课程卡片网格。

分类策略：

- 分类很多时使用左侧列表，而不是顶部挤满标签。
- 分类支持分组折叠、分组计数、当前分类高亮。
- 分类区顶部提供搜索课程。
- 移动端改为分类抽屉。

课程卡片：

- 必须有封面图或封面色块。
- 展示课程状态、课程标题、简介、进度条、章节数、资料数。
- 左下角放业务摘要。
- 右下角放圆形入口。
- 当前学习课程使用浅橙底或橙色进度。

### 课程详情页

课程详情页包含：

- 全站导航栏
- 面包屑或返回课程列表
- 课程封面头图
- 课程标题、分类、简介
- 主按钮：继续学习/开始学习
- 课程章节列表
- 学习进度卡
- 课程资料卡
- 课后练习入口

章节列表要明确显示当前学习、未开始、已完成状态，并给当前章节主操作。

### 播放页

播放页包含：

- 全站导航栏或压缩版导航栏，不能完全省略。
- 视频播放区。
- 课程标题和本节说明。
- 章节目录。
- 学习笔记。
- 课程资料。
- 课后动作。
- 下一节入口。

进度要区分：

- 课程总进度
- 章节完成进度
- 当前视频播放进度
- 今日学习计划完成度

这些进度不能混用一条进度条。

### 课程状态

必须覆盖：

- 无课程
- 无资料
- 未开始
- 学习中
- 已完成
- 加载中
- 加载失败
- 网络失败后重试

## 考试系统

考试系统采用内容列表模板，但更偏“测评任务中心”。

页面结构：

- 顶部标题：考试系统
- 顶部概览：可参加考试、错题数、收藏题、最近分数
- 筛选：全部、待完成、已完成、模拟测评、错题复练
- 主区：考试卡片列表
- 右侧：今日测评建议、错题复盘入口

考试卡片展示：

- 试卷标题
- 题量
- 预计时长
- 难度或赛道
- 完成状态
- 最近成绩
- 主操作：开始考试/继续考试/查看结果

错题本和收藏题保持独立子页面，但视觉继承：白底、细边框、中文标题、黑色主按钮、橙色当前状态。

## 在线会议

在线会议采用操作工作台模板。

页面结构：

- 顶部标题：在线会议
- 指标：参与记录、进行中、已结束
- 左侧主卡：会议接入
- 右侧主卡：最近会议
- 下方可选：创建会议室、会议历史、参会说明

会议接入卡：

- 会议号输入
- 入会密码输入
- 记住参会信息
- 加入会议按钮
- 最近加入提示

最近会议列表：

- 会议标题
- 日期/时间
- 参与人数
- 状态：进行中/已结束
- 操作：进入/复盘/查看

会议房间 `/meeting/:id` 暂不全面重绘，但需要继承新的按钮、状态、面板和中文标题规范。

## 项目团队

项目团队采用数据工作台模板。由于现有页面功能复杂，第一阶段重构重点是信息层级，而不是删减功能。

页面结构：

- 顶部标题：项目团队
- 主按钮：分配任务
- 指标条：团队成员、任务总数、交付物、路演评分
- 主区：任务看板
- 侧栏：团队成员
- 下方扩展：交付物、路演复盘、能力证据

任务看板：

- 任务标题
- 负责人
- 截止时间
- 任务状态
- 交付物状态
- 操作入口

成员栏：

- 头像
- 姓名
- 岗位
- 在线状态
- 当前任务数

复杂的教师观察、能力雷达、路演记忆等模块不在首页级页面首屏堆满，放入下方分区或标签。

## 智能PPT

智能PPT采用操作工作台模板，但要保留生成流程的专业感。

一级页结构：

- 顶部标题：智能PPT
- 左侧：创建任务/上传材料/选择模式
- 右侧：生成流程、材料完整度、历史任务
- 下方：模板库、最近生成、PPT 讲稿联动

创建任务区：

- 路演PPT
- 课程/教学PPT
- 从完整材料生成
- 从想法补全生成
- 上传材料
- 补充说明
- 开始生成

状态展示：

- 材料待上传
- 材料诊断中
- 内容卡片待确认
- 设计渲染中
- 生成完成
- 生成失败

现有 `PptEditor.vue` 是复杂工作台，第一阶段不强行拆成简单页面，但应逐步抽离为：左侧控制区、中部预览区、右侧反馈/日志区，并统一视觉规范。

## 数据分析

数据分析采用数据工作台模板。

页面结构：

- 顶部标题：数据分析
- 时间范围选择
- 指标条：平均评分、完成路演、重复问题、下一步行动
- 主图：评分趋势
- 右侧：下一步建议
- 下方：维度雷达、问题分布、最近路演、闭环状态

数据呈现原则：

- 图表背景简洁，不使用深色科技感。
- 关键数据用黑色大数字。
- 变化趋势用橙色或绿色。
- 行动建议必须可点击进入任务、课程、PPT或复盘。

## 复杂页面继承规则

以下页面暂不完整重绘，但需要继承设计系统：

- 会议房间
- AI评分报告
- PPT编辑器
- PPT历史详情
- 脚本编辑器

继承内容：

- 中文标题
- 黑色主按钮
- 橙色当前状态
- 白底细边框卡片
- 统一的错误、空态、加载态
- 全站导航或明确的返回入口

复杂页面可保留工作台密度，但不再使用大量英文小标题、深色科技背景和装饰轨道。

## 数据流与交互

重设计不改变后端 API 合同，优先复用现有请求逻辑：

- 首页继续使用 `/api/home/dashboard`。
- 课程继续使用 `/api/courses` 和课程详情接口。
- 考试继续使用 `/api/exams`、错题、收藏接口。
- 会议继续使用会议创建、加入、历史接口。
- 团队继续使用项目团队相关接口。
- PPT继续使用现有 PPT 任务、模板、历史接口。
- 数据分析继续使用 `/api/statistics/overview`。

新增前端层抽象：

- 页面级布局组件：标准页面壳、标准标题区、标准指标条。
- 业务卡片组件：课程卡片、任务卡片、会议记录、考试卡片。
- 状态组件：空态、错误态、加载骨架、状态标签。
- 进度组件：圆形进度、线性进度、播放进度。

## 错误与边界状态

每个一级页面都必须设计：

- 加载骨架
- 空数据状态
- 接口失败状态
- 重试入口
- 无权限状态
- 移动端窄屏状态

错误提示不应只依赖 Element Plus Message。页面主体要有可恢复的错误区域，用户能重新加载或回到上一步。

## 响应式规则

桌面端：

- 最大内容宽度约 1440px。
- 顶部导航固定。
- 首页和一级页面使用 30px 左右页边距。
- 两栏/三栏布局优先。

平板端：

- 导航保留核心入口，部分右侧项目状态可收起。
- 卡片从三列变两列。
- 课程分类可保持左侧但宽度收缩。

移动端：

- 使用底部导航或移动导航。
- 顶部导航简化。
- 首页模块单列堆叠。
- 课程分类进入抽屉。
- 播放页章节和笔记进入底部折叠面板。

## 测试与验收

视觉验收：

- 首页与 `homepage-final-v1.html` 保持一致的视觉标准。
- 全站不出现英文标题式 eyebrow。
- 橙色只作为点睛，不形成满屏橙。
- 每个一级页面首屏都有清晰主操作。
- 每个卡片右下或底部有自然收口，不出现大块空白。

功能验收：

- 现有路由不丢失。
- 导航高亮逻辑正确。
- 登录态和未登录跳转不变。
- 原接口数据能映射到新 UI。
- 课程、考试、会议、团队、PPT、数据分析的主要动作可完成。

技术验收：

- `npm run build` 通过。
- 核心页面桌面和移动端截图检查。
- 关键接口失败时有页面级错误态。
- 课程播放页区分课程进度、章节进度、播放进度。
