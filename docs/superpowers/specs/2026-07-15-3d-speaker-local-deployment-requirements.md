# 3D-Speaker 本地部署环境与资源要求

日期：2026-07-15

## 1. 结论

Windows 和 macOS 都可以作为竞赛大脑的用户端，上传录像或参加在线路演不要求用户电脑运行人物识别模型。3D-Speaker 应运行在平台私有部署环境中的独立评分节点，通过本机文件或内网流接收音视频证据。

当前代码和真实长视频已在 Apple Silicon Mac 上跑通。正式生产推荐 Linux x86_64；Windows 10/11 推荐通过 WSL2、Linux 容器或 Linux 虚拟机运行，不承诺 Windows 原生 Python 环境直接生产可用。

## 2. 操作系统兼容矩阵

| 环境 | 当前结论 | 适用场景 | 说明 |
|---|---|---|---|
| macOS Apple Silicon | 已实测可运行 | 开发、演示、单任务私有部署 | 当前 M4/24GB 已完成 55 分钟真实视频验证 |
| macOS Intel | 理论可运行，尚未门禁验证 | 开发 | 上线前须重新跑安装、性能和准确率门禁 |
| Windows 10/11 原生 | 当前不作为生产支持项 | 用户端 | 上游安装脚本和当前适配器依赖 Bash、POSIX 进程与软链接语义 |
| Windows 10/11 + WSL2 | 可支持，须独立验收 | 本地私有部署 | 推荐 Ubuntu 22.04/24.04；使用 NVIDIA 时配置 WSL2 CUDA |
| Linux x86_64 | 推荐 | 正式生产 | 容易标准化部署、监控、限流和 GPU 驱动 |

## 3. 已测资源数据

测试对象为 54 分 30 秒、720×406、24fps 的真实路演录像。

| 项目 | 实测值 |
|---|---:|
| 固化运行目录 | 约 1.7GB |
| 其中模型权重 | 约 345MB |
| 其中 Python 运行环境 | 约 1.4GB |
| 60 秒任务完整进程树峰值内存 | 约 2.62GB |
| 55 分钟任务处理时间 | 16 分 29.7 秒 |
| 当前单机并发 | 每 worker 1 个任务 |

2.62GB 是人物识别任务自身的峰值，不包含 Java 服务、主 Python 评分服务、MySQL、Redis、操作系统页缓存和监控。因此不能据此把整机最低内存写成 3GB。

## 4. 推荐部署档位

### 开发与演示节点

- CPU：8 核以上，Apple Silicon 或 x86_64。
- 内存：最低 16GB，推荐 24GB。
- 磁盘：至少预留 10GB；真实业务还需额外容纳临时音频、代理视频和结果文件。
- 并发：1。
- 说明：适合开发和单任务演示，不作为高并发 SLA 承诺。

### 正式 CPU 节点

- CPU：12 至 16 个高性能核心。
- 内存：32GB。
- 磁盘：至少 20GB 可用空间，临时媒体目录另按峰值任务量配置。
- 并发：默认 1；完成同机双任务压力门禁后才允许提高。
- 说明：当前 Mac 实测 55 分钟视频为 16 分 29.7 秒，处于 40 分钟保护上限以内。

### 正式 GPU 节点

- 操作系统：Linux x86_64。
- GPU：NVIDIA，建议 8GB 以上显存。
- CPU：8 至 16 核。
- 内存：32GB。
- 并发：从 1 开始，按显存峰值、端到端延迟和准确率测试逐级放开。
- 说明：GPU 是达到更低延迟的推荐路线，但必须用同一批真实视频重新完成准确率和延迟门禁，不能只依据理论加速比上线。

## 5. 网络、隐私与 OSS

- 运行期不需要 OSS，也不要求视频或音频具有公网 URL。
- 上传视频直接读取平台私有存储文件；在线路演使用内网音视频分片或会后合并文件。
- 模型权重只在部署或升级时下载，固化后可以断网运行。
- 若客户环境完全离线，应通过离线安装包导入固定版本代码、依赖和权重，并校验清单哈希。
- 现有云端 ASR 若继续使用，属于独立证据分支；3D-Speaker 本地人物归属本身不依赖 OSS。

## 6. 架构边界

3D-Speaker 只负责把 ASR 片段和人物证据关联，不产生评分，也不修改已有评分引擎的分数。音频、画面和口型是人物归属证据；正式得分仍由现有版本化赛道评分规则计算。

上传视频和在线路演共用同一套最终人物归属契约：统一时间轴、人物候选、声纹与主动说话证据融合、无法确认时保留“发言人待确认/画外发言人”，最后由 Java 持久化。

## 7. 上线门禁

满足以下条件后，才能把影子人物结果公开给用户：

1. 真实长视频人物数量、身份锚点和时间线人工抽检通过。
2. 40 分钟仅作为无响应进程的看门狗，不参与成功结果的发布资格判定。模型报错、进程非零退出、结果契约损坏时立即失败，不等待看门狗到期。
3. 同机并发、崩溃恢复、磁盘清理和进程树内存监控通过。
4. Windows/WSL2 或目标 Linux 机器必须在目标硬件上重新执行完整门禁。
5. Java 终态与历史人工修正不被旧模型结果覆盖。
6. 显式打开发布开关前，前端继续只显示可靠的未知人物状态。
