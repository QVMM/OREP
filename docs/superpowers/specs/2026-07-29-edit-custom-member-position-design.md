# 团队成员页支持编辑自定义岗位

## 背景

创建团队时已经支持教师输入自定义岗位并保存到当前租户岗位库，但团队工作台“成员”页仍使用固定原生下拉框。团队创建后，教师无法把选手岗位修改为岗位库之外的新角色，两个入口的能力不一致。

## 目标

- 在团队工作台成员表格中搜索和选择已有岗位。
- 允许教师输入新岗位并立即保存。
- 新岗位保存到当前租户岗位库，当前页面其他成员可立即复用。
- 岗位确认后自动更新成员信息，不增加额外保存按钮。
- 与创建团队页保持一致的校验、反馈和视觉体验。

## 非目标

- 不修改系统角色和团队角色规则。
- 不开放指导教师的岗位编辑。
- 不提供岗位库的重命名、删除、停用或排序管理。
- 不修改数据库结构或现有后端接口。

## 交互设计

成员表格“岗位”列的原生 `select` 替换为 Element Plus 可创建选择器：

1. 点击后展示当前租户岗位库。
2. 输入关键词时过滤已有岗位。
3. 输入内容与已有岗位不完全相同时，可确认创建。
4. 选择已有岗位后立即更新该成员岗位。
5. 创建新岗位时，先保存岗位库，再更新该成员岗位。
6. 新岗位成功保存后加入当前页面选项，其他成员无需刷新即可选择。
7. 保存期间只禁用当前成员的岗位选择器。
8. 队长和普通成员允许编辑，指导教师保持禁用。

## 数据流

选择已有岗位：

```text
选择岗位
  → PATCH /api/project-teams/{teamId}/members/{memberUserId}/position
  → 更新成功提示
```

创建新岗位：

```text
输入并确认新岗位
  → POST /api/project-teams/position-roles
  → 将返回岗位加入当前页面岗位列表
  → PATCH /api/project-teams/{teamId}/members/{memberUserId}/position
  → 更新成功提示
```

岗位名称仍作为字符串传递，不引入岗位 ID 绑定。

## 状态与校验

- 岗位名称去除首尾空格，并清理换行、制表符。
- 空白岗位不允许提交。
- 岗位名称最长 80 个字符。
- 与当前岗位库同名时直接复用，不重复创建。
- 每个成员保存自己的 `savingPosition` 状态，避免一名成员保存时锁住整张表。
- 每个成员保存 `savedRole`，用于错误时恢复界面。

## 异常处理

- 岗位库创建失败：恢复该成员原岗位，提示岗位保存失败，不调用成员更新接口。
- 成员岗位更新失败：重新加载团队数据，恢复服务端真实岗位；已经成功创建的新岗位保留在岗位库中。
- 页面数据重新加载后，岗位选项从团队仪表盘的 `positionRoles` 重新获取。
- 成功提示使用页面现有通知机制；错误使用页面现有错误栏。

## 验证

契约测试覆盖：

- 成员岗位使用可搜索、可创建选择器。
- 新岗位通过岗位创建接口保存。
- 新岗位成功后加入当前页面岗位选项。
- 成员岗位通过现有更新接口保存。
- 空白和 80 字符限制存在。
- 指导教师岗位仍不可编辑。

构建与浏览器验证：

- 运行教师端全部契约测试。
- 运行教师端生产构建。
- 在 `/teacher/team/3?tab=members` 创建一个新的验证岗位。
- 将该岗位分配给一名普通成员。
- 为另一名成员打开岗位选择器，确认新岗位可复用。
- 刷新页面，确认成员岗位和岗位库选项均已持久化。
