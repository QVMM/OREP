# 启发·竞赛大脑产品价值提炼 Skill 设计

## 1. 目标

创建一个可被 Codex 自动发现的专属 skill，用于从产品代码、页面、文档、赛事规则和用户资料中提炼“启发·竞赛大脑”的完整产品价值体系，并生成可直接用于 Web 首页的文案母本。

最高层价值主张为：**以真实成长赢得比赛。**

学生必须通过平台真正学到东西、完成真实项目工作、形成可迁移的能力；比赛成绩是这些成长经得住检验的结果。

## 2. 产品价值顺序

价值排序按真实受益程度，不按付费权、决策权或组织级别：

1. 参赛学生：学会、做成、复盘并在真实任务中持续进步。
2. 指导教师：看见真实问题，作出专业判断，实施有针对性的指导。
3. 校领导：看见备赛质量、学生成长和人才培养成果。
4. 学校：沉淀项目、方法、证据与可复用的人才培养能力。

教师和组织价值必须由学生的真实成长自然推导，不能反过来用采购话术覆盖学生价值。

## 3. 品牌声音

文案声音融合三种特质：

- 教育理想主义者的底色：相信人的成长，关心学生究竟获得了什么。
- 冠军教练的判断力：直面问题，强调训练、反馈、修改、复验与结果。
- 产品大师的克制：不煨情，不堆概念，不用形容词代替事实。

文案应该有判断、画面、节奏与情感，但所有高度都必须回到可验证的产品行为和学生成长。

## 4. 技能架构

技能采用混合型架构：自身包含产品事实、价值提炼方法、品牌声音和输出合同；通用营销技能只作为可选增强，不构成运行依赖。

安装位置：`~/.codex/skills/competition-brain-positioning/`

```text
competition-brain-positioning/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   ├── product-truth.md
│   ├── value-extraction.md
│   ├── voice-and-quality.md
│   └── output-contracts.md
└── scripts/
    └── lint-copy.py
```

### 4.1 `SKILL.md`

定义发现关键词、必须执行的端到端流程、资料路由、停止条件和最终输出顺序。主文件保持精简，详细方法下沉至 `references/`。

### 4.2 `product-truth.md`

记录已确认的品牌名称、目标赛事、价值顺序、最高主张、当前产品机制、能力边界与不可编造的声明。它是产品事实的基线，不硬编未被证明的竞赛结果。

### 4.3 `value-extraction.md`

定义从产品能力到学生价值的推导链，以及对核心命题的反向压力测试。

### 4.4 `voice-and-quality.md`

定义品牌人格、句式节奏、用词偏好、反例、去 AI 腔规则和中文成稿质量门槛。

### 4.5 `output-contracts.md`

定义完整价值母本的标准结构，以及 Web 首页、宣传册、汇报 PPT 等下游载体如何从母本派生。

### 4.6 `lint-copy.py`

执行确定性文本检查，至少覆盖：常见中文 AI 套话、官方空话、过量对称排比、不可证明的绝对化词语、疑似虚构数字与高频形容词。脚本只负责机械检查，不代替编辑判断。

## 5. 运行流程

### 5.1 事实采矿

优先阅读当前代码库中的首页、功能页、产品文档、赛事规则和用户明确提供的信息。生成事实账本：

- 已证实：产品当前真实具备。
- 可推导：有较强依据，但需要用户或数据确认。
- 待补证：具有宣传价值，但尚缺少证据。
- 禁止声称：产品没有、无法验证或容易误导的内容。

### 5.2 建立学生价值链

对每项候选能力完成以下推导：

> 产品做了什么 → 学生因此改变什么行为 → 学会什么 → 形成什么能力 → 如何帮助比赛

无法走完这条链的功能不进入核心宣传，只能作为辅助能力或待验证假设。

### 5.3 寻找唯一核心

从价值链中提炼一句能统领整个产品的核心命题。母命题为“以真实成长赢得比赛”，但每次仍必须检查：

1. 竞争对手是否也能原样使用。
2. 当前产品行为是否能够证明。
3. 参赛学生是否能立即理解。
4. 是否能统领项目、训练、材料、路演、反馈和复验。

命题失败时，回到价值链重新提炼，不用更华丽的句子掩盖逻辑缺口。

### 5.4 构建价值体系

围绕学生、指导教师、校领导和学校逐层展开。每一层都必须说明目标对象、原有困境、行为变化、实际收获和可信证据。

### 5.5 成稿

产生三个不同角度的核心表达，内部对比其真实性、区分度、学生相关性、统领力和中文质感，最终只推荐一个主方向，并保留不超过两个有明确取舍的备选。

### 5.6 反向审稿

分别从参赛学生、指导教师、怀疑者和中文主编四种视角复审。对每一句核心文案追问：

1. 它说的是什么事实？
2. 它为什么值得学生在意？
3. 凭什么相信？

审稿失败时必须回到对应阶段修订，不得只删除几个 AI 高频词便宣布合格。

## 6. 标准交付物

完整运行必须交付一份“产品价值母本”，包含：

1. 一句话产品定位。
2. 核心价值命题。
3. 价值主张阐释。
4. 学生、指导教师、校领导、学校四层价值。
5. 核心功能到真实价值的映射。
6. 典型应用场景与使用前后变化。
7. 差异化与真实替代方案比较。
8. 品牌宣言与品牌声音。
9. Web 首页信息架构。
10. Hero、功能区、场景区、证明区和 CTA 文案。
11. 已证实事实、待验证假设与待补证据清单。

当用户只请求其中某个交付物时，skill 仍必须完成必要的事实核对和价值链推导，但只输出用户请求的部分。

## 7. 异常处理

- 资料不足：交付可用的第一版，明确标记假设、证据缺口与对结论的影响。
- 资料冲突：优先采用用户当前明确确认的信息，其次是可运行产品行为，再其次是最新产品文档，最后是历史文案。
- 功能缺少学生价值链：降级为辅助能力或待验证假设，不强行进入核心宣传。
- 主张无法证明：删除、改成可验证表达，或列入待补证据。
- 只有气势没有信息：判定为不合格，回到价值链与事实账本重新提炼。

## 8. 质量门槛

最终产物必须同时满足：

- 真实：没有虚构数字、案例、能力和比赛结果。
- 锋利：核心主张不能被任意教育 AI 产品原样照搬。
- 学生优先：每项核心价值最终落到学生学会了什么、完成了什么或形成了什么能力。
- 完整：能够统领项目、训练、材料、路演、反馈与复验。
- 克制：不依靠宏大形容词和政策口号制造高级感。
- 有人味：朗读自然，有节奏、观点和适度的不对称，不像模板拼装。
- 可落地：价值母本能够直接派生首页、宣传册和汇报材料。

## 9. 验证设计

按 skill 创作的 RED-GREEN-REFACTOR 流程验证。

### 9.1 RED 基线场景

在不提供新 skill 的情况下，要求独立代理完成：

1. 从当前代码和首页提炼完整产品价值体系。
2. 将一组零散功能统一成一个核心命题。
3. 将一版典型 AI 腔宣传稿改写为克制、有判断的产品文案。

记录基线输出中的具体缺陷，包括功能罗列、采购话术压过学生价值、无证据主张、套话、过度排比或缺少唯一核心。

### 9.2 GREEN 技能场景

用相同任务加载新 skill，检查是否真正改变了代理的研究、提炼和写作行为，而不是只在结果中多出几个标题。

### 9.3 REFACTOR

对比基线与加载 skill 的输出，根据仍存在的跳步、偷懒或风格漂移修订技能，重新执行测试。

## 10. 范围边界

本设计只负责产品价值提炼与宣传文案母本，不包含：

- 直接修改当前 `Intro.vue` 或首页视觉设计。
- 虚构用户证言、获奖数据、客户数量或转化效果。
- 把通用营销框架原样搬进技能。
- 自动发布文案或修改生产环境。

## 11. 完成定义

1. 用官方 `init_skill.py` 生成技能目录。
2. 技能目录符合 Agent Skills 结构与命名规则。
3. `quick_validate.py` 验证通过。
4. `lint-copy.py` 包含至少一个先失败、后通过的确定性测试。
5. 三类前向测试完成，并与无 skill 基线输出对比。
6. 技能能被 Codex 发现，且不依赖第三方技能也可完整运行。
