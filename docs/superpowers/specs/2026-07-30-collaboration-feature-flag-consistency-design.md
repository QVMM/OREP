# 协作功能开关一致性修复

## 问题

协作功能由前端 `VITE_COLLABORATION_ENABLED` 和后端 `OREP_COLLABORATION_ENABLED` 两个开关共同控制，但二者默认值不一致：

- 开发前端默认开启，生产前端默认关闭。
- 后端在没有显式环境变量时默认关闭。
- Spring Boot 不会自动读取项目中的 `.env.local`，导致本地前端能打开浮窗，但接口返回功能未启用。

## 方案

采用“默认启用、允许显式关闭”的统一策略：

- 前端在未设置 `VITE_COLLABORATION_ENABLED` 时默认启用。
- 后端在未设置 `OREP_COLLABORATION_ENABLED` 时默认启用。
- 两端仍接受环境变量值 `false`，用于紧急关闭。
- 不修改协作接口、数据结构、任务逻辑和完整协作台路由。

## 验收标准

1. 本地未配置协作环境变量时，点击侧栏入口弹出协作浮窗。
2. 本地协作接口不再返回“协作功能尚未启用”。
3. 线上未注入前端构建变量时，点击协作入口仍弹出浮窗。
4. 显式设置任一端开关为 `false` 时，原有关闭机制仍有效。
5. 协作任务加载、发起多人协作和完整协作台入口回归通过。

## 发布

- 更新前端生产构建并部署用户端容器。
- 更新后端默认配置；线上已有显式 `OREP_COLLABORATION_ENABLED=true`，行为保持开启。
- 重启本地后端，使新的默认配置即时生效。
