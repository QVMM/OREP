# 统一媒体证据流水线检查与验收方案

**对应设计：** `docs/superpowers/specs/2026-07-14-unified-media-evidence-pipeline-design.md`  
**用途：** 开发检查点、测试设计、影子运行、上线门禁和事故排查  
**原则：** 任何一项 P0 门禁失败，禁止进入下一放量阶段

## 1. 检查等级

- **P0：** 影响正式分权威性、证据完整性、数据安全、录音完整性或任务终态，失败即阻断发布。
- **P1：** 影响说话人准确性、性能、恢复能力或用户理解，失败不得全量发布。
- **P2：** 影响运营效率、诊断信息或非核心体验，可在明确期限内补齐。

## 2. 开发前基线检查

### P0

- [ ] 保存当前主分支/工作区真实长视频结果，记录正式分、15 个观测点、扣分账目、待办、9 位评委和证据数量。
- [ ] 对 `/Users/liuyixing/Movies/Videos/e9df998256bca0a6cbba604c1390330e.mp4` 记录当前各阶段耗时。
- [ ] 对 `/Users/liuyixing/Movies/Videos/e2c9e380898472f1d3418172b72e6bad.mp4` 记录当前各阶段耗时。
- [ ] 保存会话 26 已有结果和媒体 hash，用于不重跑视频的回放测试。
- [ ] 确认当前评分规则版本、赛道绑定和 Python/Java 回调契约版本。
- [ ] 确认工作区不是 Git 仓库时，采用文件级备份、功能开关和结果快照作为回滚手段，禁止假设可以 `git reset`。

### P1

- [ ] 记录当前 ASR 分片数、视觉选中帧数、视觉批次数和各阶段 tokens。
- [ ] 记录当前页面从上传完成到 100% 的真实耗时，不只使用 Python 日志耗时。
- [ ] 记录外部 API 并发配额、QPS、单任务时长和地域限制。

## 3. 架构边界检查

### P0：证据层无评分权

- [ ] `EvidenceCandidate` 和 `EvidencePackage` schema 不含 `overall_score`、`dimension_score`、`deducted_points`、`max_recoverable_points`、`predicted_score`。
- [ ] 证据层输出禁用字段时契约校验失败，不能只记 warning。
- [ ] 视频内部 `gesture.score/posture.score` 进入统一证据包前已改名为信号值或置信度。
- [ ] `speaker_scoring_service` 输出不参与 evidence snapshot hash、官方总分、扣分和可追回分。
- [ ] 只有正式评分服务和规则执行器可写 observation/deduction/score projection。

### P0：统一流程

- [ ] 上传与在线使用同一 `EvidencePackage` schema 和版本。
- [ ] 来源差异只存在于 source/provider 层，不扩散到评分和报告字段。
- [ ] 相同证据包不因来源类型不同产生不同的评分输入序列。
- [ ] Java 持久化与报告 API 对两种来源使用同一套表和 DTO。

## 4. 媒体输入检查

### P0

- [ ] 用 ffprobe 校验真实编码、容器、时长、采样率、声道、音视频轨数量和旋转信息。
- [ ] 文件扩展名与实际编码不一致时按真实编码处理或明确失败。
- [ ] 多音轨文件明确选择音轨，不能默认把无声轨或系统音轨当主音频。
- [ ] 标准音频为 16 kHz、16 bit、单声道，并保存转码时间偏移。
- [ ] 空文件、零时长、无音轨、损坏尾部和部分上传文件有明确错误码。
- [ ] 媒体 hash 在处理前后可追溯，不能因移动路径改变事实身份。

### P1

- [ ] 可变帧率视频的画面时间与音频时间对齐。
- [ ] 手机旋转视频在关键帧和播放页方向一致。
- [ ] 一小时高码率视频不会整体载入 Python/JVM/浏览器内存。
- [ ] Range 播放和 AI 处理使用同一媒体资产版本。

## 5. 上传视频 ASR 与说话人分离检查

### P0

- [ ] 离线 Fun-ASR 实际返回 `speaker_id`，不是 SDK 接受参数但模型忽略参数。
- [ ] 说话人分离在整场音频上保持全局一致。
- [ ] 若采用分片，必须有跨片 embedding 聚类；禁止直接拼接每片 `SPEAKER_0/1`。
- [ ] `speaker_count` 只是参考，返回人数不等于提示人数时不得裁剪结果。
- [ ] ASR 失败不再自动把全部片段伪装为 `SPEAKER_0`。
- [ ] 时间戳统一为毫秒，开始时间小于结束时间且整体单调。
- [ ] 分片合并没有重复句、丢句和时间偏移累积。
- [ ] 转写覆盖率低于门禁时状态为 `evidence_incomplete`，不能进入完整成功。

### P1

- [ ] 同一人远近、朝向、扩音变化时检查是否被错误拆簇。
- [ ] 相似声音检查是否被错误合并。
- [ ] 2 秒以内短发言标记置信度不足，不强制做身份匹配。
- [ ] 主持人、评委和团队成员均可保留，不受 team size 裁剪。
- [ ] 背景宣传片、人声播放和现场真人声音有来源标识或低置信度提示。
- [ ] 多人同时发言被标为 overlap，不整段归属一人。

## 6. 在线路演实时网关检查

### P0：录音优先

- [ ] 关闭听悟连接时本地录音持续且 hash/时长正确。
- [ ] 关闭 Omni 连接时本地录音和听悟持续。
- [ ] 模拟云端慢响应时浏览器到本地的音频采集不被反压。
- [ ] 本地写盘失败立即进入媒体故障，不继续伪装录音正常。
- [ ] 浏览器刷新、短断网和 WebSocket 重连后序号不倒退、不冲突。

### P0：顺序与幂等

- [ ] 每个 PCM 块有 sequence、start/end、payload hash。
- [ ] 重复 sequence+hash 只处理一次。
- [ ] 相同 sequence 不同 hash 触发冲突告警。
- [ ] 乱序块被重排或明确拒绝，不能静默改变时间线。
- [ ] 会议停止事件幂等，重复停止不重复触发供应商会后计费。

### P1：实时语义

- [ ] Omni 只输出证据候选，不输出正式分。
- [ ] 连接轮换时阶段摘要可续接，原始候选已在本地持久化。
- [ ] 会议超过 Omni 原始音频上下文后不会丢失已保存候选。
- [ ] 文本输出模式关闭音频回复，避免会议现场回声和无意义费用。
- [ ] 实时候选标记 `PROVISIONAL`，会后才允许 `FINAL`。

## 7. 说话人身份检查

### P0

- [ ] `rawSpeakerId` 不可由人工修正覆盖。
- [ ] 显示名称、真实姓名、角色、置信度、来源和状态独立保存。
- [ ] 无身份锚点时只显示匿名发言人，不猜姓名。
- [ ] 人工确认优先级高于所有自动映射。
- [ ] 人工否定后，同版本自动任务不能重新写回被否定身份。
- [ ] 人工修正一次后，本场所有相同原始声音簇统一更新。
- [ ] 报告审计仍能看到原始标签和映射来源。

### P1

- [ ] 自我介绍与交接语句的时间范围和对应声纹片段一致。
- [ ] 仅内容风格推断角色时显示“疑似”并降低置信度。
- [ ] 视频嘴部活动与声音不同步时不自动确认身份。
- [ ] 同项目声纹复用需要授权和租户隔离。
- [ ] 不同租户之间绝不共享声纹 embedding。

## 8. 视频与音画对齐检查

### P0

- [ ] 选中帧数量、采样策略、场景变化阈值和最大帧数与基线对账。
- [ ] 并发后输出仍按原始时间排序。
- [ ] 批次失败逐帧恢复，失败项不静默丢弃。
- [ ] 视频证据锚点跳转到真实时间，误差在约定阈值内。
- [ ] 屏幕共享与摄像头双源不能相互覆盖证据来源。
- [ ] 无视觉数据时明确缺失，不编造画面证据。

### P1

- [ ] 黑帧、转场、遮挡和重复帧不被当成独立强证据。
- [ ] OCR 文本与画面时间一致，不能把后一页文字绑定到前一段发言。
- [ ] 画面中播放的录制视频与现场动作区分来源。
- [ ] 前端视频播放的媒体版本与关键帧 hash 对应。

## 9. 证据合并与质量门禁检查

### P0

- [ ] 所有时间单位在边界处显式转换，内部统一毫秒。
- [ ] 规范 JSON hash 不包含临时 URL、凭证、日志字段和非确定性时间。
- [ ] 同输入/版本多次运行时证据数组顺序稳定。
- [ ] transcript、speaker turn、frame 和 anchor 的引用不存在悬空 ID。
- [ ] 证据候选去重按来源、时间、内容和 hash 处理，不能简单按文本相等误删重复强调。
- [ ] 完整性门禁输出明确原因：音频覆盖、视频覆盖、时间戳、分离状态、缺失阶段。
- [ ] `EvidencePackage FINAL` 后评分只读，不能被迟到实时事件原地修改。
- [ ] 人工修正生成新 snapshot/version，旧评分仍可追溯旧 hash。

### P1

- [ ] 音频和视频矛盾被保存为事实候选，不在证据层决定扣分。
- [ ] 低置信度证据不会伪装成强证据。
- [ ] 实时候选和会后候选合并时优先终版来源，保留来源审计。

## 10. 评分隔离与回归检查

### P0

- [ ] 相同旧证据快照经新适配器进入评分时，15 个观测点结构完整。
- [ ] 评分阶段 A 是唯一核心模型分来源，B/C 不改分。
- [ ] Python 继续自下而上重算维度分与总分。
- [ ] 规则执行器最终分、扣分账目和预测区间可对账。
- [ ] 缺证据封顶/不得分继续由评分规则处理，不在证据层提前扣分。
- [ ] 核心评分技术失败返回 null/review_required，不返回业务 0 分。
- [ ] B/C 截断只重跑失败阶段，不缩减 9 位评委或报告模块。
- [ ] 个人 speaker 诊断结果不改变团队正式分。

### P1

- [ ] 新说话人标签只改善人物转写和团队协作证据定位，不产生隐藏加减分。
- [ ] 旧报告重放后的权威分不被 Python 原始中间分覆盖。
- [ ] 多人格评委使用同一冻结证据快照。

## 11. Java 回调与持久化检查

### P0

- [ ] Python 同时校验 HTTP 2xx 和响应业务 `code == 200`。
- [ ] 完成回调失败自动重试并保留 payload 幂等键。
- [ ] `evidence_ready` 不把会话错误标成 completed。
- [ ] completed/failed 终态不被迟到进度覆盖。
- [ ] failed 允许有效 completed 重放恢复报告。
- [ ] 进度百分比不倒退。
- [ ] 同一 session completed 重放不会重复插入报告、segment、frame、identity 或 anchor。
- [ ] 大 JSON 字段类型在 Python/Java DTO 一致，避免反序列化失败被 HTTP 200 掩盖。
- [ ] 回写重试耗尽明确进入 `RESULT_WRITEBACK_FAILED`。

### P1

- [ ] 阶段 job 保存 provider、attempt、input/output hash 和 duration。
- [ ] 错误信息用户可理解，日志保留 requestId 供供应商排查。
- [ ] 会话状态、报告状态、stage job 状态之间不存在矛盾终态。

## 12. 并发、限流和资源检查

### P0

- [ ] 并发任务使用有界线程池/协程信号量，不创建无限任务。
- [ ] 每个供应商有独立并发和速率限制。
- [ ] 429/5xx 使用有限指数退避和随机抖动。
- [ ] 重试不重复计入已完成进度，不重复写入结果。
- [ ] 所有临时文件在成功、失败、取消路径均清理。
- [ ] 任务取消不会删除仍被其他阶段引用的共享文件。
- [ ] 单场 60 分钟视频峰值内存、磁盘和文件句柄在部署预算内。

### P1

- [ ] ASR 与视觉真正存在时间重叠，不是代码声明 async 但内部阻塞事件循环。
- [ ] CPU 密集转码、hash 和本地模型不运行在 FastAPI 主事件循环。
- [ ] 视觉默认并发 3 在供应商配额内，不因 429 反而变慢。
- [ ] 三阶段评分保持依赖顺序，不做竞争分数并发。
- [ ] 多会话并发时单个大任务不能饿死其他会话。

## 13. 临时 OSS 与本地部署检查

### P0

- [ ] OSS bucket 私有，禁止匿名 list/get。
- [ ] 只上传派生单声道音频，不上传原始视频。
- [ ] 对象名随机，不含项目名、姓名、手机号或赛道敏感信息。
- [ ] 使用最小权限 RAM/STS，凭证不硬编码。
- [ ] 签名 URL 短时有效，日志和数据库不保存完整 URL。
- [ ] 成功、失败、超时均触发删除。
- [ ] 定时清理能删除孤儿对象并产生审计记录。
- [ ] `CLOUD_AUDIO_PROCESSING_ENABLED=false` 时没有任何隐藏云端回退。

### P1

- [ ] 上传带宽和 OSS 上传耗时计入端到端指标。
- [ ] OSS 地域与模型地域兼容，避免跨区延迟和数据合规问题。
- [ ] 删除失败有重试和告警，不阻塞已完成报告但必须可追踪。

## 14. 失败注入检查

每种故障都必须自动化或脚本化复现：

### P0

- [ ] 浏览器实时 WebSocket 在第 10 分钟断开并重连。
- [ ] 听悟连接断开 30 秒。
- [ ] Omni 返回 429、500 和超时。
- [ ] 离线 ASR 任务提交成功但轮询长期不完成。
- [ ] 离线 ASR 返回成功但结果 JSON URL 下载失败。
- [ ] 视觉第 N 批失败并逐帧恢复。
- [ ] 阶段 A/B/C 分别返回截断 JSON。
- [ ] Java 返回 HTTP 200 但业务 code 非 200。
- [ ] 完成回调成功后再到达旧 95% 进度。
- [ ] 服务在 `EVIDENCE_FINALIZING` 和 `WRITING_BACK` 阶段分别重启。
- [ ] 磁盘空间不足和临时文件删除失败。

验收要求：录音事实不丢、终态不乱、失败阶段可重试、页面不无限停留、日志可定位。

## 15. 性能检查方案

### 15.1 计时边界

- 上传视频：从 Java 标记上传完成并成功派发任务，到报告 API 返回 completed。
- 在线路演：从会议停止事件被服务端确认，到报告 API 返回 completed。
- 上传文件本身耗时单独记录，不混入 AI 分析耗时。
- Python 内部耗时、Java 回调耗时和前端可见耗时同时记录。

### 15.2 阶段预算

| 场景 | 阶段 | P95 预算 |
|---|---|---:|
| 上传 | 标准化 | 1 分钟 |
| 上传 | 并行证据提取 | 7 分钟 |
| 上传 | 合并门禁 | 1 分钟 |
| 上传 | 正式评分 | 5 分钟 |
| 上传 | 回写 | 1 分钟 |
| 在线 | 会后终结与校正 | 4 分钟 |
| 在线 | 合并门禁 | 1 分钟 |
| 在线 | 正式评分 | 5 分钟 |
| 在线 | 回写 | 1 分钟 |

### 15.3 首期真实回归

- [ ] 两个真实长视频分别至少运行 3 次，记录冷启动和热启动。
- [ ] 会话 26 使用保存结果做回调回放，确认无需重跑媒体。
- [ ] 构造一场约 60 分钟在线会议录制，检查会后耗时。
- [ ] 首期样本不足时不宣称统计意义上的 P95，只报告每次实测值。
- [ ] 影子运行积累至少 20～30 场后再发布 P50/P95。

### 15.4 性能发布门禁

#### P0

- [ ] 60 分钟上传视频受控实测每次不超过 15 分钟。
- [ ] 60 分钟在线路演会后受控实测不超过 12 分钟。
- [ ] 没有任何任务无明确状态挂起 30 分钟。
- [ ] 帧数、分片数、15 个观测点、9 位评委和完整报告模块与基线一致。
- [ ] 性能提升不是通过降低 tokens 上限造成截断风险。

## 16. 数据真实性与人工抽查

不建设永久黄金样本集不等于不做质量检查。首期使用真实会话人工抽查：

### P0

- [ ] 随机抽取至少 30 个发言片段，核对时间、原文和视频跳转。
- [ ] 抽取所有说话人切换点附近片段，检查明显串人。
- [ ] 抽取所有 overlap 和低置信度片段，确认没有强行实名。
- [ ] 抽取正式扣分引用的证据，确认来自冻结证据包且时间可定位。
- [ ] 抽取无证据扣分，确认其语义是“证据缺失”，不是伪造时间锚点。

### P1

- [ ] 统计检测说话人数与人工观察人数的差异。
- [ ] 统计人工修正次数、修正后传播范围和再次被覆盖次数。
- [ ] 对同一项目再次路演检查映射复用是否经过授权且置信度合理。

## 17. 前端验收

### P0

- [ ] 用户端始终只显示一个正式 AI 分数。
- [ ] 实时临时证据不显示正式扣分或提分承诺。
- [ ] 说话人未知时显示“发言人待确认/1号发言人”，不虚构角色。
- [ ] 说话人分离失败有明确状态，不把全场显示为已确认同一人。
- [ ] 点击转写、事件和章节定位到同一视频时间轴。
- [ ] 人工修正一次全场更新，刷新后仍然存在。
- [ ] 结果页、待办页、依据页使用同一报告权威分。

### P1

- [ ] 在线路演会中状态与会后终版状态语言清楚。
- [ ] 页面不会长时间停留在虚假 95%，显示真实阶段与最近更新时间。
- [ ] 右侧大量人物转写滚动性能可接受，不一次渲染全部长列表。

## 18. 安全与合规验收

### P0

- [ ] 声纹复用有租户策略和授权开关。
- [ ] 未授权场景不持久化跨场 voice embedding。
- [ ] 删除会话时按产品策略删除临时云对象和本地派生音频。
- [ ] API 鉴权覆盖视频、转写、身份修正和证据包接口。
- [ ] 用户 A 不能访问用户 B 的媒体、转写或声纹映射。
- [ ] 日志脱敏检查通过。

## 19. 影子运行与放量检查

### 影子阶段

- [ ] 新旧流同时跑，新流不改变正式报告。
- [ ] 对比证据覆盖、说话人数、耗时、失败率和 API 成本。
- [ ] 新流技术失败自动回到旧流，用户无额外失败。

### 10% 阶段

- [ ] 仅按会话 feature flag 开启。
- [ ] 每日检查 P95、失败率、人工修正率和回写失败。
- [ ] 任一 P0 异常立即关闭开关。

### 30% 阶段

- [ ] 至少跨多个赛道、不同团队人数和不同录音环境。
- [ ] 没有出现规则版本、证据 hash 或报告分数串场。

### 100% 阶段

- [ ] 连续观察窗口内满足性能和稳定性门禁。
- [ ] 回滚手册、值班告警和孤儿对象清理已验证。
