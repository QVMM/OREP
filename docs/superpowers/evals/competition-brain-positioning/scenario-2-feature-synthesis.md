# Scenario 2 — 散乱功能的价值综合

## 输入

以下是本场景可使用的全部产品信息。每项定义只说明中性输入、输出或边界，不预设其价值排序：

| 功能或诉求 | 中性定义与边界 |
| --- | --- |
| 项目工作台 | 汇集一个参赛项目的成员、材料、任务和状态；不代表材料质量已经被判断。 |
| 按日训练 | 接收每日训练安排与完成记录，输出按日期组织的训练记录；不保证训练计划本身有效。 |
| 课程 | 提供课程内容及学习记录；课程与具体参赛项目如何关联未给出。 |
| 考试 | 接收作答并形成考试结果记录；考试结果不等同于竞赛结果。 |
| PPT/讲稿版本 | 保存 PPT 或讲稿的多个版本及版本信息；不自动说明哪个版本更好。 |
| 线上路演 | 支持一次远程展示活动及其过程记录；参与方式与评价规则未给出。 |
| 上传视频评分 | 接收展示视频并形成评分或反馈记录；评分主体、方法与准确性未给出。 |
| 证据锚点 | 将某条评价关联到材料或视频中的具体位置；锚点只提供可追溯位置，不证明评价本身正确。 |
| 教师审核 | 接收待审核内容并记录教师的审核意见或状态；审核时效与结论效力未给出。 |
| 整改任务 | 将待改问题记录为任务并跟踪状态；任务建立不代表整改已完成或有效。 |
| 下一轮复验 | 对更新后的材料或表现再次记录检查结果；不保证结果必然改善。 |
| 校领导希望统一看进展 | 组织管理诉求，不等同于已实现的产品能力；是否进入核心价值需要判断。 |
| 管理员希望统一入口 | 运营管理诉求，不等同于已实现的产品能力；是否进入核心价值需要判断。 |

## 任务

将这些散乱功能综合为一套产品价值表达：找到**一个统一核心命题**，并把每项功能映射到实际受益人与价值。你需要自行确定受益人排序、功能之间的关系与价值层级，并说明两项组织管理诉求在整体价值体系中的位置。

最终产物必须包含：

1. 一句话核心命题；
2. 实际受益人、各自问题与产品价值，并说明受益人排序；
3. 功能之间关系及其价值层级的说明；
4. 全部功能到实际受益人与价值的映射，并处理两项组织管理诉求；
5. 一段可用于产品介绍页的克制中文文案；
6. 必要的假设与无证据主张清单。没有则明确写“无”。

## 约束

- 不得用重新排序的功能清单代替综合；必须解释映射关系。
- 不得声称输入未提供的能力、自动化程度、准确率、效果、成绩或案例。
- 不得把组织诉求直接当作已实现功能。
- 只返回最终产物，不描述思考过程，不向用户提问。
