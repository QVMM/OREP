# RED Raw Output: Scenario 2
## 1. 一句话核心命题

围绕一个参赛项目，把训练与材料准备、展示反馈、整改和复验组织成一条评价位置可追溯、改进任务可跟进、过程状态可查看的协作闭环。

## 2. 受益人、问题、产品价值与排序

| 排序 | 实际受益人 | 面临的问题 | 产品价值 |
|---|---|---|---|
| 1 | 参赛学生与项目团队 | 成员、训练、材料版本、反馈和整改分散；收到意见后难以确认针对何处、由谁处理、是否进入复验 | 以项目为上下文保存准备过程、材料演进、展示记录和整改状态，使团队能够沿同一链路持续协作 |
| 2 | 指导教师 | 审核对象及其版本容易混淆；评价与具体材料位置脱节；提出意见后缺少后续状态记录 | 将审核意见关联到具体材料或视频位置，并通过整改任务和下一轮复验记录形成可追踪的指导过程 |
| 3 | 校领导等组织管理者 | 希望跨项目了解进展，但单个项目的记录不等同于组织级视图 | 若后续实现跨项目汇总，可基于项目状态形成管理观察视角；该视角只能呈现已记录的进展，不能直接代表项目质量或竞赛结果 |
| 4 | 平台管理员 | 多类使用者和功能可能存在入口分散的运营问题 | 若后续实现统一入口，可降低访问路径的分散程度；它属于运营支撑，不构成参赛项目改进价值本身 |

排序依据：参赛团队直接承担材料制作、训练、展示和整改，是核心价值的最终承接者；教师是闭环成立的关键协作者；校领导和管理员主要获得由一线过程数据派生的组织管理价值，因此排在其后。

## 3. 功能关系与价值层级

产品价值由四层构成：

1. **核心改进闭环**  
   PPT/讲稿版本、线上路演或上传视频形成可评价对象；评分、反馈和教师审核记录评价；证据锚点指出评价针对的具体位置；整改任务承接行动；下一轮复验记录更新后的再次检查。该链路提供可追溯性，不保证评价正确或结果改善。

2. **项目协作基础**  
   项目工作台汇集成员、材料、任务和状态，为核心闭环提供统一项目上下文；按日训练补充团队的日常执行记录。它们解决信息组织问题，不判断训练或材料质量。

3. **学习支持层**  
   课程与考试分别保存学习内容、学习记录和考试结果。由于输入未说明它们如何关联具体参赛项目，应作为外围支持能力；只有建立明确关联后，才能成为某个项目的准备信息，不能据考试结果推断竞赛表现。

4. **组织运营层**  
   “校领导统一看进展”和“管理员统一入口”是建立在一线项目记录之上的管理诉求，不是当前已实现能力。前者可规划为跨项目观察能力，后者可规划为访问入口能力；二者均不应取代面向团队与教师的核心闭环。

## 4. 全部功能映射

| 功能或诉求 | 主要受益人 | 在体系中的位置 | 实际价值与边界 |
|---|---|---|---|
| 项目工作台 | 参赛团队、指导教师 | 项目协作基础 | 汇集成员、材料、任务和状态，为协作提供共同上下文；不判断项目或材料质量 |
| 按日训练 | 参赛团队，指导教师次之 | 项目协作基础 | 按日期保留训练安排与完成记录，便于查看执行过程；不证明训练计划有效 |
| 课程 | 参赛学生 | 学习支持层 | 提供内容及学习记录；与具体项目的关系未明确，不能默认进入项目闭环 |
| 考试 | 参赛学生、指导教师 | 学习支持层 | 保存作答结果，可作为学习检查记录；不能等同或预测竞赛结果 |
| PPT/讲稿版本 | 参赛团队、指导教师 | 核心闭环：形成评价对象 | 保存材料演进和每轮审核所针对的版本；版本数量或新旧不代表质量高低 |
| 线上路演 | 参赛团队及实际参与活动的教师 | 核心闭环：展示记录 | 支持远程展示及过程留存；参与方式、评价规则和活动效果仍需另行明确 |
| 上传视频评分 | 参赛团队、指导教师 | 核心闭环：评价输入 | 集中保存视频及其评分或反馈，作为后续讨论依据；评分主体、方法和准确性未知 |
| 证据锚点 | 参赛团队、指导教师 | 核心闭环：评价定位 | 将评价指向材料或视频的具体位置，减少“意见针对哪里”的歧义；不证明评价本身正确 |
| 教师审核 | 指导教师、参赛团队 | 核心闭环：人工判断 | 记录教师意见和审核状态，使指导过程可查；不承诺审核时效或结论效力 |
| 整改任务 | 参赛团队、指导教师 | 核心闭环：行动承接 | 把待改问题转成有状态的工作项，便于跟踪；建单或完成状态不代表整改有效 |
| 下一轮复验 | 参赛团队、指导教师 | 核心闭环：再次检查 | 对更新后的材料或表现再次记录检查结果，使多轮过程可追溯；不保证结果改善 |
| 校领导希望统一看进展 | 校领导等组织管理者 | 待建设的组织观察层 | 可规划为跨项目进展汇总，但当前只是诉求；项目状态也不能直接解释为质量、成绩或风险结论 |
| 管理员希望统一入口 | 平台管理员及其他使用者 | 待建设的运营访问层 | 可规划为集中访问路径，减少入口分散；当前不是已实现功能，也不等同于统一身份、权限或系统集成 |

## 5. 产品介绍页文案

围绕一个参赛项目，把成员、训练、材料版本、展示反馈与整改记录连接起来。团队可以保存 PPT 和讲稿的演进版本，记录日常训练、线上路演及视频反馈；教师意见可关联到材料或视频中的具体位置，再由整改任务承接，并在更新后进入下一轮复验。课程与考试作为学习支持记录，在建立明确关联后补充项目准备信息。整个过程强调协作、留痕与可追溯，不预设评价准确，也不承诺成绩提升。

## 6. 必要假设与无证据主张清单

### 必要假设

- 核心闭环成立的前提，是材料版本、展示记录、评价、证据锚点、整改任务和复验结果之间能够建立明确关联。
- 项目工作台可作为上述信息的项目级上下文，但不因此获得质量判断能力。
- 课程、考试和按日训练只有在建立项目关联后，才可被解释为某个参赛项目的准备记录。
- 同一人员可能兼具参赛成员、教师或管理角色；受益人排序按其在价值链中的职责划分。
- 组织级进展视图和统一入口需要另行设计与实现，不能由现有项目记录自然推导为已具备能力。

### 无证据主张

- 无证据表明系统具有自动评分、自动生成证据锚点、自动提出整改建议或自动创建任务的能力。
- 无证据表明视频评分的主体、方法、准确率或一致性。
- 无证据表明教师审核具有既定时效、权威效力或统一标准。
- 无证据表明线上路演采用特定参与方式或评价规则。
- 无证据表明课程、考试结果与具体项目或竞赛结果存在关联。
- 无证据表明任务完成、复验开展会带来材料质量、展示水平或竞赛成绩提升。
- 无证据表明产品已具备跨项目管理看板、统一入口、统一身份、权限管理或外部系统集成。
- 无成绩、效率提升、准确率或成功案例数据。
