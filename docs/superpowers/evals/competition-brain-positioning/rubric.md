# Competition Brain Positioning Evaluation Rubric

本规约用于统一评审三个场景的最终产物。七个维度均须评分，不使用 N/A；每项 0–2 分，总分 14 分。最高价值锚点是“以真实成长赢得比赛”：产品价值最终应回到学生真实学会、做成并带走的能力，以及这些成长在比赛中的作用，而非只证明流程更顺畅。

## 裁决原则

### 维度边界

- **Evidence** 只评事实忠实度、来源可追溯性，以及事实与推断的边界。
- **Student priority** 只评受益人排序及学生成长的实质内容，不评成长如何被产品机制促成。
- **Core proposition** 只评是否形成一个有辨识度、能统摄产物的主导信息。
- **Value chain** 只评产品动作如何连接到学生行为、学习、能力与比赛作用，不评受益人排序或是否覆盖了全部输入。
- **Coverage** 只评任务要求与输入信息是否完整处理，不评表达是否优美或洞察是否独特。
- **Chinese voice** 只评中文语言质量与语气，不评事实真伪或结构完整度。
- **Actionability** 只评最终产物能否被目标使用者直接采用，不评主张是否有证据。

### 禁止重复扣分

同一根本缺陷只在最直接负责的维度扣分。例如，无来源的效果承诺只扣 Evidence，不能再以“夸张”重复扣 Chinese voice；遗漏一个功能只扣 Coverage，不能仅因该遗漏再扣 Value chain。只有当同一证据片段分别触发两个**相互独立**的可观察缺陷时，才可在两个维度扣分，且必须分别写明不同理由。

## 评分维度

### 1. Evidence（证据）

**可观察判据：**关键事实能否回溯到给定文件或输入；引用是否支持随后的提炼，而非只摘抄页面标题；是否把推断、假设和现有事实混写；是否新增能力、效果、成绩、数据或因果声明。

- **0 分**：关键定位主要无依据，或出现实质性虚构、与来源冲突的声明。
- **1 分**：主要事实有依据，但若干关键结论缺少锚点，或事实与推断的边界不稳定。
- **2 分**：关键事实可追溯，证据与结论之间关系明确，推断被恰当标识，且没有越过来源边界的声明。

### 2. Student priority（学生优先）

**可观察判据：**价值排序最终服务谁；学生是否只是功能接受者或宣传对象；是否明确学生学会了什么、做成了什么、形成了什么可迁移能力；是否区分已证实的成长与待验证结果；教师、学校、组织管理和技术价值是否从学生成长推导，而非挤占其主位。

- **0 分**：主要从平台、技术、学校管理或教师效率出发，学生价值缺席或仅作口号点缀。
- **1 分**：学生被列为受益者，但价值仍泛化，或与组织、教师、技术价值并列而没有清楚优先级。只说明学生“知道做什么”“信息更清楚”“协作更可追溯”等流程便利，而没有说明真实学习与能力形成，最高 1 分。
- **2 分**：学生的真实成长构成叙事重心，明确说明学生学会了什么、做成了什么、形成了什么可迁移能力，并区分已证实与待验证；教师、学校及其他受益者价值由学生成长推导。

### 3. Core proposition（核心命题）

**可观察判据：**是否只有一个清晰的主导信息；其余内容能否被该命题统摄；是否回答产品为何值得存在并说明产品价值为何导向人的真实成长；执行“把品牌名替换为任意教育 AI 产品后，这句话是否仍普遍成立”的替换测试。

- **0 分**：没有主导信息，或多个口号彼此竞争，无法判断什么是核心价值。
- **1 分**：存在主导信息，但仍较宽泛、与部分内容脱节，或替换测试下只有有限辨识度。只强调“闭环、协作、可追溯、项目进步”等通用价值，却未说明它们为何导向人的真实成长，最高 1 分。
- **2 分**：形成一个明确、有边界、有产品辨识度的主导信息，能说明产品价值为何导向人的真实成长，稳定组织其余表达，并通过品牌替换测试。

### 4. Value chain（价值链）

**可观察判据：**是否超越功能罗列；是否完整说明“产品动作 → 学生行为变化 → 学习收获 → 能力形成 → 比赛中的作用”；各段关系是否有解释；哪些是输入已证实、哪些是合理推断或待验证结果是否被明确标记。

- **0 分**：基本是功能清单或并列口号，没有解释价值如何产生。
- **1 分**：建立了部分关系，但关键连接含混、跳跃，或只用抽象概念代替机制。只写“证据 → 反馈 → 任务 → 复验”等操作闭环，最多证明流程成立，不能证明学习或能力形成，最高 1 分。
- **2 分**：完整、连贯地写出“产品动作 → 学生行为变化 → 学习收获 → 能力形成 → 比赛中的作用”，关键连接有解释，并明确标记证据、推断与待验证结果的边界。

### 5. Coverage（覆盖度）

**可观察判据：**是否处理场景要求的所有交付项；是否覆盖给定功能或来源中的重要信息；是否存在结构性遗漏；删减是否针对纯口号而非必要事实。

- **0 分**：遗漏多数关键输入或交付项，产物不能回答任务。
- **1 分**：覆盖主体内容，但遗漏至少一个重要输入、板块或必要约束。
- **2 分**：完整处理任务要求与重要输入；必要删减有合理边界，没有结构性缺口。

### 6. Chinese voice（中文表达）

**可观察判据：**空泛修饰是否多于实质信息；是否依赖机械、整齐的排比制造气势；是否使用能承载判断的具体动作；自然朗读时是否像成熟中文而非模板拼接；整体是否克制、有教育判断。

- **0 分**：空泛修饰和整齐排比主导文本，缺少具体动作，朗读明显生硬或模板化。
- **1 分**：整体可读且有部分具体表达，但仍有空转句、机械节奏或语气不稳定。
- **2 分**：语言自然、克制、准确，具体动作与判断相互支撑，朗读流畅且没有依赖口号制造价值感。

### 7. Actionability（可行动性）

**可观察判据：**交付形式是否适配场景；信息层级与对应关系是否明确；目标使用者是否无需补做关键判断即可采用。

- **0 分**：停留在理念或散点表达，无法用于场景指定用途。
- **1 分**：基本可用，但仍缺少关键层级、映射、顺序或成稿质量，需要明显补充。
- **2 分**：形式与内容均可直接用于场景指定用途，关键层级、映射或成稿已经明确。

## 场景适配

七个维度在三个场景中全部评分。通用定义是评分基线；下表按交付物形态细化判据，并明确 Scenario 3 的必要例外。若下表与通用判据冲突，以场景适配判据为准。

| 维度 | Scenario 1 | Scenario 2 | Scenario 3 |
| --- | --- | --- | --- |
| Evidence | 定位结论引用冻结文件中的具体证据，并区分事实与推断 | 不超出给定功能定义、边界和组织诉求 | 允许把“支持学生成长”重组为以成长为主导的编辑表达，但不得新增成长机制、可验证结果或源文没有的事实关系；不要求外部引用 |
| Student priority | 在自行判断受益人排序后，学生真实价值是否处于主位，并满足通用真实成长判据 | 是否说明各功能及组织诉求与学生价值的关系和价值层级，并满足通用真实成长判据 | **来源受限例外：**源文只提供“支持学生成长”，不要求虚构具体能力；保持学生成长为主导且不新增声明即可得 2 分 |
| Core proposition | 仅摘抄或重组现有首页最高 1 分；2 分须识别至少两个现有定位或信息架构缺陷，并基于跨文件的不同产品行为证据重建统一命题 | 散乱功能是否被一个统一命题组织 | **例外：**2 分只要求用一个清晰的编辑焦点组织原文允许事实，不执行“替换任意教育 AI 产品”测试；焦点完全脱离允许事实或只剩通用教育格言，最高 1 分 |
| Value chain | 仅摘抄或重组现有首页最高 1 分；2 分须识别至少两个现有定位或信息架构缺陷，并基于跨文件的不同产品行为证据重建能力与价值的关系，同时满足通用五段链条判据 | 各功能与学生价值之间的关系是否清楚且不靠隐藏先验，并满足通用五段链条判据 | **来源受限例外：**2 分只要求忠实呈现原文已有关系，不要求补充机制或因果；新增因果由 Evidence 裁决，不在此重复扣分 |
| Coverage | 是否同时完成定位审计、价值体系和首页信息架构，并处理边界 | 是否处理全部功能、组织诉求与其价值层级 | 是否保留允许保留的源文信息，或合理删去纯口号而不损害事实主干 |
| Chinese voice | 定位与首页表达是否自然、克制、有判断 | 综合表达是否摆脱功能说明书语气 | 成稿是否成熟、克制、有教育判断并可自然朗读 |
| Actionability | 首页结构可执行 | 功能到价值映射可执行 | 文案可直接使用 |

### Scenario 3 的 Evidence 编辑判断边界

- “比赛价值不止结果”可以作为编辑者的价值判断，但必须与产品事实区分，不得伪装成产品已经证明的事实关系。
- “训练/评分/复盘使学生持续成长”把源文并列信息改写成了具体因果，属于新增声明，必须扣 Evidence；同一缺陷不再重复扣 Value chain。
- 同理，“比赛结果只是检验”等源文没有的事实性关系不得作为产品事实写入；若仅作为价值主张，必须使用能清楚表明其判断性质的表达。

## 通过规则

总分至少达到 12/14，且 Evidence 与 Student priority 均不得为 0 分。任一硬性维度为 0 时，无论总分多少均判定不通过。

## 评审记录要求

评审必须逐项记录：

1. 维度分数（0、1 或 2）；
2. 判定理由；
3. 凡维度低于 2 分，必须逐字记录导致扣分的一个或多个原句，字段名为“扣分原句”；若因结构性遗漏扣分，记录“扣分原句：无——缺少〔具体内容〕”；
4. 总分与通过/不通过结论；
5. Evidence 或 Student priority 为 0 时，明确注明触发硬性不通过条件。

建议格式：

```text
维度：Evidence
得分：1/2
判定理由：……
扣分原句：①“……” ②“……”
```
